## 〇、大白话总览

### "导航" = 三个问题

```
① 怎么走（大方向）？   → 全局规划（A*）   —— 地图级，秒级
② 怎么躲（障碍物）？   → 局部避障（DWA）  —— 10-100ms 级
③ 怎么走准（细节）？   → 控制器（PP/MPC） —— 1-10ms 级
```

> [!note] 打个比方
> 开车去陌生城市：**导航（全局规划）**说"上高速、走 3 号出口"（大方向，秒级更新）；**看路（局部避障）**躲开前车和路障（近处反应）；**打方向盘（控制）**让车在车道里走直（毫秒级执行）。
> **"全局想得远、局部反应快、控制执行准"**——三层的时间尺度完全不同，这就是"分层"的原因。

### 和端到端的关系（全库对照）

```
传统方案（本篇）:  A* 规划 → DWA 避障 → 状态机决策 → PID 执行
端到端方案:        一个神经网络替代这一切（[[端到端自动驾驶概览]]）
```

> 💡 [[端到端自动驾驶概览]] 的 UniAD/VLA 本质上是**用神经网络替代本篇的状态机+规划器+控制器**——**先懂传统分层，才能理解端到端在"替代什么"**（这是全库最重要的"对照视角"之一）。

## 一、规划 vs 控制的层次

```
┌─────────────────────────────────────────────┐
│  全局规划 (Global Planner)    ← 地图级       │
│  A* / Dijkstra / RRT*        ← 秒级更新     │
├─────────────────────────────────────────────┤
│  局部规划 (Local Planner)     ← 10-100ms 级  │
│  DWA / TEB / Pure Pursuit     ← 避障+轨迹    │
├─────────────────────────────────────────────┤
│  控制器 (Controller)          ← 1-10ms 级    │
│  PID / Stanley / MPC          ← 执行器指令   │
└─────────────────────────────────────────────┘
```

> 循迹小车 (L1)：不需要规划，直接反馈控制。
> 导航小车 (L3+)：全局 A* 规划 → 局部 DWA 避障 → PID 执行。

> [!warning] 三层架构 = 量产车的"规划-控制"分层（面试谈资）
> **时间尺度决定分层**：全局规划秒级（地图大、更新慢）、局部避障 10-100ms（近处动态）、控制 1-10ms（执行器）。**"不同频率的任务分不同层"**——和 [[华为ADS端到端架构]] 的 PDP（决策/规划）+"小脑"（控制）分层是同一个思想，只是小车版更简单。**面试"导航架构怎么设计"= 答出这三层 + 每层算法选型。**

## 二、全局路径规划

### A* 算法

最经典的图搜索算法。在栅格地图上找从起点到终点的最短路径。

```
代价函数: f(n) = g(n) + h(n)
  g(n): 从起点到 n 的实际代价（已走路程）
  h(n): 从 n 到终点的启发式估计（直线距离）

A* 保证找到最短路径（当 h(n) 是 admissible 时）
```

```python
import heapq

def astar(grid, start, goal):
    """grid: 2D list, 0=free, 1=obstacle"""
    rows, cols = len(grid), len(grid[0])
    
    def heuristic(a, b):
        return abs(a[0]-b[0]) + abs(a[1]-b[1])  # 曼哈顿距离
    
    open_set = [(0, start)]
    came_from = {}
    g_score = {start: 0}
    
    while open_set:
        _, current = heapq.heappop(open_set)
        
        if current == goal:
            # 回溯路径
            path = []
            while current in came_from:
                path.append(current)
                current = came_from[current]
            path.append(start)
            return path[::-1]
        
        for dx, dy in [(0,1),(1,0),(0,-1),(-1,0)]:  # 四邻域
            neighbor = (current[0]+dx, current[1]+dy)
            if not (0 <= neighbor[0] < rows and 0 <= neighbor[1] < cols):
                continue
            if grid[neighbor[0]][neighbor[1]] == 1:
                continue
            
            tentative_g = g_score[current] + 1
            if tentative_g < g_score.get(neighbor, float('inf')):
                came_from[neighbor] = current
                g_score[neighbor] = tentative_g
                f = tentative_g + heuristic(neighbor, goal)
                heapq.heappush(open_set, (f, neighbor))
    
    return None  # 无路径
```

> [!note] A* 的直觉："g（已走）+ h（估的）"
> **Dijkstra** 只按"已走的路"（g）找——慢（四面开花）；**贪心** 只按"估计"（h）找——快但不保证最优（可能绕远）。**A* = g + h**：既顾"实际已走"又顾"目标方向"——**"最优 + 高效"的平衡**。**h 的"admissible"（不高估）是 A* 最优性的前提**——面试常问"为什么 A* 保证最优"（因为 h 不高估，f 不会漏掉最优路径）。

### RRT (Rapidly-exploring Random Tree)

**适用场景**：连续空间、非栅格地图、高自由度。

```python
# 简化版 RRT 思路
def rrt(start, goal, obstacles, max_iter=1000, step=0.1):
    tree = [start]  # 树节点
    parent = {start: None}
    
    for _ in range(max_iter):
        # 1. 随机采样
        if random.random() < 0.1:
            sample = goal  # 10% 概率直接朝向目标
        else:
            sample = (random.uniform(-5,5), random.uniform(-5,5))
        
        # 2. 找最近节点
        nearest = min(tree, key=lambda n: dist(n, sample))
        
        # 3. 朝采样点延伸一步
        direction = ((sample[0]-nearest[0]), (sample[1]-nearest[1]))
        length = math.hypot(*direction)
        new = (nearest[0] + direction[0]/length * step,
               nearest[1] + direction[1]/length * step)
        
        # 4. 碰撞检测
        if is_collision(nearest, new, obstacles):
            continue
        
        # 5. 加入树
        tree.append(new)
        parent[new] = nearest
        
        if dist(new, goal) < step:
            return reconstruct_path(parent, new)  # 到达目标！
    
    return None
```

> [!note] RRT 的直觉："随机撒点长树"
> **随机采样 → 找最近的树节点 → 朝采样点延伸 → 碰撞检测**——树在自由空间里"疯长"，碰到目标就回溯路径。**适用"连续空间/高维"**（A* 需要栅格，RRT 不用）；**不保证最优**（随机性）——RRT* 改进为渐进最优。**"10% 概率直接采样目标"是加速技巧**（朝向目标的偏置采样）。

### 小车用哪个？

| 场景 | 推荐算法 | 理由 |
|------|----------|------|
| 有栅格地图（SLAM 建图） | A* | 最优、确定性强 |
| 无地图、有障碍物 | RRT | 探索性好 |
| ROS2 现成方案 | `nav2` 的 Smac Planner | 基于 A* 的改进版 |
| 循迹场景 | 不需要 | PID 反馈够用 |

> [!warning] 选型逻辑（面试谈资）
> **有地图（SLAM 建了栅格图）→ A***（地图是现成的栅格，A* 最优确定）；**没地图/动态环境 → RRT**（探索）；**工程上用 nav2（内置 Smac Planner）**。**"算法选型 = 你有什么信息 × 你要什么性质"**——有图要最优选 A*，无图要探索选 RRT。

## 三、局部避障

### DWA (Dynamic Window Approach)

在速度空间 `(v, ω)` 中采样，评估每条轨迹，选最优：

```
评分 = α·朝向目标 + β·远离障碍 + γ·速度大

速度窗口 = 动力学可达速度 ∩ 安全不撞的速度
```

```python
# DWA 简化伪代码
def dwa(current_pose, goal, obstacles):
    best_score = -inf
    best_v, best_w = 0, 0
    
    for v in linspace(v_min, v_max, 20):
        for w in linspace(w_min, w_max, 20):
            # 模拟轨迹
            traj = simulate(current_pose, v, w, dt=0.1, steps=20)
            
            # 评分
            heading = score_heading(traj[-1], goal)   # 朝向目标
            clearance = score_clearance(traj, obstacles)  # 离障碍物远
            velocity = v / v_max                      # 速度快
            
            score = α * heading + β * clearance + γ * velocity
            
            if score > best_score and clearance > 0:
                best_score = score
                best_v, best_w = v, w
    
    return best_v, best_w
```

> ROS2 `nav2` 内置了 DWA 和 TEB (Timed Elastic Band)，直接用即可。

> [!note] DWA 的直觉："先模拟，再挑好的"
> **在速度空间采样（v, ω 各 20 档 = 400 条候选）→ 每条模拟一条轨迹 → 按"朝向目标 + 远离障碍 + 速度快"评分 → 选最优**。"**动态窗口**" = 只考虑"动力学可达"（当前能加速到的速度）∩ "安全"（不撞）的速度——**"模拟 + 评分 + 选择"是局部避障的通用框架**（和 [[端到端前沿2025+]] 生成式规划"采样候选评分"同构！）。

## 四、路径跟踪控制器

有了路径（waypoints 序列），怎么让车轮准确沿着路径走？

### Pure Pursuit（纯追踪）

最经典的几何路径跟踪。核心思想：车前一定距离找一个目标点，转方向盘去追它。

```
          目标点 (lookahead)
         /
        /
       /  L (前视距离)
      /
     ☆ ← 圆弧
    /
   ● (后轴中心)
```

```python
def pure_pursuit(current_pose, path, lookahead=0.5, wheelbase=0.2):
    """返回转向角"""
    # 1. 找前视距离处的目标点
    target = None
    for i, pt in enumerate(path):
        if dist(current_pose[:2], pt) >= lookahead:
            target = pt
            break
    
    if target is None:
        return 0.0
    
    # 2. 转换到车辆坐标系
    dx = target[0] - current_pose[0]
    dy = target[1] - current_pose[1]
    
    # 旋转到车体坐标
    cos_t = math.cos(-current_pose[2])
    sin_t = math.sin(-current_pose[2])
    dx_local = dx * cos_t - dy * sin_t
    dy_local = dx * sin_t + dy * cos_t
    
    # 3. 纯追踪公式: δ = arctan(2·L·sin(α) / Ld)
    #    α 是前视点到车体纵轴的角度
    alpha = math.atan2(dy_local, dx_local)
    curvature = 2 * math.sin(alpha) / lookahead
    steering_angle = math.atan(curvature * wheelbase)
    
    return steering_angle
```

> [!note] Pure Pursuit 的直觉："追前方的一个点"
> **在路径上找"前视距离处"的目标点 → 算它相对车头的角度 → 用"圆弧拟合"求转向角**——像"追着眼前的一个点走"。**`lookahead（前视距离）` 是唯一关键参数**：调大 → 走得稳但切弯（cut corner）；调小 → 贴路径但震荡。**"前视距离 = 前瞻性 vs 跟随性"的权衡**（和人类开车"看远处 vs 看近处"一样）。

### Stanley 控制器

Stanley 是 Pure Pursuit 的改进版，多了一个横向误差项：

```python
def stanley_control(current_pose, path, velocity, k=0.5):
    """返回转向角"""
    # 1. 找最近路径点
    nearest_idx = min(range(len(path)), 
                      key=lambda i: dist(current_pose[:2], path[i]))
    
    # 2. 计算横向误差 (cross-track error)
    target = path[nearest_idx]
    dx = target[0] - current_pose[0]
    dy = target[1] - current_pose[1]
    
    # 横向误差 (带符号)
    cte = dx * math.sin(-current_pose[2]) + dy * math.cos(-current_pose[2])
    
    # 3. 航向误差
    target_heading = math.atan2(
        path[min(nearest_idx+1, len(path)-1)][1] - path[nearest_idx][1],
        path[min(nearest_idx+1, len(path)-1)][0] - path[nearest_idx][0]
    )
    heading_error = target_heading - current_pose[2]
    heading_error = math.atan2(math.sin(heading_error), math.cos(heading_error))
    
    # 4. Stanley 公式:
    #    δ = heading_error + arctan(k·cte / v)
    steering = heading_error + math.atan2(k * cte, max(velocity, 0.1))
    
    return max(-0.6, min(0.6, steering))  # 限幅
```

> [!note] Stanley vs Pure Pursuit（面试对比）
> **PP：追"前方一个点"（几何，不看横向偏差）**；**Stanley：追"最近点 + 修正横向误差"（航向误差 + 横向误差）**——**Stanley 多了一个"离路径多远"的修正项**（`arctan(k·cte/v)`：偏得越多打得越猛，速度越快修得越轻）。**适用**：PP 简单够用（L2-L3），Stanley 精确（L3 贴路径）。**"PP 前瞻、Stanley 纠偏"**一句话区分。

### MPC (Model Predictive Control)

MPC 是"工业级"控制器：在每个时刻求解一个优化问题，考虑未来 N 步的最优控制。

```python
"""
MPC 的核心优化问题（简化）:
    min Σ (x_k - x_ref)² · Q + Σ u_k² · R
     s.t. x_{k+1} = f(x_k, u_k)    # 动力学约束
           x_min ≤ x_k ≤ x_max     # 状态约束
           u_min ≤ u_k ≤ u_max     # 控制约束

对小车来说，MPC 通常 overkill。PID / Pure Pursuit 足够。
MPC 的价值在你知识库的 L4 量产车场景（考虑轮胎滑移、执行器延迟等）。
"""
```

| 控制器 | 复杂度 | 效果 | 适用 |
|--------|:--:|------|------|
| **PID** | 最低 | 简单线性好 | L1 循迹 |
| **Pure Pursuit** | 低 | 几何直观 | L2-L3 路径跟踪 |
| **Stanley** | 低 | 比 PP 多了横向误差 | L3 精确跟踪 |
| **MPC** | 高 | 最优但费算力 | L4 高速/高精度 |

> [!warning] MPC 为什么"overkill"？（选型谈资）
> **MPC = 每时刻解一个优化问题（预测未来 N 步 + 动力学/约束）**——"最优但贵"（求解慢、要模型）。**小车低速场景 PID/PP 够用**（简单、快、够准）；**量产车高速场景才需要 MPC**（考虑轮胎滑移、执行器延迟——[[华为ADS端到端架构]] 的 PDP 底层控制）。**"控制器选型 = 速度 × 精度 × 算力"**——低速简单控制器，高速工业级控制器。

## 五、状态机（行为决策）

在"规划"和"控制"之间，需要一个行为决策层：

```python
class StateMachine:
    """
    States:
        LANE_FOLLOW  — 正常车道保持
        OBSTACLE_AHEAD — 前方障碍，减速
        STOPPING     — 停车
        OVERTAKE     — 绕行（如果有空间）
        EMERGENCY    — 急停
    """
    def __init__(self):
        self.state = "LANE_FOLLOW"
    
    def update(self, perception, localization):
        front_dist = perception.get('front_distance', 999)
        left_dist = perception.get('left_distance', 999)
        
        if front_dist < 0.15:
            self.state = "EMERGENCY"
        elif front_dist < 0.5:
            if left_dist > 0.4:
                self.state = "OVERTAKE"
            else:
                self.state = "STOPPING"
        else:
            self.state = "LANE_FOLLOW"
        
        return self.state

# 规划器根据状态选择策略
if state == "LANE_FOLLOW":
    cmd = lane_follower(image)
elif state == "STOPPING":
    cmd = (steer=90, throttle=0)
elif state == "EMERGENCY":
    cmd = (steer=90, throttle=-255)  # 全速倒车/刹车
```

> 💡 你知识库里的 [[端到端自动驾驶概览]] 本质上就是要用神经网络替代这个状态机 + 规划器。

> [!note] 状态机 = "规则版行为决策"（面试谈资）
> **"感知（距离）→ 状态判断（if-else）→ 选择策略（执行）"**——状态机是**手写的规则决策**（"0.15m 内急停、0.5m 内可绕行就绕行"）。**它和 [[端到端自动驾驶概览]] 的端到端决策是两种哲学**：状态机可解释但写不尽所有情况（"人写的 if-else"），端到端学数据但黑盒。**理解状态机 = 理解端到端在"替代什么"**——这是全库最重要的对照视角之一。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **L1 循迹就上 A***——循迹不需要全局规划（PID 反馈够）；**"规划需求跟着任务走"**（L1 反馈、L3+ 规划）。
> 2. **把全局规划和局部避障混在一起**——A* 管"大方向"（秒级），DWA 管"近处躲"（10-100ms），两层职责不同。
> 3. **小车用 MPC**——MPC overkill（低速 PID/PP 够）；**"控制器选型 = 速度×精度×算力"**。
> 4. **Pure Pursuit 前视距离乱调**——lookahead 是唯一关键参数（大→稳但切弯，小→贴但震荡），一次只调一个。
> 5. **忽略行为决策层**——规划器和控制器之间必须有"状态机"（什么时候跟/停/绕）——**"三层"其实是"四层"**（决策在规划和控制之间）。
> 6. **以为端到端"不需要本篇"**——不懂传统分层就理解不了端到端在替代什么（[[端到端自动驾驶概览]] 的对照视角）。

> 提示：全局/局部/控制。

> [!success]- 参考答案
> 全局规划（地图级，秒级）：A*/Dijkstra/RRT——"去哪"；局部规划（10-100ms）：DWA/TEB——"怎么躲"；控制器（1-10ms）：PID/Pure Pursuit/Stanley/MPC——"走准"。三层时间尺度不同所以分层——"全局想得远、局部反应快、控制执行准"。L1 循迹只需控制器，L3+ 导航才要全三层。

> [!question] Q2：A* 的 f = g + h 各是什么？为什么 h admissible 时保证最优？
> 提示：已走+估计。

> [!success]- 参考答案
> g(n) = 从起点到 n 的实际代价（已走路程），h(n) = 从 n 到终点的启发式估计（直线距离）。f = g + h 既顾"实际已走"又顾"目标方向"（Dijkstra 只有 g 慢，贪心只有 h 不保证最优）。h admissible（不高估）时 A* 保证最优：因为不会"低估 f 值"导致漏掉最优路径（f 是路径代价的下界）。

> [!question] Q3：Pure Pursuit 和 Stanley 的区别？lookahead 怎么调？
> 提示：追点 vs 纠偏。

> [!success]- 参考答案
> PP：追"前视距离处的目标点"（几何圆弧拟合，只看前方不看横向偏差）；Stanley：追"最近点 + 修正横向误差"（航向误差 + arctan(k·cte/v)，偏得越多打得越猛）。lookahead 是 PP 唯一关键参数：大→稳但切弯（cut corner），小→贴路径但震荡。选型：PP 简单（L2-L3），Stanley 精确（L3 贴路径）。

> [!question] Q4：MPC 为什么小车 overkill、量产车需要？
> 提示：求解优化/模型约束。

> [!success]- 参考答案
> MPC = 每时刻解一个优化问题（预测未来 N 步 + 动力学/状态/控制约束），最优但求解慢、需要精确模型。小车低速场景 PID/PP 够用（简单快）；量产车高速/高精度需要 MPC（考虑轮胎滑移、执行器延迟等约束）。选型逻辑："速度 × 精度 × 算力"——低速简单控制器，高速工业级控制器。

> [!question] Q5：状态机在"规划-控制"里扮演什么角色？和端到端什么关系？
> 提示：行为决策层。

> [!success]- 参考答案
> 状态机是"行为决策层"（规划和控制之间）：感知（距离）→ if-else 状态判断（跟/停/绕/急停）→ 选择策略执行。它是"手写规则决策"（可解释但写不尽所有情况）；端到端（[[端到端自动驾驶概览]]）用神经网络替代状态机+规划器（学数据但黑盒）。理解状态机 = 理解端到端在替代什么——全库最重要的对照视角。

## 🛠 动手练习

### 练习 1：手写 A* 并可视化（60 分钟）

用第五节代码（astar），在 20×20 栅格上：
1. 手动设置几个障碍物（1），起点 (0,0) 终点 (19,19)。
2. 跑 A*，打印路径。
3. 用 matplotlib 画出来（起点/终点/障碍/路径）。
4. 改 heuristic（曼哈顿 → 欧氏），观察路径和搜索节点数的变化。

> [!tip] 这是"图搜索"的入门仪式
> 亲手画出 A* 路径，你就理解了"g+h 怎么导向目标"。**"先手写 A*，再理解 nav2 的 Smac Planner"**（面试"你写过路径规划吗"→ 有图有真相）。

### 练习 2：Pure Pursuit 路径跟踪仿真（60-90 分钟）

用第六节 pure_pursuit，仿真小车跟一段路径：
1. 定义一条折线/圆弧路径（waypoints）。
2. 仿真小车（差速模型 [[SLAM与定位]]）沿路径跟踪，打印轨迹。
3. 调 lookahead（0.3/0.5/0.8），对比轨迹（切弯？震荡？）。
4. 画轨迹图：不同 lookahead 的跟线效果。

> [!tip] 这是"路径跟踪"的核心实验
> 亲手调 lookahead，你就理解"前瞻性 vs 跟随性"的权衡——**"看远处走得稳但切弯，看近处贴线但震荡"** 会亲眼看到。调参记录存进 [[2026-08-20]]。

### 练习 3：状态机 + 避障场景（可选，60 分钟）

用第五节 StateMachine，设计一个场景：
1. 前方 0.3m 有障碍（左有空隙）→ 应该 OVERTAKE。
2. 前方 0.3m 有障碍（左右都堵）→ 应该 STOPPING。
3. 前方 0.1m → EMERGENCY。
4. 把状态机和 Pure Pursuit 组合：不同状态执行不同控制（跟/停/绕）。

> [!tip] 这是"完整导航栈"的最小集成
> "状态机（决策）+ PP（跟踪）"组合 = 你的小车有了"自主导航"的雏形（nav2 就是把这些打包）。做完对照 [[端到端自动驾驶概览]]——"这套规则系统，端到端用一个网络替代"。
