# 三阶段训练范式：Pretrain → SFT → RL

> 一句话导读：现代自动驾驶模型（VLA/VLM 类端到端模型）的标准训练流程分三步——**预训练（学会看世界）→ 监督微调（学会开车）→ 强化对齐（学会开得安全像人）**。本篇讲清楚每阶段"为什么存在、怎么训练、有什么坑"，以及 RLHF / DPO / GRPO 三大后训练方法的本质区别。

## 〇、大白话总览

### 三个阶段的比喻

```
Stage 1 预训练:  送孩子上学读书识字 → "看懂世界"（学通用知识）
Stage 2 SFT:     跟老司机学开车     → "会开"（学驾驶行为）
Stage 3 RL:      驾校教练纠错+考试  → "开得好、开得安全"（学偏好/安全）
```

**为什么不能一步到位？**
- 只预训练：模型"知识渊博"但不会开车（没学过驾驶行为）。
- 只 SFT：模型"照葫芦画瓢"但上限=专家水平，且没有安全意识。
- 只 RL：模型不知道基本驾驶动作（RL 从头学太慢），且奖励难设计。
- **三步组合 = 先用廉价海量数据学基础（预训练）→ 再用高质量示范学行为（SFT）→ 最后用偏好/奖励学安全（RL）。**

## 二、Stage 1：预训练 (Pre-training)

### 目标

让模型获得"看懂世界"和"理解语言"的基础能力。

### 传统 CV 模型预训练

```
ImageNet 预训练 → ResNet/ViT backbone → 下游任务微调
```

局限性：自然图像 ≠ 驾驶场景，2D 特征 ≠ 3D 空间理解。

### 现代自动驾驶预训练

| 预训练内容 | 方法 | 学到什么 |
|-----------|------|----------|
| **视觉编码器** | MAE, DINOv2 | 通用视觉特征 |
| **3D 空间理解** | 自监督深度/占据预测 | 3D 几何表征 |
| **多模态对齐** | 图像-文本对比学习 | 视觉和语言的对齐 |
| **视频预训练** | 未来帧预测、时序对比 | 运动理解和预测 |

> [!note] 为什么预训练越来越"驾驶化"？
> ImageNet 预训练的问题是"领域不对齐"（自然图片 vs 驾驶场景）。现代趋势：**预训练数据尽量贴近驾驶**——MAE/DINOv2 在驾驶视频上自监督、视频预训练学"运动规律"、3D 自监督学"空间几何"。**预训练任务越贴近下游，迁移效果越好**（[[模型基础知识补充]] 讲过）。

### 理想汽车 VLA 的空间智能预训练

```
3D 高斯均匀初始化 + 传感器输入
      ↓
3D 高斯环境建模与场景重建 (自监督)
      ↓
预测未来帧的高斯场景
      ↓
自监督信号: 2D RGB 图像重建 → 不需要 3D 标注!
```

**关键**：利用自监督从海量无标注驾驶视频中学习 3D 空间表征，是纯视觉方案的重要基础。

> [!note] 理想方案的精妙之处
> 用 **3D 高斯（3DGS）** 作为中间表示做自监督：输入多传感器 → 建模 3D 场景 → 预测未来帧 → 用"2D 图像重建"做监督信号（重建得越像，说明 3D 场景理解越准）。**全程不需要任何 3D 标注**——海量无标注驾驶视频就是训练数据。这就是"空间智能"的预训练。

### 华为 GOD 基础模型预训练

```
海量驾驶数据 (图像 + LiDAR + 时间序列)
      ↓
云端昇腾集群大规模预训练
      ↓
得到一个通用的 3D 场景理解基础模型
      ↓
可以通过微调适配不同车型/场景
```

## 三、Stage 2：SFT — 监督微调

### 什么是 SFT

**SFT = Supervised Fine-Tuning = 监督微调 = 模仿学习 (Imitation Learning)**

```
核心逻辑:
  给模型看: "在这个场景下，人类专家是这样开的"
  让模型学: 直接模仿人类专家的驾驶行为

训练数据:
  输入 (x): 传感器数据 + 自车状态 + 导航信息
  标签 (y): 人类专家的驾驶动作 (方向盘转角/油门/刹车)
        或 人类驾驶的未来轨迹
```

### SFT 的数学形式

```
损失函数 (行为克隆 Behavior Cloning):

  L_SFT = -Σ log P(y_t | y_<t, x)

即: 让模型输出 y 的概率最大化
```

**本质**：SFT 是在做"抄作业"——人类专家怎么开，模型就怎么学。

### SFT 在自动驾驶中的作用

| 作用 | 说明 |
|------|------|
| **冷启动** | 让模型从通用 VLM 变成"懂驾驶的模型" |
| **格式对齐** | 学会输出结构化结果（如 `<perception>` → `<planning>` 三段式） |
| **基础驾驶能力** | 学习跟车、变道、过路口等基本操作 |
| **领域适应** | 从通用知识迁移到驾驶领域知识 |

### SFT 数据来源

```
高质量示范数据:
  ├── 专业司机驾驶记录 (最纯净)
  ├── 自动驾驶测试车安全员数据 (有监督)
  ├── 量产车人类驾驶员数据 (规模大，质量参差)
  └── 仿真中的专家策略 (无限量，但 domain gap)
```

> [!warning] 数据质量的权衡（面试加分点）
> 量产车数据**规模大但质量参差**（普通司机也可能开得不好）；专业司机数据**质量高但规模小**。所以 SFT 数据的理想组合是"**少量高质量（专业司机）+ 大规模中质量（量产车）+ 仿真补充**"，并用"轨迹质量筛选"（加速度、偏离度等）过滤掉坏示范。

### SFT 的局限性

```
问题 1: 分布漂移 (Distribution Shift)
  训练时: 模型看到的都是"正确路径"上的状态
  部署时: 模型一旦偏离正确路径 → 进入没见过的状态 → 不知道怎么恢复
  结果: 小错累积 → 大错 → 接管/事故

问题 2: 无法超越专家
  SFT 的上限 = 人类专家的水平
  无法学会"比人更好"的驾驶策略

问题 3: 没有安全意识
  模仿学习只学"怎么做"，不学"为什么这么做"
  不知道什么是危险，只知道照着学
```

> [!warning] 这就是为什么需要 Stage 3 — 后训练/强化学习。
> SFT 的三大问题正是 [[端到端自动驾驶概览]] 里"模仿学习"的三大问题（distribution shift、上限=专家、无因果/安全意识）——**三阶段范式把"模仿学习"标准化成 Stage 2，再用 Stage 3 补它的坑**。理解这条逻辑链，就理解了为什么"SFT + RL"是标配。

## 四、Stage 3：后训练 / 强化对齐

### 什么是 Post-training

**在 SFT 之后，通过额外的监督信号（偏好、奖励、对抗场景）让模型从"会开"变成"开得好、开得安全"。**

### 四大后训练范式

| 范式 | 监督信号 | 怎么做 | 代表方法 |
|------|----------|--------|----------|
| **知识蒸馏** | 更强的教师模型 | 大模型教小模型 | CAT-K, RoaD |
| **偏好对齐** | 人类偏好对比 | 好轨迹 vs 坏轨迹 → 优化 | DPO, RLHF |
| **强化学习** | 奖励函数 | 试错+奖励驱动 | GRPO, PPO, CORL |
| **推理时优化** | 验证器 | 不更新权重，推理时选最优 | 多候选投票 |

> [!note] 四类的区别一句话
> 蒸馏 = "抄好学生的答案"；偏好对齐 = "学人类的好恶"；强化学习 = "按规则试错拿分"；推理时优化 = "多写几个答案挑最好的"（不训练，只推理）。**前两类改权重，最后一类只改推理策略。**

### RLHF — 从人类反馈中强化学习（经典三步）

```
┌─────────────────────────────────────────────────┐
│              RLHF (经典三步骤)                   │
│                                                  │
│  Step 1: SFT 模型 (已完成)                       │
│           ↓                                      │
│  Step 2: 训练奖励模型 (Reward Model)             │
│    人类标注员对比两条轨迹:                        │
│    "轨迹 A 比轨迹 B 更安全/更舒适"                │
│           ↓                                      │
│    训练一个神经网络来预测人类偏好                  │
│           ↓                                      │
│  Step 3: 用奖励模型引导策略优化 (PPO)             │
│    模型生成动作 → 奖励模型打分 → 优化模型         │
│                                                  │
│  注意: 必须加 KL 约束，防止策略偏离 SFT 太远     │
│        否则模型会"作弊"骗奖励而非真正变好         │
└─────────────────────────────────────────────────┘
```

> [!warning] KL 约束为什么是 RLHF 的生死线？（面试高频）
> 奖励模型不是完美的——模型可以"钻空子"：找到一个奖励模型喜欢、但实际很差的轨迹（比如"急加速冲过路口"可能被奖励模型误判为"高效"）。**KL 惩罚约束策略不能偏离 SFT 模型太远**（SFT 模型代表"人类示范的行为分布"），相当于给优化"拴了根绳子"，防止模型为了骗奖励而走极端。

### DPO — 直接偏好优化（RLHF 的简化版）

```
RLHF:  需要训练奖励模型 → 用 PPO 优化 (复杂，不稳定)

DPO:   直接从偏好数据优化策略 (简单，稳定)

  L_DPO = -log σ( β·[log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)] )

  直观理解:
  → 提升"好轨迹" (y_w) 的相对概率
  → 降低"坏轨迹" (y_l) 的相对概率
  → 以 SFT 模型 (π_ref) 为锚点，防止偏太远
```

**在驾驶中的应用**：
- **人类接管 = 模型的输出不够好** → y_w = 人类实际驾驶, y_l = 模型规划的轨迹
- **AEB 激活 = 模型太危险了** → 惩罚这种轨迹

> [!note] DPO vs RLHF 的本质区别（必考）
> - RLHF：**先训练一个"偏好裁判"（奖励模型），再用它打分**（两阶段，复杂）。
> - DPO：**数学上证明"奖励模型可以被消掉"**——直接从"好/坏轨迹对"优化策略（一阶段，简单稳定）。
> - **共同点**：都以 SFT 模型为锚（KL/π_ref 约束），都是"偏好对齐"。
> - **驾驶里的天然偏好数据**：接管 = "模型不够好"（y_l），人类实际驾驶 = "好"（y_w）——**影子模式的接管数据可以直接当 DPO 数据**（[[数据闭环总览]] 的联动！）。

### GRPO — 组相对策略优化（RLHF 的升级版）

```
GRPO (Group Relative Policy Optimization):

  对同一个场景，采样 G 个候选输出:
    y_1: 轨迹 (保守, 但慢)
    y_2: 轨迹 (激进, 但快)
    y_3: 轨迹 (适中, 安全)
    ...
    y_G

  分别打分:
    组内排名 → 优势 (advantage) = (自己分数 - 组平均)/组标准差

  优化: 提高"相对更好的"输出的概率  ← 只需要组内对比，不需要绝对阈值
```

> [!note] GRPO 为什么比 PPO 简单？（面试高频）
> PPO 需要**一个价值网络（Critic）**估计"绝对优势"（这个动作比平均好多少），训练复杂且不稳定。GRPO 的洞察：**不用学价值网络——直接在组内采样 G 个候选，用"自己分数 vs 组平均"的相对排名当优势**。省掉 Critic = 更简单、更稳定、显存更省。这就是为什么 GRPO 成为 2024 后 LLM/VLA 后训练的主流。

**AutoDrive-P3 的三阶段 GRPO**：

```
总奖励 = λ_format·R_format + λ_perc·R_perc + λ_pred·R_pred + λ_plan·R_plan
          格式            感知             预测            规划
          1               2                2               5

关键: 不只奖励最终规划好，还要奖励"中间推理正确"!
     → 避免模型靠猜对轨迹但感知全错 (假性成功)
```

> [!warning] "奖励中间推理"是 P3 的核心贡献
> 如果只奖励最终规划轨迹，模型可能"感知全错但轨迹碰巧对"（假性成功）——就像学生"答案对了但过程全错"。P3 把奖励拆成 格式/感知/预测/规划 四项（规划权重最高 5），**逼模型把每步推理都做对**。这告诉我们：**奖励函数设计决定了模型"学到的是真本事还是应试技巧"**。

### CoReVLA 的接管学习

```
部署模型上路 → 人类接管 → 记录该场景
      ↓
对比: 模型规划 vs 人类驾驶
      ↓
DPO 微调: 提升人类驾驶行为的概率
      ↓
下次遇到类似场景 → 不再需要接管!
```

> [!note] CoReVLA 是"数据闭环 × 三阶段范式"的完美结合
> **接管数据（数据闭环产出）→ DPO 微调（三阶段 Stage 3）→ 模型变强 → 接管变少**——这是"影子模式 + 偏好对齐"在量产里的标准打法，把 [[数据闭环总览]] 和本篇的知识串成了一条线。

## 五、完整训练流程示例（三个真实案例）

### 以 AutoDrive-P3 为例

```
Stage 1: 预训练 (已有)
  Qwen2.5-VL-3B ← 已在海量图文数据上预训练完成

Stage 2: SFT 冷启动
  数据: P3-CoT 结构化数据 (nuScenes 25K帧 + NAVSIM 115K帧)
  训练: 标准语言模型损失
  效果: 模型学会输出 <perception> → <prediction> → <planning> 三段式推理

Stage 3: P3-GRPO 后训练
  采样: 每个场景生成 8 条候选回答
  奖励: 格式(1) + 感知(2) + 预测(2) + 规划(5)
  优化: GRPO 组内比较
  效果: 碰撞率从 0.17% → 0.06%, 感知/预测也同步提升
```

### 以 Poutine (Waymo 挑战赛冠军) 为例

```
Stage 1: VLT 预训练 (Vision-Language-Trajectory)
  用海量驾驶数据 (含长尾场景) 做自监督 next-token 预测
  让 3B VLM 学会驾驶的基本语言

Stage 2: SFT (可选, 或者包含在 Stage 1 中)

Stage 3: GRPO 后训练
  用少量人类偏好标注做强化微调
  结果: Waymo 端到端挑战赛第 1 名
```

### 以理想 MindVLA 为例

```
Stage 1: 空间智能预训练 (3D 高斯自监督)
  + 语言智能预训练 (MindGPT 驾驶专用 LLM)

Stage 2: SFT
  驾驶示范数据微调

Stage 3: RLHF 对齐
  人类偏好数据集 (接管数据 + 好驾驶数据)
  → Diffusion 模型的行为对齐
```

> [!note] 三个案例的共同模式（记住这个模式！）
> **Stage 1（预训练）负责"域内知识"（驾驶视觉/空间/语言）→ Stage 2（SFT）负责"行为与格式"（三段式输出/驾驶动作）→ Stage 3（RL）负责"安全与偏好"（碰撞率/接管率）**。无论模型大小（3B-7B）、无论机构（学术/厂商），套路一致——这就是"三阶段范式"成为行业标准的原因。

## 六、关键概念速查

| 缩写 | 全称 | 含义 |
|------|------|------|
| **SFT** | Supervised Fine-Tuning | 监督微调：用标注数据教模型模仿专家 |
| **RLHF** | Reinforcement Learning from Human Feedback | 从人类反馈中强化学习 |
| **DPO** | Direct Preference Optimization | 直接偏好优化：直接从偏好对中学习 |
| **GRPO** | Group Relative Policy Optimization | 组相对策略优化：组内比较替代绝对打分 |
| **PPO** | Proximal Policy Optimization | 近端策略优化：经典 RL 算法 |
| **IL** | Imitation Learning | 模仿学习 ≈ SFT 在驾驶中的叫法 |
| **BC** | Behavior Cloning | 行为克隆：IL 的具体实现 |
| **KL Penalty** | KL 散度惩罚 | 防止 RL 后模型偏离 SFT 太远的关键约束 |
| **Cold Start** | 冷启动 | 用 SFT 让模型先学会"格式+基础能力"再 RL |

---

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为三阶段是"可选的"**——现代 VLA/VLM 端到端模型基本都是三阶段，"Pretrain→SFT→RL"已是行业标准流程，不是论文里的特殊技巧。
> 2. **混淆 SFT 和 RL 的数据**——SFT 用"示范数据"（专家怎么开），RL 用"偏好/奖励"（什么好什么坏）。数据类型不同，训练目标不同。
> 3. **以为 RLHF 和 DPO 是"两个竞争方法"**——DPO 是 RLHF 的简化实现（省掉奖励模型），本质都是"偏好对齐"，选型看工程复杂度。
> 4. **忽略 KL/π_ref 锚定**——无论 RLHF 还是 DPO 都必须锚定 SFT 模型，否则模型会"骗奖励"或"偏太远"。
> 5. **只奖励最终结果**——P3 的教训：奖励函数必须覆盖"中间推理"（感知/预测），否则模型学"应试技巧"（轨迹对但感知全错）。

## ✅ 检验自己（自测题）

> [!question] Q1：说出三阶段各自的"目标、数据、方法"，并解释为什么不能跳过 SFT 直接 RL。
> 提示：知识 → 行为 → 安全。

> [!success]- 参考答案
> Stage 1 预训练：目标=通用视觉/语言/3D 表征，数据=海量图文视频，方法=自监督（MAE/对比学习/next-token）。Stage 2 SFT：目标=驾驶行为与格式，数据=人类示范，方法=行为克隆。Stage 3 RL：目标=安全与偏好，数据=偏好对/奖励，方法=RLHF/DPO/GRPO。不能跳过 SFT：模型连基本驾驶动作都不会，RL 从头学太慢且奖励难以覆盖基础行为——SFT 是 RL 的"行为先验"（RL 的锚点，KL/π_ref 都基于 SFT）。

> [!question] Q2：SFT 的三大局限是什么？Stage 3 分别怎么补？
> 提示：分布漂移 / 上限=专家 / 无安全意识。

> [!success]- 参考答案
> ① 分布漂移（部署偏离训练分布）：RL/闭环训练让模型在"自己产生的状态"里学习（自举），缓解未见过状态；② 上限=专家：RL 用奖励函数可以超越人类示范（奖励≠示范，可以比专家更优）；③ 无安全意识：偏好对齐/奖励直接编码"安全"（AEB 数据惩罚危险轨迹、人类接管作为"模型不够好"的信号）。核心：SFT 学"怎么做"，RL 学"什么好"。

> [!question] Q3：RLHF 的三步是什么？KL 约束为什么必不可少？
> 提示：SFT → 奖励模型 → PPO。

> [!success]- 参考答案
> ① 用 SFT 模型作为初始策略；② 人类标注员对比轨迹对训练奖励模型（预测人类偏好）；③ 用 PPO 以奖励模型为信号优化策略。KL 约束必不可少：奖励模型不完美，模型可能"钻空子"骗奖励（找到奖励模型喜欢但实际很差的轨迹），KL 惩罚把策略拴在 SFT 附近（SFT=人类示范分布），防止走极端。

> [!question] Q4：DPO 相比 RLHF 简化了什么？GRPO 相比 PPO 简化了什么？
> 提示：奖励模型 / 价值网络。

> [!success]- 参考答案
> DPO：数学上消掉了"奖励模型"——直接从好/坏轨迹对优化策略（一阶段 vs RLHF 两阶段），更简单稳定，仍需以 SFT 为锚（π_ref）。GRPO：消掉了"价值网络（Critic）"——不再估计绝对优势，而是对同一场景采样 G 个候选，用"自己分数 vs 组平均"的相对排名当优势，省掉 Critic 的训练与显存。两者都是"把 RL 复杂组件省掉"的简化，是工程友好趋势。

> [!question] Q5：AutoDrive-P3 的奖励为什么分 4 项？"只奖励规划"会有什么问题？
> 提示：假性成功。

> [!success]- 参考答案
> P3 奖励 = 格式(1) + 感知(2) + 预测(2) + 规划(5)，不只奖励最终轨迹。如果只奖励规划：模型可能"感知全错但轨迹碰巧对"（假性成功）——像学生答案对但过程全错。分项奖励逼模型把感知/预测/规划每步都做对，避免"应试技巧"。启示：奖励函数设计决定模型学到的是真本事还是捷径。

## 🛠 动手练习

### 练习 1：给一个 VLA 模型设计三阶段方案（30 分钟）

假设你要训练一个 7B 的视觉-语言-动作模型做城市驾驶，请设计：
1. Stage 1：用什么预训练数据和方法？（给出 2 种自监督任务）
2. Stage 2：SFT 数据从哪来？输出格式怎么定？
3. Stage 3：用 RLHF 还是 DPO 还是 GRPO？为什么？（提示：工程复杂度 + 驾驶场景的奖励可定义性）
4. 写出你的奖励函数 3 项（含权重）。

> [!tip] 参考思路
> ① 视频 next-token 预测 + 3D 自监督重建；② 量产车示范数据 + 三段式 CoT 格式；③ GRPO 更稳（省 Critic），奖励 = 格式 + 感知 + 规划（参考 P3）。重点是**说出每个选择的理由**，没有标准答案。

### 练习 2：手算 GRPO 的优势（15 分钟）

一个场景采样 4 条轨迹，奖励分：A=8.0, B=7.0, C=6.5, D=5.5。
1. 算组平均和标准差。
2. 每条轨迹的 advantage = (score - mean) / std。
3. 哪个 advantage 最高？GRPO 会提升哪条轨迹的概率、降低哪些？

> [!tip] 算完你会发现
> advantage 是**相对**的（组内排名），不需要绝对阈值——这正是 GRPO 省掉 Critic 的数学基础。如果把 D 的 5.5 改成 2.0，它的 advantage 会怎样？（更负 → 被压制得更狠）

### 练习 3：用接管数据设计 DPO 数据集（可选，45 分钟）

假设你有 1 万条"人类接管"记录（模型规划轨迹 + 人类实际轨迹）：
1. 怎么筛选出"值得训练"的接管？（提示：接管原因、时长、场景稀有度）
2. y_w 和 y_l 分别是什么？
3. 设计 3 条数据清洗规则（比如"接管发生在红绿灯正常停车时 → 删除"，为什么？）

> [!tip] 这个练习是 [[数据闭环总览]] 的联动
> 接管数据 = 影子模式产出的偏好数据，是 DPO 的天然素材。清洗规则设计 = 数据闭环"挖掘效率"的实战。写完把思路记进 [[2026-08-20]]。
