## 〇、大白话总览

### 训练金字塔——"三层楼"

```
第三层 持续学习:  OTA 后增量学习（世界在变，模型要跟着变）
第二层 微调:      特定场景适配（基础模型 → 我的场景）
第一层 预训练:    大规模通用能力（先用海量数据打底）
```

> [!note] 打个比方
> - **预训练** = "大学通识教育"（什么都学，打基础）。
> - **微调** = "入职培训"（针对岗位（场景）快速上手）。
> - **持续学习** = "在职进修"（世界变了（新路况），持续更新不落伍）。
> **三层缺一不可**：不预训练 → 学不动；不微调 → 不适配；不持续学习 → 过时。

```
┌─────────────────────────────────────────────────────┐
│                    训练金字塔                        │
│                                                     │
│                        ┌────────┐                   │
│                        │ 持续   │  OTA 后增量学习   │
│                        │ 学习   │                   │
│                    ┌───┴────────┴───┐               │
```

> [!note] 三层的核心矛盾

> - **微调 vs 持续学习**：一次性适配 vs 持续更新（世界不变 vs 世界总在变）。
> **"三层金字塔"是面试"训练范式"题的标准框架**——先讲三层，再讲每层的关键技术。

## 二、预训练 (Pre-training)

### 自动驾驶中的预训练

| 预训练方式 | 数据 | 学什么 | 举例 |
|-----------|------|--------|------|
| **ImageNet 预训练** | 自然图像 | 通用视觉特征 | ResNet 初始化 |
| **自监督预训练** | 驾驶视频无标注 | 时序/3D 表征 | MAE, BEiT |
| **多模态预训练** | 图像+LiDAR+文本 | 跨模态对齐 | CLIP 风格 |
| **驾驶专项预训练** | 大规模驾驶数据 | BEV 特征、占据 | 华为 GOD 基础模型 |

### 为什么预训练重要

```
从头训练 (from scratch):
  需要: 海量标注数据 + 巨大算力 + 数周训练时间
  结果: 可能只学到当前数据集特征

预训练 + 微调:
  需要: 少量标注数据 + 适中算力 + 数小时微调
  结果: 继承通用知识 + 快速适配新场景
```

> [!note] 预训练的演进方向（和 [[三阶段训练范式]] 呼应）
> ImageNet（通用）→ 自监督（驾驶视频）→ 驾驶专项（BEV/占据）——**预训练数据越来越"贴驾驶"**。**"预训练任务越贴近下游，迁移效果越好"**（[[模型基础知识补充]] 的预训练策略）——华为 GOD 基础模型就是这个方向的产品化。

## 三、微调 (Fine-tuning)

### 微调策略分类

#### 按冻结程度

| 策略 | 做法 | 适用场景 |
|------|------|----------|
| **全量微调** (Full FT) | 所有参数可更新 | 大场景变化（如从美国适配中国） |
| **部分微调** (Partial FT) | 冻结 backbone，只训 head | 新增检测类别 |
| **LoRA** | 插入低秩适配矩阵 | 高效适配，参数少 |
| **Adapter** | 插入小型适配模块 | 多任务切换 |
| **Prompt Tuning** | 只学习少量 prompt token | VLM 适配驾驶场景 |

#### LoRA (Low-Rank Adaptation)

```
原始权重 W ∈ R^{d×d}  (冻结)
插入: A ∈ R^{d×r}, B ∈ R^{r×d}  (训练)
输出: h = W·x + B·A·x

参数量: 2×d×r  (r << d, 如 r=8)
```

**在自动驾驶中的应用**：
- 基础感知模型 → LoRA 微调 → 适配新车型/新传感器配置
- 每个城市的驾驶风格不同 → 不同 LoRA 权重

> [!warning] LoRA 的原理（面试必讲，手推）
> **全量微调要更新 W（d×d 参数），LoRA 只学两个低秩矩阵 A（d×r）和 B（r×d）**：`W·x + B·A·x`——A/B 的乘积模拟"对 W 的低秩更新"，参数量从 d² 降到 2dr（r=8 时省几千倍）。**直觉：模型更新其实在低维子空间里**（大模型微调时真正有效的方向很少），LoRA 用低秩矩阵"近似这个子空间"。**参数量级**：7B 模型全量微调 70 亿参数，LoRA（r=8）只需约 4000 万（<0.1%）。

### 微调中的数据平衡

**核心问题**：微调数据通常偏向 corner case，容易导致**灾难性遗忘**。

```
错误做法: 只用 corner case 数据微调
  → 模型在 corner case 变好，但在常见场景退化

正确做法: 混合数据微调
  corner case 数据 (30%) + 原始数据回放 (70%)
  → 两个场景都好
```

> [!warning] "灾难性遗忘"是微调的头号陷阱（面试必考）
> 只用新数据（corner case）微调 → 模型"学新忘旧"（[[数据闭环总览]] 的"回归风险"是它的量产表现）。**解法：混合数据（新数据 + 旧数据回放）**——"corner case 30% + 原始数据 70%"是经验比例。**"微调 = 新数据 + 旧数据"是铁律。**

## 四、持续学习 (Continual Learning)

### 为什么需要持续学习

自动驾驶的世界不断变化：
- 新的道路类型（如刚通车的隧道）
- 新的交通规则
- 新的障碍物类型
- 季节/天气变化

**不可能每次都全量重训**，需要增量更新。

### 持续学习三大方法

| 方法 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| **回放 (Replay)** | 保留核心数据集，和新数据混合训练 | 简单有效 | 需要存储旧数据 |
| **正则化 (Regularization)** | 惩罚重要参数的更新 (EWC, SI) | 不需要存储旧数据 | 效果有限 |
| **参数隔离 (Isolation)** | 不同任务用不同的参数子集 | 无遗忘 | 模型膨胀 |

> [!note] 三方法的直觉（面试谈资）
> - **回放** = "复习旧题"（存核心数据，混合训练）——简单有效，业界主流。
> - **正则化** = "重要参数别乱动"（EWC：对重要参数加惩罚）——不存数据但效果有限。
> - **参数隔离** = "不同任务各用各的参数"（防遗忘）——无遗忘但模型膨胀。
> **工业界主流 = 回放（核心数据集 Replay）**——因为它和 [[数据闭环总览]] 天然衔接（核心数据集就是数据闭环沉淀的）。

### 业界实践：核心数据集回放 (Core Set Replay)

```
训练流程:
  1. 维护一个"核心数据集" D_core (如 10000 张代表性样本)
  2. 新 corner case 数据来了 → 和 D_core 混合训练
  3. 新模型经过测试 → 用不确定性采样更新 D_core
  4. 循环往复

优势:
  - D_core 只占原始数据 < 1%
  - 兼顾新旧场景
  - 训练效率高
```

### 华为 ADS 的训练节奏

```
数据采集 (车端) → 汇聚云端 → 自动标注
                              ↓
                     5 天一迭代:
                        ├── 增量数据 + 核心数据
                        ├── 昇腾集群训练
                        ├── 仿真评测
                        └── OTA 推送
```

> [!note] 华为 5 天迭代 = 持续学习的量产实践
> "增量数据 + 核心数据"就是回放（Replay）——**每次迭代都是"新数据 + 核心集"混合训练**（[[华为ADS技术方案]] 的迭代节奏落地）。**"持续学习"不是论文概念，是量产每天都在跑的事**——面试答"华为怎么持续训练"就是这套流程。

## 五、多任务联合训练

### 自动驾驶常见多任务

```
共享 Backbone (BEV 特征)
    │
    ├── 3D 检测 Head
    ├── BEV 分割 Head
    ├── 车道线检测 Head
    ├── 占据预测 Head
    ├── 轨迹预测 Head
    └── 规划 Head
```

### 训练策略

| 策略 | 做法 | 适用 |
|------|------|------|
| **同步训练** | 所有任务一起训 | 任务相关性高 |
| **轮流训练** | 交替训不同任务 | 任务冲突时 |
| **课程学习** | 先简单后难 | 规控来架训需要先有感知能力 |
| **渐进式** | 逐步解冻层 | 预训练 backbone → 微调 head |

### UniAD 的两阶段训练

```
Stage 1: 感知模块预训练
  训练: BEV Encoder + TrackFormer + MapFormer + MotionFormer
  冻结: Planner

Stage 2: 端到端联合微调
  解冻所有模块
  联合优化: L_total = L_track + L_map + L_motion + L_occ + L_plan
```

> [!note] UniAD 两阶段 = 多任务训练的"防冲突"方案
> **先训感知（Stage 1），再解冻联合（Stage 2）**——因为早期感知不准会给规划错误输入（[[UniAD详解]] 分阶段训练的原因）。**"课程学习"的智驾版：先有感知能力，再学规划**。面试答"多任务怎么训"：同步/轮流/课程/渐进四选 + UniAD 案例。

## 六、损失函数设计

### 多任务损失平衡

```
总损失 = Σ w_i × L_i

如何确定 w_i？
```

| 方法 | 做法 | 特点 |
|------|------|------|
| **固定权重** | 手动设定 w_i | 简单但需要调参 |
| **不确定性加权** | w_i = 1/(2σ_i²), σ 可学习 | 自动平衡 |
| **梯度归一化** | GradNorm, 均衡各任务梯度大小 | 训练稳定性好 |
| **动态调整** | 根据各任务学习速度动态调整 | 复杂但效果好 |

### 自动驾驶特有损失

| 损失 | 用途 |
|------|------|
| **Focal Loss** | 目标检测分类（处理类别不平衡） |
| **L1/Smooth L1** | 3D 框回归 |
| **IOU Loss** | 检测框质量 |
| **深度监督 Loss** | BEVDepth 用 LiDAR 点云监督深度 |
| **Collision Loss** | 规划轨迹碰撞惩罚 |
| **Imitation Loss** | 模仿人类驾驶行为 |
| **Contrastive Loss** | 学习区分性特征（Re-ID） |

> [!note] 多任务损失平衡的深层（和 [[训练排错实战手册]] 联动）
> 多任务 loss 尺度失衡（检测 ~5 vs 规划 ~0.01）是**训练震荡的头号来源**（[[训练排错实战手册]] 4.2）——固定权重/不确定性加权/GradNorm 都是"让各任务梯度量级接近"的手段。**"损失平衡"既是设计问题也是排错问题**——面试串起来讲更显功力。

## 八、关键概念速记

| 概念 | 含义 |
|------|------|
| **Pre-training** | 在大规模通用数据上训练基础能力 |
| **Fine-tuning** | 在特定数据上调整模型适应新任务 |
| **LoRA** | 低秩适配，参数高效的微调方法 |

## 九、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为微调 = 只用新数据**——只用 corner case 微调 = 灾难性遗忘；**必须"新数据 + 旧数据回放"混合**。
> 2. **以为 LoRA 是"压缩模型"**——LoRA 不改模型大小（推理时 W 不变），是**训练时只更新少量参数**（推理时合并 B·A 进 W 或保留分支）。
> 3. **以为持续学习 = 定期全量重训**——全量重训贵且慢；持续学习 = 增量更新 + 核心集回放（华为 5 天迭代模式）。
> 4. **忽略多任务损失失衡**——检测 loss ~5 vs 规划 ~0.01，不平衡就震荡（[[训练排错实战手册]] 4.2）。
> 5. **以为预训练一定用 ImageNet**——现代趋势是"驾驶专项预训练"（MAE on 驾驶视频/华为 GOD 基础模型），ImageNet 只是起点。

## ✅ 检验自己（自测题）

> [!question] Q1：训练金字塔三层各自的目标和数据是什么？
> 提示：通用/适配/增量。

> [!success]- 参考答案
> 预训练：大规模通用能力（海量数据：ImageNet/驾驶视频/多模态）——打底。微调：特定场景适配（少量标注数据 + 预训练权重）——上手。持续学习：增量更新（新数据 + 核心集回放）——不落伍。三层对应"大学通识 → 入职培训 → 在职进修"，是面试"训练范式"题的标准框架。

> [!question] Q2：LoRA 的原理是什么？参数量怎么算？
> 提示：低秩近似。

> [!success]- 参考答案
> 冻结原始权重 W（d×d），插入两个低秩矩阵 A（d×r）和 B（r×d），输出 h = W·x + B·A·x——用低秩矩阵乘积近似"对 W 的更新"。参数量从 d² 降到 2dr（r=8 时省几千倍）。直觉：大模型微调的有效更新方向在低维子空间。7B 模型 LoRA（r=8）只需约 4000 万参数（<0.1%）。推理时可把 B·A 合并进 W（无额外开销）。

> [!question] Q3：灾难性遗忘是什么？怎么防？
> 提示：学新忘旧。

> [!success]- 参考答案
> 只用新数据（corner case）微调 → 模型在 corner case 变好但常见场景退化（学新忘旧）。防法：① **回放**（新数据 + 核心数据集混合训练，业界主流，比例如 30%+70%）；② 正则化（EWC：重要参数惩罚）；③ 参数隔离。量产表现 = [[数据闭环总览]] 的"回归风险"，华为 5 天迭代就是"增量+核心集"回放的实践。

> [!question] Q4：多任务联合训练的损失平衡有哪些方法？
> 提示：固定/不确定性/GradNorm/动态。

> [!success]- 参考答案
> ① 固定权重（手动调，简单费事）；② 不确定性加权（w=1/(2σ²)，σ 可学习，自动平衡）；③ GradNorm（按梯度范数均衡学习速度）；④ 动态调整（按各任务学习速度）。目标都是"让各任务梯度量级接近"——检测 loss ~5 vs 规划 ~0.01 差 500 倍，不平衡会震荡（[[训练排错实战手册]] 4.2）。UniAD 用"分阶段训练"绕开此问题。

> [!question] Q5：为什么"断点续训快"是量产训练基础设施的关键指标？
> 提示：训练稳定性。

> [!success]- 参考答案
> 大模型训练要数周，中途故障（断电/网络）是必然事件——断点续训快 = 每次故障损失小。华为云端"90% 可用率 + <10 分钟恢复"是量产标准。训练基础设施 = 算力（多少 EFLOPS）+ 稳定性（长稳 30 天）+ 恢复速度（断点续训）三件套，缺一不可。

## 🛠 动手练习

### 练习 1：手算 LoRA 参数量（15 分钟）

一个 d=4096 的 Transformer 层：
1. 全量微调这层的 W 需要多少参数？（4096² = 1678 万）
2. LoRA（r=8）需要多少？（2 × 4096 × 8 = 6.5 万）
3. 节省了多少倍？（约 257 倍）
4. 如果 7B 模型有 28 层这样的层，LoRA 总共多少参数？（约 1800 万）

> [!tip] 算完你会发现
> LoRA 的"参数效率"是数量级级别的（几百倍）——这就是它能"多任务低成本切换"（每个任务一个小 LoRA 权重）的原因。面试手算一遍，比背结论深刻得多。

### 练习 2：设计"灾难性遗忘"实验（45-60 分钟）

用 [[本地训练方案]] 的 DAVE-2（行为克隆）做一个实验：
1. 用直道数据训练 → 记录直道性能。
2. 只用弯道数据微调 → 测直道性能（应该退化 = 灾难性遗忘）。
3. 用"弯道 30% + 直道回放 70%"微调 → 测两者（都应该好）。
4. 画两条曲线对比，写结论。

> [!tip] 这是"灾难性遗忘"的亲身验证
> 亲手复现"学新忘旧"和"回放解决"，比读十篇论文都深刻。做完把结果存进 [[2026-08-20]]，面试讲"我做过灾难性遗忘实验"直接加分。

### 练习 3：多任务损失平衡模拟（可选，30 分钟）

设计一个模拟：3 个任务 loss 分别是 5.0 / 0.5 / 0.05：
1. 直接相加 → 前向传播梯度主要来自哪个任务？（第一个——梯度被它主导）
2. 用不确定性加权（σ 可学习）→ 收敛时 σ 分别多大？（简单任务 σ 小权重高）
3. 用 GradNorm 思路 → 怎么动态平衡？

> [!tip] 这个模拟 = [[训练排错实战手册]] 4.2 的配套练习
> 纸上推演"loss 尺度失衡 → 梯度主导"的机制，面试答"多任务怎么训"时就有底层逻辑。
