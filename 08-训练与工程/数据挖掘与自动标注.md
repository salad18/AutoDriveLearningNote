# 数据挖掘与自动标注

> 从 PB 级驾驶数据中挖出金子，再让 AI 自己写标签 — 这是数据闭环的两大核心效率杠杆。

---

## 一、数据挖掘 (Data Mining)

### 问题定义

```
从海量数据中找到最有价值的场景:

原始数据:  100,000 小时驾驶数据
           ↓ (数据挖掘)
高价值数据: 1,000 小时 (1%)
           ↓ (标注 + 训练)
模型提升:   相当于用全部 100,000 小时数据训练的 95%
```

**核心问题**：如何定义"高价值"？

### 挖掘策略

#### 1. 基于规则挖掘

| 规则类型 | 示例 | 方法 |
|----------|------|------|
| **安全事件** | AEB/急刹触发的前后 30 秒 | 车辆 CAN 信号 |
| **接管事件** | 人工接管智驾 | 系统状态切换 |
| **模型失败** | 检测漏检/误检 | 模型输出 vs 真值对比 |
| **场景标签** | 特定天气/光照/道路类型 | 传感器元数据 |
| **行为异常** | 轨迹偏离、速度突变 | 统计学检测 |

#### 2. 基于不确定性挖掘

```
模型在未标注数据上推理:
  高置信度 (confident)    → 简单场景 → 不采
  低置信度 (uncertain)    → 模型不确定 → 有价值! → 采集
  高熵 (high entropy)     → 模型困惑  → 最有价值! → 优先采集
```

**不确定性度量**：

| 指标 | 含义 | 计算方式 |
|------|------|----------|
| **预测熵** | 模型对预测结果的确定程度 | `H = -Σ p_i log(p_i)` |
| **认知不确定性** | 缺乏知识导致的不确定 | 多次 MC Dropout 的方差 |
| **偶然不确定性** | 数据固有噪声 | 模型直接输出 |
| **特征空间距离** | 与训练数据的分布差异 | OOD 检测 |

#### 3. 基于主动学习挖掘 (Active Learning)

```
  ┌─────────────────────────────────────┐
  │       主动学习循环 (Active Loop)     │
  │                                      │
  │  已标注数据 → 训练模型 → 在未标注数据上推理
  │       ↑                           ↓
  │       │                    按价值评分排序
  │       │                           ↓
  │       └────── 标注 ─────── 选出最有价值的 K 个
  └─────────────────────────────────────┘
```

**ActiveAD** (2024) 提出了规划导向的主动学习：

```
数据选择指标:
  1. 多样性 (Diversity):
     - 场景类型: 天气 × 光照 × 驾驶指令
     - 初始选择覆盖各种组合

  2. 位移误差 (Displacement Error):
     - 规划轨迹 vs 真值轨迹的 L2 距离
     - 误差大 → 模型不擅长这个场景 → 需要更多数据

  3. 软碰撞 (Soft Collision):
     - 规划轨迹与障碍物的潜在碰撞风险

  4. Agent 不确定性 (Agent Uncertainty):
     - 对其他 agent 轨迹预测的不确定性
     - 附近 agent 权重更高（距离加权）
```

**效果**：只用 **30% nuScenes 数据**，达到全量数据 95% 的表现。

#### 4. 基于场景嵌入挖掘

```
用 BEV 特征提取"场景指纹"：

所有未标注数据 → 模型推理 → BEV 特征 → 降维聚类
                                          ↓
                              找到离群点 (outlier) → 稀有场景!
                              找到聚类边缘 → 模棱两可场景!
```

## 二、自动标注 (Auto-Labeling)

### 为什么需要自动标注

| 标注方式 | 速度 | 成本/帧 | 精度 |
|----------|:--:|:--:|:--:|
| **纯人工** | ~15 min/frame | 高昂 | 高 |
| **半自动** | ~5 min/frame | 中等 | 较高 |
| **AI 标注+人工抽检** | ~0.1 sec/frame | 低 | 中高 |
| **全自动 (大模型)** | ms 级 | 极低 | 接近人工 |

**目标**：从"人标注"到"AI 标注，人审核"。

### 自动标注技术栈

#### 1. 离线大模型标注

```
用最强的模型离线标注:
  车载传感器数据 → 云端超大模型推理 → 伪标签 (Pseudo Label)

然后用这些伪标签去训练车端轻量模型
→ 大模型知识蒸馏到小模型
```

**华为做法**：用盘古大模型做自动标注，标注效率显著提升。

#### 2. 多传感器交叉验证标注

```
同一时刻:
  Camera 检测到: "车辆" (可能有误检)
  LiDAR 检测到:  3D BBox (有距离但无语义)
  Radar 检测到:  运动点 (有速度)

交叉验证:
  IF Camera 检测到车辆 AND LiDAR 有对应 3D 框 AND Radar 有对应速度
  → 高置信度标签，无需人工确认

  IF 只有一个传感器检测到
  → 低置信度标签，需要人工审核
```

#### 3. 时序一致性标注

```
单帧检测可能不稳定：
  Frame t:   检测到
  Frame t+1: 丢失
  Frame t+2: 检测到

利用时序一致性:
  → 中间帧 (t+1) 大概率也有目标
  → 用插值/追踪补齐中间帧的标签
```

#### 4. 3D 场景重建 + 自动标注

```
多帧图像 → NeRF / 3DGS → 3D 场景重建
                              ↓
                    在统一 3D 空间中进行标注
                    (不需要逐帧标注!)
                              ↓
                    投影回 2D → 所有帧都有标注
```

**华为盘古大模型**结合 NeRF 技术，将不同时刻的驾驶视频重建为 3D 空间，然后在该空间中自动标注，大幅降低人工参与。

#### 5. VLM 自动标注

```
图像 → VLM (如 GPT-4V / Qwen-VL)
           ↓
    "前方有一个红色轿车，正在左车道，距离约 20 米，
     前方人行道上有两个行人正在等待过马路"
           ↓
    解析 → 3D BBox 标签 + 语义标签 + 场景描述
```

## 三、数据增强与生成

### 传统数据增强

| 方法 | 适用 |
|------|------|
| 翻转/旋转/缩放 | 通用 |
| 颜色抖动 | 光照变化 |
| 随机裁剪 | 部分遮挡 |
| MixUp / CutMix | 场景混合 |
| Mosaic | 多图拼接（YOLO 系列） |

### 生成式数据增强

#### NeRF/3DGS 场景编辑

```
真实场景 → NeRF 重建 → 编辑场景元素:
  ├── 添加/删除车辆
  ├── 改变天气/光照
  ├── 修改道路结构
  └── 注入 corner case 事件
          ↓
      渲染 → 新的训练数据
```

#### 扩散模型生成

```
文本描述: "雨夜，高速公路，前方货车掉落纸箱"
           ↓
扩散模型 (如 Stable Diffusion) → 场景图像
           ↓
    作为训练数据补充 corner case
```

#### 仿真生成

```
CARLA/自定义仿真 → 无限场景数据:
  ├── 极端天气 (暴雪/浓雾)
  ├── 危险场景 (鬼探头/逆行车)
  ├── 罕见路况 (塌方/洪水)
  └── 传感器故障模拟
```

## 四、数据版本管理

### 为什么重要

```
模型 v3.2 表现退化了 → 是用哪批数据训练的？ → 数据版本缺失 → 无法定位
```

### 数据版本管理要素

```
每个数据样本应记录:
  ├── 数据 ID + 版本号
  ├── 采集时间 + 地点 + 车辆 ID
  ├── 传感器配置 + 标定参数
  ├── 天气 + 光照 + 道路类型
  ├── 标注方式 (人工/AI) + 标注版本
  ├── 使用记录 (被哪些模型训练过)
  └── 数据血缘 (Data Lineage)
```

### 数据-模型-评测 统一血缘

```
训练样本 ID → 模型版本 → 评测结果 → 部署版本
     └─────────────────── 可追溯 ─────────────────┘
```

## 五、核心指标

| 指标 | 含义 | 目标 |
|------|------|:--:|
| **挖掘效率** | 有价值数据 / 总采集数据 | > 5% |
| **标注自动化率** | AI 标注 / 总标注量 | > 90% |
| **标注一致性** | 多轮标注的一致性 | > 99% |
| **corner case 覆盖率** | 已覆盖类型 / 已知类型 | 持续增长 |
| **数据周转时间** | 采集→标注可用 | < 24h |
