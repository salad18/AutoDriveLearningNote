## 〇、大白话总览

### 后训练的核心问题（一句话）

**SFT 让模型"会做事"（模仿专家），后训练让模型"做得好"（符合偏好/安全/奖励）**——本篇所有技巧都在回答三个问题：

```
问题 1: 怎么定义"好"？       → 偏好对 / 奖励函数 / 规则
问题 2: 怎么用"好"的反馈？   → RLHF（奖励模型）/ DPO（直接偏好）/ GRPO（组内比较）
问题 3: 数据/算力不够怎么办？ → 蒸馏 / 合成数据 / 在线采样
```

> [!note] 打个比方
> - SFT = **"照着老司机学"**（模仿）。
> - RLHF = **"请教练打分"**（先训练一个"裁判"，再让模型按裁判标准优化）。
> - DPO = **"直接看回放学"**（不用裁判，直接对比"好动作 vs 坏动作"学）。
> - GRPO = **"同场竞技排名"**（同一场景采样多个动作，按组内相对排名学）。
> - 蒸馏/合成数据 = **"抄好学生答案 / 请 AI 出模拟题"**（解决数据不够）。

## 一、GRPO 深入（2025 年后训练主力）

### 1.1 GRPO 完整流程（手推一遍）

```
对每个 prompt/场景 s:

Step 1: 采样 G 个候选输出（组）
  从当前策略 π_θ 采样:  y_1, y_2, ..., y_G

Step 2: 打分（奖励）
  用规则/奖励模型给每个 y_i 打分:  r_1, r_2, ..., r_G

Step 3: 计算组内优势（advantage）
  mean = (1/G) Σ r_i
  std  = sqrt((1/G) Σ (r_i - mean)²)
  A_i  = (r_i - mean) / std          ← 相对排名，不是绝对分数!

Step 4: 策略优化（类似 PPO 的 loss，但无 Critic）
  L = -E[ min(ρ_i·A_i, clip(ρ_i, 1-ε, 1+ε)·A_i) ]
  其中 ρ_i = π_θ(y_i|s) / π_ref(y_i|s)   ← 重要性采样比
```

### 1.2 GRPO 为什么省掉 Critic？（关键理解）

```
PPO:  A(s,a) = r + γ·V(s') - V(s)      ← 需要价值网络 V（估计绝对优势）
GRPO: A_i   = (r_i - mean) / std        ← 只要组内相对排名，不需要 V
```

> [!note] GRPO 的洞察（面试必讲）
> PPO 的价值网络 V(s) 是"学出来的绝对评分器"，训练复杂且不稳定（Critic 也要训）。GRPO 发现：**同一场景下采样 G 个候选，它们共享同一个状态 s——直接用"自己分数 vs 组平均"的相对排名当优势，完全不需要学 V**。**"省掉 Critic = 更简单、更稳定、省一半显存"**——这就是 2024 后 GRPO 取代 PPO 成为后训练主力的原因。

### 1.3 on-policy vs off-policy（Revisiting GRPO 2025 的核心讨论）

> 论文：[Revisiting GRPO](https://ar5iv.labs.arxiv.org/html/2505.22257)（Noukhovitch et al., 2025）——对 GRPO 的 on/off-policy 训练行为做深入分析。

| 概念 | 含义 | 在 GRPO 中 |
|------|------|-----------|
| **on-policy** | 用"当前策略"采样的数据训练 | GRPO 每步用当前 π_θ 采样 → 天然 on-policy |
| **off-policy** | 用"旧策略/其他策略"的数据训练（复用） | 可复用历史采样 → 省采样算力，但引入分布偏差 |

**Revisiting GRPO 的关键发现（面试谈资）**：
1. GRPO 本质是 **on-policy** 方法（数据来自当前策略）——样本效率低（每次采样用完即弃），但梯度信号最"新鲜"。
2. 论文分析发现 GRPO 的成功**部分来自 on-policy 特性**：采样的多样性（G 个候选）提供了"探索"，组内对比提供了"相对信号"。
3. **off-policy 复用**（用旧数据）会引入分布偏差 → 需要重要性采样修正或"回放缓冲区"设计——**"on-policy 保质量，off-policy 省算力"的权衡是工程选型核心**。

> [!warning] 面试怎么聊 Revisiting GRPO
> 不用背论文细节，抓两个点：① GRPO 是 on-policy（每步重采样，质量高但费算力）；② 2025 的研究在探索 off-policy 复用（省算力）并分析其偏差——**"知道 GRPO 有 on/off-policy 的权衡"就比 90% 的候选人深一层**。

## 二、DPO 及其变体家族（"直接偏好优化"的进化树）

### 2.1 DPO 回顾（[[三阶段训练范式]] 有基础，这里只给关键公式）

```
L_DPO = -log σ( β·[log π(y_w|x)/π_ref(y_w|x) - log π(y_l|x)/π_ref(y_l|x)] )
        ↑ 提升"好"相对概率    ↑ 降低"坏"相对概率    ↑ 锚定 SFT（防偏太远）
```

### 2.2 变体家族（面试"DPO 有哪些改进"就答这张表）

| 变体 | 改了什么 | 解决什么问题 | 一句话记忆 |
|------|----------|-------------|-----------|
| **DPO** (2023) | 原始版 | 省掉奖励模型 | 直接用偏好对优化 |
| **IPO** (2023) | 目标函数改为"恒等偏好优化" | DPO 的"奖励过度优化"倾向 | 更稳的 DPO |
| **KTO** (2023) | 只要"好/坏"标签，不要成对数据 | 配对数据难标（哪个比哪个好难判断） | 单边标签也能训 |
| **SimPO** (2024) | 去掉 π_ref 参考模型 + 长度归一化 | 省显存、对长输出更公平 | 无参考模型的 DPO |
| **ORPO** (2024) | 微调时同时做 SFT 和偏好优化 | 不用单独 SFT 阶段 | 一步到位 |

> [!note] 变体选择的直觉（面试加分）
> - 数据是"成对偏好"（好 vs 坏）→ **DPO/SimPO**。
> - 数据只有"单个好坏标签"（KTO 场景：AEB 触发=坏，正常=好）→ **KTO**。
> - 显存紧张 / 想省一个阶段 → **SimPO**（去参考模型）/ **ORPO**（去单独 SFT）。
> - **智驾场景的偏好数据**：接管数据天然是"成对"（模型轨迹 vs 人类轨迹）→ DPO 系直接可用；AEB/急刹数据是"单边标签"→ KTO 更合适（[[三阶段训练范式]] 的 CoReVLA 是 DPO 应用案例）。

## 三、蒸馏（Distillation）——"抄好学生的答案"

### 3.1 为什么蒸馏？（"数据贵"的解药之一）

```
直接训练小模型:  需要海量标注数据（贵）
蒸馏:           大模型（老师）生成答案 → 小模型（学生）模仿
                → 学生"继承"老师的能力，数据来自老师（免费生成）
```

### 3.2 离线 vs 在线蒸馏

| 方式 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **离线蒸馏** | 先让老师生成全部数据，再训学生 | 简单、可并行 | 数据固定，学生学不到老师"最新"能力 |
| **在线蒸馏** | 学生边训边让老师生成新数据 | 数据随学生水平更新（渐进式） | 复杂、老师要在线 |

> [!note] 和智驾的联系（面试串联）
> 蒸馏 = [[模型基础知识补充]] 里"知识蒸馏"的**大模型版**——智驾 BEV 蒸馏（大模型教小模型）和 LLM 蒸馏（教师生成数据）是同一个思想。**VLA 智驾的小模型化（1-3B 上车）几乎都靠蒸馏**——这是 [[模型部署与延迟优化]] 的"轻量化"在模型层面的答案。

## 四、合成数据（Synthetic Data）——"请 AI 出模拟题"

### 4.1 三种合成数据范式

| 范式 | 做法 | 代表 | 智驾对应 |
|------|------|------|----------|
| **Self-Instruct** | 让 LLM 自己生成"问题+答案"再自训 | Self-Instruct (2022) | — |
| **模型蒸馏生成** | 大模型生成偏好对/推理链 | 蒸馏的延伸 | 语言标注自动化（[[大模型与自动驾驶]]） |
| **世界模型生成** | 用世界模型合成场景/轨迹 | **DriveVLA-W0**、GAIA-1 | [[世界模型]] 的数据增强 |

> [!note] 合成数据的核心价值
> **"数据不够，AI 来造"**——解决"标注贵/数据稀缺"（[[数据闭环总览]] 的生成式增强趋势）。注意陷阱：**合成数据有"模型偏见"**（老师会的学生会，老师错的也会）→ 需要真实数据校准（"合成打底 + 真实兜底"）。

### 4.2 智驾/VLA 的合成数据实践

```
LLM 生成推理链:     VLA 需要"语言/推理"标注 → LLM 自动生成 CoT → 人工抽查
世界模型合成场景:   驾驶 corner case 难采集 → WM 生成 → VLA 训练（DriveVLA-W0）
仿真数据:           CARLA 等 → 行为克隆数据（有 domain gap，需混合真实）
```

> [!warning] 合成数据的质量陷阱（面试常问）
> 合成数据用多了会让模型"过拟合到合成分布"（真实世界的分布反而学不到）。**工程答案：混合比例 + 真实数据校准**——"合成数据打底（量大便宜） + 真实数据校准（量少保真）"，比例靠实验调（如 70% 真实 + 30% 合成）。

## 五、与 VLA/智驾训练的衔接（本篇的"应用出口"）

### 5.1 VLA 训练 = LLM 三阶段 + 动作头

```
Stage 1: 互联网预训练（视觉+语言能力）   ← 和 LLM 一样
Stage 2: SFT（示范数据，图+语言+动作）    ← 多了动作维度
Stage 3: RL/偏好对齐（接管/偏好数据）     ← 和 LLM 一样，但奖励含安全项
```

### 5.2 技巧映射表（"LLM 技巧 → VLA 智驾怎么用"）

| LLM 技巧 | VLA/智驾的用法 |
|----------|----------------|
| GRPO 组内采样 | 同一驾驶场景采样多个轨迹候选 → 组内排名（AutoDrive-P3 就是 GRPO） |
| DPO/KTO | 接管数据（成对）→ DPO；AEB/急刹（单边）→ KTO |
| 蒸馏 | 大 VLA 教师 → 1-3B 学生（上车部署） |
| 合成数据 | LLM 生成推理链 + 世界模型生成场景（DriveVLA-W0） |
| on/off-policy 权衡 | 仿真 RL 用 on-policy（探索），云端历史数据复用用 off-policy（省算力） |

> [!note] 面试"VLA 训练和 LLM 训练有什么区别"的答案
> **相同**：三阶段范式、偏好对齐（DPO/GRPO）、蒸馏、合成数据——**LLM 后训练的全套技巧直接可用**。
> **不同**：① **动作维度**（连续动作 + 动作头，Flow Matching）；② **数据**（图+语言+动作三对齐，更难）；③ **奖励**（安全项权重高，如碰撞惩罚）；④ **实时性**（部署到车要蒸馏小模型）。
> **结论：VLA 训练 = "LLM 训练技巧 + 智驾领域约束"**——你掌握的 LLM 训练技巧在 VLA 智驾里 80% 直接复用。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为 GRPO 和 PPO 是"两个方法"**——GRPO 是 PPO 的变体（省掉 Critic），核心还是"策略优化"。
> 2. **混淆 on/off-policy**——GRPO 是 on-policy（每步重采样）；复用旧数据 = off-policy（省算力但有偏差）。
> 3. **以为 DPO 万能**——DPO 需要"成对偏好数据"；只有单边标签时用 KTO。
> 4. **忽视参考模型/锚定**——DPO 的 π_ref、RLHF 的 KL 约束都是"锚定 SFT"，去掉会"偏太远"（SimPO 去掉是有代价的）。
> 5. **合成数据无脑用**——会过拟合合成分布，必须真实数据校准（混合比例靠实验）。
> 6. **以为蒸馏只是"压缩"**——蒸馏同时也是"数据生成"（老师造数据），是数据稀缺的解药。

## ✅ 检验自己（自测题）

> [!question] Q1：GRPO 的组内优势怎么算？为什么不需要 Critic？
> 提示：相对排名。

> [!success]- 参考答案
> 对同一场景采样 G 个候选，打分后计算 mean 和 std，每个候选的 advantage = (r_i - mean)/std——**组内相对排名**。不需要 Critic 因为：同场景的 G 个候选共享同一个状态，相对排名本身就表达了"哪个更好"，不需要学一个绝对价值函数 V 来估计优势。省掉 Critic = 更简单、更稳定、省显存——这是 GRPO 取代 PPO 成为主力的原因。

> [!question] Q2：on-policy 和 off-policy 在 GRPO 里怎么权衡？
> 提示：质量 vs 算力。

> [!success]- 参考答案
> GRPO 本质是 on-policy（用当前策略采样），梯度信号新鲜但样本用完即弃（费采样算力）。off-policy 复用旧数据省算力，但引入分布偏差（旧策略的分布 ≠ 当前策略），需要重要性采样修正或回放缓冲。**工程权衡：算力充足用 on-policy 保质量；算力紧张用 off-policy 省成本 + 修正偏差**（Revisiting GRPO 2025 分析了这个权衡）。

> [!question] Q3：DPO 家族各变体解决什么问题？智驾数据怎么选？
> 提示：成对/单边/省参考模型。

> [!success]- 参考答案
> DPO 原始版省奖励模型；IPO 解决奖励过度优化（更稳）；KTO 支持单边标签（不需要成对数据）；SimPO 去掉参考模型（省显存）；ORPO 合并 SFT+偏好（省一个阶段）。智驾选型：接管数据天然成对（模型轨迹 vs 人类轨迹）→ DPO/SimPO；AEB/急刹是单边标签（坏）→ KTO；部署显存紧张 → SimPO。

> [!question] Q4：蒸馏为什么既是"压缩"又是"数据生成"？离线/在线怎么选？
> 提示：老师造数据。

> [!success]- 参考答案
> 蒸馏让学生模仿老师的输出——① 压缩：大模型能力传给小模型（部署）；② 数据生成：老师可以无限生成训练数据（解决数据贵）。离线蒸馏（先全量生成再训学生）简单可并行，但数据固定；在线蒸馏（边训边生成）数据随学生水平更新更优但复杂。工程上小模型起步用离线，追求上限用在线。

> [!question] Q5：合成数据有什么陷阱？智驾/VLA 怎么用才安全？
> 提示：合成分布过拟合。

> [!success]- 参考答案
> 陷阱：合成数据有"模型偏见"（老师会的学生会，老师错的也会），用多了模型过拟合合成分布、真实世界分布学不到。安全用法：① 混合比例（合成打底 + 真实校准，比例靠实验）；② 人工抽查合成质量；③ 世界模型合成场景 + 真实数据兜底。VLA 智驾的合成数据：LLM 生成推理链（抽查）、世界模型生成场景（DriveVLA-W0 路线）、仿真数据（混合真实）。

## 🛠 动手练习

### 练习 1：手算 GRPO 优势（15 分钟）

一个驾驶场景采样 6 条轨迹（G=6），奖励分：8.0, 7.5, 7.2, 6.8, 6.0, 5.5。
1. 算 mean 和 std。
2. 算每条轨迹的 advantage。
3. 哪条轨迹被提升最多？哪条被压制最狠？如果分数改成"全部接近"（7.5, 7.4, 7.4, 7.3, 7.3, 7.2），advantage 会怎样？（提示：std 变小 → 优势放大——**组内差异小时，微小差距也会被放大**，这是 GRPO 的特性）

> [!tip] 算完你会发现
> GRPO 的"组内相对"特性：**即使绝对分数都很高（7.5 都算好），组内最低的也会被压制**——所以采样质量很重要（全是好轨迹时，最差的好轨迹也被压）。这解释了为什么 GRPO 需要多样化的采样。

1. Stage 2（SFT）：用什么数据？怎么组织？（提示：示范数据 + CoT 格式）
