## 〇、大白话总览

### 两个核心效率杠杆

```
杠杆 1 数据挖掘:  100,000 小时数据 → 挖出 1,000 小时高价值的（1%）
杠杆 2 自动标注:  人工 15 分钟/帧 → AI 0.1 秒/帧（快 9000 倍）
```

> [!note] 打个比方
> - **数据挖掘** = "淘金"——河沙（海量数据）里筛出金子（高价值场景）。
> - **自动标注** = "让老师傅带徒弟干活"——先让最强的模型（老师傅）标，人工只抽查（徒弟复核）。
> **两个杠杆合起来**：挖得准（少标）→ 标得快（便宜）→ 数据闭环才转得起来。

## 一、数据挖掘 (Data Mining)

### 问题定义

```
从海量数据中找到最有价值的场景:

原始数据:  100,000 小时驾驶数据
           ↓ (数据挖掘)
高价值数据: 1,000 小时 (1%)
           ↓ (标注 + 训练)
模型提升:   相当于用全部 100,000 小时数据训练的 95%
```

**核心问题**：如何定义"高价值"？

> [!warning] "1% 数据 = 95% 效果"为什么成立？（面试核心）
> 100,000 小时里 99% 是"平凡场景"（直行/跟车）——**模型早已学会，重复训练边际收益≈0**；真正有用的是那 1% 的 corner case 和模型不擅长的场景。**"数据挖掘"的本质 = 找到"模型还没学会的场景"**——不是"找最多数据"，是"找最有信息量的数据"。

### 挖掘策略

#### 1. 基于规则挖掘

| 规则类型 | 示例 | 方法 |
|----------|------|------|
| **安全事件** | AEB/急刹触发的前后 30 秒 | 车辆 CAN 信号 |
| **接管事件** | 人工接管智驾 | 系统状态切换 |
| **模型失败** | 检测漏检/误检 | 模型输出 vs 真值对比 |
| **场景标签** | 特定天气/光照/道路类型 | 传感器元数据 |
| **行为异常** | 轨迹偏离、速度突变 | 统计学检测 |

> [!note] 规则挖掘的直觉
> **"车自己报告它遇到了什么"**——AEB 激活（车觉得危险）、人工接管（人觉得模型不行）、检测漏检（模型自知失败）……**规则 = 把"车的行为"翻译成"数据价值信号"**。简单直接，是数据挖掘的第一层。

#### 2. 基于不确定性挖掘

```
模型在未标注数据上推理:
  高置信度 (confident)    → 简单场景 → 不采
  低置信度 (uncertain)    → 模型不确定 → 有价值! → 采集
  高熵 (high entropy)     → 模型困惑  → 最有价值! → 优先采集
```

**不确定性度量**：

| 指标 | 含义 | 计算方式 |
|------|------|----------|
| **预测熵** | 模型对预测结果的确定程度 | `H = -Σ p_i log(p_i)` |
| **认知不确定性** | 缺乏知识导致的不确定 | 多次 MC Dropout 的方差 |
| **偶然不确定性** | 数据固有噪声 | 模型直接输出 |
| **特征空间距离** | 与训练数据的分布差异 | OOD 检测 |

> [!note] 不确定性挖掘的直觉（和 [[训练排错实战手册]] 无关，是数据侧）
> **"模型自己最知道自己哪里不会"**——高置信度（已学会，不采）、低置信度（没学会，采）、高熵（完全困惑，优先采）。**不确定性 = "模型不会做"的自动标记器**，比规则更细粒度（规则只能发现"事件"，不确定性能发现"模型薄弱点"）。

#### 3. 基于主动学习挖掘 (Active Learning)

```
  ┌─────────────────────────────────────┐
  │       主动学习循环 (Active Loop)     │
  │                                      │
  │  已标注数据 → 训练模型 → 在未标注数据上推理
  │       ↑                           ↓
  │       │                    按价值评分排序
  │       │                           ↓
  │       └────── 标注 ─────── 选出最有价值的 K 个
  └─────────────────────────────────────┘
```

**ActiveAD** (2024) 提出了规划导向的主动学习：

```
数据选择指标:
  1. 多样性 (Diversity):
     - 场景类型: 天气 × 光照 × 驾驶指令
     - 初始选择覆盖各种组合

  2. 位移误差 (Displacement Error):
     - 规划轨迹 vs 真值轨迹的 L2 距离
     - 误差大 → 模型不擅长这个场景 → 需要更多数据

  3. 软碰撞 (Soft Collision):
     - 规划轨迹与障碍物的潜在碰撞风险

  4. Agent 不确定性 (Agent Uncertainty):
     - 对其他 agent 轨迹预测的不确定性
     - 附近 agent 权重更高（距离加权）
```

**效果**：只用 **30% nuScenes 数据**，达到全量数据 95% 的表现。

> [!warning] ActiveAD 的"规划导向"（面试谈资）
> 主动学习循环 = "训练→选样本→标注→再训练"的闭环。**ActiveAD 的进化：选样本的标准从"感知误差"变成"规划误差"**（位移误差/软碰撞）——**"以规划安全为导向选数据"**（呼应 [[UniAD详解]] 的 Planning-Oriented 思想）。**"30% 数据 = 95% 效果"是主动学习的核心卖点**——数据效率数量级提升。

#### 4. 基于场景嵌入挖掘

```
用 BEV 特征提取"场景指纹"：

所有未标注数据 → 模型推理 → BEV 特征 → 降维聚类
                                          ↓
                              找到离群点 (outlier) → 稀有场景!
                              找到聚类边缘 → 模棱两可场景!
```

> [!note] 场景嵌入挖掘的直觉
> **"把场景变成指纹，看谁长得不一样"**——BEV 特征降维聚类后，**离群点 = 稀有场景（没见过的），聚类边缘 = 模糊场景（介于两类之间）**。这是"无监督版"的不确定性挖掘——不需要模型输出置信度，只看特征分布。

## 二、自动标注 (Auto-Labeling)

### 为什么需要自动标注

| 标注方式 | 速度 | 成本/帧 | 精度 |
|----------|:--:|:--:|:--:|
| **纯人工** | ~15 min/frame | 高昂 | 高 |
| **半自动** | ~5 min/frame | 中等 | 较高 |
| **AI 标注+人工抽检** | ~0.1 sec/frame | 低 | 中高 |
| **全自动 (大模型)** | ms 级 | 极低 | 接近人工 |

**目标**：从"人标注"到"AI 标注，人审核"。

> [!warning] 标注方式的核心权衡（面试谈资）
> **人工：准但慢贵（15 分钟/帧）；AI：快但可能错（0.1 秒/帧）**。量产答案不是"全 AI"或"全人工"，是 **"AI 标注 + 人工抽检"**——用置信度分级：高置信度标签直接过（免人工），低置信度标签人工审。**"人机协同标注"是成本与质量的平衡点**（类似 [[大模型训练技巧进阶]] 的"合成打底+真实校准"）。

### 自动标注技术栈

#### 1. 离线大模型标注

```
用最强的模型离线标注:
  车载传感器数据 → 云端超大模型推理 → 伪标签 (Pseudo Label)

然后用这些伪标签去训练车端轻量模型
→ 大模型知识蒸馏到小模型
```

**华为做法**：用盘古大模型做自动标注，标注效率显著提升。

> [!note] 离线大模型标注 = "知识蒸馏的数据侧"
> 用最强的模型（云端大模型）标数据 → 伪标签 → 训练车端小模型——**"大模型教小模型"**（[[模型训练与微调]] 的知识蒸馏）。**这是 [[三阶段训练范式]] 蒸馏概念的"数据生产版"**：蒸馏不只在训练时，还在数据标注时。

#### 2. 多传感器交叉验证标注

```
同一时刻:
  Camera 检测到: "车辆" (可能有误检)
  LiDAR 检测到:  3D BBox (有距离但无语义)
  Radar 检测到:  运动点 (有速度)

交叉验证:
  IF Camera 检测到车辆 AND LiDAR 有对应 3D 框 AND Radar 有对应速度
  → 高置信度标签，无需人工确认

  IF 只有一个传感器检测到
  → 低置信度标签，需要人工审核
```

> [!note] 交叉验证标注的直觉（[[多传感器融合基础]] 的应用）
> **"三个证人说同一件事 = 可信"**——Camera（语义）+ LiDAR（几何）+ Radar（速度）同时命中 = 高置信度标签（免人工）；只有一个传感器 = 存疑（人工审）。**"多模态投票" = 自动标注的置信度来源**。

#### 3. 时序一致性标注

```
单帧检测可能不稳定：
  Frame t:   检测到
  Frame t+1: 丢失
  Frame t+2: 检测到

利用时序一致性:
  → 中间帧 (t+1) 大概率也有目标
  → 用插值/追踪补齐中间帧的标签
```

> [!note] 时序标注的直觉
> **"物体不会瞬移消失"**——相邻帧检测到目标，中间帧"丢失"大概率是漏检，用插值/追踪补齐。**"时间连续性 = 免费的标注约束"**（和 [[计算机视觉基础]] 的跟踪思想一致）。

#### 4. 3D 场景重建 + 自动标注

```
多帧图像 → NeRF / 3DGS → 3D 场景重建
                              ↓
                    在统一 3D 空间中进行标注
                    (不需要逐帧标注!)
                              ↓
                    投影回 2D → 所有帧都有标注
```

**华为盘古大模型**结合 NeRF 技术，将不同时刻的驾驶视频重建为 3D 空间，然后在该空间中自动标注，大幅降低人工参与。

> [!warning] 3D 重建标注 = 自动标注的"核武器"（面试谈资）
> **在 3D 空间标一次，投影回所有帧**——把"逐帧标注"变成"3D 标一次 + 自动投影"。**"3D 一致性"让标注量从 O(帧数) 降到 O(场景数)"**——这是 [[华为ADS技术方案]] 盘古+NeRF 自动标注的原理。**"重建-标注-投影"是 2024-2026 自动标注的旗舰路线。**

#### 5. VLM 自动标注

```
图像 → VLM (如 GPT-4V / Qwen-VL)
           ↓
    "前方有一个红色轿车，正在左车道，距离约 20 米，
     前方人行道上有两个行人正在等待过马路"
           ↓
    解析 → 3D BBox 标签 + 语义标签 + 场景描述
```

> [!note] VLM 标注 = "让大模型看图说话转成标签"
> VLM 输出自然语言描述 → 解析成结构化标签。**价值**：① 语义标签（场景描述）人工标不了；② 长尾类别（VLM 见过"施工围挡"等）能标。**局限**：VLM 可能幻觉（[[大模型与自动驾驶]] 的幻觉问题）→ 需交叉验证/抽检。

## 三、数据增强与生成

### 传统数据增强

| 方法 | 适用 |
|------|------|
| 翻转/旋转/缩放 | 通用 |
| 颜色抖动 | 光照变化 |
| 随机裁剪 | 部分遮挡 |
| MixUp / CutMix | 场景混合 |
| Mosaic | 多图拼接（YOLO 系列） |

### 生成式数据增强

#### NeRF/3DGS 场景编辑

```
真实场景 → NeRF 重建 → 编辑场景元素:
  ├── 添加/删除车辆
  ├── 改变天气/光照
  ├── 修改道路结构
  └── 注入 corner case 事件
          ↓
      渲染 → 新的训练数据
```

#### 扩散模型生成

```
文本描述: "雨夜，高速公路，前方货车掉落纸箱"
           ↓
扩散模型 (如 Stable Diffusion) → 场景图像
           ↓
    作为训练数据补充 corner case
```

#### 仿真生成

```
CARLA/自定义仿真 → 无限场景数据:
  ├── 极端天气 (暴雪/浓雾)
  ├── 危险场景 (鬼探头/逆行车)
  ├── 罕见路况 (塌方/洪水)
  └── 传感器故障模拟
```

> [!note] 生成式增强 = 自动标注的"供给侧"（和 [[世界模型]] 联动）
> 挖掘是"从已有数据找"，生成是"造没有的数据"——**NeRF 编辑（真实场景改）、扩散生成（文本造场景）、仿真（规则造场景）**三种方式补齐 corner case。**"找 + 造"双管齐下 = 长尾数据解决方案**（[[数据闭环总览]] 生成式增强趋势 + [[世界模型]] 数据增强应用的完整版）。

## 四、数据版本管理

### 为什么重要

```
模型 v3.2 表现退化了 → 是用哪批数据训练的？ → 数据版本缺失 → 无法定位
```

### 数据版本管理要素

```
每个数据样本应记录:
  ├── 数据 ID + 版本号
  ├── 采集时间 + 地点 + 车辆 ID
  ├── 传感器配置 + 标定参数
  ├── 天气 + 光照 + 道路类型
  ├── 标注方式 (人工/AI) + 标注版本
  ├── 使用记录 (被哪些模型训练过)
  └── 数据血缘 (Data Lineage)
```

### 数据-模型-评测 统一血缘

```
训练样本 ID → 模型版本 → 评测结果 → 部署版本
     └─────────────────── 可追溯 ─────────────────┘
```

> [!warning] 数据版本管理 = "看不见但致命"的工程（面试加分点）
> **模型退化时最怕"不知道用哪批数据训的"**——数据版本管理让"样本→模型→评测→部署"全链路可追溯（[[评测消融与GT构造]] 的评测回归前提）。**"可复现性"不只是代码（[[训练排错实战手册]] Q2），还包括数据版本**——这是量产工程和论文复现的本质区别之一。

## 五、核心指标

| 指标 | 含义 | 目标 |
|------|------|:--:|
| **挖掘效率** | 有价值数据 / 总采集数据 | > 5% |
| **标注自动化率** | AI 标注 / 总标注量 | > 90% |
| **标注一致性** | 多轮标注的一致性 | > 99% |
| **corner case 覆盖率** | 已覆盖类型 / 已知类型 | 持续增长 |
| **数据周转时间** | 采集→标注可用 | < 24h |

> [!note] 两个最该盯的指标（和 [[数据闭环总览]] 呼应）
> - **挖掘效率**：挖出 100 段几段有用？（>5% 是及格线）——太低说明挖掘规则差。
> - **数据周转时间**：采集到标注可用 <24h——**"数据进闭环的速度"= 迭代速度**（华为 5 天迭代的前提）。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为数据挖掘 = 多采数据**——是"从海量里找最有信息量的 1%"（1% 数据 ≈ 95% 效果），不是数据越多越好。
> 2. **以为自动标注 = 全自动无人工**——量产是"AI 标注 + 人工抽检"（高置信度免审、低置信度人审），全自动不现实。
> 3. **忽视数据版本管理**——模型退化查不到数据来源 = 事故；"样本→模型→评测→部署"血缘是量产生命线。
> 4. **以为生成数据可以替代真实数据**——生成数据有分布偏差（[[大模型训练技巧进阶]] 的"合成打底+真实校准"）。
> 5. **只挖不标 / 只标不挖**——挖掘决定"标什么"，标注决定"标多快"，两个杠杆缺一不可。

## ✅ 检验自己（自测题）

> [!question] Q1：为什么"1% 数据 = 95% 效果"？数据挖掘的本质是什么？
> 提示：最有信息量的场景。

> [!success]- 参考答案
> 99% 的数据是"平凡场景"（模型已学会，重复训练边际收益≈0），真正有用的是 1% 的 corner case 和模型不擅长的场景。数据挖掘的本质 = 找到"模型还没学会的场景"（最有信息量的数据），不是"找最多数据"。方式：规则（事件）、不确定性（模型自报薄弱点）、主动学习（规划误差导向）、场景嵌入（特征聚类离群点）。

> [!question] Q2：主动学习循环是什么？ActiveAD 的"规划导向"体现在哪？
> 提示：训练→选样→标注→再训。

> [!success]- 参考答案
> 循环：已标注数据训练模型 → 在未标注数据上推理 → 按价值评分排序 → 选最有价值的 K 个标注 → 加入训练 → 循环。ActiveAD 的进化：选样标准从"感知误差"变成"规划误差"（位移误差/软碰撞/Agent 不确定性）——**"以规划安全为导向选数据"**（Planning-Oriented）。效果：30% 数据 = 95% 表现。

> [!question] Q3：五种自动标注技术分别是什么？各自原理一句话？
> 提示：大模型/多传感器/时序/3D/语言。

> [!success]- 参考答案
> ① 离线大模型标注：云端强模型标伪标签 → 蒸馏给小模型；② 多传感器交叉验证：Camera+LiDAR+Radar 同时命中 = 高置信免人工（"多模态投票"）；③ 时序一致性：相邻帧有目标则中间帧补全（"物体不瞬移"）；④ 3D 重建标注：NeRF 重建 3D 空间标一次投影回所有帧（"核武器"）；⑤ VLM 标注：大模型看图说话解析成标签（语义标签，需防幻觉）。

> [!question] Q4：数据版本管理为什么是量产生命线？
> 提示：可追溯。

> [!success]- 参考答案
> 模型退化时最怕"不知道用哪批数据训的"——数据版本管理记录每个样本的血缘（ID/采集信息/标注方式/使用记录），实现"样本→模型→评测→部署"全链路可追溯。可复现性不只靠代码（[[训练排错实战手册]] Q2），还靠数据版本——这是量产工程和论文复现的本质区别。

> [!question] Q5：生成式数据增强有哪些方式？有什么风险？
> 提示：NeRF/扩散/仿真。

> [!success]- 参考答案
> ① NeRF/3DGS 场景编辑（真实场景重建后改元素）；② 扩散模型生成（文本→场景图像）；③ 仿真生成（CARLA 造极端场景）。风险：生成数据有分布偏差（"模型偏见"）——需真实数据校准混合（"合成打底+真实兜底"）。"找（挖掘）+ 造（生成）"双管齐下是长尾数据解决方案。

## 🛠 动手练习

### 练习 1：设计一套挖掘规则（30 分钟）

假设你有 1 万小时驾驶数据，设计挖掘方案：
1. 列出 5 条规则（安全事件/接管/模型失败/场景标签/行为异常各想一条）。
2. 给每条规则写"触发条件"（可量化）。
3. 估算：1 万小时里你的规则大概能挖出多少小时？（合理吗？）

> [!tip] 算完自问
> ① 规则太多（挖出 50%）说明不聚焦，太少（0.01%）说明太严——"挖掘效率 >5%"是目标；② 规则和不确定性挖掘怎么结合？（规则发现候选，不确定性排优先级）

### 练习 2：设计"AI 标注 + 人工抽检"流程（45 分钟）

设计一个自动标注流水线：
1. 输入：1000 小时多传感器数据。
2. 分级：高置信度（多传感器交叉命中）→ 直接过；低置信度 → 人工审。
3. 估算：人工审核量占比？（假设高置信 80%，人工只审 20%）
4. 加一道 VLM 语义标注（场景描述）→ 怎么和 3D 框标注衔接？

> [!tip] 这是"人机协同标注"的完整设计
> 参照 [[多传感器融合基础]]（交叉验证）和 [[数据闭环总览]]（标注环节）。能说清"AI 标什么、人审什么、置信度怎么定"，面试"自动标注怎么落地"就过关了。

### 练习 3：写数据版本管理方案（可选，30 分钟）

给一个 5 人算法团队设计数据版本管理：
1. 每个样本要记录哪些字段？（参照第四节清单精简到 5 个必填）
2. 数据-模型-评测怎么串血缘？（一个简单表格）
3. 模型退化时，靠这套方案怎么定位问题？

> [!tip] 这是"工程思维"的体现
> 面试官爱问"你怎么保证可复现"——能主动讲数据版本管理 = 有量产经验的味道。写完存进 [[2026-08-20]]。
