# 场景诊断手册：模型在某个场景表现不好怎么办

> 一句话：**先切片（在哪错）→ 再归因（为什么错）→ 再决策（加数据还是改模型）→ 最后验证（切片涨、整体不掉）**。跳过前三步直接"加点数据"，是大多数团队浪费时间的方式。

---

## 〇、通用五步法

```
① 复现与切片：把"表现不好"变成"哪个切片、什么错误类型、多少帧"
② 错误归因：FP / FN / 定位 / 分类 / 时序 / ID / 规划
③ 根因分层：数据覆盖 / 标签 / 模型容量 / 训练 / 后处理 / 评测
④ 实验设计：单变量、A/B、切片指标、置信区间
⑤ 修复与回归：切片涨 + 整体不掉 + 硬门槛不破
```

### 错误类型 → 先查什么

| 错误类型 | 先查 | 常见根因 |
|----------|------|----------|
| **FN（漏检）** | 该场景训练集覆盖率、标注可见性 | 没见过 / 标太松 / 太小 / 遮挡 |
| **FP（误检）** | 负样本、后处理阈值 | 缺困难负样本 / 阈值低 / 反光 |
| **定位漂** | 深度/标定/远距 | 深度误差、外参漂移、分辨率 |
| **分类错** | 类别混淆矩阵 | 长尾类别、定义模糊 |
| **时序抖** | 帧间一致性 | 无时序、跟踪断、ID 跳 |
| **规划差** | 预测/规则/地图 | 交互没建模、规则缺失、拓扑错 |

## 一、先判：加数据还是改模型？

### 决策树

```
这个场景，训练集里见过吗？
├─ 几乎没见过（覆盖率 < 1%）→ 加数据（优先）
├─ 见过但学不会（训练 loss 也高）→ 改模型/容量/表示
├─ 见过、训练 loss 低、验证差 → 过拟合/分布差异 → 加多样性 + 正则
├─ 标签本身错/歧义 → 修标注（加数据没用）
└─ 评测口径错 → 修评测（加数据更没用）
```

### 三个判断实验

| 实验 | 怎么读 |
|------|--------|
| **覆盖率统计** | 该场景帧数 / 总帧数 < 1% → 先补数据 |
| **训练集 vs 验证集 loss** | 训练低验证高 → 过拟合/分布差；都高 → 容量/表示不足 |
| **加容量小实验** | 加宽后切片涨 → 容量问题；不涨 → 数据/标签问题 |

> [!warning] 最常见的误判
> 把"标签错"当成"数据少"，加了一堆同样标错的数据——**越加越差**。

## 二、加什么数据：六类 + 三条配方原则

### 六类数据

| 类型 | 作用 | 例子 |
|------|------|------|
| **正样本（多样）** | 补覆盖 | 夜间：不同路灯/无灯/雨夜，而不是同一条路 |
| **困难负样本** | 压 FP | 反光、井盖、阴影、路面修补、广告牌 |
| **边界样本** | 补决策边界 | 远距最小像素、临界遮挡、临界光照 |
| **时序样本** | 补时序 | 遮挡前后 5s、鬼探头全过程 |
| **配对样本** | 控变量 | 同场景白天/夜间、同路口晴/雨 |
| **合成/重建** | 补极端 | 3DGS 编辑加锥桶/改天气 |

### 三条配方原则

1. **配额试水**：先按 5-10% 配额加入，扫到拐点（见 [[数据跷跷板问题]]），不要一次灌 30%。
2. **多样性优先于数量**：1000 帧同一条路 ≪ 300 帧 20 个不同路口。
3. **配比 + 回放**：新数据加入时保留旧数据回放，防遗忘。

> [!note] 加数据前先问三个问题
> ① 这个场景我**标得对吗**？② 我加的是**同款**还是**同类**？③ 加完**哪个切片该涨**、怎么验证？

## 三、模型侧策略：六类

| 类别 | 手段 | 适用 |
|------|------|------|
| **输入** | 更高分辨率、多帧、多传感器、长焦 | 远距、小目标、夜间 |
| **结构** | 多尺度、更强 backbone、专用头 | 容量不足、尺度差异大 |
| **表示** | OCC/几何兜底、开放词汇、场景图 | 异形物、长尾类别 |
| **时序** | track、memory、遮挡推理 | 遮挡、鬼探头、抖动 |
| **训练** | 难例挖掘、蒸馏、后训练 RL、损失平衡 | 长尾、博弈、舒适性 |
| **后处理/规则** | NMS 调参、TTC 阈值、AEB、降级 | 安全兜底、舒适性 |

> [!warning] 顺序
> **先数据后模型，先表示后容量，先规则后 RL。** 一上来就改结构，通常是把数据问题拖成模型问题。

## 四、12 个场景处置卡

### S1 夜间无路灯

- **表现**：行人/两轮车漏检，远距框漂。
- **根因**：低照度噪声 + 标注少 + 车灯眩光。
- **验证**：按光照/时间切片，看 FN 集中的距离段。
- **加数据**：无灯/弱灯/雨夜多场景正样本；同场景白天-夜间配对；标注加"可见性"属性；困难负样本（路灯倒影、广告牌）。
- **模型**：多帧时序、LiDAR/Radar 权重上调、高分辨率输入、低光增强前端（可选）。
- **指标/坑**：夜间 FN、分距离召回；坑是"只加同一条路"。

### S2 雨天 / 反光 / 水雾

- **表现**：地面反光假目标、相机噪点、LiDAR 噪点。
- **根因**：反射与散射；训练缺"反光负样本"。
- **加数据**：雨天多场景 + 反光/积水负样本 + 水雾序列。
- **模型**：Radar 权重、多帧、去雨/去雾前端、置信度校准。
- **指标/坑**：雨天 FP（反光）与 FN 一起看；坑是只压 FP 把真目标也压掉。

### S3 隧道进出（明暗突变）

- **表现**：进出瞬间过曝/欠曝，短时漏检。
- **根因**：相机自动曝光滞后。
- **加数据**：进出隧道前后各 5s 序列（多隧道、多天气）。
- **模型**：HDR/曝光策略、时序、短时降级（限速/提示）。
- **指标/坑**：进出 3s 内 FN；坑是只标"隧道内"，不标"进出瞬间"。

### S4 逆光 / 远光

- **表现**：目标成剪影、车道线丢失。
- **根因**：动态范围不足。
- **加数据**：逆光/远光样本，标注"剪影/可见性"；配对样本。
- **模型**：HDR、轮廓/几何特征、LiDAR 补位。
- **指标/坑**：逆光切片 FN；坑是标注员也看不清 → 必须标可见性。

### S5 大车遮挡（盲区）

- **表现**：被遮挡目标突然出现，AEB 晚。
- **根因**：单帧看不到；缺时序/预测。
- **加数据**：遮挡全过程序列（遮挡前-中-后）、被遮挡目标轨迹补标。
- **模型**：时序/遮挡推理、OCC、行为预测、防御性规划。
- **指标/坑**：遮挡场景 TTC、接管；坑是单帧标注看不到 → 用前后帧补。

### S6 远距小目标（>80m）

- **表现**：锥桶/行人/两轮车漏检。
- **根因**：像素太少 + 标注规范缺失。
- **加数据**：远距正样本、长焦/高分辨率、LiDAR 稀疏区样本。
- **模型**：高分辨率、多尺度、远距专用头、时序累积。
- **指标/坑**：分距离召回（0-30/30-60/60-100/100+）；坑是"最小像素"标注规范不统一。

### S7 异形障碍物（掉落物/纸箱/轮胎）

- **表现**：漏检；类别无法穷举。
- **根因**：封闭类别集 + 训练缺样本。
- **加数据**：异形物正样本 + 困难负样本（井盖/阴影/修补）。
- **模型**：**OCC/GOD 几何兜底** + 开放词汇 + 白名单语义。
- **指标/坑**：异形物召回、误报率；坑是只加类别不加几何兜底。

### S8 两轮车 / 鬼探头

- **表现**：横穿/逆行/突然出现，漏检或晚刹。
- **根因**：目标小、速度快、遮挡、姿态多。
- **加数据**：两轮车多姿态/夜间/遮挡；鬼探头全过程序列。
- **模型**：时序、预测、OCC、AEB 规则兜底。
- **指标/坑**：TTC、漏检、误刹；坑是只加"静止两轮车"。

### S9 施工区

- **表现**：锥桶/围挡/临时改道，地图失效。
- **根因**：临时结构 + 地图过期。
- **加数据**：施工区多形态（锥桶摆放/围挡/临时标线）。
- **模型**：在线建图、OCC、规则降级（限速/绕行）。
- **指标/坑**：施工区通过率、接管；坑是把"临时标线"标成常设车道。

### S10 无保护左转 / 弱路权

- **表现**：犹豫、抢行、通行效率低。
- **根因**：交互没建模、规则模糊、标注歧义。
- **加数据**：路口博弈序列、意图/交互/路权标注（见 [[面试速答-弱路权与模态归一]]）。
- **模型**：多模态预测、博弈/POMDP、规则硬约束、后训练 RL。
- **指标/坑**：让行合规、通行时间、接管；坑是"人类也犹豫"→ 多标裁决。

### S11 加塞 / Cut-in

- **表现**：急刹、误刹。
- **根因**：预测晚、TTC 阈值激进/保守。
- **加数据**：近距离低速加塞序列、被加塞负样本。
- **模型**：预测、TTC 分层阈值、舒适性约束。
- **指标/坑**：急刹率、误刹率；坑是只优化"不撞"，牺牲舒适。

### S12 泊车 / 地库

- **表现**：低矮障碍（地锁/锥桶/消防栓）漏检、窄车位、定位失效。
- **根因**：近场盲区、GPS 无信号、鱼眼畸变。
- **加数据**：地库多场景、低矮障碍、鱼眼/超声波数据。
- **模型**：近场感知（环视/超声波）、建图定位、泊车规划。
- **指标/坑**：泊入成功率、刮蹭率；坑是只用行车数据训泊车。

## 五、多场景速查表

| 场景 | 首要根因 | 先加数据？ | 模型主招 | 关键指标 |
|------|----------|:--:|----------|----------|
| 夜间无灯 | 覆盖 + 照度 | ✅ | 时序/融合/高分辨率 | 夜间 FN |
| 雨/反光 | 负样本缺失 | ✅ | Radar + 校准 | 雨天 FP/FN |
| 隧道进出 | 曝光 | ✅ | HDR/时序/降级 | 进出 3s FN |
| 逆光 | 动态范围 | ✅ | HDR + LiDAR | 逆光 FN |
| 大车遮挡 | 时序缺失 | ✅ | 遮挡推理/OCC/预测 | 遮挡 TTC |
| 远距小目标 | 分辨率/规范 | ✅ | 高分辨率/专用头 | 分距离召回 |
| 异形物 | 类别封闭 | ✅ | **OCC + 开放词汇** | 异形召回/误报 |
| 两轮车 | 姿态/遮挡 | ✅ | 时序/预测/AEB | TTC/漏检 |
| 施工区 | 地图过期 | ✅ | 在线建图/OCC/规则 | 通过率 |
| 弱路权 | 交互/标注歧义 | ✅ | 博弈 + 规则 + 后训练 | 合规/效率 |
| 加塞 | 预测晚 | ⚠️ | 预测/TTC/舒适 | 急刹/误刹 |
| 泊车地库 | 近场/定位 | ✅ | 环视/超声波/建图 | 成功率/刮蹭 |

> "先加数据？"列 ⚠️ 表示：加塞更偏"预测+阈值"，数据是辅助。

## 六、面试怎么答（模板）

**面试官**："模型在 XX 场景表现不好，你怎么解决？"

**答法（60-90 秒）**：
> "我先切片，把'不好'变成'哪个距离段、哪类错误、多少帧'——比如夜间主要是 60m 外两轮车 FN。
> 然后归因：查训练集覆盖率、看标签可见性、对比训练/验证 loss。如果覆盖率极低，先补数据：同场景多路口、白天夜间配对、加可见性标注；如果 coverage 够但学不会，再动模型：多帧时序 + LiDAR 权重 + 高分辨率。
> 最后验证：夜间切片召回涨、白天不掉、硬门槛不破；线上灰度看接管率。"

**追问应对**：
- "为什么先加数据？" → 覆盖率 <1% 时模型没见过，改结构收益低。
- "加多少？" → 先 5-10% 配额扫拐点，看边际替代率。
- "怎么证明是数据的功劳？" → 单变量 + 配对 + 切片指标 + 多 seed。
- "加了没用怎么办？" → 回头查标签和评测，别继续加。
