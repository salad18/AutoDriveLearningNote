# 数据的跷跷板问题：诊断与解法

> 一句话：**跷跷板不是"模型不听话"，是"分布、容量、梯度"三者博弈的必然结果**。解法顺序是：先判真假 → 再画权衡曲线 → 数据侧治因 → 训练侧配合 → 评测侧定优先级。

---

## 〇、先分清：三种跷跷板

| 类型 | 表现 | 典型场景 |
|------|------|----------|
| **切片跷跷板** | 长尾↑，常见↓ | 加夜间/施工区数据，白天掉点 |
| **指标跷跷板** | 召回↑，精度↓；安全↑，效率↓ | 阈值移动、保守策略 |
| **任务跷跷板** | 检测↑，预测↓；感知↑，规划↓ | 多任务/端到端联合训练 |

> [!warning] 面试先说这句
> "跷跷板分三种——切片、指标、任务。**大多数是切片跷跷板，根因是分布偏移 + 容量固定；少数是任务跷跷板，根因是梯度冲突。**"——先分类，再谈解法。

---

## 一、为什么会发生：四个根因

### 1. 分布偏移（最常见）

加数据 = 改变训练分布。模型在固定容量下，会在新旧分布之间**重新分配"拟合预算"**：

$$L(\theta)=\sum_d w_d\, L_d(\theta)$$

$w_d$ 是各域权重。你把 $w_{长尾}$ 调大，最优解就向长尾偏移，常见域的损失上升——**这是数学必然，不是 bug**。

### 2. 容量瓶颈

模型参数量/感受野固定。判断方法：**加容量后如果两个切片同时涨 → 是容量问题；如果还是此消彼长 → 是冲突问题**。

### 3. 梯度冲突（任务跷跷板）

多任务时，两个任务的梯度方向可能相反：

$$\cos(g_A, g_B) < 0$$

沿 $g_A$ 更新会**增大** $L_B$。共享 backbone 越深，冲突越明显。

### 4. 采样零和

总 step/epoch 固定。A 数据从 20% 提到 40%，B 数据见的次数就少了——**配比是零和的**。

> [!note] 还有第五个"假根因"
> **标签噪声**：难例里混着错标，你越加权，噪声被放大得越狠。看起来像"跷跷板"，其实是"越训越偏"。

---

## 二、第一步：先判"真假跷跷板"

很多跷跷板是**评测假象**，动数据反而越调越糟。

### 三种假象

| 假象 | 怎么识别 | 怎么破 |
|------|----------|--------|
| **样本太少** | 该切片只有几百帧，波动 ±2 点 | 报置信区间 / 扩切片 |
| **指标耦合** | 总指标被大类主导，小类掉了看不出来 | 看 per-class / 分切片，不看总分 |
| **评测集过拟合** | val 涨、留出集不涨 | 留出集"少用、后用、不调参" |

### 诊断树（按顺序问）

```
① 真的掉了吗？
   → 配对 bootstrap 看 CI 是否跨 0；跑 3 个 seed 看方差
② 掉在哪？
   → 切片：夜间/雨天/远距/类别/城市/密度
③ 为什么掉？
   → 数据变了（配比/去重/标注版本）
   → 训练变了（lr/epoch/seed/增强）
   → 评测变了（口径/样本）
④ 是容量还是冲突？
   → 加容量：两者同时涨 = 容量；仍互斥 = 冲突
⑤ 是冲突还是噪声？
   → 看梯度 cosine；看难例标签抽检
```

> [!tip] 一句话原则
> **"先证伪，再归因，最后动手。"** 90% 的"跷跷板"死在第一步——差异不显著。

---

## 三、第二步：把权衡画成曲线（Pareto）

不要凭感觉调比例，**扫出来**：

```
A 数据占比：10% / 20% / 30% / 40% / 50%
记录：A 切片指标、B 切片指标、总指标
画图：横轴 A 占比，纵轴两条指标曲线
找：A 开始涨、B 还没掉的"拐点区间"
```

典型结果（示例数字）：

| A 占比 | A 切片 | B 切片 | 结论 |
|:--:|:--:|:--:|------|
| 10% | +1.0 | 0 | 安全区 |
| 20% | +2.0 | −0.2 | **拐点** |
| 30% | +2.6 | −0.9 | 开始跷跷板 |
| 40% | +3.0 | −2.0 | 不划算 |

**结论**：选 20%，而不是"越多越好"。**这就是"边际替代率"**——多涨 1 点 A，要牺牲多少 B。

> [!note] 面试加分说法
> "我们不问'加多少数据'，问'**这桶数据的边际替代率是多少**'——超过拐点就不加了，把预算给别的桶。"

## 四、数据侧七招（治因主力）

### 1. 分层配额，而不是全局加权

```
错误：所有长尾样本 loss ×3        → 长尾涨、常见崩
正确：按桶设配额（夜间 ≤20%、长尾 ≤15%）→ 每桶有下限也有上限
```

**配额是"硬约束"，加权是"软引导"**——硬约束更不容易失控。

### 2. 重采样，而不是重加权

- 重加权：同一批数据，loss 权重变大 → 梯度方差大、易过拟合；
- 重采样：按频率采样，稀有类多出现几次 → 更稳。
- 常用：类别平衡采样（CBGS）、温度采样（$p_i \propto n_i^\alpha$，$\alpha<1$ 平滑长尾）。

### 3. 回放（replay）：防遗忘的底线

新数据混入时，固定比例回放旧数据（经验起点 70/30），并在**旧域验证集**上设门禁。
> 回放比例本身也要扫——回放太多，新域学不动；太少，旧域崩。

### 4. 去噪：先保证"加的是对的"

- 难例里过滤低置信标签（几何一致性/多传感器交叉）；
- 语义去重，防重复路段主导；
- 抽检"高 loss 但标签可疑"的样本——**很多跷跷板是脏数据造成的**。

### 5. 增强，而不是硬加

在不改变分布的前提下扩样本：光照/天气仿真、Copy-Paste、重建式编辑。
> 增强是"同一分布的更多视角"，硬加是"换分布"——前者不引发跷跷板。

### 6. 课程学习：别让分布"突然跳变"

- 先混后专：前期混合训练保旧能力，后期侧重目标域；
- 难例逐步加入，而不是一次性灌入；
- 监控"最后见到的数据"（recency bias）。

### 7. 配比搜索：小规模代理 + 全量确认

- 10% 数据上扫配比（快、便宜），找 2-3 个候选；
- 全量只验证候选，不暴力网格；
- 记录每次配比的"切片曲线"，形成配比知识库。

## 五、训练侧四招（配合数据）

| 方法 | 解决什么 | 一句话 |
|------|----------|--------|
| **不确定性加权**（Kendall） | 多任务权重 | 让模型自己学各任务权重（加下界防爆炸） |
| **GradNorm** | 任务学习速度不平衡 | 按梯度范数动态调权重 |
| **PCGrad / 梯度手术** | 梯度方向冲突 | 把冲突梯度投影到正交方向，减少互相抵消 |
| **容量/MoE** | 本质冲突 | 加宽，或分专家（不同任务走不同专家） |

> [!warning] 顺序别反
> **先调数据，再调损失权重。** 数据分布错了，损失权重只是在错误的方向上找平衡；反过来，数据对了但任务冲突严重，才上 PCGrad/MoE。

## 六、评测与决策：把"权衡"变成"契约"

### 1. 定义综合分 + 硬门槛

```
综合分 = w1·安全 + w2·常见场景 + w3·长尾
硬门槛：安全指标零退化；任一常见切片掉 > 0.5 点 → 阻断
```

权重是**产品决策**，不是算法调参——要提前定，不能事后改。

### 2. 回归门禁 + 灰度

- 发版前跑全量切片；任一硬门槛不过 → 阻断/人工审；
- 线上灰度 + 影子模式验证"线下权衡"是否成立。

### 3. 接受"必要的跷跷板"

有些权衡是物理的，不是 bug：

| 权衡 | 本质 | 怎么处理 |
|------|------|----------|
| 安全 vs 效率 | 保守让行 vs 快速通过 | 显式定优先级 + 场景化策略 |
| 召回 vs 精度 | 阈值移动 | 按业务定工作点，不追求单指标 |
| 延迟 vs 精度 | 算力预算 | 分层模型/蒸馏 |

> [!note] 面试的高分收尾
> "有些跷跷板不能'解'，只能'选'。**我的做法是把它变成显式契约**：谁负责哪个切片、硬门槛是多少、权衡由谁拍板——而不是让算法在暗处替我选。"

## 七、三个真实案例（示例数字）

### 案例 1：加夜间数据，白天掉点

- **现象**：夜间 +3.0，白天 −1.5。
- **诊断**：夜间占比从 8% 提到 25%，分布偏移 + 白天样本被稀释。
- **解法**：夜间配额压到 15% + 白天回放 + 夜间增强（而非硬加）。
- **结果**：夜间 +2.2，白天 −0.2（可接受）。

### 案例 2：长尾过采样 5×，常见崩

- **现象**：长尾 +2.0，常见 −0.8。
- **诊断**：过采样放大噪声 + 梯度方差大。
- **解法**：降到 2×，改"重采样 + 难例过滤"，加旧域回放。
- **结果**：长尾 +1.6，常见 −0.1。

### 案例 3：检测↑预测↓（任务跷跷板）

- **现象**：检测 +1.0，预测 −0.6。
- **诊断**：共享 backbone 梯度 cosine 为负。
- **解法**：PCGrad + 预测头加宽 + 预测数据增配。
- **结果**：检测 +0.6，预测 +0.2（双赢）。

## 八、面试速答

**60 秒版**：
"跷跷板分三种：切片、指标、任务。先判真假——用置信区间和多 seed 排除评测噪声；再画配比-指标曲线找拐点，算边际替代率。数据侧四招：分层配额、重采样、旧数据回放、去噪；训练侧配合：不确定性加权、PCGrad、必要时加容量或分专家。最后有些权衡是物理的（安全 vs 效率），要变成显式契约和硬门槛，而不是假装能消除。"

**高频追问**：

| 追问 | 一句话 |
|------|--------|
| 怎么判断是容量还是冲突？ | 加容量：同时涨=容量；仍互斥=冲突 |
| 为什么不用 loss 加权？ | 加权放大噪声、梯度方差大；配额/重采样更稳 |
| 回放比例怎么定？ | 扫曲线，以旧域门禁不破为准 |
| 多任务梯度冲突怎么办？ | PCGrad 投影 / GradNorm / MoE |
| 跷跷板能彻底消除吗？ | 不能，有些是产品权衡，要显式定优先级 |
| 怎么证明不是评测噪声？ | 配对 bootstrap + 多 seed + 扩切片 |
