## 〇、大白话：训练是加工，评测是质检

```
数据 = 原料，训练 = 加工，模型 = 产品，评测 = 质检，OTA = 出货
```

> [!note] 一个比喻：工厂
> - **数据配方** = 配料表（放多少钢材、多少塑料）——配错了，工艺再好也白搭；
> - **训练策略** = 工艺参数（温度、压力、时间）——决定良品率；
> - **评测** = 质检线（抽检 + 全检 + 压力测试）——决定这批货能不能出厂；
> - **回归门禁** = "老款不能比新款差"的红线。
> **数据闭环的竞争力 = 配料表迭代的速度 + 质检的可信度。**

## 一、数据配方：训练的第一性变量

### 1.1 配比的本质：你在改变"训练分布"

模型学的不是"数据"，是**数据的分布**。配比就是在**人为设计训练分布**：

```
真实世界分布:  高速 40% / 城区 45% / 泊车 10% / 其他 5%
业务重心分布:  城区 NOA 是卖点 → 希望模型在城区更强
训练配比:      高速 25% / 城区 55% / 泊车 15% / 其他 5%   ← 主动偏离真实分布
```

> [!warning] 配比不是"还原真实分布"，而是"逼近业务分布"
> 真实分布里 90% 是简单直行，全按真实分布训 = 模型在简单场景上过拟合、在关键场景上欠拟合。**要按"业务重要性 × 模型薄弱度"加权，而不是按"路上出现频率"加权。**

### 1.2 四个配比维度

| 维度 | 怎么分桶 | 目的 |
|------|----------|------|
| **场景** | 高速/城区/泊车/园区；天气/时段 | 覆盖业务场景 |
| **来源** | 不同城市/车型/传感器配置 | 防域偏置 |
| **难度** | 旧模型 loss / 漏检率 分位 | 补短板 |
| **类别** | 车/人/两轮/异形/锥桶 | 防长尾类别崩溃 |

### 1.3 怎么做配比实验（可执行流程）

```
第 1 步：基线 —— 当前配比训一版，记录 all / 各切片指标
第 2 步：单桶消融 —— 每类数据 ±50%，看哪个切片动
第 3 步：learning curve —— 该类数据 10%/30%/60%/100%，找饱和点
第 4 步：混比扫描 —— 在饱和点附近细扫（如 20%/30%/40%）
第 5 步：确认 —— 在 hard set + 闭环上复验（防只在一个指标上涨）
```

> [!note] "数据量翻倍指标不涨"说明什么
> 说明**这一类数据已经饱和**，或者**瓶颈不在数据量而在数据质量/模型容量**。这时候继续加数据是浪费——应该转向：换更难的数据、提标注质量、改模型结构。

### 1.4 课程与难例：顺序也影响结果

| 策略 | 做法 | 风险 |
|------|------|------|
| **先易后难** | 前 N 个 epoch 用简单样本 | 训练轮次变多 |
| **难例优先** | 高 loss 样本加权/过采样 | 错标和不可学样本被放大 |
| **课程 + 回放** | 难例逐步加入 + 保留简单样本 | 实现复杂 |

> [!warning] 难例加权的头号陷阱
> 高 loss 样本里混着**错标**（人工/自动标注错误）和**本质不可学**（严重遮挡、超远距）。**直接加权 = 放大噪声**。正确做法：难例 + 置信度过滤，或难例 + 人工核验。

### 1.5 去重与泄漏：配比前必须做

- **训练集内部去重**：同一路段重复采集 → 主导分布；
- **训练/评测泄漏**：同一场景（甚至同一帧的不同裁剪）同时进 train 和 val → 指标虚高；
- **跨版本泄漏**：新数据里混进了旧评测集的帧 → 回归对比失效。

> 📚 检索与去重方法见 [[数据引擎与场景检索]] 第六节。

## 二、训练策略：四种模式与三个配套技术

### 2.1 四种模式怎么选

| 模式 | 触发条件 | 优点 | 风险 |
|------|----------|------|------|
| **从零训练** | 新架构、新模态、数据量足够 | 上限最高 | 贵、慢、难调 |
| **全参微调** | 新域数据 ≥ 万级 | 适应快 | 灾难性遗忘 |
| **LoRA / 冻结骨干** | 新域数据千级、算力紧 | 便宜、稳 | 容量不足 |
| **持续/增量学习** | 周级迭代、不能全量重训 | 快 | 遗忘 + 回放成本 |

### 2.2 蒸馏：把"大"变成"能上车"

| 类型 | 教什么 | 适用 |
|------|--------|------|
| **Logit 蒸馏** | teacher 的软标签分布 | 分类/检测分类头 |
| **Feature 蒸馏** | 中间层特征对齐 | 检测/分割（BEV 特征） |
| **Response 蒸馏** | 最终输出（框/轨迹） | 端到端 |
| **数据侧蒸馏** | teacher 标伪标签 | 自动标注（见 [[自动标注与4D标注]]） |

> [!note] 蒸馏在数据闭环里的双重身份
> ① **模型侧**：大模型 → 车端小模型（降延迟、降算力）；
> ② **数据侧**：离线 teacher → 伪标签 → 训 student（扩数据）。
> **同一个思想，两个杠杆**——面试时能把这两层分开讲，说明你真理解"以 AI 养 AI"。

### 2.3 灾难性遗忘：四个解法

| 方法 | 原理 | 代价 |
|------|------|------|
| **数据回放（replay）** | 混入旧数据（如 70/30） | 存储 + 训练成本 |
| **EWC** | 对重要参数加正则（Fisher 信息） | 实现复杂、效果有限 |
| **LwF** | 旧模型输出当软标签约束新模型 | 需保存旧模型 |
| **LoRA/冻结** | 只改少量参数 | 容量受限 |

> [!warning] 最常见的错误：只加新数据，不回放旧数据
> 新域数据占比一高，旧域指标就掉。**"旧 70% + 新 30%"是经验起点，不是定律**——要用旧域验证集做回归，按退化程度调比例。

### 2.4 超参与大 batch：几条经验规则

| 项 | 经验 | 说明 |
|----|------|------|
| **学习率** | 线性缩放（batch ×2 → lr ×2）+ warmup | 大 batch 必备 |
| **分层学习率** | backbone 小、head 大（如 0.1×） | 防破坏预训练特征 |
| **EMA** | 权重滑动平均 | 稳定、常涨点 |
| **AMP** | fp16/bf16 + loss scaling | 省显存、加速 |
| **梯度裁剪** | clip norm 1-10 | 防 NaN |
| **梯度累积** | 小显存模拟大 batch | 注意 BN 统计 |

> 📚 分布式与显存优化见 [[AI-Infra详解]]；训练崩了见 [[训练排错实战手册]]。

## 三、训练工程：可复现、可追踪、可扩展

### 3.1 可复现三件套

```
代码版本（git commit） + 数据版本（dataset hash） + 环境版本（镜像/cuda/驱动）
```

再加两个"软"条件：
- **固定 seed**（Python/NumPy/PyTorch/CUDA）；
- **确定性算子**（`torch.use_deterministic_algorithms`，至少验证集跑通）。

> [!warning] "上次能涨这次不涨"的三大元凶
> ① 数据版本变了（新数据混入）；② 配置没锁（增强/采样随机）；③ 环境变了（驱动/cuDNN 版本）。**先查这三个，再怀疑模型。**

### 3.2 实验追踪：一次实验一个 ID

| 记录项 | 为什么 |
|--------|--------|
| 实验 ID + 时间 + 人 | 可追溯 |
| 数据版本 + 配比 | 归因 |
| 完整 config（含默认值） | 复现 |
| 指标曲线 + 最终指标 | 对比 |
| ckpt 路径 + 大小 | 回滚 |
| GPU 小时 + 峰值显存 | 成本 |

### 3.3 吞吐与成本：面试常问的"工程感"

| 指标 | 含义 | 怎么优化 |
|------|------|----------|
| **samples/s** | 吞吐 | 数据加载（多 worker/prefetch）、混合精度、更大 batch |
| **MFU** | 算力利用率 | 并行策略、算子融合、通信重叠 |
| **GPU 小时/版** | 单版成本 | 早停、小模型预筛、冻结骨干 |
| **峰值显存** | 能否跑 | ZeRO/FSDP、梯度检查点、offload |

### 3.4 并行策略怎么选

| 规模 | 策略 |
|------|------|
| 单机多卡 | DDP |
| 多机 + 显存不够 | FSDP / ZeRO-2/3 |
| 超大模型 + 超长序列 | 张量并行 / 序列并行 |
| 稀疏大 Embedding | 参数服务器/分片 |

## 四、评测（一）：指标体系与陷阱

### 4.1 四类任务的指标

| 任务 | 主指标 | 辅助 | 陷阱 |
|------|--------|------|------|
| **3D 检测** | mAP、NDS | mATE/mASE/mAOE/mAVE/mAAE | NDS = (5·mAP + 5 项误差)/10，**只刷 mAP 会忽略定位/速度** |
| **跟踪** | AMOTA/MOTA | IDS（ID switch） | 只看 MOTA 会忽略 ID 跳变 |
| **占据** | mIoU（per class）、RayIoU | 几何/语义分开 | 类别极不平衡，平均会掩盖小类 |
| **预测** | minADE/minFDE、MissRate | 多模态概率校准（brier/NLL） | 只报 minADE 会鼓励"撒点" |
| **规划/端到端** | L2、碰撞率、PDMS | 舒适度、进度、接管率 | **L2 低 ≠ 安全**（可能贴边开） |

### 4.2 三个"看起来涨了其实没涨"的陷阱

1. **类别不平衡**：mIoU 被大类主导 → 要看 per-class + 加权；
2. **指标可刷**：只优化 NDS 会牺牲定位；只优化 minADE 会输出多模态散点；
3. **切片掩盖**：总指标涨 1 点，但夜间掉 3 点 → **必须分场景切片**。

> 📚 指标定义与 GT 质量见 [[评测消融与GT构造]]、[[模型基础知识补充]]。

## 五、评测（二）：开环 vs 闭环

### 5.1 三种"仿真"的真实含义

| 类型 | 自车 | 其他 agent | 能测什么 |
|------|------|------------|----------|
| **开环** | 按人类轨迹 | 按日志 | 拟合精度 |
| **非反应式闭环** | 模型自己开 | 按日志（不响应） | 累积误差、偏离、恢复能力 |
| **反应式闭环** | 模型自己开 | 响应自车 | 交互、博弈、让行 |

> [!warning] 端到端最大的坑：开环指标和闭环能力脱节
> 开环喂的是人类轨迹，模型永远在"正确状态"上预测下一帧；闭环里模型一旦偏 20cm，下一帧输入就分布外了——**误差累积（compounding error）**。**这就是为什么端到端必须做闭环，哪怕只是非反应式。**

### 5.2 主流基准（面试可点名）

| 基准 | 类型 | 指标 | 特点 |
|------|------|------|------|
| **nuScenes** | 开环 | NDS/mAP | 感知标准集 |
| **NAVSIM** | 非反应式闭环 | **PDMS** | 端到端规划评测，轻量、可复现 |
| **Bench2Drive** | 反应式闭环（CARLA） | 驾驶分数 + 成功率 | 多场景、多能力 |
| **CARLA Leaderboard** | 反应式闭环 | 路线完成 + 违规 | 老牌，视觉 gap 大 |
| **nuPlan** | 规划闭环 | CLS | 规划器专用，含反应式/非反应式 |

**PDMS 的组成**（NAVSIM）：无责任碰撞（NC）、可行驶区域合规（DAC）、碰撞时间（TLC）、舒适度（Comfort）、自车进度（EP）——加权成分数（不同版本还可能含行驶方向合规 DDC）。面试说清"PDMS 不只看安全，还看进度和舒适"，就比只背缩写真懂。

### 5.3 闭环评测的三个工程问题

| 问题 | 表现 | 解法 |
|------|------|------|
| **仿真 gap** | 仿真里好、实车差 | 重建/真实数据仿真 + 混合验证 |
| **方差大** | 同一模型两次跑分数差很多 | 固定场景集 + 多种子 + 置信区间 |
| **不可复现** | 场景/初始状态随机 | 场景版本化、固定初始状态 |

## 六、评测（三）：体系设计与回归门禁

### 6.1 评测集怎么建

```
标准集（固定版本，可比）
  + 困难集（历史 bad case，哨兵）
  + 切片集（夜间/雨天/远距/施工/非机动车）
  + 留出集（只在新版本发布前用，防过拟合）
  + 闭环场景集（回归用）
```

> [!warning] 评测集也会"过拟合"
> 反复在同一个 val 上调参 = 把 val 变成了 train。**留出集必须"少用、后用、不调参"**；发现 val 涨、留出集不涨，就是过拟合信号。

### 6.2 回归门禁（Release Gate）

| 门禁 | 判据 | 不通过 |
|------|------|--------|
| 标准集 | 不低于 baseline | 阻断 |
| 困难集 | 不劣化 | 阻断 |
| 切片 | 任一劣化 > 1 点 | 人工审 |
| 安全 | 碰撞/侵入零退化 | 阻断 |
| 性能 | 延迟/显存超预算 | 阻断 |
| 闭环 | 分数不低于 baseline | 人工审 |

### 6.3 统计显著性：涨 0.3 点算不算数

| 方法 | 怎么做 | 回答什么 |
|------|--------|----------|
| **Bootstrap CI** | 对评测集重采样 1000 次，算指标分布 | 指标的置信区间 |
| **配对检验** | 同场景同 seed 配对差值，Wilcoxon/配对 t | 差异是否显著 |
| **多 seed** | 每个配置跑 3-5 个 seed | 训练方差 |
| **最小可检测效应** | 先算"评测集能分辨多大差异" | 该不该信这个涨点 |

```python
import numpy as np

def bootstrap_ci(scores, n_boot=1000, alpha=0.05, seed=0):
    rng = np.random.default_rng(seed)
    n = len(scores)
    boots = [scores[rng.integers(0, n, n)].mean() for _ in range(n_boot)]
    lo, hi = np.percentile(boots, [100*alpha/2, 100*(1-alpha/2)])
    return scores.mean(), lo, hi
# 若 [lo, hi] 跨 0（对比差值时），则"涨点"不显著
```

> [!note] 面试标准答法
> "我会报均值 + 95% 置信区间，用配对 bootstrap 比较新旧模型；如果区间跨 0 或者只在单切片显著，我会认为证据不足，再补 seed 或扩评测集。"

### 6.4 评测的"元评估"（少有人做，但很加分）

- **评测集本身准不准**：人工抽检 GT 质量（[[评测消融与GT构造]]）；
- **指标和业务是否相关**：NDS 涨了，接管率降了吗？
- **评测的稳定性**：同一模型重复评测的方差多大？
- **评测的覆盖面**：场景簇覆盖率、长尾占比。

## 七、线上评测：影子、A/B、灰度

| 机制 | 怎么做 | 能回答 |
|------|--------|--------|
| **影子模式** | 新模型后台跑，不控车，对比人类/主模型 | "它会在哪犯错" |
| **A/B** | 同车型/同区域分流 | "上线后真的更好吗" |
| **灰度** | 1%→10%→50%→100% | "事故半径可控吗" |
| **回滚** | 指标越界自动回退 | "出错能不能快速止损" |

> [!warning] 线上指标 ≠ 线下指标
> 线下评测是"固定场景集"，线上是"真实分布 + 用户行为"。**线下涨、线上不涨**的常见原因：评测集过时、场景分布变了、线上有并发/延迟约束。**必须建立"线上指标 → 线下切片"的映射。**

## 八、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **配比拍脑袋**——不做单桶消融和 learning curve，直接照搬"70/30"。
> 2. **只加新数据不回放**——灾难性遗忘，旧场景掉点。
> 3. **难例直接加权**——把错标和不可学样本一起放大。
> 4. **实验不可复现**——数据/配置/seed 没锁，涨点无法归因。
> 5. **只看总指标**——切片退化被平均掩盖。
> 6. **开环当闭环**——端到端必须做闭环，否则上线翻车。
> 7. **把 val 当 test**——反复调参 = 评测集过拟合。
> 8. **不看置信区间**——0.3 点的差异可能只是噪声。

## ✅ 检验自己（自测题）

> [!question] Q1：数据配比应该还原真实分布吗？为什么？
> 提示：业务分布 vs 真实分布。

> [!success]- 参考答案
> 不应该。真实分布里 90% 是简单场景，按真实分布训会导致简单场景过拟合、关键场景欠拟合。应该按"业务重要性 × 模型薄弱度"加权，主动偏离真实分布、逼近业务分布。定法：分层设桶 → 单桶消融 → learning curve 找饱和点 → 混比细扫 → hard set/闭环复验。

> [!question] Q2：蒸馏在数据闭环里有哪两层身份？
> 提示：模型侧 / 数据侧。

> [!success]- 参考答案
> ① 模型侧：大 teacher → 车端小 student（logit/feature/response 蒸馏），降延迟降算力；② 数据侧：离线 teacher 生成伪标签 → 训 student，扩大数据规模（"以 AI 养 AI"）。同一思想两个杠杆，前者解决"能不能上车"，后者解决"数据够不够"。

> [!question] Q3：开环、非反应式闭环、反应式闭环各测什么？为什么端到端必须闭环？
> 提示：拟合/累积误差/交互。

> [!success]- 参考答案
> 开环测拟合（喂人类轨迹，比 L2）；非反应式闭环测累积误差和偏离（模型自己开，其他 agent 按日志）；反应式闭环测交互（其他 agent 响应自车）。端到端必须闭环，因为开环下模型永远在"正确状态"上预测，闭环里一旦偏离就进入分布外，误差会累积（compounding error）——开环高分会掩盖这个问题。

> [!question] Q4：涨了 0.3 个点，你怎么判断是不是真的？
> 提示：CI、配对、seed、切片。

> [!success]- 参考答案
> ① 报均值 + 95% bootstrap 置信区间，看是否跨 0；② 用配对检验（同场景同 seed）而不是两组独立均值；③ 跑 3-5 个 seed 看训练方差；④ 看是否只在单切片显著（可能是评测集偏差）；⑤ 看闭环指标是否同向。证据不足就补评测集或扩 seed，不硬下结论。

> [!question] Q5：回归门禁应该设哪几条？哪条最容易被忽略？
> 提示：标准/困难/切片/安全/性能/闭环。

> [!success]- 参考答案
> ① 标准集不低于 baseline；② 困难集（历史 bad case 哨兵）不劣化；③ 任一场景切片劣化 > 1 点人工审；④ 安全指标（碰撞/侵入）零退化；⑤ 延迟/显存不超预算；⑥ 闭环分数不低于 baseline。最容易被忽略的是 **④ 安全零退化和 ③ 切片**——总指标涨了容易掩盖单场景的安全退化。

## 🛠 动手练习

### 练习 1：设计一次配比消融（40 分钟）

假设你有四桶数据：城区/高速/泊车/长尾异形。当前配比 40/30/20/10，城区指标是短板。
1. 设计单桶消融矩阵（每桶 ±50%，共几组实验）。
2. 每组的评测看哪几个切片。
3. 预算只够跑 5 组，你选哪 5 组？为什么。

> [!tip] 做完自问
> ① 你会固定哪些变量（seed/epoch/增强）？② 如果城区涨了但高速掉了 2 点，算成功吗？③ 怎么用 learning curve 判断"该加数据还是改模型"。

### 练习 2：写一个回归门禁脚本（60 分钟，代码）

输入：新旧模型在标准集/困难集/切片集上的指标 JSON。
1. 实现六条门禁判断，输出 PASS/BLOCK + 原因。
2. 加"切片劣化 > 1 点"的检测。
3. 用假数据跑三种情况（全过/切片退化/安全退化）。

> [!tip] 这就是面试里"你怎么保证不发回归版本"的实证
> 能说"我写过门禁脚本，安全退化直接阻断"，比背概念强。

### 练习 3（进阶）：算一次最小可检测效应

1. 取一个评测集（如 1000 帧），对某个指标做 bootstrap。
2. 算 95% CI 宽度。
3. 回答：这个评测集能分辨 0.3 点的差异吗？如果不能，需要多少帧？

> [!tip] 答案方向
> CI 宽度 ≈ 1.96 × σ/√n。若 σ=5 点、n=1000，CI 半宽 ≈ 0.31 点——**刚好分辨不了 0.3 点**。要分辨 0.3 点需要约 4 倍数据。**这就是"评测集大小决定你能不能说涨点"的量化解释。**
