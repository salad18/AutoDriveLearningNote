## 〇、大白话总览——2025 Infra 一图流

```
训练侧:  单卡 → 多卡 DDP/FSDP → 万卡集群/超节点（昇腾超节点等）
推理侧:  FP16/INT8 → KV cache → 投机解码 → MoE 稀疏推理
数据侧:  数据加载 → 数据湖/管道 → 合成数据管线
                ↓
   智驾对照: 云端（大集群训练 VLA/GOD）+ 车端（边缘推理毫秒级）
```

> [!note] 三个前沿的一句话直觉
> - **超节点/万卡集群** = "把一万张卡当成一台超级计算机"（互联带宽是灵魂）。
> - **推理优化** = "让大模型从'想得慢'变'答得快'"（KV cache 省重复计算、投机解码"小模型带路大模型"、MoE"只激活一部分专家"）。
> - **数据基础设施** = "数据管道像自来水一样稳定供给"（[[数据闭环总览]] 的 Infra 侧）。

## 一、集群与超节点——"万卡如一卡"

### 1.1 背景：模型规模 vs 算力

```
万亿参数模型训练 ≈ 需要 1 万+ 张 GPU 连续训几个月
关键瓶颈不是"卡多"，是"卡之间通信"（互联带宽）
```

### 1.2 超节点是什么

```
传统集群:  很多服务器，服务器之间网络通信（慢，PCIe/以太网）
超节点:    把大量 NPU/GPU 用高速互联（如昇腾的 HCCS/超节点互联）连成"一台大机器"
          → 单卡显存不够 → 超节点共享显存池 → 训练超大模型像训单卡模型
```

> 参考：[昇腾超节点实践发布，使能全行业 AI 大模型创新落地](https://news.zol.com.cn/1051/10519893.html) ｜ [新华三超节点助力万亿级大模型高效训推](https://tech.gmw.cn/2025-12/01/content_38450530.htm)

> [!note] 超节点的核心价值（面试谈资）
> 大模型训练的两大障碍：① 显存不够（参数+梯度+优化器+激活）；② 通信太慢（卡间同步成为瓶颈）。**超节点 = "显存池化 + 高带宽互联"**——把"分布式训练的通信开销"降到接近单机的水平。**和 [[AI-Infra详解]] 的 FSDP 对比：FSDP 是在"现有网络"上切分显存，超节点是在"物理上把卡焊在一起"。** 国产算力（昇腾）走超节点路线，是对 NVIDIA 集群路线的差异化竞争。

### 1.3 与智驾的对照

```
华为智驾云端训练（[[华为ADS技术方案]]）: 7.5 EFLOPS 昇腾集群
  → 昇腾超节点 = 这套云端训练基础设施的"最新形态"
  → VLA 智驾模型（[[VLA入门与智驾应用]]）训练 = 超节点级算力需求
```

## 二、推理优化前沿——"让大模型快起来"

### 2.1 三大技术（面试必讲）

| 技术 | 原理 | 一句话记忆 |
|------|------|-----------|
| **KV Cache** | 自回归生成时缓存已算的 K/V，避免重复计算 | "记住算过的，不重算" |
| **投机解码 (Speculative Decoding)** | 小模型"打草稿" → 大模型"校验"，一次校验多步 | "小秘书起草，大领导审批" |
| **MoE 推理** | 每次只激活部分专家（如 8/64），算力按激活算 | "只让该干活的专家上班" |

### 2.2 细节

```
KV Cache:
  自回归生成第 t 个 token 时，前 t-1 个 token 的 K/V 已经算过
  → 缓存它们 → 生成时间从 O(n²) 降到 O(n)（长序列尤其明显）
  → 代价: 显存（KV cache 占显存大头）→ KV cache 量化/剪枝是研究热点

投机解码:
  1. 小模型快速生成 M 个候选 token（草稿）
  2. 大模型并行"校验"这 M 个 token（一次 forward 验证 M 步）
  3. 正确的采纳，错误的从错误处重新开始
  → 速度提升 2-3 倍，且**输出分布不变**（无损加速！）

MoE 推理:
  模型有 N 个专家，每个 token 只路由到 top-K 个专家
  → 计算量 = 激活的专家数 × 单专家计算（远小于全量）
  → 但"路由"需要通信（专家在不同卡）→ 推理引擎要优化路由
```

> [!warning] 面试怎么聊推理优化
> 三个技术对应三个问题：**KV cache 管"重复计算"、投机解码管"自回归串行"、MoE 管"稀疏计算"**——都是"算得少但效果不变"。**和 [[模型部署与延迟优化]] 的关系：TensorRT/INT8 是"部署侧"优化，KV cache/投机解码是"推理引擎侧"优化——两层叠加才是"端到端延迟"的完整答案。**

### 2.3 与智驾车端的对照

```
LLM/VLA 推理: KV cache + 投机解码（云端大模型）
智驾车端:    TensorRT + INT8 + 小模型蒸馏（[[模型部署与延迟优化]]）
共同逻辑:    都是"延迟预算内尽量准"——只是规模差 1000 倍
```

## 三、数据基础设施——"数据管道的自来水"

### 3.1 内容

```
数据管道 (Data Pipeline):  采集 → 清洗 → 存储 → 供给训练
数据湖:                    原始数据的统一存储（PB 级）
合成数据管线:              世界模型/LLM 生成 → 校验 → 混入训练（[[大模型训练技巧进阶]]）
```

### 3.2 与智驾的对照

```
LLM Infra 数据管道:  互联网爬取 → 清洗 → tokenize → 预训练
智驾数据管道:        车队采集 → 影子模式 → 自动标注 → 训练（[[数据闭环总览]]）
共同挑战:            数据质量校验（垃圾进垃圾出）、数据版本管理、PB 级存储
```

> [!note] "数据基础设施"为什么是 Infra 前沿？
> 模型架构趋同后，**"数据质量和供给速度"成为拉开差距的关键**（[[数据闭环总览]] 的"数据飞轮速度 = 竞争力"）。**Infra 不只是算力，还包括数据管道**——面试被问"Infra 是什么"时，答"算力 + 数据 + 推理三件套"比只说"分布式训练"完整得多。

## 四、与智驾 Infra 的完整对照（面试核心）

| 维度 | LLM/大模型 Infra | 智驾 Infra | 共通底层 |
|------|------------------|-----------|----------|
| **云端训练** | 万卡集群/超节点、FSDP/ZeRO | 昇腾集群（7.5 EFLOPS）训 VLA/GOD | 分布式训练（[[AI-Infra详解]]） |
| **云端推理** | KV cache、投机解码、MoE | 云端大模型辅助决策 | 推理优化 |
| **车端/边缘推理** | — | TensorRT/INT8/蒸馏小模型 | [[模型部署与延迟优化]] |
| **数据管道** | 互联网数据管线 | 车队数据闭环 | [[数据闭环总览]] |
| **监控/Profiling** | GPU 利用率、延迟监控 | 车端时延、云端训练监控 | [[AI-Infra详解]] 第六节 |

> [!note] 面试"智驾 Infra 和 LLM Infra 的区别"
> **相同**：分布式训练、推理优化、数据管道的底层技术完全一致。
> **不同**：① 智驾多一个**车端边缘侧**（毫秒级、低功耗、模型小 1000 倍）；② 智驾数据来自**物理世界车队**（不是互联网）；③ 智驾的延迟预算更硬（100ms 级 vs LLM 的秒级）。
> **结论：智驾 Infra = "通用 AI Infra + 边缘实时约束"**——你懂 LLM Infra 就懂智驾云端，补上车端部署就是全栈。

## 五、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为"卡越多越快"**——万卡集群的瓶颈是通信（互联带宽），超节点就是解决这个的；扩展效率才是关键指标。
> 2. **混淆 KV cache 和投机解码**——KV cache 省"重复计算"（显存换速度），投机解码省"自回归串行"（小模型带路）；两个独立技术。
> 3. **以为 MoE 推理"免费"**——MoE 省了计算但多了路由通信，稀疏化不是无代价的。
> 4. **把 Infra 只当"分布式训练"**——Infra = 算力（训练）+ 推理 + 数据三件套，只说训练不完整。
> 5. **忽略边缘侧**——智驾 Infra 的灵魂是"云端训练 + 车端实时"两端，只讲云端是半个答案。

## ✅ 检验自己（自测题）

> [!question] Q1：超节点解决大模型训练的两个什么障碍？
> 提示：显存/通信。

> [!success]- 参考答案
> ① 显存不够（参数+梯度+优化器+激活超单卡）→ 超节点共享显存池；② 通信太慢（卡间同步成瓶颈）→ 超节点高带宽互联把通信开销降到接近单机。本质 = "显存池化 + 高带宽互联"，把"分布式训练"变成"一台大机器训练"。和 FSDP 的对比：FSDP 在现有网络上切分显存，超节点在物理上把卡连成一体。

> [!question] Q2：KV cache、投机解码、MoE 推理分别解决什么问题？
> 提示：重复/串行/稀疏。

> [!success]- 参考答案
> KV cache：自回归生成时缓存已算的 K/V，避免重复计算（显存换速度，长序列从 O(n²) 降到 O(n)）。投机解码：小模型打草稿、大模型并行校验，一次校验多步，加速 2-3 倍且无损（输出分布不变）。MoE 推理：每 token 只激活 top-K 专家，计算量按激活数算（省计算但多了路由通信）。

> [!question] Q3：智驾 Infra 和 LLM Infra 的相同点与不同点？
> 提示：边缘侧/物理数据。

> [!success]- 参考答案
> 相同：分布式训练（FSDP/ZeRO）、推理优化、数据管道的底层技术一致。不同：① 智驾有车端边缘侧（毫秒级、低功耗、小模型）；② 智驾数据来自物理世界车队（不是互联网）；③ 延迟预算更硬（100ms vs 秒级）。结论：智驾 Infra = 通用 AI Infra + 边缘实时约束。

> [!question] Q4：为什么"数据基础设施"也算 Infra 前沿？
> 提示：数据飞轮速度。

> [!success]- 参考答案
> 模型架构趋同后，数据质量和供给速度成为拉开差距的关键（[[数据闭环总览]] 的"数据飞轮速度 = 竞争力"）。数据管道（采集→清洗→存储→供给）、数据湖、合成数据管线都属于 Infra——"Infra = 算力 + 推理 + 数据三件套"，只说训练不完整。

> [!question] Q5：国产算力（昇腾）走超节点路线，和 NVIDIA 集群路线有什么差异？
> 提示：物理互联。

> [!success]- 参考答案
> 超节点 = 用高速互联（如昇腾 HCCS）把大量 NPU 连成"一台大机器"，显存池化、通信接近单机——在单卡性能不如 NVIDIA 的情况下，用"互联密度"补"单卡差距"（集群规模优势）。NVIDIA 走"单卡强 + NVLink 集群"路线。这是国产算力的差异化竞争策略：**"单卡不强，互联来凑；集群规模换单卡性能"。**

### 练习 2：手算 KV cache 省多少（20 分钟）

一个 7B 模型，生成 1000 个 token，无 KV cache 时每次生成要重算前 t 个 token 的 K/V：
1. 无 cache 总计算量 ≈ Σt（1..1000）≈ 50 万次 token 级计算。
2. 有 cache ≈ 1000 次（每步只算新 token）。
3. 加速比是多少？（≈500 倍！）代价是什么？（显存——KV cache 要存 1000 个 token 的 K/V）

> [!tip] 算完你会发现
> KV cache 是"用显存换 500 倍速度"——所以 KV cache 量化/剪枝成为热点（省显存）。这也是"长上下文很贵"的根源（[[AI-Infra详解]] 的显存估算思维的应用）。
