# 面试速答卡：在线建图 · 多模态 · 扩散

> 一句话：**32 道前沿题，每题只背「结论 + 三点 + 坑」**——面试现场够用，不追求讲全。

> **用法**：每题只背三样——**一句话结论 + 三点展开 + 一个坑**。30-60 秒说完，不推导、不画图。面试官追问时，再从"坑"里往外掏细节。

---

## 一、在线建图 / MapTR（12 题）

### Q1｜"无图"为什么还要在线建图？

- **结论**：无图 ≠ 不用地图，是把"离线高精地图"换成"**实时感知出的矢量地图**"。
- **三点**：① 覆盖——全国道路不可能都采；② 鲜度——施工改道是天级变化；③ 成本——高精地图采集+标注极贵、还会过期。
- **坑**：千万别说"无图就是不要地图"，会被追问"那导航和路口拓扑从哪来"。

### Q2｜MapTR 一句话讲清？

- **结论**：**把地图元素建模成"点集折线"，用 DETR 式并行解码一次出矢量地图**。
- **三点**：① 输入多相机图像 → BEV 特征；② 每个地图元素用 N 个点（如 20 个）表示，点坐标 + 类别；③ 输出是 vector，不用栅格化 + 后处理。
- **坑**：它输出的是"感知坐标系下的局部地图"，不是全局地图——全局要靠多帧/多趟拼接。

### Q3｜permutation-equivalent（排列等价）是什么？不处理会怎样？

- **结论**：**同一条折线，点从哪开始、往哪个方向排，都是同一个地图元素**；不处理，模型会被"顺序不同"惩罚。
- **三点**：① 闭合多边形有 2N 种等价排列（N 个起点 × 2 个方向）；② 开放折线有 2 种（正/反）；③ MapTR 用**层级匹配**在所有等价排列里取最小代价匹配，而不是固定顺序回归。
- **坑**：这是 MapTR 相对 VectorMapNet（自回归、顺序敏感）的核心优势，面试常拿来问"为什么不直接当序列预测"。

### Q4｜层级 query 怎么工作？

- **结论**：**一个 instance query 管"这是不是一个元素、什么类别"，N 个 point query 管"每个点在哪"**。
- **三点**：① instance query 与 BEV 特征交互，得到元素级 embedding；② 它给 N 个 point query 提供上下文；③ point query 各自回归 2D 坐标，合起来就是一条折线。
- **坑**：点数是**预设固定**的（如 20），不是自适应——超长车道线会被"压缩"，这是精度损失来源之一。

### Q5｜为什么用 polyline，不用 mask / 栅格？

- **结论**：**下游要的是拓扑和几何，不是像素**。
- **三点**：① 矢量化天然带顺序和连接关系，规划可直接用；② 存储/传输小；③ 不需要"栅格→矢量"的后处理（那一步误差大）。
- **坑**：polyline 对"复杂路口的面状区域"表达弱，所以现在也有 lane graph / 拓扑预测的路线。

### Q6｜MapTR vs HDMapNet vs VectorMapNet？

- **结论**：**HDMapNet 是分割+后处理，VectorMapNet 是自回归序列，MapTR 是一阶段并行 + 排列等价**。
- **三点**：① HDMapNet：BEV 语义分割 + instance embedding + 后处理，慢且后处理重；② VectorMapNet：polyline 当序列自回归生成，顺序敏感、慢；③ MapTR：并行、端到端、匹配时考虑排列等价。
- **坑**：被问"谁精度高"时，答"看数据集和指标口径"，别硬报数。

### Q7｜MapTRv2 改了什么？

- **结论**：**主要改训练，不改范式**——解耦自注意力、一对多辅助匹配、稠密监督。
- **三点**：① decoupled self-attention：instance 和 point 分开做注意力，减少干扰；② 一对多匹配：加速收敛；③ 加辅助监督（深度/分割），让 BEV 特征更好。
- **坑**：v2 的价值是"**收敛更快、精度更高**"，不是"换了个模型"。

### Q8｜在线建图怎么评测？

- **结论**：**主指标是 Chamfer 距离下的 mAP**，但拓扑要单独看。
- **三点**：① 预测折线与 GT 折线的 Chamfer 距离，按阈值（0.5/1.0/1.5m）算 AP；② 分元素类别报（车道线/路沿/人行横道）；③ 拓扑（连接关系）目前多数 benchmark 不直接评，工程上要单独验。
- **坑**：Chamfer 低 ≠ 能开——**拓扑错（该连的没连）比几何偏 10cm 更致命**。

### Q9｜数据闭环里怎么用 MapTR 做车道线自动标注？

- **结论**：**把在线模型离线化，多趟融合 + 矢量化 + 人工只修拓扑**。
- **三点**：① 同一路段跑 N 趟，多趟推理 + 位姿对齐融合；② 输出 vector 后做拓扑构建；③ 与旧图 diff，只人工复核变化区域。
- **坑**：单趟遮挡多，**必须多趟**；另外要防"把临时施工标线当常设车道线"。

### Q10｜在线建图最难的是什么？

- **结论**：**远距 + 遮挡 + 拓扑 + 时序一致性**，四个都难。
- **三点**：① 远距：50m 外车道线只有几个像素；② 遮挡：大车挡住路口，拓扑断；③ 时序：帧间抖动导致线"跳"；④ 拓扑：路口内连接关系没有显式监督。
- **坑**：别说"精度不够就加大模型"——先看是不是标注/拓扑定义的问题。

### Q11｜它和 BEV 感知是什么关系？

- **结论**：**共享 BEV 特征，任务不同**——检测出"物体"，建图出"道路结构"。
- **三点**：① 很多方案共用 backbone/BEV encoder，多任务头；② 建图更依赖几何和长程上下文；③ 联合训练能互补（道路结构帮助检测，检测帮助剔除动态遮挡）。
- **坑**：被问"能不能一个模型全出"，答"可以多任务，但**评测要分开**，否则互相掩盖"。

### Q12｜端到端时代还需要显式建图吗？

- **结论**：**需要，但形态可能变**——从"输出给规划的地图"变成"中间表征/辅助监督"。
- **三点**：① 可解释、可校验（规控要能查"它认为这是不是路口"）；② 可作为端到端模型的辅助任务/预训练；③ 无图量产仍要"实时建图"兜底。
- **坑**：别站队"端到端会干掉建图"——**安全冗余和可解释性**是量产绕不过去的。

## 二、多模态 CLIP / VLM（10 题）

### Q1｜CLIP 怎么训的？

- **结论**：**4 亿图文对做对比学习**，把图像和文本映射到同一向量空间。
- **三点**：① 一个 batch 里 N 张图 × N 段文本，算 N×N 相似度矩阵；② 对角线是正样本，其余是负样本，用**对称 InfoNCE** 拉近正对、推远负对；③ 温度参数可学习。
- **坑**：CLIP 不是生成模型，**不能"看图说话"**，只能算相似度——被问"CLIP 能描述图片吗"要纠正。

### Q2｜为什么 CLIP 能 zero-shot 分类？

- **结论**：**把类别名写成句子，算文本向量和图像向量的相似度，取最大**。
- **三点**：① prompt 模板（"a photo of a {class}"）影响很大；② 不需要训练分类头；③ 类别空间是开放的（只要能用文字描述）。
- **坑**：zero-shot 在**细粒度**（车型/颜色）和**空间关系**上很差。

### Q3｜VLM 的三段结构？

- **结论**：**视觉编码器 + 投影层 + 大语言模型**。
- **三点**：① 视觉编码器（ViT/CLIP）出 patch 特征；② 投影层把视觉特征映射成 LLM 能吃的 token；③ LLM 自回归输出文本。
- **坑**：VLM ≠ VLA——VLM 输出文字，VLA 多一个**动作头**输出动作。

### Q4｜视觉 token 怎么进 LLM？Q-Former 和 MLP 有什么区别？

- **结论**：**Q-Former 是"用固定数量 query 压缩"，MLP 是"直接投影全部 patch"**。
- **三点**：① Q-Former（BLIP-2）：可学习的 query 去"抽取"视觉信息，输出固定长度，省 token；② MLP（LLaVA）：每个 patch 直接投成 token，信息全但 token 多；③ 取舍：Q-Former 省算力、可能丢细节；MLP 保细节、上下文压力大。
- **坑**：被问"哪个好"——答"看任务：**要细节用 MLP，要效率用 Q-Former**"。

### Q5｜VLM 在智驾有哪三种用法？

- **结论**：**数据标注、场景理解、端到端决策**，从轻到重。
- **三点**：① 标注：给 clip 打场景标签/事件描述/驾驶指令（最成熟）；② 理解：解释"为什么该让行"，做可解释性；③ 决策：DriveVLM/MindVLA 这类直接输出行为或轨迹（最激进）。
- **坑**：量产主流是**前两种**，第三种还在验证——别把 demo 当量产。

### Q6｜VLM 幻觉怎么防？

- **结论**：**不让它单独决定安全相关输出**——感知验证 + 约束 + 兜底。
- **三点**：① 感知层交叉验证（它说"有行人"，检测器要能对上）；② 输出约束/结构化（只允许填预定字段）；③ 规则兜底（幻觉输出不进控制链路）。
- **坑**：RLHF 只能降低概率，**不能消除**——面试官想听"工程兜底"，不是"训得更好"。

### Q7｜VLM 延迟这么大，怎么上车？

- **结论**：**分层 + 压缩 + 异步**。
- **三点**：① 分层：VLM 做低频高层决策（秒级），传统模型做高频控制（毫秒级）；② 压缩：蒸馏到小模型、INT8/INT4 量化、KV cache；③ 异步：VLM 提前输出"行为意图"，控制层持续执行。
- **坑**：别说"用更快的 GPU"——**架构分层**才是答案。

### Q8｜CLIP 在数据闭环里怎么用？

- **结论**：**语义检索 + 自动打标**，把"找场景"变成"搜文字"。
- **三点**：① 所有 clip 出图像 embedding 入库；② 文本 query（"雨夜施工"）检索 top-K；③ 零样本分类器给场景打多标签，做配比/切片。
- **坑**：CLIP 对**空间关系**（"左车道的纸箱"）几乎无效，细粒度要靠结构化标签或场景图。

### Q9｜为什么 CLIP 不擅长空间关系？

- **结论**：**它是全局池化的图文对齐，丢掉了位置信息**。
- **三点**：① 对比学习目标是"整张图和整句话像不像"；② 池化后没有"哪个 patch 对应哪个词"；③ 训练数据里空间描述也少。
- **坑**：要空间关系，得用**region-level 对齐 / 场景图 / 检测框 + 文本**。

### Q10｜ViT 和 CNN 一句话区别？

- **结论**：**CNN 有局部归纳偏置，ViT 靠全局注意力、更吃数据**。
- **三点**：① CNN：局部感受野 + 权重共享，小数据也能训；② ViT：patch + 全局 self-attention，大数据/大模型下上限更高；③ 实践：混合（ConvNeXt/Swin）常是性价比选择。
- **坑**：被问"智驾用哪个"——答"看算力和数据，**车端常用轻量 CNN/混合**，云端可用 ViT"。

## 三、扩散 / Flow Matching（10 题）

### Q1｜DDPM 的前向和反向各是什么？

- **结论**：**前向是逐步加噪（固定），反向是学一个去噪网络（可学）**。
- **三点**：① 前向：$q(x_t|x_0)=\mathcal{N}(\sqrt{\bar\alpha_t}x_0,(1-\bar\alpha_t)I)$，一步到位；② 反向：学 $p_\theta(x_{t-1}|x_t)$，逐步去噪；③ 训练时随机采 t，加噪后让网络预测噪声。
- **坑**：前向**没有参数**，别把它说成"训练出来的"。

### Q2｜训练目标是什么？

- **结论**：**预测噪声 ε（或 x₀ / v），MSE 回归**。
- **三点**：① 从数据 x₀ 采样，随机 t，加噪得 x_t；② 网络输入 (x_t, t) 预测 ε；③ loss = ||ε - ε_θ(x_t,t)||²。
- **坑**：预测 ε / x₀ / v 三种参数化等价但**数值稳定性不同**，v-prediction 在高噪声段更稳。

### Q3｜采样为什么慢？怎么加速？

- **结论**：**要迭代几十到上千步**；加速靠"跳步"和"更好的求解器"。
- **三点**：① DDIM：确定性采样，20-50 步；② DPM-Solver：少步高阶求解；③ 蒸馏（progressive distillation / consistency model）：1-4 步。
- **坑**：加速会**损失多样性/细节**，不是免费的。

### Q4｜classifier-free guidance 是什么？

- **结论**：**同时算"有条件"和"无条件"的噪声，把差值放大**。
- **三点**：① $\hat\epsilon=\epsilon_{uncond}+s(\epsilon_{cond}-\epsilon_{uncond})$；② s>1 更强地跟随条件；③ 训练时随机丢弃条件，让同一个网络能算两种。
- **坑**：s 太大 → 过饱和/失真；**不是越大越好**。

### Q5｜扩散 vs GAN vs VAE？

- **结论**：**扩散质量高、训练稳、但慢；GAN 快但难训；VAE 快但模糊**。
- **三点**：① GAN：对抗训练，模式崩塌；② VAE：ELBO，重建偏模糊；③ 扩散：似然建模 + 多步采样，质量最好、最慢。
- **坑**：面试官问"为什么智驾生成用扩散"——答"**质量和多样性**，且可条件控制"。

### Q6｜Flow Matching 是什么？

- **结论**：**学一个"从噪声到数据"的速度场，用 ODE 把噪声推成样本**。
- **三点**：① 定义一条概率路径（常用直线/最优传输路径）；② 回归目标速度 $v=x_1-x_0$；③ 采样 = 解 ODE，路径更直 → 步数更少。
- **坑**：Flow Matching 不是"另一种扩散"，它是**更一般的学习框架**，扩散是其一种路径选择。

### Q7｜π0 为什么用 Flow Matching 做动作？

- **结论**：**动作是多峰的，回归会给"平均动作"，生成才能表达多模态**。
- **三点**：① 同一场景有多条合理轨迹，MSE 回归会平均成"撞中间的墙"；② Flow Matching 能采样多条；③ 比扩散采样步数少，**更适合实时控制**。
- **坑**：被问"和扩散比"——答"**更少步数、更直路径、更适合高频动作块**"。

### Q8｜动作表示有哪三种方案？

- **结论**：**离散 token、连续回归、生成式（扩散/Flow）**。
- **三点**：① 离散：复用 LLM 词表，简单但有量化误差；② 回归：MLP 出头，简单但表达力弱（多峰平均）；③ 生成：扩散/Flow，表达多模态，但慢。
- **坑**：量产常是"**回归/小生成头 + 传统控制器**"，不是纯生成。

### Q9｜扩散/生成模型在数据闭环里怎么用？

- **结论**：**造长尾数据 + 做仿真**，补"采不到"的场景。
- **三点**：① 图像/视频生成（GAIA-1、DriveDreamer）造雨夜/施工/事故；② 3DGS/NeRF 重建后编辑再渲染（更可控）；③ 世界模型做闭环仿真。
- **坑**：生成数据的**物理合理性**是最大风险，必须混真实数据 + 下游验收。

### Q10｜生成数据的风险是什么？

- **结论**：**分布偏差 + 物理不合理 + 评测失真**。
- **三点**：① 生成器有自己的偏见，模型会学到"假特征"；② 穿模/阴影错/物体漂浮；③ 在生成数据上评测会虚高。
- **坑**：回答"怎么防"时给三级验收：**渲染质量 → 几何精度 → 下游真实指标**（[[3DGS与重建式数据闭环]]）。
