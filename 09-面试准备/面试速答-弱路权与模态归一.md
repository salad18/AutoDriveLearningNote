# 面试速答：弱路权场景与"模态归一"

> 这题的关键不是背定义，而是**先把"模态归一"拆成三层**——传感器、行为、标注。面试官问的往往是其中一层，你能主动拆层，就已经赢了。
> 一句话：**弱路权是"数据定义问题"，不是"模型结构问题"。**

---

## 〇、先拆题：三种"模态归一"

| 层 | "模态"指什么 | 归一成什么 | 谁负责 |
|----|--------------|------------|--------|
| **① 传感器** | Camera / LiDAR / Radar | 统一到 BEV / 世界坐标 + 共享特征 | 感知 |
| **② 行为** | 多条预测/规划轨迹（让/不让、抢/等） | 一条可执行、风险可控的决策 | 预测/规划 |
| **③ 标注与规则** | 2D/3D/OCC/轨迹/语言/路权规则 | 统一 schema（4D + 意图 + 交互 + 路权） | **数据闭环（你）** |

> [!tip] 开口第一句
> "您说的模态归一，是指传感器融合的归一，还是多模态行为的归一？我从三层都答一下。"——**先确认再展开，比直接答错层强十倍。**

---

## 一、弱路权场景：是什么、为什么现在火

**定义**：自车在通行权上处于**弱势或不明确**的场景——"该不该让"没有唯一答案。

**典型场景**：
- 无保护左转（对向直行流不断）
- 右转遇直行/非机动车
- 无信号灯路口、环岛汇入
- 窄路会车、施工绕行
- 行人/非机动车混行、加塞

**为什么 2026 火**：城区 NOA 从"能开"进入"开得顺"，**弱路权是体验与安全的分水岭**；VLA（语义理解"谁该让"）、世界模型（可交互仿真）、后训练（RL 学博弈）都在攻这块。

**三个难点**：
1. **交互**：他车意图不确定（让/不让），是博弈不是预测；
2. **规则**：交规只给原则，具体路口靠默契，甚至"反常规"；
3. **标注**：人类司机自己也犹豫——**同一段视频，两个标注员可能给出不同"正确行为"**。

## 二、传感器模态归一（感知层）

**问题**：三种模态"语言不通"——相机有语义没深度、LiDAR 有几何没语义、Radar 有速度但噪声大；频率不同、视角不同、还会缺失。

**三步归一**：

| 步骤 | 做什么 | 关键点 |
|------|--------|--------|
| **时间** | 硬件同步（PTP/PPS）+ 运动补偿 | 50ms @60km/h ≈ 0.83m 偏差 |
| **空间** | 统一到 ego BEV 或世界坐标 | 外参在线标定，防热胀/振动漂移 |
| **特征** | 模态专属 encoder → 投影到共享 BEV → 对齐 | 对比学习/蒸馏/通道归一化 |

**缺失模态鲁棒**（弱路权尤其重要）：
- 训练时**随机丢模态**（modality dropout），逼模型学会单模态兜底；
- 融合权重做**通道归一化**（如 UniBEV 的 Channel Normalized Weights），缺失一路时权重自动重分配；
- 用**可用性 mask** 显式告诉模型"这路没数据"，而不是喂零。

**弱路权的特殊性**：
- 大车遮挡 → LiDAR 看不到、相机被挡 → **Radar 和多帧时序**变得关键；
- 近距非机动车 → 相机畸变、LiDAR 盲区 → 需要**近场专门处理**；
- 雨夜 → 相机退化 → **Radar 权重必须能自动上升**。

**30 秒答**：
"传感器模态归一 = 时间同步 + 空间统一到 BEV + 特征对齐，核心是**缺失模态鲁棒**：训练随机丢模态、融合权重做通道归一、显式 mask。弱路权场景遮挡多、近距目标多，单模态兜底能力比融合精度更重要。"

**追问**：
- 外参漂移怎么办？→ 在线标定 + 重投影残差监控。
- 时间不同步影响多大？→ 60km/h 下 50ms≈0.83m，高速更致命。
- 缺 LiDAR 怎么降级？→ 单目深度/时序 + Radar 速度 + 降低置信度、保守规划。

## 三、行为模态归一（预测/规划层，最容易被追问）

**问题**：预测输出"他可能让/可能不让"多条模态，规划输出"抢/等"多条轨迹，**但车最终只能执行一条**。

**四种归一手段**：

| 手段 | 做法 | 适用 |
|------|------|------|
| **概率归一** | softmax over modes，选概率最高 | 简单，但"最可能"≠"最安全" |
| **风险加权** | 按 CVaR/最坏情况选"风险可控"的 | 弱路权首选（宁让勿抢） |
| **博弈/交互** | POMDP、level-k、把他人反应纳入 | 无保护左转、汇入 |
| **规则兜底** | 路权规则作硬约束（转弯让直行等） | 法规/安全底线 |

**还要解决两个"归一后遗症"**：
- **模态坍缩**：多模态退化成一条平均轨迹（谁都不像）→ 用多样性 loss / 锚点模式；
- **决策抖动**：帧间在"让/抢"之间反复横跳 → 加时序平滑/滞回（hysteresis）。

**弱路权的核心判断**：
> **不是选"最可能发生"的，而是选"最坏情况下仍安全"的。** 先保安全下限，再优化通行效率。

**30 秒答**：
"行为模态归一不是简单取 argmax。我会做三层：概率 + **风险加权（CVaR/最坏情况）** + **规则硬约束**；交互场景用 POMDP/博弈把对方反应纳入；再加时序滞回防抖动。弱路权下原则是**宁让勿抢，先保下限再要效率**。"

**追问**：
- 多模态坍缩怎么办？→ 多样性正则 + 锚点式输出。
- 怎么防止"犹豫蠕动"？→ 决策滞回 + 明确让行判据（TTC/间距阈值）。
- 规则和模型冲突？→ 规则作硬约束，模型在可行域内优化。

## 四、标注与规则归一（数据闭环的主场）

**问题**：弱路权场景"没有唯一正确答案"——**标注歧义**才是数据侧最大障碍。

**三件事**：

1. **统一 schema**：把一段场景标成 **4D 结构**——参与者轨迹 + 意图（让/抢/观望）+ 交互关系（谁对谁）+ **路权归属**（谁该让）。
2. **多标注 + 争议复核**：同一段多人标，一致性低的进"争议池"，由资深标注/规控专家裁决；**争议样本本身就是高价值数据**。
3. **规则归一**：把"路权规则"从自然语言变成**可计算约束**（如"转弯让直行""右方来车优先"），规则与场景卡绑定；业界已有用大模型把客户自然语言规则转成规则描述文件、再仿真验证的做法（见驭势的分级路权实践）。

**场景卡**（弱路权场景库的最小单元）：
```
场景类型：无保护左转
几何：路口 4 岔、无左转灯
参与者：对向直行 2 辆、左侧行人 1
路权：对向直行优先
期望行为：等待可接受间隙（TTC > X s）后通过
失败模式：抢行/长时间不动/压线
```

**30 秒答**：
"弱路权标注的难点不是画框，是**定义什么算对**。我们做三件事：统一 4D schema（轨迹+意图+交互+路权）、多标注投票把争议样本挑出来、把路权规则变成可计算约束绑到场景卡上。**争议样本是最值钱的训练数据。**"

**追问**：
- 标注一致性怎么保证？→ 规范 + 多标 + 争议复核 + 一致性指标。
- 规则冲突怎么办？→ 优先级（法规 > 场地规则 > 默契）+ 人工裁决。
- 怎么评"让得对"？→ 让行合规率 + 通行效率 + 舒适度 + 接管率。

## 五、数据闭环怎么支撑（你的项目怎么接）

| 环节 | 弱路权要做什么 | 指标 |
|------|----------------|------|
| **挖掘** | 用交互强度找片段：TTC 低、减速度大、冲突点多、接管、轨迹交叉 | 弱路权场景覆盖率 |
| **标注** | 4D + 意图 + 交互 + 路权；争议样本复核 | 标注一致性、争议率 |
| **训练** | 后训练：RL 奖励含安全/进度/舒适/TTC 余量 | 切片指标、闭环通过率 |
| **评测** | 弱路权切片 + 可交互闭环仿真 | 让行合规率、通行效率、接管率 |

**一句话把项目挂上去**：
> "我们不写决策算法，我们提供弱路权的**数据定义**：场景卡 + 4D 标注 + 评测切片。模型再好，没有'什么算对'的定义，也训不出来。"

> 这与 2026 的"后训练"趋势完全对齐：World Engine 那类工作，奖励函数里的 collision / progress / TTC margin / comfort，本质就是**把弱路权的"该不该让"变成可计算目标**。

## 七、一分钟口述版（背这段）

"弱路权是自车通行权弱或不明确的场景，比如无保护左转、无灯路口、非机动车混行。它的模态归一我分三层：
**传感器层**统一到 BEV，做时间同步、空间标定、特征对齐，重点是缺失模态鲁棒——随机丢模态训练、融合权重通道归一；
**行为层**把多模态预测归一到一条执行，不是取 argmax，而是概率 + 风险加权 + 规则硬约束，交互场景用博弈，再加时序滞回防抖；
**标注层**统一 4D schema（轨迹+意图+交互+路权），多标注投票挑争议样本，把路权规则变成可计算约束。
数据闭环在这件事里的价值，是**定义'什么算对'**——场景卡、4D 标注、切片评测；这也是后训练能成立的前提。"
