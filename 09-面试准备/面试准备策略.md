## 二、简历准备

### STAR 原则

每段项目经历按 STAR 格式写：

```
S (Situation 背景):
  "在 nuScenes 3D 检测任务中，目前 SOTA 方案在遮挡场景下 mAP 仅 45%..."

T (Task 任务):
  "我需要提升模型在重度遮挡场景下的检测精度到 50%+..."

A (Action 行动):
  "我提出了一种结合时序 Attention 和 BEV 特征增强的方法，核心改进包括:
   1. 引入多帧 Temporal Self-Attention 解决单帧遮挡问题
   2. 设计 Occlusion-aware Loss Function 针对遮挡样本加权
   3. 融合 LiDAR 点云补偿视觉遮挡..."

R (Result 结果):
  "在 nuScenes val set 上，遮挡场景 mAP 从 45.2% 提升至 52.8%(+7.6%)，
   NDS 从 65.1 提升至 68.3。方案被采纳为项目 baseline。"
```

### 简历关键点

**加分项**：
- 顶会论文 (CVPR/ICCV/ECCV/NeurIPS) 一作/共一
- 竞赛获奖 (nuScenes/Waymo detection track top 10)
- 开源贡献 (mmdet3d, OpenPCDet PR 或 Star >100 的个人项目)
- 量化指标 (mAP +X%, latency -Y ms, memory -Z%)

**减分项**：
- "熟悉"、"了解" — 面试官会追问到底
- 没有量化指标的项目 — 参与度存疑
- 过于宽泛的技能列表 — 没有重点
- 实习经历堆砌但无技术深度

## 三、技术栈复习路线

### 优先级分级

**P0 — 必须精通 (面试必问)**：
- BEV 感知原理: [[BEVFormer详解|BEVFormer]], [[BEVDet与BEVDepth|BEVDet/BEVDepth]], [[PETR系列|PETR]]
- Transformer 架构: [[Transformer架构详解|Self/Cross/Deformable Attention]], Position Encoding
- 3D 检测: CenterPoint, 3D NMS, NuScenes NDS 指标
- Python + PyTorch 基础

**P1 — 重点掌握 (高频)**：
- 占据网络: [[占据网络与GOD|Occ3D, SurroundOcc, GOD]]
- 多传感器融合: Camera-LiDAR Fusion
- 端到端: [[UniAD详解|UniAD]], [[VAD详解|VAD]]
- 训练技术: DDP, AMP, LoRA
- [[华为ADS技术方案|华为 ADS]] 架构 (国内面试高频!)

**P2 — 加分项 (拉开差距)**：
- 世界模型: GAIA-1, OccWorld
- 大模型+驾驶: DriveVLM, DriveGPT
- SLAM 基础
- 模型部署: TensorRT, INT8 量化

### 复习计划 (12 周)

```
第 1-2 周: 感知算法基础
  - BEV 感知核心论文精读 (LSS → BEVDet → BEVFormer → PETR)
  - Transformer 深入: Self/Cross/Deformable Attention 推导
  - 手写核心算法: Attention, NMS, IoU, Focal Loss, BN/LN
  - 每个下午: 研究一篇论文的源码实现 (mmdet3d / OpenPCDet)

第 3-4 周: 3D 检测 & 占据网络
  - 3D 检测方法对比 (PointPillars → CenterPoint → TransFusion)
  - 占据网络体系 (Occ3D → SurroundOcc → TPVFormer)
  - 华为 ADS 技术方案完整梳理 (GOD + PDP + CAS)
  - 多传感器融合 (BEVFusion, TransFusion, DeepInteraction)
  - 每周产出: 一篇论文笔记 (含公式推导 + 代码走读)

第 5-6 周: 端到端 & 前沿方向
  - 端到端自动驾驶 (UniAD → VAD → GenAD)
  - 世界模型 (GAIA-1, OccWorld, DriveDreamer)
  - 大模型+驾驶 (DriveVLM, DriveGPT4, LINGO-1)
  - 开始整理项目经历 (STAR 格式, 量化的指标)
  - 看 nuScenes/Waymo 竞赛方案 (Top 方案的技术细节)

第 7-8 周: 训练工程 & 部署
  - 分布式训练源码级理解: DDP all-reduce, FSDP 参数分片, ZeRO 1/2/3
  - 混合精度训练: AMP 完整流程, Loss Scaling 机制, FP16 vs BF16
  - 模型部署 Pipeline: PyTorch → ONNX → TensorRT, INT8 量化校准
  - 训练调优实战: LR schedule, 多任务梯度平衡, 显存优化
  - 动手: 用 TensorRT 部署一个 BEV 检测模型, 测延迟和精度损失

第 9-10 周: 模拟面试 & 查漏补缺
  - 找同学/朋友模拟技术面试 (算法推导 + 项目深挖)
  - 录下回答 → 回放改进 (特别是公式推导和架构描述)
  - 准备英文面试 (外企: 用英语讲 BEVFormer 架构)
  - 整理常见面试题答案 (口头能流畅说出, 不是背稿)
  - 查漏补缺: CUDA 基础, 模型量化原理, 数据闭环设计

第 11-12 周: 正式投递
  - 先投 2-3 家非目标公司练手
  - 每场面试后复盘 → 记录被问到的题 → 补充知识盲区
  - 根据反馈调整 → 投目标公司
  - 保持算法手感 (每天至少推导一个公式或写一段核心代码)
```

## 四、面经总结

### 面试流程

| 轮次 | 内容 | 时长 | 重点 |
|------|------|------|------|
| **一面 (技术)** | 算法题 + 基础知识 | 45-60 min | Coding + 八股 |
| **二面 (项目)** | 项目深挖 + 开放题 | 45-60 min | 技术深度 |
| **三面 (系统设计)** | 设计完整感知系统 | 45-60 min | 工程能力 |
| **四面 (主管)** | 技术视野 + 文化 | 30-45 min | 潜力 + Fit |
| **HR 面** | 薪资 + 入职 | 20-30 min | 沟通能力 |

### 各轮次重点

**一面 — 技术基础**：
- 算法推导: Attention 前向/反向推导, BN/LN 对比, Loss 函数推导
- 架构理解: BEVFormer 架构口述, Cross-Attention 机制, 3D PE 设计
- 代码实现: 手写 NMS, IoU, Attention forward (白板或 IDE)
- 考察: 基础扎实度 (不是背答案，是真正理解)

**二面 — 项目深挖 (最关键的轮次)**：
```
常见追问链:
  "为什么选这个方法而不是另一种?"
  → "另一种方法有什么问题?"
  → "你怎么评估你的方法?"
  → "如果给你更多资源，你会怎么改进?"
  → "这个方法有什么局限性?"
  → "如果在实车上效果不如离线好，你怎么排查?"
```

**三面 — 系统设计**：
- 如何设计一个完整的感知系统？
- 数据流: 传感器 → 标定 → 模型推理 → 后处理 → 跟踪 → 发给规划
- 模型选型: 为什么选 BEVFormer 不选 BEVDet?
- 评估体系: 离线指标 + 在线指标 + AB Test
- 数据闭环: 如何从线上 bad case 回溯优化模型

**四面 — 主管面**：
- 对行业的理解？未来趋势？
- 技术决策如果有争议怎么办？
- 为什么选择我们公司？
- 3-5 年职业规划？

## 五、项目准备

### 怎么讲好你的项目

```
黄金模板:

1. 为什么做 (Why):
   - 当前方案的痛点
   - 数据/用户证明了这个问题

2. 做了什么 (What):
   - 你的方法的核心创新
   - 技术选型理由

3. 怎么做 (How):
   - 关键技术细节
   - 遇到的坑和解决方案

4. 效果怎么样 (Result):
   - 量化指标提升
   - 落地/上线情况

5. 还有什么可做的 (Future):
   - 当前的局限性
   - 可能的改进方向
```

### 准备 2-3 个可深挖的项目

每个项目准备好：
- **Elevator Pitch** (30秒): 一句话说清楚你做了什么
- **Technical Deep Dive** (10分钟): 技术细节, 为什么这样设计
- **对比分析** (5分钟): 和你没有选的方案对比
- **反思** (3分钟): 什么做得不好, 学到了什么

## 六、核心算法能力

> 感知算法面试的 "算法题" 不是 LeetCode，而是**模型算法的推导和实现能力**。

### 必须能手写的算法

```python
# 1. Self-Attention / Cross-Attention 前向传播
#    - Scaled Dot-Product Attention 完整推导
#    - Multi-Head 的 split/concat 流程
#    - 复杂度分析: O(N²d) 时间和 O(N²) 空间

# 2. NMS (Non-Maximum Suppression)
#    - 2D NMS (IoU 阈值筛选)
#    - 3D NMS (BEV 空间的旋转框)
#    - Soft-NMS (分数衰减而非直接删除)

# 3. IoU 计算
#    - 2D IoU (轴对齐 + 旋转框)
#    - 3D IoU (近似方法: 采样法、投影法)
#    - GIoU/DIoU/CIoU 的递进关系

# 4. Focal Loss & 变体
#    - 标准 Focal Loss 推导: FL = -(1-p)^γ·log(p)
#    - Quality Focal Loss (IoU-aware classification)
#    - 在 3D 检测中应对正负样本不平衡

# 5. BatchNorm / LayerNorm / GroupNorm
#    - 前向传播的完整公式
#    - 训练和推理模式的区别
#    - Transformer 为什么用 LayerNorm?

# 6. RoPE (Rotary Position Embedding)
#    - 旋转矩阵的构造
#    - 为什么 q·k 天然包含相对位置信息
#    - 和绝对位置编码、ALiBi 的对比
```

### 必须能推导的公式

| 公式 | 面试频率 | 推导难度 |
|------|----------|----------|
| Self-Attention 梯度反向传播 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐ |
| Softmax + CrossEntropy 联合求导 | ⭐⭐⭐⭐ | ⭐⭐ |
| BatchNorm 反向传播 | ⭐⭐⭐ | ⭐⭐⭐ |
| Focal Loss 梯度推导 | ⭐⭐⭐ | ⭐⭐ |
| Deformable Attention 采样偏移梯度 | ⭐⭐ | ⭐⭐⭐⭐ |

### 必须能分析的问题

```
1. 显存分析
   "BEVFormer 在 bs=4, BEV=128×128, 6 个 camera 下的显存如何估算?"
   → 参数 + 梯度 + 优化器 + 激活值(多帧) + 数据 → 每项算出来

2. 计算量分析
   "Deformable Attention 将复杂度从 O(N²) 降到 O(NK),
    如果 N=16384, K=4, 理论加速多少? 实际为什么达不到?"
   → 理论 vs 实际 (通信开销、kernel launch overhead)

3. 精度分析
   "FP16 训练 BEV 模型，哪些层应该保持 FP32? 为什么?"
   → Depth estimation, exp/softmax, large dynamic range 的层

4. 延迟分析
   "如何分析一个 BEV 模型的端到端延迟瓶颈?"
   → 分模块计时 → profiler 可视化 → 定位 bottleneck
```
