# 从 ADS 跳槽：能力对照与查漏补缺

> 一句话导读：**在 ADS 做数据闭环，你手里最值钱的是"大规模量产数据链路的经验"，最危险的是"只会用内部工具、只会说内部黑话"**。本篇把"跳去其他智驾厂商"拆成三件事：**你的经验怎么翻译、别人要什么、你差哪几块**，并给一份 90 天补齐计划。

> [!warning] 先说最重要的一句
> **跳槽不是"把 ADS 的经历复述一遍"，而是"把 ADS 的经历翻译成对方能验证的能力"。** 对方不关心你内部系统叫什么，只关心：**你能否在他们的数据规模、他们的模型栈、他们的算力约束下，把闭环跑起来。**

## 一、先认清：什么最值钱，什么带不走

### 1.1 你真正值钱的东西（要放大讲）

| 资产 | 为什么值钱 | 怎么讲 |
|------|------------|--------|
| **大规模量产数据链路** | 多数公司数据量没到 ADS 量级，处理过 PB 级是稀缺经验 | "我处理过每天 X TB 回传、PB 级存储、千万级 clip 检索" |
| **多模态（LiDAR+Camera）标注** | 纯视觉公司正在补 LiDAR/多模态，你有现成经验 | "我做过 LiDAR 稠密化 + 多相机交叉验证的自动标注" |
| **中国复杂城区场景** | 城区 NOA 是当前主战场 | "我处理过加塞/电动车/施工区/异形障碍的长尾" |
| **大模型标注/重建落地** | 盘古/NeRF/3DGS 这类"大模型进数据链"的经验稀缺 | "我用大模型做预标注 + 重建做新视角 GT" |
| **量产工程规范** | 灰度、回滚、版本、合规，是创业公司最缺的 | "我建过回归门禁和灰度发布流程" |
| **跨团队协作** | 数据/感知/规控/质量多方对齐 | "我推动过 X 团队统一标注规范" |

### 1.2 带不走的东西（别当卖点）

| 带不走 | 风险 | 对策 |
|--------|------|------|
| **内部平台/工具链** | 对方用的是开源栈或自研另一套 | 提前补 mmdet3d/OpenPCDet/Spark |
| **特定芯片/硬件** | 换到地平线 BPU/小鹏图灵/蔚来神玑，工具链全变 | 补量化/部署原理，不背工具命令 |
| **内部数据与指标** | 涉密，不能写 | 用"量级 + 比例 + 趋势"脱敏表达 |
| **内部黑话** | 面试官听不懂，显得"只会一套" | 做"术语翻译"（见 1.3） |

### 1.3 术语翻译表（面试前背下来）

| ADS 内部说法 | 对外通用说法 |
|--------------|--------------|
| GOD | 通用障碍物检测 / 占据感知（ occupancy） |
| PDP | 端到端决策规划网络 |
| CAS | 安全兜底 / 规则校验层 |
| RCR | 实时建图 / 在线地图 |
| 盘古（用于数据） | 大模型自动标注 / 场景生成 |
| 昇腾集群 | 国产 AI 算力集群 |
| 影子模式 | shadow mode（业界通用） |
| 数据飞轮 | data flywheel / data engine（业界通用） |

> [!note] 一句话原则
> **"用对方的语言讲你的能力"**——同一个东西，说"GOD"对方可能愣住，说"通用障碍物/占据感知"立刻懂。

## 三、12 项能力对照表（查漏补缺主表）

> **目标岗位：数据算法岗 + 算法岗**（不做平台/评测专员）。所以 #4 平台仅作备选、优先级下调；#8 部署只对芯片/成本型公司重要。两岗的差异化打法见 [[投递定位-数据算法岗与算法岗]]。
>
> 用法：给自己打分（1-5），低于 3 的就是要补的。

| # | 能力 | ADS 里常见水平 | 外部要求 | 差距 | 补法 |
|:--:|------|----------------|----------|------|------|
| 1 | **纯视觉 BEV / 端到端** | 多模态为主，纯视觉细节可能弱 | 小鹏/卓驭/元戎以纯视觉为主 | 高 | [[BEV感知全景]]、[[BEVDet与BEVDepth]]、[[BEVFormer详解]]、[[端到端自动驾驶概览]] |
| 2 | **自动标注（离线 teacher/4D）** | 强（大模型标注） | 各家都要，但要求"能落地" | 低 | [[自动标注与4D标注]] |
| 3 | **数据挖掘 / 表征检索** | 中（可能偏规则） | 小鹏明确要"表征模型"；各家要向量检索 | 中高 | [[数据引擎与场景检索]] |
| 4 | **数据平台（Spark/Flink/湖仓）** | 中（可能只调 API） | 仅平台岗要求；数据算法岗"会用即可" | 低（备选） | 会用 Spark SQL/向量库即可，不深挖调优 |
| 5 | **训练工程（分布式/蒸馏/持续学习）** | 中高 | 各家用 A100/国产卡，要求能训大模型 | 中 | [[AI-Infra详解]]、[[数据闭环的训练与评测]] |
| 6 | **评测（开环/闭环/PDMS/NAVSIM）** | 中（偏内部体系） | 端到端公司要求闭环评测 | 高 | [[数据闭环的训练与评测]]、[[评测消融与GT构造]] |
| 7 | **仿真（CARLA/nuPlan/3DGS）** | 中（NeRF/3DGS 有积累） | 蔚来/百度/文远重视仿真 | 中 | [[3DGS与重建式数据闭环]]、[[世界模型]] |
| 8 | **部署量化（TensorRT/INT8/BPU）** | 中（可能依赖工具链） | 地平线/卓驭必问 | 高 | [[模型部署与延迟优化]] |
| 9 | **Python 手撕与工程** | Python 熟，但白板默写少 | 现场手撕（Python 可）+ numpy 向量化/多进程 | 中 | [[Python手撕速答卡]]（默写）+ [[手写算法-Python版]]（理解）|
| 10 | **开源栈（mmdet3d/OpenPCDet）** | 弱（内部自研） | 面试常问"你读过源码吗" | 高 | [[开源栈追问速答卡-mmdet3d]]、[[源码走读指南-BEVFormer]]、[[开源项目索引]] |
| 11 | **前沿（VLA/世界模型/基础模型）** | 中高 | 小鹏/理想/蔚来必问 | 中 | [[VLA入门与智驾应用]]、[[论文索引]] |
| 12 | **业务与成本（车型/算力/法规）** | 中 | 低成本车型公司极看重 | 中 | 补"算力预算 → 模型选型"的推导 |

> [!warning] 高差距（按目标岗位分）
> **算法岗**：#1 纯视觉、#10 开源栈；**数据算法岗**：#3 挖掘/表征检索、#6 闭环评测；**两岗共有**：#6 评测（都要）。
> **#8 部署量化**只对芯片/成本型公司（地平线/卓驭）是硬门槛，其他公司按加分项准备。
> **#9 手撕用 Python 即可**，不必为跳槽专门转 C++。

## 四、面经里反复出现的五类问题（附来源）

> 说明：以下为公开面经/JD/技术文章的**共性归纳**；标注 ✅ 的是我已读到原文的，⏳ 的是仅见标题、建议你自己点开读。

### 4.1 第一类：项目深挖（必考，权重最高）

- "你负责的那段闭环，**指标是什么、提升了多少、怎么归因**？"
- "**踩过最大的坑**是什么？怎么发现的？怎么修的？"
- "如果让你重新设计，你会改什么？"

> [!example] 答题骨架（数据闭环版）
> S：数据量/迭代周期卡点 → T：把某类场景的挖掘有效率/标注自动化率/迭代周期做到 X → A：三个动作（检索、分级标注、回归门禁）→ R：数字 → L：一个坑 + 一个反思。
> 📚 完整模板见 [[数据闭环面试专题]] 第四节。

### 4.2 第二类：数据闭环设计题

- "给你 1000 万段数据、10% 标注预算，怎么做？"
- "某个路口频繁接管，怎么定位和修？"
- "怎么从 PB 级数据里找出模型不会的场景？"

📚 [[数据闭环全链路]]、[[数据闭环面试专题]] Q19/Q20。

### 4.3 第三类：自动标注 / OCC 真值的工程细节

这一类是**区分"看过文章"和"做过系统"**的关键。公开的工程实录里反复出现这些坑：

| 坑 | 现象 | 处理思路 |
|----|------|----------|
| **静态可动元素残影** | 收费站抬杆/道闸在多帧叠加后拖影 | 单独分离 + 时序跟踪 + 只放当前时刻状态 |
| **可移动障碍物（Void）** | 被挪动的垃圾桶/路障留下残影 | 用多帧命中次数投票，低于阈值置空 |
| **小目标（锥桶）闪现** | 盲区导致漏框/ID 跳变，点云放不进去 | 固定实例全局位姿，按生命周期"脑补"补帧 |
| **上游误差级联** | 分割错/框不全 → 点云残留 → "空中杂点" | 动静分离 + 去噪 + 人工抽检 + 上游质量门禁 |
| **算力/存储黑洞** | 全域帧叠加 + 稠密体素化，内存时间爆炸 | 稀疏化、分块、缓存、只算 ROI |

> 📚 这类细节我已整理进 [[自动标注与4D标注]] 的"工程实录"小节。**面试时能说出"抬杆残影怎么处理"，比背十个模型名更能证明你做过量产。**

### 4.4 第四类：训练/评测（涨点归因、开环闭环）

- "指标涨了 0.5 点，怎么证明是数据的功劳？"
- "开环涨了闭环不涨，为什么？"
- "新数据混进去老场景掉了，怎么办？"

📚 [[数据闭环的训练与评测]]。

### 4.5 第五类：代码（Python 手撕为主）

- NMS/IoU/Attention/BN/LN、卡尔曼、Top-k、匈牙利匹配、手写 softmax。
- 华为系流程还含**机试**（三道算法题，150 分钟，400 分制），外部厂商多为**现场手撕**——**Python 写即可**，重点是白板默写和边界条件。

📚 [[Python手撕速答卡]]、[[手写算法-Python版]]、[[LeetCode刷题规划]]、[[智驾算法面试题库]] Q44-Q48。

## 六、简历改写：把 ADS 经验翻译成通用语言

> [!example] Before（内部黑话，对方看不懂）
> "负责 GOD 数据闭环，基于盘古做自动标注，支撑 PDP 迭代，迭代周期 5 天。"

> [!success] After（通用语言 + 数字 + 方法）
> "负责量产车数据闭环中的**挖掘与自动标注**：① 用**场景 embedding + 向量检索**把单点 bad case 扩展成批量场景集，挖掘有效率从 X% 提到 Y%；② 搭**离线大模型预标注 + 多传感器几何校验 + 三级置信度**流水线，自动化率 X%、返工率 Y%；③ 建**分场景回归门禁**，把模型迭代周期从 X 周压到 Y 周。"

> [!note] 三个改写原则
> ① **去黑话**（GOD→通用障碍物，PDP→端到端决策规划）；② **加数字**（量级、比例、周期，全部脱敏）；③ **加方法**（embedding/检索/置信度分级/门禁，让对方能追问技术细节）。

## 七、竞业与保密：三条红线（别踩）

> [!warning] 这一节比技术更重要
> 1. **不写、不说前雇主机密**：具体数据规模、内部架构图、未公开指标、客户/项目名，一律不写进简历、不口述。用"量级 + 比例 + 趋势"脱敏。
> 2. **离职前确认竞业协议**：华为等公司竞业条款较严，**入职前找 HR/律师确认**新公司是否在竞业名单、补偿金怎么算。**别抱着"应该没事"的心态。**
> 3. **不带走任何文件/代码/数据**：包括"我自己写的脚本"——职务作品归属公司。**面试演示用公开数据集重写一遍。**

## 八、常见误区速查

> [!warning] 跳槽准备最常踩的坑
> 1. **只讲内部系统**——对方没听过 GOD/PDP，讲完等于没讲；先翻译再讲。
> 2. **没有脱敏数字**——"我们数据量很大"没有说服力，"每天 X TB、PB 级、X 万 clip"才有。
> 3. **忽略纯视觉/闭环评测**——从多模态大厂跳纯视觉公司，这两块最容易被问穿。
> 4. **手撕只看不写**——白板默写和看代码是两回事；面试前至少手写 3 遍，重点练边界（空输入/除零/mask）。
> 5. **不看 JD 族**——平台岗/算法岗/评测岗话术完全不同，用错族 = 答非所问。
> 6. **踩竞业红线**——技术再好，竞业/保密出问题就是职业生涯事故。

## ✅ 检验自己（跳槽前自检）

> [!question] 能用"通用语言"3 分钟讲清你的数据闭环吗？
> 检查：有没有黑话？有没有脱敏数字？有没有一个技术选择？有没有一个坑？

> [!success]- 自检标准
> 全程不出现内部缩写（或出现即解释）；有 3 个以上脱敏数字（TB/%、周期/量级）；有一个"为什么这么设计"的技术选择；有一个"踩过什么坑"的具体故事。

> [!question] 12 项能力里，你有几项 ≥ 3 分？哪三项最低？
> 提示：纯视觉、闭环评测、开源栈是最常见的三个低分项。

> [!success]- 自检标准
> 至少 9 项 ≥ 3 分才建议投目标公司；低于 3 分的项，按 90 天计划的前 4 周优先补。**三项最低的，就是你面试最可能挂的地方。**

> [!question] 你能说出目标公司"数据闭环最痛的一件事"吗？
> 提示：纯视觉公司的痛点是"没有 LiDAR 真值"；低成本公司的痛点是"算力/成本"；Robotaxi 的痛点是"长尾 + 安全"。

> [!success]- 参考方向
> 纯视觉（小鹏/卓驭/元戎）：缺 LiDAR 几何真值 → 靠重建/多视角/基础模型补；低成本（卓驭）：算力预算紧 → 模型压缩/量化/数据效率；Robotaxi（文远/小马/百度）：长尾 + 安全冗余 + 仿真；芯片公司（地平线）：算法-芯片协同 + 量化。**能说出对方的痛点，反问环节就赢了。**
