> 一句话导读：传统自动驾驶只回答"**现在**看到了什么"，世界模型回答"**下一步会发生什么**"——用神经网络"想象未来"，让车在真正行动之前先在脑子里推演一遍。

## 〇、大白话总览

### 什么是世界模型？——"让车有想象力"

人类司机的优势之一是**预判**：看到前车刹车灯亮，会"想象"前车要减速，提前松油门。世界模型就是给自动驾驶装上的这种"想象力"：

```
传统感知:  传感器 → 现在有什么（检测框/占据）
世界模型:  传感器 → 现在有什么 → 未来会发生什么（预测下一时刻）
```

> [!note] 打个比方
> - 传统系统像**"近视眼的记录员"**：只记录当下看到的。
> - 世界模型像**"会下棋的高手"**：不仅看当前棋盘，还能在脑子里推演"如果我走这步，对手会怎么走"。
> **世界模型 = 环境的"内部模拟器"**——训练它"预测未来"，让系统在行动前先在脑内推演。

### 关键定义

```
世界模型 = 环境动态的隐式表征 + 未来状态预测器

给定: 当前观测 o_t + 动作 a_t
预测: 未来观测 o_{t+1}, o_{t+2}, ..., o_{t+T}
```

## 一、什么是世界模型

### 定义

```
世界模型 = 环境动态的隐式表征 + 未来状态预测器

给定: 当前观测 o_t + 动作 a_t
预测: 未来观测 o_{t+1}, o_{t+2}, ..., o_{t+T}
```

### 在自动驾驶中的角色

```
传感器 → 观测 → 世界模型 → 预测未来 → 规划 → 动作
              ↑                                   ↓
              └───────── 实际结果对比 ──────────────┘
```

世界模型让你的自动驾驶系统不仅能**感知现在**，还能**想象未来**。

> [!note] "预测未来"和"感知"的关系
> 感知回答"现在在哪"（检测/占据），世界模型回答"下一步去哪"（预测）。**预测建立在感知之上**（先知道现在有什么，才能预测未来怎么变）——所以世界模型通常**吃感知输出**（占据栅格/目标列表），而不是原始传感器。

## 二、主流世界模型

### 1. GAIA-1 (Wayve, 2023)——"生成式世界模型的里程碑"

> **论文**: GAIA-1: A Generative World Model for Autonomous Driving

**核心方案**：用生成式世界模型，从视频+动作预测未来驾驶场景。

```
输入: 当前视频帧 + 自车动作 (速度/转向)
       ↓
  Encoder (图像 → Token)
       ↓
  World Model (Transformer, 类似 GPT)
       ↓
  Decoder (Token → 视频)
       ↓
输出: 未来 5-15 秒的视频预测
```

**关键能力**：
- 生成逼真的未来驾驶视频
- 场景一致性保持（建筑、道路不变形）
- 动作条件生成（不同动作 → 不同未来）
- 可通过文本 prompt 控制（如"前方来车"）

**视频示例**：给定一段驾驶视频，GAIA-1 可以生成长达 30 秒的未来视频，画面逼真、语义一致。

**模型规模**：6.5B 参数，在 4700 小时驾驶数据上训练。

> [!note] GAIA-1 的本质：**"视频界的 GPT"**
> 它把驾驶视频"分词"（图像 → token），用 GPT 式的自回归 Transformer 预测下一个 token（未来帧），再"解码"回视频。**"不同动作 → 不同未来"** 是关键能力：输入"右转"动作，生成右转的未来视频——**动作条件生成**让世界模型可以被"引导"。

### 2. DriveDreamer / DriveDreamer-2 (2023-2024)——"可控生成"

> **机构**: 中科院自动化所 / 旷视

**核心方案**：世界模型 + 可控生成

```
当前图像 → Image Encoder
HD Map   → Map Encoder       → World Model → 未来视频
3D Box   → Structure Encoder
动作      → Action Token
```

**特点**：
- 结构信息引导（3D BBox + HD Map），保证几何一致性
- 可控生成：可以指定目标 agent 的行为
- DriveDreamer-2 支持多视角一致性生成

> [!note] DriveDreamer vs GAIA-1 的差异
> GAIA-1 从"纯视频"学（结构信息全靠模型自己悟）；DriveDreamer **显式注入结构信息**（HD Map + 3D Box）——**"给生成器看结构图，生成就更守几何规则"**。这和我们反复看到的模式一致：**显式先验让模型更稳**（[[占据网络与GOD]] 的"几何兜底"思想）。

### 3. OccWorld (2024)——"3D 占据世界模型"（重点！）

> **论文**: OccWorld: Learning a 3D Occupancy World Model for Autonomous Driving

**核心创新**：用 3D 占据栅格代替视频像素作为世界模型的输入/输出。

```
当前 3D 占据 → 世界模型 → 未来 3D 占据
      ↓                         ↓
  更高效的表示            更直接支持规划
```

**为什么用占据而非像素**：
- 像素级生成需要大量计算（6.5B 参数的 GAIA-1）
- 占据栅格更紧凑、更适合规划
- 3D 占据天然滤除了纹理噪声

**架构**：
```
当前占据 (X×Y×Z) → 3D Tokenizer → GPT-like Transformer → 3D De-tokenizer → 未来占据
```

> [!warning] OccWorld 是"表示选择"的教科书案例（面试重点）
> GAIA-1 预测**视频像素**（6.5B 参数、计算爆炸、还要解码成视频再用）；OccWorld 直接预测**3D 占据栅格**（紧凑、和 [[占据网络与GOD]] 的感知输出同构、规划可以直接消费）。
> **关键洞察：世界模型的输出应该匹配"下游需要的表示"**——规划需要"未来哪里被占据"，那就直接预测占据，不需要绕道"生成视频再看"。
> **记忆点**：像素级 = 信息全但贵；占据级 = 信息够且便宜。**"输出表示的选择"决定了世界模型的实际价值。**

### 4. Drive-WM / Vista (2024)

- **Drive-WM**：世界模型用于端到端规划中的安全性验证
- **Vista**：高效世界模型，可在边缘设备运行

## 三、世界模型的应用——"想象力"用在哪

### 1. 安全验证（最重要的应用）

```
规划器输出轨迹 → 世界模型模拟 → 检查是否碰撞 → 拒绝不安全规划
```

在实际执行前，用世界模型"脑内模拟"一遍，相当于给了自动驾驶系统**想象力**。

> [!note] 为什么这是"最重要的应用"？
> 传统安全靠"测试中发现 bug"（被动）；世界模型让车**在行动前主动推演**（主动）：规划器说"我要变道"，世界模型模拟"变道后 2 秒会不会和后方来车相撞"——**撞就拒绝这条轨迹**。这是从"事后测试"到"事前推演"的安全范式升级（和 [[华为ADS端到端架构]] 的 CAS 兜底互补：CAS 是物理规则兜底，世界模型是"预测推演"兜底）。

### 2. 数据增强（解决长尾）

```
少量真实驾驶数据 → 世界模型 → 生成大量多样化场景 → 训练规划器
```

**解决核心问题**：自动驾驶的训练数据 99% 是平凡驾驶，缺乏 corner case。世界模型可以**定向生成**罕见场景。

> [!note] 和 [[数据闭环总览]] 的联动
> 世界模型是数据闭环"生成式数据增强"趋势的核心工具：**"AI 造数据"**——用世界模型生成"前车掉落货物"这类 corner case，喂给规划器训练。长尾采集难（真车难碰到），但**生成容易**（世界模型想生成多少都行）。

### 3. 端到端训练的辅助信号

```
Encoder → 世界模型 (预测未来) → 辅助损失
   ↘
   规划器 → 主要损失
```

世界模型的预测能力可以正则化 Encoder，使其学到更好的世界表征。

> [!note] 直觉：**"会预测未来的表征才是好表征"**
> 如果 Encoder 输出的特征能让世界模型准确预测未来，说明这个特征**抓住了世界的规律**（而不只是当前帧的像素）。所以"预测未来"可以作为**辅助监督信号**，逼 Encoder 学到更有预测力的表征——无标注，纯自监督。

### 4. 闭环仿真（比真实更逼真的仿真）

```
世界模型 → 虚拟环境 → Agent 交互 → 闭环训练
```

比传统仿真更逼真，比真实世界更安全。

> [!note] 世界模型 vs 传统仿真器
> 传统仿真（CARLA）是**手工建模的规则世界**（"物理引擎 + 预置场景"）；世界模型是**从数据学出来的动态**（"见过的真实世界的分布"）。前者逼真但有限（写不出所有物理细节），后者灵活但可能违反物理（生成的车可能变形）——**两者互补：规则仿真管"已知"，世界模型管"未知长尾"。**

## 四、技术架构对比

| 模型 | 输入 | 输出 | 参数量 | 特点 |
|------|------|------|:--:|------|
| **GAIA-1** | 视频 + 动作 | 视频 | 6.5B | 逼真视频生成、文本可控 |
| **DriveDreamer** | 图像 + Map + Box | 视频 | 中 | 结构引导、可控 |
| **OccWorld** | 3D 占据 | 3D 占据 | 小 | 高效、规划友好 |
| **UniWorld** | 多模态 | 多模态未来 | 大 | 统一框架 |
| **ADriver-I** | 视频 + 文本 | 视频 + 动作 | 中 | MLLM 驱动 |

> [!note] 读表的维度
> **输入/输出类型决定一切**：视频进出（GAIA-1）= 逼真但贵；占据进出（OccWorld）= 高效但抽象；多模态进出（UniWorld）= 统一但复杂。**"表示的选择" = "用途的选择"**：要数据增强就视频级（逼真），要规划验证就占据级（高效）。

## 五、核心挑战

| 挑战 | 说明 |
|------|------|
| **长时一致性** | 预测超过 5 秒后场景容易崩溃 |
| **物理真实性** | 生成视频可能有物理错误（车辆变形等）|
| **因果关系** | 模型可能学到 spurious correlation |
| **计算成本** | 6.5B 参数模型无法实时运行 |
| **3D 几何** | 像素级生成可能违反几何约束 |
| **可控性** | 如何精确控制生成场景中的其他 agent |

> [!warning] "长时一致性"和"因果混淆"是根本难题
> - **长时一致性**：预测 5 秒内还行，10 秒后场景可能"崩"（车变形、建筑扭曲）——因为误差随时间累积（和 [[端到端自动驾驶概览]] 的 distribution shift 是同一类"自举误差"问题）。
> - **因果混淆**：模型可能学到"统计相关"而非"因果"（比如"看到红灯就预测停车"是因果，"看到红灯和看到停车标记同时出现"才是相关）——[[端到端自动驾驶概览]] 的 Causal Confusion 在世界模型里同样致命。

## 七、世界模型的终极目标

```
世界模型 → 完全替代真实道路测试
  ↓
在 NVIDIA GPU 集群上同时跑 10000 个虚拟车
  ↓
24/7 训练 → 每夜更新模型 → 上车部署
  ↓
数据飞轮: 真实数据 → 训练世界模型 → 生成训练数据 → 训练规划器 → 部署 → 更多数据
```

> Wayve 的 LINGO-1 和 GAIA-1 已经初步展示了这个愿景的可行性。

> [!note] 终极愿景 = "虚拟道路测试"
> 如果世界模型足够逼真，"上路测试"可以大部分在"虚拟世界"完成：10000 辆虚拟车同时跑（真实世界不可能），每夜更新模型，第二天部署——**测试速度提升几个数量级**。这个愿景如果实现，会彻底改变自动驾驶的开发模式（也是 [[数据闭环总览]] "闭环仿真验证"趋势的终极形态）。

## 八、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为世界模型 = 视频生成器**——视频生成只是"像素级"世界模型的一种输出形式；OccWorld 证明"预测占据"更有用（匹配下游）。
> 2. **以为世界模型替代感知**——世界模型**吃感知输出**（占据/目标），不替代感知；它是"感知之后的一层预测"。
> 3. **以为预测得越逼真越好**——逼真（像素级）≠ 有用（下游可消费）；OccWorld 的"够用且便宜"往往比"逼真且贵"更实用。
> 4. **忽略长时一致性崩溃**——5 秒内的预测可信，10 秒以上可能全崩，应用时要考虑预测时域。
> 5. **混淆"世界模型预测"和"安全兜底"**——世界模型是"预测推演"（统计的、可能错的），CAS 是"物理规则"（确定的、必须对的）；两者互补，世界模型不能替代硬兜底。

## ✅ 检验自己（自测题）

> [!question] Q1：用你自己的话定义"世界模型"，并说明它和"感知"的区别。
> 提示：现在 vs 未来。

> [!success]- 参考答案
> 世界模型 = 环境动态的隐式表征 + 未来状态预测器：给定当前观测和动作，预测未来观测。感知回答"现在有什么"（检测/占据），世界模型回答"接下来会发生什么"（预测未来状态）。感知是"看现在"，世界模型是"想未来"——世界模型通常吃感知输出（占据/目标列表）而不是原始传感器。

> [!question] Q2：GAIA-1 和 OccWorld 分别预测什么？为什么 OccWorld 更"规划友好"？
> 提示：像素 vs 占据。

> [!success]- 参考答案
> GAIA-1 预测未来视频像素（6.5B 参数，逼真但计算爆炸，且要解码回视频才能用）；OccWorld 直接预测未来 3D 占据栅格（紧凑、与感知输出同构、规划可直接消费）。OccWorld 更规划友好的核心：**输出表示匹配下游需求**——规划需要"未来哪里被占据"，直接预测占据比"生成视频再分析"高效得多。表示选择决定实际价值。

> [!question] Q3：世界模型的四大应用是什么？哪个最重要、为什么？
> 提示：安全验证/数据增强/辅助信号/闭环仿真。

> [!success]- 参考答案
> ① 安全验证：规划轨迹先在世界模型里"脑内模拟"，碰撞就拒绝（最重要——从"事后测试"到"事前推演"的安全范式升级）；② 数据增强：定向生成 corner case（解决长尾，与数据闭环联动）；③ 辅助信号：预测未来作为 Encoder 的自监督正则（会预测的表征才是好表征）；④ 闭环仿真：比规则仿真更逼真的虚拟训练环境。

> [!question] Q4：世界模型"长时一致性崩溃"和"因果混淆"分别是什么问题？
> 提示：误差累积 / 统计相关。

> [!success]- 参考答案
> 长时一致性崩溃：预测误差随时间累积（自举误差），5 秒内可信、10 秒后场景可能变形崩溃——和模仿学习的 distribution shift 同类。因果混淆：模型学到"统计相关"而非"因果机制"（如看到红灯和停车标记同时出现就预测停车，而非理解"红灯→停"的因果）——预测可能在数据分布改变时失效。

> [!question] Q5：世界模型能替代"安全兜底"（如 CAS）吗？为什么？
> 提示：统计 vs 物理。

> [!success]- 参考答案
> 不能。世界模型是**统计预测**（从数据学的，可能违反物理、可能错）；CAS 是**物理规则**（确定性、可验证、必须对）。世界模型做"预测推演"（提前发现风险场景），CAS 做"硬性兜底"（规则触发强制干预）——两者互补：前者让车"更聪明"，后者保证"不出事"。
