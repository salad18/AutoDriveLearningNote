# 决策规划基础（PnC）

> 一句话导读：感知回答"周围是什么"，预测回答"别人会怎么走"——规划+控制（PnC, Planning & Control）回答"**我该怎么开**"。这是量产智驾岗位的必备知识（Momenta 面经直接问 LQR/MPC/EM Planner）。本篇讲清分层架构、经典算法（Hybrid A*/EM Planner/Frenet/LQR/MPC）和端到端的冲击。

> [!tip] 用"老司机开车"理解 PnC
> 老司机开车分三步：**① 决策**（"前面堵车，变道"）→ **② 规划**（"从哪条线变、变快还是变慢"）→ **③ 控制**（"方向盘打多少、油门踩多深"）。PnC 就是把这个过程拆成数学问题：**决策 = 选策略，规划 = 生成轨迹，控制 = 跟踪轨迹**。

## 一、PnC 分层架构（自上而下）

```
① 行为决策（Behavior Decision）
   输入: 环境 + 预测 + 导航目标
   输出: 语义决策（跟车/变道/超车/停车/让行）
   ↓
② 路径规划（Path Planning）
   输入: 决策结果 + 地图/障碍物
   输出: 几何路径（x(s), y(s)——东西向的"线"）
   ↓
③ 速度规划（Speed Planning）
   输入: 路径 + 动态障碍物
   输出: 速度曲线（v(t)——时间上的"节奏"）
   ↓
④ 轨迹跟踪控制（Control）
   输入: 规划轨迹 + 自车状态
   输出: 方向盘/油门/刹车（底层执行器命令）
```

> [!note] 横纵向解耦：工程上最常用的简化
> 路径 = 横向（左右），速度 = 纵向（快慢）。把 2D 规划拆成"横向做什么 + 纵向做什么"两个 1D 问题——**计算量小、易调试**。代价是可能**次优**（路径规划时不知道车速，速度规划时路径已定）——这是端到端想解决的（见第五节）。

## 二、经典路径规划算法

### 2.1 Hybrid A*（混合 A*）——"搜索 + 车辆动力学"

- **A*** 在网格上搜索最短路径；**Hybrid A*** 的"Hybrid"在于：搜索节点不是格子，而是**车辆的位姿 (x, y, θ)**，并考虑**运动学约束**（车不能横着走、有转弯半径限制）。
- 特点：能搜出"可被车执行的路径"（曲率受限），适合**泊车/狭窄场景**。
- 面试点：A* 会搜出"贴墙角"的路径（几何最优），Hybrid A* 因为运动学约束，路径更"像车开的"。

### 2.2 Frenet 坐标系 + EM Planner（百度 Apollo 经典）

**Frenet 坐标系**：以道路中心线为参考线，用 (s, l) 表示位置——s = 沿路的前进距离，l = 横向偏移。好处：路径规划变成"在 s-l 平面上找一条线"，天然处理弯道。

**EM Planner = 横纵向解耦 + DP 决策 + QP 优化**（Momenta 面经必考）：

```
路径规划:
  ① Frenet 下撒采样点
  ② DP（动态规划）搜索避障最优路径（粗糙、有折点）
  ③ QP（二次规划）平滑 → 光滑路径

速度规划:
  ① 在 ST 图（时间-路程）上 DP 搜索初步速度曲线（加速/减速/停车）
  ② QP 平滑 → 光滑速度曲线
```

- **DP 管"决策"**（走左边还是右边、加速还是减速），**QP 管"平滑"**（让轨迹可执行、舒适）。
- 价值：把复杂问题分解，工程可行、可调试。
- 局限：横纵向解耦 → 次优；规则代价函数难调。

### 2.3 其他经典方法

| 方法 | 思路 | 场景 |
|------|------|------|
| **RRT / RRT*** | 随机采样树搜索 | 复杂空间、非结构化 |
| **Lattice Planner** | 预生成"格点轨迹库"选最优 | Apollo 一代方案 |
| **优化法（OSQP）** | 把轨迹生成建模为凸优化 | 平滑、约束多 |

## 三、控制：LQR vs MPC（Momenta 高频）

### 3.1 LQR（线性二次型调节器）

- 求**固定反馈律** `u = -Kx`，使二次代价最小；K 通过解 Riccati 方程**离线**获得。
- 优点：计算快、稳定、可离线。
- 缺点：**不能显式处理约束**、无滚动优化。
- 场景：高速巡航/变道的**横向控制**（简单工况够用）。

### 3.2 MPC（模型预测控制）

- 每步：**预测未来 N 步 + 优化控制序列 → 只执行第一步 → 下一步重来**（滚动优化）。
- 优点：**天然处理约束**（控制量/状态/避撞）、处理非线性。
- 缺点：**计算量大**（每步解优化问题）。
- 场景：城市复杂场景、有避障需求。

### 3.3 怎么选？

| 场景 | 推荐 |
|------|------|
| 高速巡航、简单变道 | LQR（快、稳） |
| 城市、避障、硬约束 | MPC |
| 混合 | LQR 给 MPC 提供初值 |

> 面试口述："**LQR 是离线求出的固定律，MPC 是每步重新优化**——所以 MPC 能力更强（约束/非线性）但更贵。量产里常组合用：横向 LQR、纵向 PID，复杂场景上 MPC。"

## 四、评估与指标

| 指标 | 含义 |
|------|------|
| **安全性** | 碰撞率、最小距离 |
| **舒适性** | 加速度/加加速度（jerk）变化平缓 |
| **合规性** | 是否压线、超速、逆行 |
| **效率** | 到达时间、平均速度 |
| **实时性** | 规划耗时（量产硬指标，通常 ≤10ms 级） |

## 五、端到端 vs 传统 PnC（面试热点）

**传统 PnC 的问题**：规则多、参数难调、横纵向解耦次优、长尾场景（加塞/鬼探头）难覆盖。

**端到端的冲击**：
- UniAD 把跟踪/预测/规划串成一个网络（[[端到端自动驾驶概览]]）——用数据学"规划"，而不是手写规则。
- 但量产上**端到端规划仍难完全替代传统 PnC**：可解释性、安全兜底、法规要求 → 产业趋势是**"端到端 + 规则兜底"**（华为分体式架构、Momenta D.L.P.，[[华为ADS端到端架构]]）。
- 面试口述："端到端负责'像人一样开'（泛化/长尾），传统 PnC 负责'不出事'（可解释/兜底）——两者是分工，不是替代。"

## ✅ 自测一下（先想答案，再点开）

> [!question] Q1：PnC 的分层架构是什么？为什么横纵向解耦？

> [!success]- 参考答案
> 行为决策（选策略）→ 路径规划（横向）→ 速度规划（纵向）→ 轨迹跟踪控制。横纵向解耦：把 2D 规划拆成"横向 1D + 纵向 1D"，计算量小、工程好调试；代价是可能次优（路径规划不知道车速）。

> [!question] Q2：EM Planner 里 DP 和 QP 各做什么？

> [!success]- 参考答案
> DP（动态规划）负责**搜索/决策**：在 Frenet 采样点或 ST 图上搜出"避障/速度"的初步方案（粗糙、有折点）；QP（二次规划）负责**平滑**：把粗糙轨迹优化成光滑可执行的轨迹。路径和速度都走"DP 初解 → QP 平滑"两遍。

> [!question] Q3：LQR 和 MPC 的本质区别？为什么 MPC 更"强"？

> [!success]- 参考答案
> LQR 离线解出固定反馈律 u=-Kx，不处理约束、不滚动；MPC 滚动优化——每步预测未来 N 步、解带约束的优化、只执行第一步。MPC 更强因为能显式处理约束（避撞/控制量限制）且适应时变环境；但计算量大。高速简单工况 LQR 够用，复杂场景 MPC。
