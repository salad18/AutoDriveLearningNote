# 大模型与自动驾驶

> 一句话导读：传统端到端模型"只开车不说话"，大模型（LLM/VLM）让车**"看懂了再说、说了再开"**——用语言和常识推理补充传统感知的盲区。本篇讲清楚大模型能带来什么、怎么接入驾驶、有哪些落地难点。

## 〇、大白话总览

### 传统自动驾驶缺什么？

一辆车检测到了"前方有车"（检测框），但它不知道：
- 这辆车是**警车**吗？（正在执行任务需要让行？）
- 路口的**红灯**快变绿了，还是刚变红？
- 前车在**礼让行人**，还是在减速？

**这些"常识"传统模型学不到**——它只认框，不理解"场景语义"。大模型（VLM/LLM）补的正是这块：**"理解"而不是"看见"**。

> [!note] 打个比方
> 传统端到端 = 一个**只认字不理解的速记员**（把看到的都记下来）；大模型驱动 = **一个懂交通规则的老司机**（不仅看到，还知道"警车鸣笛要让路"这种常识）。
> **大模型不是替代感知，而是给感知加"脑子"。**

### 三个新能力（记住这三点）

1. **常识推理**：知道"警车鸣笛要让路"而不是仅检测到"车辆"
2. **可解释性**：能输出决策理由（"我减速因为前方行人犹豫"）
3. **开放词汇**：不限于预定义类别（"前方有施工围挡"这种描述性理解）

## 一、为什么大模型 + 自动驾驶

### 传统方法的局限

| 传统方法 | 大模型驱动方法 |
|----------|--------------|
| 只能处理见过的场景 | 泛化到未见过的情况 |
| 输出检测框/轨迹点 | 输出自然语言解释 + 决策 |
| 需要大量标注数据 | 可从大规模网络数据预训练 |
| 黑盒决策，不可解释 | 可以问"为什么这么做" |
| 场景理解局限于分类 | 理解交通规则、意图、常识 |

### 大模型带来什么

1. **常识推理**：知道"警车鸣笛要让路"而不是仅检测到"车辆"
2. **开放词汇**：不限于预定义类别
3. **可解释性**：能输出决策理由
4. **多模态融合**：文本 + 图像 + 点云统一理解

> [!warning] 但注意：大模型不是"万能药"
> 它带来了 4 个新能力，同时引入 3 个新问题：**慢**（推理秒级 vs 毫秒级）、**幻觉**（可能"看到"不存在的物体）、**不可证明安全**（LLM 的决策无法形式化验证）。**"能力多"和"敢上车"是两回事**——这就是为什么大模型目前定位"辅助"而非"控制"。

## 二、主流方法分类——大模型怎么接入驾驶

### 1. VLM 驱动驾驶（视觉-语言模型直接输出决策）

```
相机图像 → VLM (如 LLaVA) → 自然语言输出:
  "前方有行人正在横穿马路，需要减速并在斑马线前停车"
```

**定位**：端到端的"感知+决策"——图像直接进 VLM，输出语言化的决策。

### 2. LLM 作为 Planner（语言模型做规划）

```
感知结果 (文本描述) → LLM → 规划决策 → 控制器
```

**定位**：感知仍是传统模型（快），LLM 只做"高层决策"（慢但聪明）——**混合架构，工程上最现实**。

### 3. 世界模型 + LLM（先预测再推理）

```
传感器 → 世界模型 (预测未来) → LLM 推理 → 规划
```

**定位**：给 LLM 加上"想象力"（[[世界模型]] 的联动）——先预测未来场景，再基于预测做决策。

> [!note] 三种方式的本质区别（记忆框架）
> **VLM 驱动** = 大模型做"感知+决策"（最激进）；**LLM Planner** = 大模型只做"决策"（最务实）；**世界模型+LLM** = 大模型做"推理+决策"（最前沿）。
> 激进程度递减，工程可行性递增。**当前量产（华为/理想）走的是"LLM 辅助决策"路线**，不是 VLM 直接控车。

## 三、关键模型

### DriveVLM (2024, 清华大学)——"VLM 驾驶的里程碑"

> **论文**: DriveVLM: The Convergence of Autonomous Driving and Large Vision-Language Models

**核心方案**：
```
场景图像序列 → VLM (Qwen-VL)
                    ↓
          场景描述 (自然语言)
          规划决策 (自然语言)
          空间推理 (链式思维)
```

**三大能力**：
1. **场景描述**：看到什么
2. **场景分析**：分析关键事件和风险
3. **规划决策**：应该怎么做

**Chain-of-Thought 推理**：
```
Q: 前方路口的交通灯是什么状态？
A: 红灯亮起，车辆应该停车等待。
→ 规划：减速并在停止线前停车。
```

> [!note] Chain-of-Thought（CoT）为什么对驾驶重要？（面试高频）
> 直接让模型输出"减速停车"它可能"蒙对"；让它**先描述、再分析、最后决策**（链式思考），推理链条是显式的：
> - **可验证**：如果决策错了，能看出是哪一步推理错了（看到红灯 ✓ / 分析出要停 ✓ / 决策错了 ✗）。
> - **更稳**：多步推理比一步"猜答案"准确率高（和 [[三阶段训练范式]] 里 AutoDrive-P3 奖励"中间推理"是同一个思想）。
> - **可解释**：模型"说出"决策理由，工程师能审计。

### DriveGPT4 (2024)——"驾驶版多模态 GPT"

> 将 GPT-4 级别的多模态 LLM 用于驾驶场景理解

**特点**：
- 端到端可解释驾驶
- 输入：多帧视频 + 控制信号
- 输出：规划动作 + 自然语言解释

> [!note] DriveGPT4 vs DriveVLM
> DriveVLM 偏"场景理解 + 决策建议"（VLM），DriveGPT4 偏"视频理解 + 动作输出"（视频多模态 LLM）。共同点：**都输出"语言解释 + 决策"**——可解释性是它们的共同卖点。

### AD-MLP / BEVGPT

- 将 BEV 信息 + LLM 推理结合
- 用 LLM 处理复杂交通规则和交互

> [!note] 这类工作的共同思路
> 感知还是 BEV（快、稳），**把 BEV 的语义信息"翻译"成 LLM 能理解的 token/文本**，让 LLM 基于"结构化场景描述"做推理——**"传统感知 + LLM 大脑"的混合架构**是当前主流探索方向。

## 四、技术架构

### 典型 VLM 驾驶 Pipeline

```
┌─────────────────────────────────────────────────────┐
│                    VLM-Driven Driving                │
│                                                      │
│  ┌─────────────────────┐                             │
│  │ 视觉编码器           │ ← 多帧序列/多视角图像       │
│  │ (ViT / InternViT)   │                             │
│  └──────────┬──────────┘                             │
│             │ Visual Tokens                          │
│             ▼                                        │
│  ┌─────────────────────┐                             │
│  │ Q-Former / MLP      │ ← 图像特征 → LLM 空间      │
│  └──────────┬──────────┘                             │
│             │ Aligned Visual Features                 │
│             ▼                                        │
│  ┌─────────────────────────────────────────────┐    │
│  │  LLM (Qwen / LLaMA / GPT)                   │    │
│  │                                              │    │
│  │  System Prompt:                              │    │
│  │  "你是一个自动驾驶助手，需要根据当前        │    │
│  │   场景做出安全的驾驶决策..."                  │    │
│  │                                              │    │
│  │  Chain-of-Thought:                           │    │
│  │  1. 场景描述 → 2. 关键分析 → 3. 决策        │    │
│  └──────────────┬──────────────────────────────┘    │
│                 │ Text Response                       │
│                 ▼                                     │
│  ┌─────────────────────────────────────────────┐    │
│  │ 输出解析 → 控制信号 (油门/刹车/转向)         │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

> [!note] 三步走明白
> **① 视觉编码**：图像 → 视觉 token（ViT 提取，[[Transformer架构详解]] 的 ViT 部分）；**② 模态对齐**：Q-Former/MLP 把视觉 token 映射到 LLM 的"语言空间"（让 LLM 能"看懂"图）；**③ LLM 推理**：System Prompt（驾驶规则）+ CoT（描述→分析→决策）→ 输出文本决策 → 解析成控制信号。
> **关键在"对齐"**：LLM 只懂文本，视觉特征必须"翻译"成它能理解的表示——模态对齐的质量决定了整个 pipeline 的上限。

### 知识增强——"把交规写进 Prompt"

将交通规则、驾驶手册等文本知识注入 Prompt：
```
System Prompt:
"你是一个遵守中国交通法规的自动驾驶系统：
 - 红灯必须停车
 - 斑马线前减速让行
 - 不允许实线变道
 - 高速公路上速度不低于60km/h..."
```

> [!note] 知识增强的价值与局限
> **价值**：交规是文本知识，LLM 天生擅长文本——**不需要训练，改 Prompt 就能注入新规则**（加一条"雨天跟车距离加倍"就是改几个字）。**局限**：Prompt 里的规则是"软约束"（模型可能不遵守），不能替代硬编码的安全兜底（[[华为ADS端到端架构]] 的 CAS 3.0 才是硬兜底）。

## 五、核心挑战

| 挑战 | 问题 | 解决方向 |
|------|------|----------|
| **实时性** | LLM 推理太慢 (秒级) | 蒸馏小模型、量化、边端推理 |
| **幻觉** | LLM 可能"看到"不存在的物体 | 感知+语言双层验证 |
| **安全对齐** | LLM 可能做出不安全决策 | RLHF 安全训练、规则约束 |
| **场景理解深度** | 传统 VLM 缺乏 3D 空间理解 | 3D-aware VLM、BEV token |
| **闭环控制** | 语言输出如何转精确控制 | 混合架构：LLM 决策 + 传统控制 |
| **成本** | 大模型部署成本高 | 端侧小模型、云端协同 |

> [!warning] 两个最"致命"的挑战（面试重点）
> - **幻觉**：LLM 会"一本正经地胡说"——可能把"路边的广告牌上的车"当成"前方车辆"。**驾驶场景幻觉 = 假阳性障碍 = 急刹或事故**。解法：感知层（传统检测）先验证，LLM 只做"高层推理"（感知+语言双层验证）。
> - **实时性**：LLM 推理秒级，而驾驶要求 100ms 级（[[模型部署与延迟优化]] 的延迟预算）。解法：1-3B 小模型蒸馏 + 量化 + 只让 LLM 做"低频决策"（不是每帧）。**"LLM 做慢决策、传统模型做快控制"是量产的现实答案。**

## 六、与端到端的融合方向

```
传统端到端 (UniAD/VAD)  ──→  大模型增强端到端
       │                            │
  ✗ 不可解释                  ✓ 输出推理过程
  ✗ 封闭类别                  ✓ 开放词汇理解
  ✗ 规则硬编码                ✓ 常识推理
  ✗ 数据贪婪                  ✓ 预训练知识迁移
```

### 混合架构（当前最现实的融合形态）

```
感知层: 传统 BEV 感知 (快速)
推理层: LLM 做高层决策 (慢但安全)
控制层: 传统 MPC/控制器 (精确)
```

> [!note] 为什么"混合"而不是"全替换"？
> **各层用各层擅长的**：感知用 BEV（毫秒级、可靠）、决策用 LLM（聪明、可解释、但慢）、控制用 MPC（精确、可验证）。**大模型是"军师"，不是"驾驶员"**——军师出主意（策略），驾驶员执行（控制）。这个定位既拿到了大模型的理解能力，又不牺牲实时性和安全性。

## 八、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为大模型已经"上车控车"了**——量产是"LLM 辅助决策/场景理解"，不是 VLM 直接控制（幻觉和安全验证不过关）。
> 2. **以为 VLM 能替代 BEV 感知**——VLM 缺 3D 空间理解（没有深度/占据），感知还是要传统模型。
> 3. **忽略幻觉问题**——LLM 在驾驶里"一本正经胡说"是致命缺陷（假阳性 → 急刹），必须感知层验证。
> 4. **以为 Prompt 注入规则 = 安全**——Prompt 是软约束，模型可能不遵守，硬安全必须靠规则兜底（CAS）。
> 5. **拿 LLM 的推理延迟和传统模型比**——LLM 定位是"低频决策"（秒级），传统感知是"高频控制"（毫秒级），两者是互补不是竞争。

## ✅ 检验自己（自测题）

> [!question] Q1：大模型给自动驾驶带来哪 4 个新能力？分别对应传统方法的什么局限？
> 提示：常识/开放/解释/多模态。

> [!success]- 参考答案
> ① 常识推理：知道"警车鸣笛要让路"（传统只检测"车辆"类别）；② 开放词汇：不限于预定义类别（理解"施工围挡"等描述）；③ 可解释性：输出决策理由（传统黑盒）；④ 多模态融合：文本+图像+点云统一理解。核心是"从看见（分类）到理解（语义/常识）"。

> [!question] Q2：大模型接入驾驶的三种方式是什么？各自激进程度如何？
> 提示：VLM / LLM Planner / 世界模型+LLM。

> [!success]- 参考答案
> ① VLM 驱动：图像直接进 VLM 输出决策（最激进，感知+决策都交给大模型）；② LLM as Planner：传统感知 + LLM 高层决策（最务实，感知快、决策聪明）；③ 世界模型+LLM：先预测未来再推理决策（最前沿）。激进程度 VLM > 世界模型+LLM ≈ LLM Planner 的激进程度取决于定位，工程可行性反之。当前量产走"LLM 辅助决策"路线。

> [!question] Q3：Chain-of-Thought 在驾驶决策里为什么有价值？给出三点。
> 提示：可验证/更稳/可解释。

> [!success]- 参考答案
> ① 可验证：决策错了能定位是哪一步推理错（描述/分析/决策）；② 更稳：多步推理比一步"猜答案"准确率高（与 P3 奖励中间推理同理）；③ 可解释：模型"说出"理由，工程师可审计（量产安全验证需要）。CoT 把"黑盒决策"变成"可审计的推理链"。

> [!question] Q4：幻觉为什么在驾驶里是"致命"问题？怎么缓解？
> 提示：假阳性障碍物。

> [!success]- 参考答案
> LLM 可能"看到"不存在的物体（把广告牌上的车当真实车辆），产生假阳性障碍物 → 急刹/误判/事故。缓解：① 感知层（传统检测）先验证，LLM 只做高层推理（感知+语言双层验证）；② RLHF 安全对齐让模型学会"不确定就说不知道"；③ 规则约束（幻觉输出不直接进控制链路）。

> [!question] Q5：为什么"混合架构"（BEV 感知 + LLM 决策 + MPC 控制）是当前最现实的融合形态？
> 提示：各层用各层擅长的。

> [!success]- 参考答案
> 因为各层的"擅长"不同：BEV 感知毫秒级可靠（实时性）、LLM 聪明可解释但慢且可能幻觉（决策质量）、MPC 精确可验证（控制精度）。混合架构 = 感知给 LLM 提供"结构化事实"（防幻觉）、LLM 给 MPC 提供"高层策略"（防黑盒）、MPC 负责"精确执行"（防抖动）——各取所长，同时规避了大模型慢、幻觉、不可验证三大短板。

## 🛠 动手练习

### 练习 1：给 VLM 写 System Prompt（30 分钟）

假设你在设计一个驾驶 VLM 的系统提示词，请写一段完整的 System Prompt 包含：
1. 角色设定（自动驾驶助手）
2. 3 条交通规则（中国交规）
3. 输出格式要求（CoT 三段式：描述/分析/决策）
4. 1 条"安全优先"原则（不确定时怎么办）

> [!tip] 写完自问

### 练习 2：分析一个"LLM 决策场景"（30 分钟）
