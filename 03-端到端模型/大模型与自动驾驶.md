# 大模型与自动驾驶

> LLM/MLLM 进入自动驾驶 —— 从「只看前方」到「理解交通场景语义」。

---

## 一、为什么大模型 + 自动驾驶

### 传统方法的局限

| 传统方法 | 大模型驱动方法 |
|----------|--------------|
| 只能处理见过的场景 | 泛化到未见过的情况 |
| 输出检测框/轨迹点 | 输出自然语言解释 + 决策 |
| 需要大量标注数据 | 可从大规模网络数据预训练 |
| 黑盒决策，不可解释 | 可以问"为什么这么做" |
| 场景理解局限于分类 | 理解交通规则、意图、常识 |

### 大模型带来什么

1. **常识推理**：知道"警车鸣笛要让路"而不是仅检测到"车辆"
2. **开放词汇**：不限于预定义类别
3. **可解释性**：能输出决策理由
4. **多模态融合**：文本 + 图像 + 点云统一理解

---

## 二、主流方法分类

### 1. VLM 驱动驾驶

用视觉-语言模型 (VLM) 做端到端驾驶。

```
相机图像 → VLM (如 LLaVA) → 自然语言输出:
  "前方有行人正在横穿马路，需要减速并在斑马线前停车"
```

### 2. LLM 作为 Planner

```
感知结果 (文本描述) → LLM → 规划决策 → 控制器
```

### 3. 世界模型 + LLM

```
传感器 → 世界模型 (预测未来) → LLM 推理 → 规划
```

## 三、关键模型

### DriveVLM (2024, 清华大学)

> **论文**: DriveVLM: The Convergence of Autonomous Driving and Large Vision-Language Models

**核心方案**：
```
场景图像序列 → VLM (Qwen-VL)
                    ↓
          场景描述 (自然语言)
          规划决策 (自然语言)
          空间推理 (链式思维)
```

**三大能力**：
1. **场景描述**：看到什么
2. **场景分析**：分析关键事件和风险
3. **规划决策**：应该怎么做

**Chain-of-Thought 推理**：
```
Q: 前方路口的交通灯是什么状态？
A: 红灯亮起，车辆应该停车等待。
→ 规划：减速并在停止线前停车。
```

### DriveGPT4 (2024)

> 将 GPT-4 级别的多模态 LLM 用于驾驶场景理解

**特点**：
- 端到端可解释驾驶
- 输入：多帧视频 + 控制信号
- 输出：规划动作 + 自然语言解释

### AD-MLP / BEVGPT

- 将 BEV 信息 + LLM 推理结合
- 用 LLM 处理复杂交通规则和交互

## 四、技术架构

### 典型 VLM 驾驶 Pipeline

```
┌─────────────────────────────────────────────────────┐
│                    VLM-Driven Driving                │
│                                                      │
│  ┌─────────────────────┐                             │
│  │ 视觉编码器           │ ← 多帧序列/多视角图像       │
│  │ (ViT / InternViT)   │                             │
│  └──────────┬──────────┘                             │
│             │ Visual Tokens                          │
│             ▼                                        │
│  ┌─────────────────────┐                             │
│  │ Q-Former / MLP      │ ← 图像特征 → LLM 空间      │
│  └──────────┬──────────┘                             │
│             │ Aligned Visual Features                 │
│             ▼                                        │
│  ┌─────────────────────────────────────────────┐    │
│  │  LLM (Qwen / LLaMA / GPT)                   │    │
│  │                                              │    │
│  │  System Prompt:                              │    │
│  │  "你是一个自动驾驶助手，需要根据当前        │    │
│  │   场景做出安全的驾驶决策..."                  │    │
│  │                                              │    │
│  │  Chain-of-Thought:                           │    │
│  │  1. 场景描述 → 2. 关键分析 → 3. 决策        │    │
│  └──────────────┬──────────────────────────────┘    │
│                 │ Text Response                       │
│                 ▼                                     │
│  ┌─────────────────────────────────────────────┐    │
│  │ 输出解析 → 控制信号 (油门/刹车/转向)         │    │
│  └─────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────┘
```

### 知识增强

将交通规则、驾驶手册等文本知识注入 Prompt：
```
System Prompt:
"你是一个遵守中国交通法规的自动驾驶系统：
 - 红灯必须停车
 - 斑马线前减速让行
 - 不允许实线变道
 - 高速公路上速度不低于60km/h..."
```

## 五、核心挑战

| 挑战 | 问题 | 解决方向 |
|------|------|----------|
| **实时性** | LLM 推理太慢 (秒级) | 蒸馏小模型、量化、边端推理 |
| **幻觉** | LLM 可能"看到"不存在的物体 | 感知+语言双层验证 |
| **安全对齐** | LLM 可能做出不安全决策 | RLHF 安全训练、规则约束 |
| **场景理解深度** | 传统 VLM 缺乏 3D 空间理解 | 3D-aware VLM、BEV token |
| **闭环控制** | 语言输出如何转精确控制 | 混合架构：LLM 决策 + 传统控制 |
| **成本** | 大模型部署成本高 | 端侧小模型、云端协同 |

## 六、与端到端的融合方向

```
传统端到端 (UniAD/VAD)  ──→  大模型增强端到端
       │                            │
  ✗ 不可解释                  ✓ 输出推理过程
  ✗ 封闭类别                  ✓ 开放词汇理解
  ✗ 规则硬编码                ✓ 常识推理
  ✗ 数据贪婪                  ✓ 预训练知识迁移
```

### 混合架构

```
感知层: 传统 BEV 感知 (快速)
推理层: LLM 做高层决策 (慢但安全)
控制层: 传统 MPC/控制器 (精确)
```
