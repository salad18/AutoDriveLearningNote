# 轨迹预测（Trajectory Prediction）

> 一句话导读：跟踪告诉你"车现在在哪、多快"，预测要回答"**它接下来会去哪**"——这是感知和规划之间最容易被忽略、却最影响安全感的一环（前车会让还是不让？路口车会不会抢行？）。感知/端到端岗高频考点。本篇讲清：**输入输出、主流方法（DenseTNT/QCNet/MTR）、多模态的本质、评估指标**。

> [!tip] 用"预判别人怎么走"理解预测
> 开车时你一直在做轨迹预测：前车刹车灯亮了 → 预测它要减速；路口有车缓慢前移 → 预测它要抢行。**你预测的是"别人的意图和动作"**，而不是"物理上它只能这么走"。自动驾驶的轨迹预测也一样——**关键是建模"意图的不确定性"**（他可能让、可能不让），所以预测输出天然是"多条可能轨迹 + 各自的概率"。

## 一、输入输出：预测要"吃"什么、"吐"什么

### 输入（预测的上下文）

| 输入 | 说明 |
|------|------|
| **历史轨迹** | 每个目标的过去 N 帧位置/速度/朝向（跟踪的输出，如 2s 历史） |
| **地图** | 车道线、路口、人行横道、限速（无图方案下由在线建图提供） |
| **交通参与者** | 周围所有车辆/行人/自行车的历史与位置（交互） |
| **交通信号** | 红绿灯状态（可选） |

### 输出（预测的结果）

- **多模态轨迹**：每个目标输出 K 条候选未来轨迹（如 K=6），每条带**概率**。
- **时间跨度**：常见 3s（短）到 8s（长）预测。
- **格式**：轨迹点序列（每帧 x,y）+ 概率。

> [!note] 为什么必须是"多模态"？
> 同一时刻，前车可能"减速让行"也可能"加速抢行"——**单一确定的轨迹是错的**。所以输出是"概率分布"：`{轨迹1: 0.6（减速）, 轨迹2: 0.3（保持）, 轨迹3: 0.1（加速）}`。规划器据此做**风险加权**决策（而不是押注一条轨迹）。

## 二、方法演进：从"规则"到"学习"

### 2.1 早期：规则 + 物理模型

- 匀速/匀加速外推（物理模型）；或"跟车/换道"规则。
- 问题：交互场景（路口博弈）完全无解。

### 2.2 学习式方法（主流）

#### DenseTNT（2021）——"密集目标 + 目标点预测"

- 思路：把未来轨迹**离散成"目标点"（goal）**——网格上的每个点都是一个候选终点，模型预测每个终点的概率，再生成到终点的轨迹。
- 关键：**锚点（anchor）思想**——用"目标点"降低连续轨迹的建模难度。

#### QCNet（2023）——"查询中心 + 相对位置编码"

- 用 **query-centric 相对位置编码**：每个目标只编码自己关心的相对信息（其他目标相对它的位置），更省算力、更泛化。
- 多模态：输出多组轨迹 + 概率。

#### MTR（2023, Waymo）——"多模态轨迹 + 运动查询"

- 核心：**Motion Query Pair**——一条轨迹 = 一对 query（终点 + 路径），用 query 池生成多样化轨迹。
- 优点：多模态质量高；缺点是 query 池大小影响泛化。

### 2.3 统一趋势（2025+）

- 预测逐渐与**端到端模型融合**（UniAD 的 MotionFormer 就是预测模块）——预测不再独立，而是作为端到端的一部分。
- 和世界模型结合：预测"场景未来"而非"单目标轨迹"（[[世界模型]]）。

## 三、评估指标

| 指标 | 含义 | 注意 |
|------|------|------|
| **minADE** | 预测 K 条里**最接近**真值那条的平均位移误差（K 条取最小） | 常用 K=6 |
| **minFDE** | 终点的最小位移误差 | 反映"终点准不准" |
| **Miss Rate** | 预测轨迹"偏太远"的比例（超过阈值算 miss） | 越低越好 |
| **Brier / NLL** | 概率校准（预测的概率准不准） | 多模态评估关键 |

> 面试口述："多模态预测的标准指标是 **minADE/minFDE**（K 条取最小），但要注意——min 指标会"奖励乱猜"（K 条里总有一条撞上），所以还要看 **Miss Rate 和概率校准**。"

## 四、预测 vs 规划（最容易混淆的一对）

| 维度 | 轨迹预测 | 规划 |
|------|---------|------|
| **问题** | 别人**会**怎么走？ | 我**该怎么**走？ |
| **输入** | 环境 + 他车历史 | 预测结果 + 自车目标 |
| **输出** | 他车的多模态未来 | 自车的一条（或少数）最优轨迹 |
| **目标** | 准确 + 概率校准 | 安全 + 舒适 + 合规 + 效率 |

> [!note] 一句话区分
> **预测是"读心术"（猜别人），规划是"决策"（决定自己）**。预测错了规划就跟着错——所以预测的"多模态 + 概率"直接决定规划的风险处理能力。

## 五、面试高频追问

> [!question] Q1：轨迹预测的输入输出是什么？为什么输出多模态？

> [!success]- 参考答案
> 输入：目标历史轨迹、地图、周围参与者、信号灯；输出：K 条候选轨迹 + 概率。多模态原因：同一场景下未来有多种合理可能（让/不让、加速/减速），单一确定预测会误导规划；多模态 + 概率让规划做风险加权。

> [!question] Q2：DenseTNT 的"目标点"思路是什么？为什么有效？

> [!success]- 参考答案
> 把未来轨迹离散成"目标点"（网格终点），模型预测每个目标点的概率，再生成到终点的轨迹。有效原因：① 连续轨迹空间难建模，离散目标点把问题变成"分类 + 回归"；② 终点是轨迹的"骨架"，先定终点再补中间，更稳；③ 锚点思想降低优化难度。

> [!question] Q3：预测和跟踪、规划分别是什么关系？

> [!success]- 参考答案
> 检测 → 跟踪（给我"过去+现在"）→ 预测（给我"未来"）→ 规划（决定"我"怎么走）。跟踪是预测的输入（历史轨迹），预测是规划的前提（别人怎么动）。端到端模型（UniAD）把跟踪/预测/规划串成一个网络，共享特征。
