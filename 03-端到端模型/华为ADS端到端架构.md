## 〇、大白话总览

### 华为的端到端哲学（一句话）

**"感知一张网（GOD），规划一张网（PDP），各司其职，联合优化，外加 CAS 物理兜底。"**

```
传感器 → GOD 大网（感知）→ 结构化 3D 场景 → PDP 网络（规划）→ 轨迹 → CAS 3.0（安全闸门）→ 执行
```

**三个词各管什么：**
- **GOD**：回答"世界现在长什么样"（感知——哪里有什么、是什么、往哪动）
- **PDP**：回答"我该怎么开"（预测+决策+规划——一条网里完成）
- **CAS**：回答"这真的安全吗"（物理规则兜底——不管网络怎么说，物理上不能撞）

> [!note] 打个比方
> 特斯拉大一统 = **"一个天才全包"**（一个人既看路又决策又开车，能力强但出了事没法复盘）。
> 华为分体式 = **"团队分工 + 安全员"**（感知员报告、决策员拿主意、规划员出路线、安全员最后把关）——**每个环节可审计，还有最后一道物理保险**。
> **没有绝对优劣**：大一统信息流最完整，分体式可验证性最强。**华为的约束是"中国量产要过安全认证、事故要能定位"，所以选分体式。**

## 一、为什么是"分体式端到端"

### 感知规划分离 vs 大一统

```
特斯拉思路:     感知 ─────────→ 规划 ─────────→ 控制
               └────────── 一个超大模型 ──────────┘

华为思路:      感知 (GOD大网) ──→ 规划 (PDP网络)
               └──── 两个网络, 端到端联合优化 ────┘
```

**华为选择分体式的原因**：

| 维度 | 大一统模型 | GOD+PDP 分体式 |
|------|-----------|---------------|
| **可解释性** | 差（黑盒） | 好（感知结果可审计） |
| **调试** | 难（无法定位问题模块） | 模块化调试 |
| **安全验证** | 困难 | 感知独立验证 |
| **迭代速度** | 整体耦合 | 模块独立迭代 |
| **冗余** | 无 | 感知输出有多重验证 |

> 华为认为：汽车安全是底线，不可解释的端到端黑盒对安全验证是灾难。

> [!warning] "分体式"和"模块化"的区别（别混淆！）
> 传统模块化：感知/预测/规划**各自独立训练**（接口是手工定义的框/轨迹，信息丢失）。
> 华为分体式：GOD 和 PDP **联合优化**（端到端梯度可以贯穿），只是**分成两张网**（中间有显式的结构化场景表示）。
> **关键区别：分体式是"可审计的端到端"，不是"退回模块化"**——联合优化保留了信息流，显式中间表示提供了可验证性。

> [!note] GOD 输出"结构化 3D 场景"的意义
> GOD 的输出不只是"检测框"，而是**结构化场景表征**（目标 + 占据 + 车道 + 场景标签）——这些显式表示有两个作用：① 给 PDP 提供丰富的输入（规划需要的都齐了）；② **可审计**（感知错了能定位是"漏检了目标"还是"占据预测歪了"）。**"结构化输出"是分体式端到端可解释性的物质基础。**

### 软关联融合机制——"华为最核心的感知创新"

华为 GOD 的关键创新：用 Transformer 的 Cross-Attention 替代硬关联 (硬标定对齐)。

```
传统硬关联:
  LiDAR 点 ←→ Camera 像素 精确对齐 (标定要求极高)
  → 一旦标定漂移, 融合失效

华为软关联:
  LiDAR 点特征 → Transformer Cross-Attention → 自适应寻找对应的图像特征
  → 不需要像素级对齐, 模型自己学习对应关系
```

**论文背景**：2022 年华为与港科大、港城大合作论文中描述了类似 TransFusion 的方法：
1. LiDAR 点云 → 初步 3D 特征/边界框
2. 将 3D 信息投影到 2D 图像 → 融合语义特征
3. 高分辨率图像 → Cross-Attention 增强小目标检测

> [!warning] 软关联 vs 硬关联（必考！和 [[多传感器融合基础]] 的 TransFusion 呼应）
> - **硬关联**：LiDAR 点用标定好的外参投影到图像取像素特征——**标定稍有漂移（温度/振动），特征就取错位置，融合直接失效**。
> - **软关联**：LiDAR 特征通过 Cross-Attention **自适应"找"对应的图像特征**（权重学习，不是点对点硬映射）——**标定漂移只影响权重分布，不导致"取错"的硬错误**。
> **本质：把"对应关系"从"手工标定"变成"可学习注意力"**——这是 [[多传感器融合基础]] 里 TransFusion "Soft Association" 思想在量产里的放大。**实车标定会漂移，软关联是量产必需，不是锦上添花。**

### GOD 的核心能力阶梯

```
Level 1: 白名单目标检测      (ADS 1.0 的 BEV)
Level 2: 异形障碍物检测      (ADS 2.0 加入 GOD)
Level 3: 占据空间理解        (像 Tesla OccNet)
Level 4: 场景语义理解        (ADS 3.0: "理解"而不仅是"看到")
Level 5: 行为预判            (在感知阶段预判其他 agent 下一步动作)
```

> [!note] 五级阶梯 = 华为感知的进化史
> 从"认白名单"（L1）→"认异形"（L2）→"懂空间"（L3）→"懂场景"（L4）→"预判行为"（L5）——**每一级都在回答"更高级的'看到'"**。L5（行为预判）把预测也融进感知，是 GOD 大网"端到端"的体现。

> [!note] PDP = [[VAD详解]] 的"显式规划"工程版
> 注意 PDP 的流程和 VAD 高度相似：**场景编码（Scene Tokens）→ 交互建模（Attention）→ 多模态轨迹生成（K 候选）→ 评分选择**。区别在量产化的三点：① 输入来自 GOD 的结构化场景（不是纯视觉特征）；② 输出带**决策标签**（变道/跟车/让行——可解释）；③ 后面接 CAS 3.0 硬兜底（学术版没有）。

### PDP 的训练

```
训练数据源:
1. 人类驾驶数据 (量产车采集)
   → 模仿学习: 你的变道时机、跟车距离
2. 仿真驾驶数据 (云端 3500 万 km/天)
   → 强化学习: 在仿真中探索极端场景
3. 影子模式数据
   → 比对: 人类实际驾驶 vs 模型预测

训练方式:
  Stage 1: 预训练 (模仿人类驾驶)   ← 学习"像人一样开"
  Stage 2: 强化学习微调            ← 安全 + 效率
  Stage 3: CAS 3.0 安全约束       ← 最后的安全兜底
```

> [!note] PDP 的训练 = [[三阶段训练范式]] 的量产版
> **模仿学习（学"像人"）→ 强化学习（学"安全+效率"）→ 规则兜底（CAS）**——这和 Pretrain→SFT→RL 的框架同构，只是把"RL 对齐"拆成"仿真 RL + 规则兜底"。**量产版把"对齐"做成了双层：软的（RL 奖励）学安全，硬的（CAS 规则）保安全。**

### PDP 为什么更类人

| 传统规则规划 | PDP 网络 |
|-------------|----------|
| "如果前车 30m 内 → 减速" | 学习人类真实的跟车距离分布 |
| 固定换道时机 | 根据场景动态决策 |
| 路口逻辑写死 | 通过大量路口数据学会"怎么过" |
| 保守到影响效率 | 类人平衡安全与效率 |

> [!note] 规则 vs 数据驱动的本质区别
> 规则规划是"人写的 if-else"（写不尽所有场景，且保守）；PDP 是"从数据学的分布"（跟车距离不再是"30m 硬阈值"，而是"人类真实跟车距离的概率分布"）。**"写死的规则"→"学出来的行为"**——这正是端到端的核心价值（[[端到端自动驾驶概览]]）。

## 四、CAS 3.0 — 安全兜底

PDP 规划 + CAS 3.0 安全层 → **双重保障**。

```
PDP 规划输出
     ↓
CAS 3.0 安全检查
     ↓
  ┌─ 通过 → 执行
  │
  └─ 冲突 → 安全干预 (减速/转向/刹停)
```

CAS 3.0 不是模型，而是基于物理约束和确定性规则的安全兜底。这解决了纯端到端模型的最核心问题：**任何模型都可能出错，必须有一层"物理定律"兜底**。

> [!warning] CAS 为什么"不是模型"？（理解量产的钥匙）
> 模型 = 统计的（可能错）；CAS = **物理/规则的（确定性）**。碰撞检测、AEB 触发条件是**可以形式化验证的物理逻辑**，不依赖神经网络。
> **量产的核心假设：模型一定会犯错**（长尾、对抗、幻觉），所以必须有一层"不管模型怎么说，物理上不能撞"的确定性闸门。**"端到端 + 规则兜底"不是技术不纯粹，是量产安全的必要条件。**（[[世界模型]] 的推演兜底和 CAS 互补：一个"预测性"一个"物理性"。）

## 五、与 UniAD / VAD 的对比

| 维度 | 华为 ADS 3.0 | UniAD | VAD |
|------|-------------|-------|-----|
| **感知架构** | GOD 大网 (LiDAR+视觉) | BEVFormer (纯视觉) | BEVFormer (纯视觉) |
| **规划架构** | PDP (端到端) | 规则+可学习 | Planning Transformer |
| **传感器** | 多传感器融合 | 纯视觉 | 纯视觉 |
| **量产** | ✅ 已量产百万级 | ❌ 研究框架 | ❌ 研究框架 |
| **实时性** | 200 TOPS 实时 | ~1.8 FPS (V100) | ~5-10 FPS |
| **安全兜底** | CAS 3.0 | 无 | 碰撞惩罚 |

> [!note] 读表的三层结论
> ① **感知**：华为多模态（LiDAR+视觉）vs 论文纯视觉——量产要全天候可靠性；② **规划**：PDP 端到端 vs UniAD 规则+可学习——华为更"端到端"但也更"可审计"（决策标签）；③ **安全**：CAS 3.0 硬兜底 vs 论文无/软惩罚——**这是量产和论文最本质的差距**。

## 六、关键洞察——华为的三个"为什么"

### 华为 ADS 3.0 的技术选择逻辑

```
为什么保留 LiDAR？
  → 纯视觉 2D→3D 升维计算量巨大
  → LiDAR 提供"免费"的 3D 信息
  → 全天候能力 (雨雾/黑夜/大光比)
  → 降低了云端算力需求 (不用花大算力把2D升成3D)

为什么分离 GOD 和 PDP？
  → 安全审计：感知错了还是规划错了？可定位
  → 独立迭代：感知提升不需要改规划
  → 规则兜底：CAS 3.0 可以在感知输出上做安全验证

为什么 200 TOPS 够用？
  → 算法优化：软关联替代硬标定，减少计算
  → 感知降维：LiDAR 提供 3D 先验，不需要从 2D 费力还原
  → 任务聚焦：不做大一统，每个网络专精
```

> [!warning] 这三个"为什么"是面试的"华为题"标准答案
> **为什么保留 LiDAR**：LiDAR 提供"免费的 3D"（纯视觉要花巨量算力从 2D 还原 3D）+ 全天候可靠。
> **为什么分体式**：可审计（事故定位）、可独立迭代、可规则兜底。
> **为什么 200 TOPS 够**：软关联省计算 + LiDAR 降维 + 专精网络（不做大一统）。
> **共同逻辑：量产约束（安全认证、算力成本、可靠性）决定技术选择**——没有绝对最优架构，只有约束下最优。

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为"分体式"= "传统模块化"**——分体式是**联合优化的两张网**（端到端梯度贯穿），只是中间有显式表示；不是"各自独立训练、接口丢信息"的老模块化。
> 2. **以为软关联 = 不需要标定**——软关联**容忍**标定漂移，不是不需要标定（初始标定仍然要，只是不依赖像素级精确）。
> 3. **以为 CAS 是"模型的一层"**——CAS 是**独立的确定性物理逻辑**（不是神经网络），这是它能"无条件兜底"的前提。
> 4. **以为大一统（特斯拉）一定更好**——大一统信息流完整但不可审计；分体式可验证但可能有中间信息损失。**约束不同选择不同，没有绝对优劣。**
> 5. **忽视"联合优化"**——GOD 和 PDP 是端到端联合训练的（不是两个模型拼装），这是"分体式端到端"和"模块化"的分水岭。

## ✅ 检验自己（自测题）

> [!question] Q1：分体式端到端和传统模块化、和特斯拉大一统，分别有什么区别？
> 提示：联合优化 vs 独立训练 vs 单网络。

> [!success]- 参考答案
> 传统模块化：各模块独立训练、手工接口（框/轨迹）、信息丢失——不是端到端。特斯拉大一统：感知→控制一个超大模型、信息流最完整、但黑盒不可审计。华为分体式：GOD 和 PDP 两张网**联合优化**（端到端梯度贯穿），中间有显式结构化场景表示——**既有端到端的信息流，又有可审计的中间表示**。分体式 ≠ 模块化，是"可审计的端到端"。

> [!question] Q2：软关联融合为什么优于硬关联？量产为什么必须软关联？
> 提示：标定漂移。

> [!success]- 参考答案
> 硬关联：LiDAR 点按标定外参投影到图像取像素特征，标定漂移（温度/振动导致）就取错位置，融合失效。软关联：LiDAR 特征通过 Cross-Attention 自适应寻找对应图像特征，标定漂移只影响权重分布、不导致"取错"的硬错误。实车标定必然漂移（尤其量产后），所以软关联是量产必需——把"对应关系"从手工标定变成可学习注意力。

> [!question] Q3：画出 GOD → PDP → CAS 的完整链路，并说明每层的职责。
> 提示：感知/规划/安全。

> [!success]- 参考答案
> 传感器 → GOD 大网（感知：多模态融合→3D 占据→结构化场景表征）→ PDP 网络（规划：场景编码→交互建模→多模态轨迹生成→评分选择→输出轨迹+决策标签）→ CAS 3.0（安全：物理规则检查，冲突则强制干预减速/转向/刹停）→ 执行器。职责：GOD 回答"世界什么样"，PDP 回答"我该怎么开"，CAS 回答"这真的安全吗"。三者各司其职、层层兜底。

> [!question] Q4：华为为什么保留 LiDAR？这和"200 TOPS 够用"有什么关系？
> 提示：免费的 3D。

> [!success]- 参考答案
> LiDAR 提供"免费的 3D 信息"：纯视觉要从 2D 图像还原 3D（[[3D视觉与投影几何]] 的单目无解问题），算力开销巨大；LiDAR 直接给出精确 3D 坐标，省下大量云端和车端算力。同时 LiDAR 全天候可靠（雨雾黑夜）。所以保留 LiDAR → 降低算力需求 → 200 TOPS 够用。**"传感器选择"和"算力需求"是联动的**——堆传感器可以换算力，堆算力可以换算法（华为选前者）。

> [!question] Q5：CAS 3.0 为什么必须是"确定性规则"而不是"模型"？
> 提示：模型会犯错。

> [!success]- 参考答案
> 量产的核心假设是"模型一定会犯错"（长尾、对抗场景、幻觉）。安全兜底必须**不依赖任何统计模型**——CAS 用物理约束和确定性规则（碰撞检测、AEB 触发条件）实现，可以形式化验证、无条件触发。如果兜底也是模型，兜底本身也会犯错，安全就无从保证。**"统计层（GOD/PDP）负责聪明，确定性层（CAS）负责不出事"**是量产安全的铁律。
