## 〇、大白话总览

### 你的硬件能做什么？（一句话）

**"CPU 慢慢训练，GPU 快快推理"**——AMD 显卡用不了 CUDA（PyTorch 训练加速的标配），但可以通过 DirectML 加速推理（10-50 倍）。

```
训练（吃兼容性）:  CPU 跑 PyTorch（慢但什么都支持）
推理（吃性能）:    ONNX Runtime + DirectML（用上 RX 7800 XT）
```

> [!note] 打个比方
> CPU 训练像"手写试卷"（慢但每题都能做），DirectML 推理像"考试用计算器"（快但只有特定题型能用）。**"训练用 CPU（保兼容），推理用 GPU（榨性能）"** 是 AMD 无 CUDA 环境下的最优策略。

### 5 个实验 = 5 个知识库知识点

```
实验 1: YOLO 检测      → [[计算机视觉基础]] 的 2D 检测实战
实验 2: 车道线分割     → [[计算机视觉基础]] 的分割 + BEV 前置
实验 3: 单目深度       → [[BEVDet与BEVDepth]] 的 LSS 深度模块
实验 4: 行为克隆       → [[端到端自动驾驶概览]] 的端到端实战
实验 5: 简化 BEV       → [[BEVDet与BEVDepth]] 的 LSS 完整流程
```

**递进逻辑**：2D 检测 → 分割 → 深度 → 端到端 → BEV——**一条从入门到进阶的本地实验路线**。

## 一、硬件评估

| 组件 | 型号 | 训练价值 |
|------|------|:--:|
| **GPU** | AMD Radeon RX 7800 XT 16GB | ⭐⭐⭐⭐ ~RTX 4070 级，但不能用 CUDA |
| **CPU** | AMD Ryzen 5 9600X 6C/12T | ⭐⭐⭐ 单核强，适合数据预处理 |
| **RAM** | 31GB DDR5 | ⭐⭐⭐⭐ 够加载 nuScenes/KITTI 全量 |
| **磁盘** | 160GB 可用 / 1.9TB 总量 | ⭐⭐⭐ 够存所有数据集 |

### 关键约束

```
❌ 无 NVIDIA GPU → 无 CUDA
❌ ROCm 在 Windows 上基本不可用
✅ 可用 DirectML (DX12) 做 GPU 加速
✅ CPU 31GB + 12 线程 → 小模型训练完全可行
```

> [!warning] 为什么"ROCm 在 Windows 上基本不可用"？
> ROCm（AMD 的 CUDA 等价物）官方只支持 Linux；Windows 上要么装 WSL2（ROCm 支持也很有限），要么用 DirectML（微软的 DX12 机器学习接口，onnxruntime 支持较好）。**结论：Windows 上无 CUDA 的现实解 = DirectML 推理 + CPU 训练。**

### GPU 使用策略

| 场景 | 方案 | 速度对比 |
|------|------|:--:|
| **训练**（PyTorch 模型） | CPU 训练 + 小模型策略 | 基准 |
| **训练**（ONNX Runtime） | DirectML EP | 3-10x CPU |
| **推理** | ONNX Runtime + DirectML | 10-50x CPU |
| **推理** | OpenVINO (Intel 优化) | 不适用 (AMD CPU) |

> 💡 **核心策略**：用 CPU 做 PyTorch 训练（灵活、兼容性好），用 ONNX Runtime DirectML 做推理加速（榨取 GPU 性能）。

> [!note] 为什么"训练不用 DirectML"？
> PyTorch 的 DirectML 后端（torch-directml）**算子覆盖不全、兼容性差**（很多模型跑不起来或报错）。而 onnxruntime-directml 成熟稳定。**"训练保兼容（CPU），推理要性能（DirectML）"** 是把"能用"放在"最快"前面的务实选择。

### Step 5：设置 CPU 线程数

```python
# 在训练脚本开头加上

torch.set_num_threads(6)  # 匹配你的 6 核 CPU，避免超线程导致性能下降

# 环境变量（也可在 PowerShell 设置）

# $env:MKL_NUM_THREADS = "6"
```

> [!warning] 为什么"6 线程"而不是"12 线程"？
> 你的 CPU 是 6 核 12 线程（超线程）。**超线程对密集数值计算（矩阵乘法）通常没有加速，反而因资源竞争变慢**——所以设成物理核心数 6，不是线程数 12。**"线程数 = 物理核心数"是 CPU 训练的第一条经验。**

**KITTI → YOLO 格式转换**：

```python
# convert_kitti_to_yolo.py
import os
from pathlib import Path

# KITTI label format: type x1 y1 x2 y2 ...
# YOLO format: class_id cx cy w h (normalized)

CLASSES = ['Car', 'Pedestrian', 'Cyclist']  # KITTI 中我们关注的
IMG_W, IMG_H = 1242, 375  # KITTI 图像尺寸

def convert_label(kitti_label_path, yolo_label_path):
    with open(kitti_label_path) as f:
        lines = f.readlines()
    
    yolo_lines = []
    for line in lines:
        parts = line.strip().split()
        obj_type = parts[0]
        if obj_type not in CLASSES:
            continue
        
        cls_id = CLASSES.index(obj_type)
        x1, y1, x2, y2 = map(float, parts[4:8])
        
        cx = ((x1 + x2) / 2) / IMG_W
        cy = ((y1 + y2) / 2) / IMG_H
        w = (x2 - x1) / IMG_W
        h = (y2 - y1) / IMG_H
        
        yolo_lines.append(f"{cls_id} {cx:.6f} {cy:.6f} {w:.6f} {h:.6f}")
    
    with open(yolo_label_path, 'w') as f:
        f.write('\n'.join(yolo_lines))

# 批量转换
for label_file in Path('D:/datasets/kitti/training/label_2').glob('*.txt'):
    convert_label(label_file, Path('labels') / label_file.name)
```

### 实验 3：单目深度估计（3-5 天）

**目标**：从单张图预测深度，理解 LSS 的深度模块

```yaml
模型: Lite-Mono (轻量), MonoDepth2-MobileNet
数据集: KITTI Depth
训练时间: ~6-12 小时 (CPU)
输出: 逐像素深度图
```

核心训练代码：

```python
# train_monodepth.py
class LiteMono(nn.Module):
    """
    轻量单目深度估计，对标 [[BEVDet与BEVDepth]] 的深度预测模块
    架构: MobileNetV2 Encoder + 轻量 Decoder
    """
    def __init__(self):
        super().__init__()
        self.encoder = torchvision.models.mobilenet_v2(pretrained=True).features
        self.decoder = DepthDecoder(num_ch_enc=[16, 24, 32, 96, 1280])
    
    def forward(self, x):
        features = []
        for i, layer in enumerate(self.encoder):
            x = layer(x)
            if i in [1, 3, 6, 13, 18]:  # 多尺度特征
                features.append(x)
        return self.decoder(features)

# 损失: L1 + SSIM + 边缘平滑
def depth_loss(pred, target):
    l1 = torch.abs(pred - target).mean()
    ssim = 1 - ssim_loss(pred, target)
    smooth = edge_smoothness(pred)
    return l1 + 0.1 * ssim + 0.001 * smooth
```

> 💡 这个实验做完后，你会真正理解 [[BEVDet与BEVDepth]] 里 LSS 的 DepthNet 为什么难训、为什么需要 LiDAR 监督。

> [!warning] 为什么深度估计"最难训"？
> 单目深度是 [[3D视觉与投影几何]] 的"几何无解问题"（一个像素对应一条射线）——模型只能靠先验"猜"。你在实验里会亲身体会：**loss 下降慢、远处深度模糊**——这正是 BEVDepth 用 LiDAR 监督深度（[[BEVDet与BEVDepth]]）要解决的问题。**"亲手训一次深度模型"= 理解 LSS 深度监督动机的最快方式。**

| E4.3 | ResNet + LSTM | CARLA 自采 | 弯道稳定性 | 不冲出道 |
| E4.4 | 加数据增强 | CARLA 自采 | 泛化能力 | 新地图可用 |

> [!note] 实验 4 是"知识库核心"的实战
> E4.1（DAVE-2）→ E4.3（加时序）→ E4.4（加增强）的递进 = [[端到端小车实战]] 的三方案递进。**E4.2 的"闭环成功率"是第一次真正意义上的"闭环评测"**——你会第一次亲身体验"开环 loss 低但闭环失败"（[[端到端自动驾驶概览]] 的核心概念）。

### 实验 5：简化 BEV 检测（进阶，7-10 天）

**目标**：在 CPU 上跑通 BEV 检测的最小版

```yaml
模型: SimpleBEV (极简版 BEVDet)
数据集: nuScenes mini
训练时间: ~24-48 小时 (CPU, 会很慢但能跑)
输出: BEV 3D 检测框
```

```python
# simple_bev.py — BEV 检测最小实现
class SimpleBEV(nn.Module):
    """
    简化版 BEVDet，帮助理解 [[BEVDet与BEVDepth]] 的核心流程
    
    流程:
      N 个相机图像 → ResNet 特征 → LSS 深度估计 → 投影到 BEV 
      → BEV Encoder (Conv) → 3D 检测头
    
    去掉了: 时序融合, 深度真值监督, 复杂的 BEV Encoder
    """
    def __init__(self, num_cameras=6, bev_size=(128, 128)):
        super().__init__()
        # 图像 backbone（每个相机共享）
        self.backbone = torchvision.models.resnet18(pretrained=True)
        self.backbone = nn.Sequential(*list(self.backbone.children())[:-2])
        
        # 深度估计头 (LSS 的 DepthNet)
        self.depth_head = nn.Sequential(
            nn.Conv2d(512, 256, 1), nn.ReLU(),
            nn.Conv2d(256, 64, 1),    # 64 = 深度 bin 数
        )
        
        # BEV Encoder
        self.bev_encoder = nn.Sequential(
            nn.Conv2d(512, 256, 3, padding=1), nn.BatchNorm2d(256), nn.ReLU(),
            nn.Conv2d(256, 128, 3, padding=1), nn.BatchNorm2d(128), nn.ReLU(),
        )
        
        # 检测头（简化版 CenterPoint）
        self.heatmap_head = nn.Conv2d(128, 3, 1)  # 3 类: Car, Ped, Cyc
        self.reg_head = nn.Conv2d(128, 2, 1)       # dx, dy offset
    
    def forward(self, images):
        # images: (B, N_cam, 3, H, W)
        B, N, C, H, W = images.shape
        
        # 1. 每个相机提取特征 + 深度
        features = []
        depths = []
        for i in range(N):
            feat = self.backbone(images[:, i])          # (B, 512, H/32, W/32)
            depth = self.depth_head(feat).softmax(dim=1) # (B, 64, H/32, W/32)
            features.append(feat)
            depths.append(depth)
        
        # 2. LSS: 特征 × 深度 → 3D Frustum → Voxel Pooling → BEV
        bev_feat = self.lss_project(features, depths)  # 见 [[BEVDet与BEVDepth]]
        
        # 3. BEV Encoder + 检测头
        bev_feat = self.bev_encoder(bev_feat)
        heatmap = self.heatmap_head(bev_feat)
        offset = self.reg_head(bev_feat)
        
        return heatmap, offset
```

> ⚠️ 这个实验在 CPU 上训练非常慢（~48h+），建议只在理解了 [[BEVDet与BEVDepth]] 后，用于验证理解，不要作为主要实验。

> [!note] 实验 5 = LSS 的"活体解剖"
> SimpleBEV 把 [[BEVDet与BEVDepth]] 的 LSS 流程拆成最小实现：**多相机特征 → 深度分布（DepthNet）→ 特征×深度 → Voxel Pooling → BEV → 检测头**。你去掉了时序/深度监督/复杂 Encoder，只留核心骨架——**当你亲手写出 `lss_project` 并让它跑通时，LSS 就再也忘不掉了。**

## 八、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **用系统 Python 3.14 直接装 PyTorch**——必然不兼容报错，**必须 Conda + Python 3.11**。
> 2. **指望 AMD 显卡跑 PyTorch 训练**——Windows 上别想了（无 CUDA、ROCm 不可用），**训练用 CPU，推理用 DirectML**。
> 3. **线程数设成 12**——超线程在数值计算上反而慢，**设 6（物理核心数）**。
> 4. **一上来跑实验 5（BEV）**——48h+ 且依赖前面实验的知识，**按推荐顺序做**。
> 5. **跳过"数据格式转换"直接训练**——KITTI→YOLO 格式不对，训练报错或学垃圾，**转换脚本先跑通再训练**。
> 6. **不验证 DirectML 可用**——`ort.get_available_providers()` 里没有 `DmlExecutionProvider` 说明驱动/DX12 有问题，**先验证再跑实验**。

## ✅ 检验自己（自测题）

> [!question] Q1：为什么"训练用 CPU、推理用 DirectML"？直接全部用 DirectML 不行吗？
> 提示：兼容性 vs 性能。

> [!success]- 参考答案
> PyTorch 的 DirectML 后端（torch-directml）算子覆盖不全、兼容性差，很多模型跑不起来；而 onnxruntime-directml 成熟稳定，推理加速 10-50 倍。所以策略是：训练用 CPU（保兼容，慢但能跑）、推理用 ONNX Runtime + DirectML（要性能）。"能用"优先于"最快"，是无 CUDA 环境下的务实选择。

> [!question] Q2：CPU 训练时线程数为什么设为 6 而不是 12？
> 提示：超线程。

> [!success]- 参考答案
> CPU 是 6 核 12 线程（超线程）。超线程对密集数值计算（矩阵乘法）通常无加速，反而因线程间资源竞争变慢。所以设成物理核心数 6（不是逻辑线程数 12）。同时配合 MKL/OMP 线程环境变量保持一致。

> [!question] Q3：5 个实验分别对应知识库的哪些理论？递进逻辑是什么？
> 提示：检测/分割/深度/端到端/BEV。

> [!success]- 参考答案
> 实验 1 YOLO 检测 = [[计算机视觉基础]] 2D 检测；实验 2 车道线分割 = [[计算机视觉基础]] 分割；实验 3 单目深度 = [[BEVDet与BEVDepth]] 的 DepthNet；实验 4 行为克隆 = [[端到端自动驾驶概览]]；实验 5 简化 BEV = [[BEVDet与BEVDepth]] 的 LSS 完整流程。递进逻辑：2D → 分割 → 深度 → 端到端 → BEV——从入门到理解 BEV 家族核心。

> [!question] Q4：实验 3（单目深度）为什么"最难训"？做完你会理解什么？
> 提示：几何无解。

> [!success]- 参考答案
> 单目深度是"几何无解问题"（一个像素对应一条射线，深度信息在投影时丢失，[[3D视觉与投影几何]]），模型只能靠先验"猜"。你会亲身体会 loss 下降慢、远处深度模糊——这正是 BEVDepth 用 LiDAR 监督深度（[[BEVDet与BEVDepth]]）要解决的问题。亲手训一次，就理解 LSS 深度监督的动机了。

> [!question] Q5：实验 4 里"闭环成功率"指标为什么比"开环 MSE"重要？
> 提示：真开 vs 预测。

> [!success]- 参考答案
> 开环 MSE 测的是"预测轨迹像不像人类"（喂人类轨迹），不暴露 distribution shift，可能 loss 很低但真开就翻车（[[端到端自动驾驶概览]]）。闭环成功率（绕圈 >80%）是真让模型自己开（CARLA 仿真里），模型自己产生状态、暴露偏离后的行为——**第一次闭环测试 = 第一次真正理解"开环高分≠会开车"**。
