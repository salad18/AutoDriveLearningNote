## 〇、大白话总览

### 行为克隆在做什么？

```
人类开小车（手柄控制）→ 录下"看到的画面 + 手上的操作" → 训练神经网络模仿 → 让网络自己开
```

**本质：把"老司机"变成"模型"**——模型学习"看到这个画面 → 打这个方向"。

> [!note] 打个比方
> 行为克隆 = **"跟着老司机学开车"**（模仿学习，[[端到端自动驾驶概览]] 的 Imitation Learning）。学出来的是"模仿能力"不是"驾驶理解"——**它不知道为什么要打方向，只知道"这个画面配这个方向"**。
> 这正是它的天花板：**模仿不到没见过的情况**（分布漂移的根源）。

### 和量产车的关系

```
量产端到端 (UniAD):  感知+预测+规划 一张网（复杂）
小车行为克隆 (DAVE-2): 图像 → 方向盘（极简）
```

**DAVE-2 是 2016 年 NVIDIA 的端到端鼻祖**——你的小车做的就是这个最简版。**规模小 1000 倍，原理完全一样**：都是"传感器 → 神经网络 → 控制"，都会遇到开环高分、闭环翻车。

## 一、什么是行为克隆

**行为克隆 (Behavior Cloning)** 是最简单的端到端自动驾驶：

```
人类驾驶数据: (图像, 方向盘角度, 油门)
         ↓ 监督学习
神经网络: 图像 → (方向盘角度, 油门)
         ↓ 部署
小车: 看路 → 自己开
```

```
┌──────────────────────────────────────────┐
│              训练阶段                      │
│  摄像头帧 → CNN → 预测 steering, throttle │
│               ↓  Loss(MSE)               │
│          人类操作(steering, throttle)      │
├──────────────────────────────────────────┤
│              部署阶段                      │
│  摄像头帧 → CNN → steering, throttle      │
│               ↓  串口                      │
│            Arduino → 舵机+电机             │
└──────────────────────────────────────────┘
```

> 💡 这对应你笔记 [[端到端自动驾驶概览]] 的核心思想，但模型规模缩小了 1000 倍。

> [!note] 为什么用 MSE 损失？（和知识库的对应）
> 训练就是让"预测的 steering"尽量接近"人类操作的 steering"（MSE 回归）——这和 [[模型基础知识补充]] 的回归损失一模一样。**注意这是"回归"不是"分类"**：方向盘角度是连续值，用 L1/L2 类损失。

## 二、数据采集——"端到端成败的 80%"

### 硬件准备

```
┌──────────────────────────────┐
│  手柄/手机                    │
│       ↓ 蓝牙                  │
│  Arduino ← 接收遥控指令        │
│       ↓ 同时                   │
│  1. 执行指令（控制舵机/电机）   │
│  2. 通过串口回传 steering/throttle │
│                              │
│  Raspberry Pi / Jetson        │
│       ↓                      │
│  1. 摄像头录制视频             │
│  2. 串口读取 Arduino 回传的标签 │
│  3. 保存 (frame, steering, throttle) │
└──────────────────────────────┘
```

> [!note] 为什么 Arduino 要"同时回传"控制量？
> 数据 = "画面 + 当时的操作"。**操作必须和画面时间对齐**（否则模型学"错位"的对应关系）。Arduino 执行指令的同时通过串口回传 steering/throttle，主机按帧率采样保存——**时间同步是数据质量的生命线**（[[多传感器融合基础]] 的"时间同步"在小车上同样重要）。

### 数据采集脚本（Pi 端）

```python
import cv2
import serial
import csv
import time
from datetime import datetime

# 配置
SERIAL_PORT = '/dev/ttyUSB0'
BAUD_RATE = 115200
OUTPUT_DIR = './training_data/'
FRAME_INTERVAL = 0.05  # 20Hz 采集

ser = serial.Serial(SERIAL_PORT, BAUD_RATE, timeout=0.1)
cap = cv2.VideoCapture(0)
cap.set(cv2.CAP_PROP_FRAME_WIDTH, 320)
cap.set(cv2.CAP_PROP_FRAME_HEIGHT, 240)

timestamp = datetime.now().strftime('%Y%m%d_%H%M%S')
csv_file = open(f'{OUTPUT_DIR}labels_{timestamp}.csv', 'w', newline='')
writer = csv.writer(csv_file)
writer.writerow(['filename', 'steering', 'throttle'])

frame_idx = 0
last_steering, last_throttle = 90, 0

print("开始采集! Ctrl+C 停止...")
try:
    while True:
        # 读串口（Arduino 回传的当前控制量）
        if ser.in_waiting:
            line = ser.readline().decode().strip()
            if line.startswith('S'):
                parts = line.split('T')
                last_steering = int(parts[0][1:])
                last_throttle = int(parts[1]) if len(parts) > 1 else 0
        
        # 读摄像头
        ret, frame = cap.read()
        if not ret: continue
        
        # 保存帧和标签
        filename = f'frame_{timestamp}_{frame_idx:06d}.jpg'
        cv2.imwrite(OUTPUT_DIR + filename, frame)
        writer.writerow([filename, last_steering, last_throttle])
        
        frame_idx += 1
        time.sleep(FRAME_INTERVAL)

except KeyboardInterrupt:
    print(f"\n采集完成! 共 {frame_idx} 帧")
finally:
    cap.release()
    csv_file.close()
    ser.close()
```

### 采集技巧（每一条都是"血的教训"）

| 技巧 | 说明 |
|------|------|
| **多跑几圈** | 至少 10 圈，数据量 > 5000 帧 |
| **多样化路线** | 直道 + 弯道 + S 弯都跑 |
| **人为制造错误** | 故意偏离中心线然后再修正——让模型学会"怎么回正" |
| **数据平衡** | 直行数据远多于转弯 → 模型学不会转弯。可以欠采样直行帧 |
| **记录环境** | 同一光照、同一赛道，换了环境要重新采集 |
| **镜像增强** | 水平翻转图像 + 反转 steering → 数据翻倍 |

> [!warning] 逐条解释"为什么"（面试/实战都考）
> - **人为制造错误**：如果数据全是"正确驾驶"，模型只见过"正常画面"；一旦自己开偏一点，看到"偏的画面"就懵了（**distribution shift 的直接对策**）——故意录"偏离→回正"的过程，让模型见过"怎么从错误中恢复"。
> - **数据平衡**：直行占 90%，模型学到的平均输出 ≈ 直行 → 弯道"懒得转"。欠采样直行让转弯占比上来。
> - **记录环境**：光照/场地变了 = 数据分布变了 = 模型失效（**domain gap**，[[领域迁移与数据闭环]] 的缩小版）。
> - **镜像增强**：零成本翻倍数据，还能天然平衡左转/右转。

## 三、模型设计——三个递进方案

### 方案 A：NVIDIA DAVE-2（推荐入门）

```python
import torch
import torch.nn as nn

class Dave2(nn.Module):
    """
    NVIDIA DAVE-2 架构 (2016)
    输入: 3×66×200 (归一化后的图像)
    输出: steering angle
    """
    def __init__(self):
        super().__init__()
        self.conv = nn.Sequential(
            # 5 层卷积
            nn.Conv2d(3, 24, 5, stride=2), nn.ReLU(),
            nn.Conv2d(24, 36, 5, stride=2), nn.ReLU(),
            nn.Conv2d(36, 48, 5, stride=2), nn.ReLU(),
            nn.Conv2d(48, 64, 3), nn.ReLU(),
            nn.Conv2d(64, 64, 3), nn.ReLU(),
        )
        self.fc = nn.Sequential(
            nn.Flatten(),
            nn.Linear(64 * 1 * 18, 100), nn.ReLU(),
            nn.Linear(100, 50), nn.ReLU(),
            nn.Linear(50, 10), nn.ReLU(),
            nn.Linear(10, 1),  # steering only
        )
    
    def forward(self, x):
        x = self.conv(x)
        return self.fc(x)
```

> [!note] DAVE-2 的架构设计意图
> 5 层卷积（提取图像特征）+ 4 层全连接（特征→方向盘）——[[计算机视觉基础]] 的"卷积提特征、FC 做决策"标准结构。**注意输入是 66×200 的小图**（不是原始 320×240）：裁剪出路面区域 + 缩小，省算力还聚焦有效信息。**"只给模型看它该看的"是端到端实战的常用技巧。**

### 方案 B：ResNet-18 + LSTM（推荐进阶）

加入时序信息，让模型"记住"之前看到的路：

```python
class TemporalE2E(nn.Module):
    """
    输入: 连续 N 帧图像 → ResNet 特征提取 → LSTM 时序建模 → 输出
    对应知识库: [[BEVFormer详解]] 的时序建模思想
    """
    def __init__(self, hidden_size=256, num_frames=5):
        super().__init__()
        # 用预训练 ResNet-18 做 backbone
        backbone = torchvision.models.resnet18(pretrained=True)
        self.backbone = nn.Sequential(*list(backbone.children())[:-1])  # 去掉 FC
        self.fc_feature = nn.Linear(512, hidden_size)
        
        self.lstm = nn.LSTM(hidden_size, hidden_size, 
                            num_layers=2, batch_first=True)
        self.head = nn.Linear(hidden_size, 2)  # steering, throttle
    
    def forward(self, x):
        # x: (B, N, 3, H, W)
        B, N, C, H, W = x.shape
        x = x.view(B*N, C, H, W)  # 合并 batch 和时序维度
        features = self.backbone(x).squeeze()  # (B*N, 512)
        features = self.fc_feature(features)    # (B*N, hidden)
        features = features.view(B, N, -1)      # (B, N, hidden)
        
        lstm_out, _ = self.lstm(features)
        output = self.head(lstm_out[:, -1, :])  # 取最后一帧的输出
        return output
```

> [!note] 为什么要加时序（LSTM）？
> 单帧图像**看不到运动**——弯道前 0.5 秒和弯道中画面几乎一样，但操作完全不同。连续 5 帧 = 让模型"看到车在往哪偏"（运动信息）→ 提前打方向（**时序让"预测"成为可能**——和 [[BEVFormer详解]] 的 Temporal Attention 同一个思想，只是从 Attention 换成 LSTM）。
> **效果**：直道摇摆（输出震荡）问题显著缓解——模型不再"一帧一决策"，而是"结合历史平滑决策"。

### 方案 C：简化 BEV + Transformer（挑战）

```python
class MiniBEV_E2E(nn.Module):
    """
    核心思路：
    1. 透视变换 → 伪 BEV 特征（手工 or 可学习）
    2. 轻量 Transformer 做 BEV 特征编码
    3. 回归 head → steering, throttle
    
    对应知识库: [[BEVFormer详解]] + [[UniAD详解]]
    但规模缩小 ~500 倍
    """
    def __init__(self, bev_size=(40, 40)):
        super().__init__()
        # CNN backbone
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 32, 3, padding=1), nn.BatchNorm2d(32), nn.ReLU(),
            nn.Conv2d(32, 64, 3, stride=2, padding=1), nn.BatchNorm2d(64), nn.ReLU(),
            nn.Conv2d(64, 128, 3, stride=2, padding=1), nn.BatchNorm2d(128), nn.ReLU(),
        )
        # 透视变换 (可学习的 IPM)
        self.ipm = nn.Sequential(
            nn.Conv2d(128, 64, 1),
            nn.AdaptiveAvgPool2d(bev_size),
        )
        # BEV Transformer encoder（轻量版）
        self.bev_encoder = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model=64, nhead=4, dim_feedforward=128),
            num_layers=2
        )
        # 回归 head
        self.head = nn.Sequential(
            nn.Flatten(),
            nn.Linear(64 * bev_size[0] * bev_size[1], 128),
            nn.ReLU(),
            nn.Linear(128, 2)  # steering, throttle
        )
    
    def forward(self, x):
        feat = self.backbone(x)
        bev_feat = self.ipm(feat)  # 伪 BEV 特征
        # BEV 特征展平为 sequence → Transformer
        B, C, H, W = bev_feat.shape
        tokens = bev_feat.flatten(2).permute(2, 0, 1)  # (H*W, B, C)
        encoded = self.bev_encoder(tokens)
        encoded = encoded.permute(1, 2, 0).view(B, C, H, W)
        return self.head(encoded)
```

> [!note] 方案 C = 把 [[BEV感知全景]] 搬上小车
> 透视变换（IPM）→ 伪 BEV → Transformer 编码 → 输出控制。**它证明了 BEV 思想可以小规模复现**——虽然和小车的行为克隆比不一定更好（小模型 + 小数据下，简单模型往往更稳），但它是"理解 BEV 范式"的最佳动手练习。**三方案递进逻辑：简单 CNN（会跑）→ 加时序（更稳）→ 加 BEV（理解范式）。**

## 四、训练

```python
import torch
from torch.utils.data import Dataset, DataLoader
import cv2
import pandas as pd
import numpy as np
from pathlib import Path

class DrivingDataset(Dataset):
    def __init__(self, csv_path, img_dir, transform=None, balance=True):
        self.df = pd.read_csv(csv_path)
        self.img_dir = Path(img_dir)
        self.transform = transform
        
        if balance:
            self._balance_data()
    
    def _balance_data(self):
        """平衡直行和转弯数据"""
        # 按 steering 值分桶，每个桶采样数不超过 max_per_bin
        bins = np.linspace(50, 130, 9)  # 8 个桶
        indices = np.digitize(self.df['steering'], bins)
        max_per_bin = 500
        keep = []
        for i in range(1, len(bins)):
            bin_idx = np.where(indices == i)[0]
            if len(bin_idx) > max_per_bin:
                bin_idx = np.random.choice(bin_idx, max_per_bin, replace=False)
            keep.extend(bin_idx)
        self.df = self.df.iloc[keep].reset_index(drop=True)
    
    def __len__(self):
        return len(self.df)
    
    def __getitem__(self, idx):
        row = self.df.iloc[idx]
        
        # 读图像
        img = cv2.imread(str(self.img_dir / row['filename']))
        img = cv2.cvtColor(img, cv2.COLOR_BGR2RGB)
        
        # 随机水平翻转（数据增强）
        if np.random.random() > 0.5:
            img = cv2.flip(img, 1)
            steering = 180 - row['steering']  # 翻转 steering
        else:
            steering = row['steering']
        
        # 预处理
        img = cv2.resize(img, (200, 66))
        img = img.astype(np.float32) / 255.0
        img = np.transpose(img, (2, 0, 1))
        
        # 标签归一化: steering 50~130 → ~-1.0~1.0
        steering_norm = (steering - 90) / 40.0
        throttle_norm = row['throttle'] / 255.0
        
        return torch.FloatTensor(img), torch.FloatTensor([steering_norm, throttle_norm])

# 训练循环
def train(model, train_loader, val_loader, epochs=50):
    model = model.cuda()
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-4)
    scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(optimizer, epochs)
    criterion = nn.MSELoss()
    
    best_val_loss = float('inf')
    
    for epoch in range(epochs):
        # 训练
        model.train()
        train_loss = 0
        for imgs, labels in train_loader:
            imgs, labels = imgs.cuda(), labels.cuda()
            optimizer.zero_grad()
            preds = model(imgs)
            loss = criterion(preds, labels)
            loss.backward()
            optimizer.step()
            train_loss += loss.item()
        
        # 验证
        model.eval()
        val_loss = 0
        with torch.no_grad():
            for imgs, labels in val_loader:
                imgs, labels = imgs.cuda(), labels.cuda()
                preds = model(imgs)
                val_loss += criterion(preds, labels).item()
        
        scheduler.step()
        
        if val_loss < best_val_loss:
            best_val_loss = val_loss
            torch.save(model.state_dict(), 'best_model.pth')
        
        print(f"Epoch {epoch+1}: train_loss={train_loss/len(train_loader):.4f}, "
              f"val_loss={val_loss/len(val_loader):.4f}")
```

> [!note] 训练代码里三个"知识库知识点"
> ① **数据平衡**（`_balance_data`）：按 steering 分桶限制每桶数量——直行数据太多就欠采样（对应采集技巧"数据平衡"）；② **镜像增强**（`cv2.flip` + `180 - steering`）：零成本翻倍数据（[[模型基础知识补充]] 的数据增强）；③ **Adam + CosineAnnealing**：[[模型基础知识补充]] 的标准配置。**训练代码本身就是一篇 [[模型基础知识补充]] 的实战演示。**

## 五、闭环测试与迭代——"真正的考试"

### 开环 vs 闭环

| 评估方式 | 怎么做 | 问题 |
|----------|--------|------|
| **开环** | 在录好的数据上算 loss | 高估性能！模型漂移不会反映在 loss 里 |
| **闭环** | 让小车实际跑，看能不能完整跑一圈 | 真正的测试 |

> 💡 你知识库里 [[端到端自动驾驶概览]] 专门讨论了开环 vs 闭环评估——在小车上你能亲身体验这个 gap。

> [!warning] 这是全项目最重要的一课
> **开环 loss 0.03 的小车，闭环可能第一圈就冲出赛道**——因为开环测的是"预测像不像人类"，闭环测的是"真开能不能行"（[[端到端自动驾驶概览]] 的核心概念）。**第一次经历"开环完美、闭环翻车"时，你就真正理解了 distribution shift。**

### 闭环测试流程

```
1. 部署模型到小车
2. 在赛道上跑一圈
3. 记录失败场景（冲出赛道 / 撞障碍）
4. 回看失败场景的帧 → 分析原因
5. 针对性补充数据 → 重新训练
6. 重复 2-5，直到稳定跑完
```

> [!note] 这就是"数据闭环"的缩小版！
> **失败 → 采集 → 训练 → 再测**的循环 = [[数据闭环总览]] 的五步闭环（采集→挖掘→标注→训练→OTA）在小车上的手工版。**你亲手把数据飞轮转起来的那一刻，量产数据闭环的思维就长在你身上了。**

### 常见失败模式与对策

| 失败模式 | 可能原因 | 解决 |
|----------|----------|------|
| 直道左右摇摆 | 模型输出震荡 | 加 LSTM 时序平滑；增大训练数据 |
| 弯道切内线 | 转向不够猛 | 补充大转向角度的训练数据 |
| 弯道冲出去 | 速度太快 | 加"弯道减速"逻辑或数据 |
| 阴影/反光误判 | 训练数据光照单一 | 数据增强：亮度/对比度/噪声 |
| 新环境完全不行 | 过拟合 | 多环境采集；DropOut；更小的模型 |
| 反应太慢 | 推理延迟大 | [[模型部署]] 的 TensorRT FP16 |

> [!note] 读表的方法：**每个失败模式都对应一个"数据或模型"层面的根因**
> - 摇摆 → 时序平滑（模型）+ 数据量（数据）
> - 切内线/冲出去 → 转弯数据不足（数据）
> - 阴影误判 → 光照单一（数据增强）
> - 新环境不行 → 过拟合（模型正则化）
> **80% 的问题出在数据，不是模型**——这是端到端实战的第一课。

## 六、进阶：从行为克隆到端到端规划

行为克隆只是"模仿"，真正的端到端自动驾驶要做预测和规划：

```
L1: 行为克隆 (Behavior Cloning)
    图像 → steering, throttle
    问题: 因果混淆、分布漂移

L2: 带辅助任务 (Auxiliary Tasks)
    图像 → 检测 + 分割 + steering
    问题: 辅助任务占算力

L3: 预测+规划 (Prediction + Planning)
    传感器 → BEV → Occupancy → 轨迹预测 → 规划
    对应: [[UniAD详解]] 的 Track→Map→Motion→Occ→Plan

L4: 世界模型 (World Model)
    预测未来帧 → 基于想象的规划
    对应: [[世界模型]], GAIA-1, DriveDreamer
```

> 小车能做到 L2 就已经很优秀了。L3-L4 是知识库里的量产车目标。

---

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **只录"完美驾驶"数据**——模型没见过"偏离状态"，一偏就不知道怎么回正（必须录"偏离→回正"）。
> 2. **数据不平衡**——直行 90%、转弯 10%，模型学成"只会直行"（欠采样直行）。
> 3. **用开环 loss 判断"学会了"**——开环 0.03 可能闭环翻车（必须闭环测试）。
> 4. **换了环境/光照不重新采集**——domain gap，模型直接失效。
> 5. **一上来就上 ResNet+LSTM/Transformer**——小数据下简单模型（DAVE-2）往往更稳，先跑通再升级。
> 6. **忽视时间同步**——画面和控制量不对齐，模型学到"错位对应"（Arduino 必须回传实时控制量）。

## ✅ 检验自己（自测题）

> [!question] Q1：为什么采集数据时要"人为制造错误"（故意偏离再回正）？
> 提示：distribution shift 的对策。

> [!success]- 参考答案
> 如果数据全是"正确驾驶"，模型只见过"正常画面"；闭环时一旦自己开偏一点（小错误），看到的"偏离画面"是训练时没见过的 → 模型不知道怎么回正 → 越偏越远（distribution shift 恶性循环）。故意录"偏离→回正"过程，让模型见过"如何从错误中恢复"——这是对抗 distribution shift 最直接的数据手段。

> [!question] Q2：直行数据远多于转弯数据会怎样？怎么解决？
> 提示：数据平衡。

> [!success]- 参考答案
> 模型在训练中 90% 的样本是"直行"（steering≈90），MSE 损失被直行主导，模型学成"几乎总是直行"——弯道来了"懒得转"，直接冲出赛道。解决：① 采集时多跑弯道；② 训练时按 steering 分桶欠采样直行帧（每桶限制数量）；③ 镜像增强（左转↔右转）天然平衡转向分布。

> [!question] Q3：开环测试和闭环测试的本质区别是什么？为什么开环会"骗人"？
> 提示：预测 vs 真开。

> [!success]- 参考答案
> 开环：在录好的数据上算 loss（喂人类轨迹，模型只需"预测得像人类"）——不暴露 distribution shift，指标虚高。闭环：让小车真开（模型自己产生状态，偏离后进入没见过的状态）——真正的驾驶能力测试。开环"骗人"因为训练数据都是"正确轨迹"，模型在"正确轨迹"上预测当然准；一旦自己掌控，小错误累积进未知状态，就崩了。

> [!question] Q4：小车"直道左右摇摆"有哪些可能的解决方向？
> 提示：模型/数据两个层面。

> [!success]- 参考答案
> ① 模型层面：加时序建模（LSTM）让输出平滑（不每帧跳变）、增大训练数据、加 DropOut 正则化；② 数据层面：补充更多直道数据、检查数据是否噪声大（时间不同步会导致标签抖动）。先排查数据（时间同步/噪声），再改模型——80% 的问题在数据。

> [!question] Q5：小车"换了个场地就不行"是什么问题？怎么解决？
> 提示：domain gap / 过拟合。

> [!success]- 参考答案
> 是 Domain Gap（域差距）：训练数据的光照/背景/赛道颜色和测试环境不同，模型过拟合到训练环境的"外观特征"（[[领域迁移与数据闭环]] 的缩小版）。解决：① 多环境采集数据（增加多样性）；② 数据增强（亮度/对比度/噪声扰动，削弱对"外观"的依赖）；③ 更小的模型/更强的正则化（减少过拟合）；④ 换环境后补充少量数据微调。

## 🛠 动手练习

### 练习 1：数据质量检查（30 分钟）

采完数据后，写一个小脚本（或直接用 pandas）检查：
1. steering 的分布直方图——是不是大部分集中在 90（直行）？（如果是，需要补转弯数据）
2. 随机抽 20 帧，人工检查"画面和控制量是否对齐"（画面里在转弯，标签是不是大角度？）
3. 统计每帧的标签是否"跳变"（相邻帧 steering 突变 = 时间同步问题）

> [!tip] 数据检查 = 训练的"质检"
> 花 30 分钟检查数据，能省 3 小时训练瞎折腾。**"垃圾进，垃圾出"——端到端的第一课就是数据质量。**

### 练习 2：跑通 DAVE-2 训练（60-90 分钟）

用 Udacity 公开数据集（[github.com/udacity/self-driving-car](https://github.com/udacity/self-driving-car)，~3GB 含方向盘标注）或你自己采的数据：
1. 用第四节代码训练 DAVE-2（CPU 即可，2-4 小时）。
2. 画出 train/val loss 曲线，观察是否过拟合。
3. 开环评估：在验证集上算 MSE。

> [!tip] 完成标准
> 开环 MSE < 0.05 且 val loss 不再下降。**注意：这只是一个"里程碑"，真正的考试在闭环（练习 3）。**

### 练习 3：闭环测试 + 迭代（核心，1-2 天）

把训练好的模型部署到小车（参考 [[模型部署]]）：
1. 在赛道上跑一圈，记录失败点（视频/截图）。
2. 用"失败模式表"分析原因（切内线？冲出去？摇摆？）。
3. 针对性补数据 → 重训 → 再测，至少迭代 3 轮。
4. 写一篇"踩坑记录"进 [[2026-08-20]]：每一轮的失败模式、根因、解决。

> [!tip] 这是全项目的"毕业考试"
> **"开环完美、闭环翻车"的体验，价值超过读十篇论文。** 三轮迭代后你的小车能稳定跑圈，恭喜——你亲手做完了 [[数据闭环总览]] 的完整闭环！

### 练习 4：进阶对比实验（可选）

依次跑三个方案（DAVE-2 → ResNet+LSTM → MiniBEV），对比闭环表现：
1. 哪个在"直道摇摆"上表现最好？（预期：LSTM）
2. MiniBEV 在小数据下真的更好吗？（不一定——记录你的发现）
3. 写 3 句话总结"模型复杂度 × 数据量"的关系。

> [!tip] 参考 [[模型基础知识补充]] 的"预训练/正则化"知识
> 小数据下简单模型更稳（少过拟合）；数据多了复杂模型才能发挥。你的实验数据会验证这个规律。
