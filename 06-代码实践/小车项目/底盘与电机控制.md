## 〇、大白话总览

### 控制链路的"最后一米"

```
上层（视觉/规划）:  "向左打 30 度，油门 40%"
        ↓ 串口
Arduino:           把指令变成"电信号"
        ↓ PWM
电机/舵机:         轮子转起来、转向转过去
```

> [!note] 打个比方
> 上层算法是"指挥官"（下命令），Arduino 是"传令兵"（翻译指令），电机是"士兵"（执行）。
> **本篇就是"传令兵和士兵"的培训**——PWM 是"用多大力推"（占空比），PID 是"推偏了自动纠正"（闭环），编码器是"士兵报告实际走了多远"（反馈）。
> **没有执行层，上层再聪明车也不动**——这是 L0/L1 的核心。

### 三个核心概念（先记住）

```
PWM:     用"占空比"控制转速/角度（开环，不校正）
PID:     根据"误差"闭环控制（测量→对比→调整，自动校正）
编码器:  告诉控制器"实际转了多少"（反馈的来源）
```

## 一、硬件接线

### 电机驱动板 L298N

```
         Arduino Uno          L298N
        ┌──────────┐      ┌──────────┐
        │      D5 ─┼──────┤ ENA (左电机 PWM)
        │  D6/D7 ─┼──────┤ IN1/IN2 (左电机方向)
        │      D9 ─┼──────┤ ENB (右电机 PWM)
        │ D10/D11─┼──────┤ IN3/IN4 (右电机方向)
        │          │      │          │
        │      5V ─┼──────┤ +5V (逻辑供电)
        │     GND ─┼──────┤ GND      │
        │          │      │          │
        │          │      │ OUT1/2 ──┤ 左电机
        │          │      │ OUT3/4 ──┤ 右电机
        │          │      │ +12V  ───┤ 电池正极
        └──────────┘      │ GND   ───┤ 电池负极
                          └──────────┘
```

> [!note] 接线的"角色分工"（理解接线图的关键）
> - **ENA/ENB（PWM 脚）**：控速——"推多大力"（占空比）。
> - **IN1-4（方向脚）**：控向——"正转还是反转"（HIGH/LOW 组合）。
> - **OUT1-4（电机脚）**：接电机。
> - **+12V/GND（电源脚）**：接电池（电机大电流不走 Arduino）。
> **"PWM 控速 + IN 控向"是电机控制的最小协议**——L298N 只是"放大器"（Arduino 的 5V 信号 → 电池的 12V 大电流）。

### 舵机（转向）

```
Arduino         舵机 (SG90 / MG996R)
    D3 ───────── 信号线 (橙色/白色)
    5V ───────── 正极 (红色)
   GND ───────── 负极 (棕色/黑色)
```

> ⚠️ 舵机不要从 Arduino 5V 取电——电流不够。用外部 5V 降压模块供电，共地即可。

> [!warning] "共地"是什么？为什么必须？（新手高频翻车点）
> **共地 = 所有设备的 GND 连在一起**（Arduino GND ↔ 舵机 GND ↔ 电池 GND）——**信号是以 GND 为参考的，不共地信号就"没有参照物"**（像两个时钟不同步）。**"外部供电 + 共地"**是舵机/模块供电的铁律：舵机电流大（不能吃 Arduino 5V），但必须和 Arduino 共 GND（信号才能读懂）。

## 二、PWM 基础

### 概念
PWM（Pulse Width Modulation）通过调节占空比来控制电机转速 / 舵机角度。

```
占空比 0%:   ────────────────────────  电机停止
占空比 50%:  ▓▓▓▓▓▓▓▓▓▓────────────────  半速
占空比 100%: ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓  全速
              |←──── 周期(Period) ────→|
```

> [!note] PWM 的直觉：**"开关开得越勤，平均出力越大"**
> 电机不是"直接给 12V"——是**高速开关（每秒几百次）**，占空比 = "开的时间比例"：50% 占空比 = 一半时间通电 = 平均半速。**PWM 用"开关比例"代替"电压大小"**——数字电路（只能开/关）也能控制模拟量（速度/角度）。

### Arduino 代码

```cpp
// === 电机控制 ===
#define ENA 5    // 左电机 PWM
#define IN1 6    // 左电机方向
#define IN2 7
#define ENB 9    // 右电机 PWM
#define IN3 10   // 右电机方向
#define IN4 11

void setup() {
    pinMode(ENA, OUTPUT); pinMode(IN1, OUTPUT); pinMode(IN2, OUTPUT);
    pinMode(ENB, OUTPUT); pinMode(IN3, OUTPUT); pinMode(IN4, OUTPUT);
}

void motorLeft(int speed) {
    // speed: -255 ~ 255 (负 = 反转)
    if (speed >= 0) {
        digitalWrite(IN1, HIGH); digitalWrite(IN2, LOW);
    } else {
        digitalWrite(IN1, LOW); digitalWrite(IN2, HIGH);
        speed = -speed;
    }
    analogWrite(ENA, constrain(speed, 0, 255));
}

void motorRight(int speed) {
    if (speed >= 0) {
        digitalWrite(IN3, HIGH); digitalWrite(IN4, LOW);
    } else {
        digitalWrite(IN3, LOW); digitalWrite(IN4, HIGH);
        speed = -speed;
    }
    analogWrite(ENB, constrain(speed, 0, 255));
}

// === 舵机控制 ===
#include <Servo.h>
Servo steering;
#define SERVO_PIN 3
#define STEER_CENTER 90    // 中位
#define STEER_LEFT_MAX 60  // 左转极限
#define STEER_RIGHT_MAX 120// 右转极限

void setupSteering() {
    steering.attach(SERVO_PIN);
    steering.write(STEER_CENTER);
}

void setSteering(int angle) {
    // angle: STEER_LEFT_MAX ~ STEER_RIGHT_MAX
    steering.write(constrain(angle, STEER_LEFT_MAX, STEER_RIGHT_MAX));
}
```

> [!note] `motorLeft(int speed)` 的封装思想（工程习惯）
> **`-255~255` 一个参数搞定"方向+速度"**（负数反转）——上层只需要说"左轮 -100"，不用管 IN 组合。**"封装 = 让调用方更简单"**——这是写库/写模块的思维（后面 Pi 端调 Arduino 只需发 "S90T120" 一个命令）。

## 三、PID 控制

### 为什么需要 PID？

开环控制（直接设 PWM）的问题：
- 电池电压下降 → 同样 PWM 转速不同
- 路面阻力变化 → 速度不稳定
- 舵机角度 ≠ 实际转向角

PID 闭环控制 = 根据误差动态调整输出。

> [!note] 开环 vs 闭环（面试/理解核心）
> **开环**：设 PWM=100 → 不管实际转速（电池没电了还是 100，但实际慢）。
> **闭环**：设目标 120RPM → 测实际（编码器）→ 慢了加 PWM、快了减 PWM → **"测量-对比-调整"循环**。
> **"闭环 = 有反馈 + 自动校正"**——这是 [[计算机视觉基础]] 卡尔曼滤波"预测-更新"同源的反馈思想，也是所有自动驾驶控制的基础。

### 数学公式

$$u(t) = K_p \cdot e(t) + K_i \int e(t)dt + K_d \frac{de(t)}{dt}$$

| 项 | 作用 | 调大效果 | 调大副作用 |
|----|------|----------|------------|
| **P (比例)** | 对当前误差响应 | 响应快 | 超调、震荡 |
| **I (积分)** | 消除稳态误差 | 精度高 | 响应慢、积分饱和 |
| **D (微分)** | 预测误差趋势 | 减少超调 | 放大噪声 |

> [!warning] 三项的直觉（面试必讲，用"开车"比喻）
> - **P（比例）**：离目标越远，打方向越猛——"按偏差比例出力"（快但有惯性，过头就超调）。
> - **I（积分）**：一直有微小偏差（比如风阻），累计起来"加把劲"——"消除长期的小偏差"（但有积分饱和风险）。
> - **D（微分）**：偏差在快速增大时提前刹车——"看趋势预判"（减少超调，但放大噪声）。
> **"P 快、I 准、D 稳"**——调参就是平衡这三者。

### Arduino PID 实现

```cpp
class PID {
private:
    float kp, ki, kd;
    float setpoint;
    float integral, prevError;
    float outMin, outMax;
    unsigned long prevTime;

public:
    PID(float p, float i, float d, float min, float max)
        : kp(p), ki(i), kd(d), outMin(min), outMax(max),
          setpoint(0), integral(0), prevError(0), prevTime(0) {}

    void setSetpoint(float sp) { setpoint = sp; }

    float compute(float input) {
        unsigned long now = micros();
        float dt = (now - prevTime) / 1e6f;
        if (dt <= 0 || dt > 0.5) { prevTime = now; return 0; }
        prevTime = now;

        float error = setpoint - input;

        // Proportional
        float pOut = kp * error;

        // Integral (with anti-windup clamping)
        integral += error * dt;
        integral = constrain(integral, outMin / ki, outMax / ki);
        float iOut = ki * integral;

        // Derivative (derivative on measurement to avoid kick)
        float dOut = kd * (error - prevError) / dt;
        prevError = error;

        float output = pOut + iOut + dOut;
        return constrain(output, outMin, outMax);
    }

    void reset() { integral = 0; prevError = 0; }
};
```

> [!note] 代码里三个"防坑"设计（面试谈资）
> ① **anti-windup（积分限幅）**：`constrain(integral, outMin/ki, outMax/ki)`——防积分饱和（一直有偏差时积分无限涨，输出卡死在极限）；② **derivative on measurement**（微分作用在误差变化上而非设定值）——防 setpoint 突变时 D 项"kick"；③ **dt 保护**（`dt>0.5` 跳过）——防长时间未调用时 dt 爆炸。**"工程代码 = 防坑代码"**（PID 算法 3 行，防坑 30 行）。

### PID 调参口诀

```
参数    上升时间    超调      稳定时间    稳态误差
────────────────────────────────────────────────
↑Kp      减小       增大      影响小      减小
↑Ki      减小       增大      增大        消除
↑Kd      影响小     减小      减小        无影响
```

**实操步骤**（Ziegler-Nichols 简化版）：

1. **Ki=0, Kd=0**，逐渐增大 Kp 直到系统开始持续震荡
2. 记下此时的 Kp 值（临界增益 $K_u$）和震荡周期 $T_u$
3. 按经验公式：`Kp=0.6*Ku, Ki=1.2*Ku/Tu, Kd=0.075*Ku*Tu`
4. 手工微调：先调 P 让响应够快，再调 D 压住超调，最后加一点 I 消除静差

> [!warning] 调参的"教科书陷阱"（新手最常犯）
> **一次只动一个参数**（调参第一纪律）。Ziegler-Nichols 是"起点"不是"终点"——按公式算出初始值后**手工微调**（P 快→D 稳→I 准的顺序）。**"调参 = 观察响应 + 单参数微调"**——不要"三个一起乱调"（那是玄学不是工程）。

### 速度 PID（控制电机）

```cpp
// 需要编码器读取实际速度
PID speedPID(2.0, 0.5, 0.1, -255, 255);

void loop() {
    float targetRPM = 120;  // 目标转速
    float actualRPM = readEncoderRPM();  // 编码器测速
    speedPID.setSetpoint(targetRPM);
    int pwm = speedPID.compute(actualRPM);
    motorLeft(pwm);
}
```

### 转向 PID（控制舵机）

```cpp
// 循迹场景：根据红外传感器偏移量调整舵机
PID steerPID(0.8, 0.0, 0.3, STEER_LEFT_MAX, STEER_RIGHT_MAX);

void loop() {
    int position = readIRArray();  // 返回 0~5000 (中线偏离量)
    steerPID.setSetpoint(2500);    // 目标：正中间 (5路红外 = 2500)
    int angle = steerPID.compute(position);
    setSteering(angle);
}
```

> [!note] 两个 PID 的"控制对象"不同（理解）
> **速度 PID**：设定 120RPM → 编码器反馈 → 调 PWM（**控制"多快"**）。
> **转向 PID**：设定 2500（中线）→ 红外反馈 → 调舵机角（**控制"往哪"**）。
> **"同一个 PID 算法，套不同的传感器和执行器"**——PID 是通用的"校正器"（[[传感器集成]] 的循迹/避障都会用到）。

## 四、串口通信协议（上位机 ↔ Arduino）

当 Pi/Jetson 做上层感知，Arduino 做底层控制时，需要设计通信协议。

### 简单文本协议

```
Pi → Arduino:  "S90T120\n"     # Steering=90, Throttle=120
Arduino → Pi:  "E2500V1.2\n"   # Encoder=2500, Voltage=1.2V
```

### Arduino 端解析

```cpp
String inputBuffer = "";

void loop() {
    // 接收串口指令
    while (Serial.available()) {
        char c = Serial.read();
        if (c == '\n') {
            parseCommand(inputBuffer);
            inputBuffer = "";
        } else {
            inputBuffer += c;
        }
    }
}

void parseCommand(String cmd) {
    if (cmd.startsWith("S")) {  // Steering
        int angle = cmd.substring(1).toInt();
        setSteering(angle);
    }
    else if (cmd.startsWith("T")) {  // Throttle
        int speed = cmd.substring(1).toInt();
        motorLeft(speed);
        motorRight(speed);
    }
    else if (cmd == "STOP") {
        motorLeft(0); motorRight(0);
    }
}

// 定时回传传感器数据
unsigned long lastReport = 0;
void reportSensors() {
    if (millis() - lastReport > 50) {  // 20Hz
        lastReport = millis();
        Serial.print("E"); Serial.print(readEncoder());
        Serial.print("V"); Serial.println(readBattery());
    }
}
```

> [!warning] 协议的三个设计要点（工程思维）
> ① **`\n` 做帧结束符**（"S90T120\n"一行一条命令）——上层按行解析，简单可靠；② **命令带前缀**（S=Steering、T=Throttle）——一个协议传多种数据；③ **Arduino 定时回传**（20Hz 报编码器/电压）——上层能"看到"底层状态（里程计/电池监控）。**"协议设计"= 帧格式 + 命令集 + 反馈机制**——这是 [[ROS2入门]] 通信架构的"手工版"。

## 五、Encoder 编码器测速

### 原理

霍尔编码器输出两路方波（A/B 相），通过相位差判断方向。

```
A: ▓▓▓▓____▓▓▓▓____▓▓▓▓    (11 脉冲/圈, 减速比 1:30 → 330 脉冲/圈)
B: ____▓▓▓▓____▓▓▓▓____    (A 超前 = 正转, B 超前 = 反转)
```

### 读取方式

```cpp
// 使用中断，不丢脉冲
volatile long encoderLeft = 0;

void encoderISR_Left() { encoderLeft++; }  // 简化版，只计数不判向

void setup() {
    attachInterrupt(digitalPinToInterrupt(2), encoderISR_Left, RISING);
}

float readEncoderRPM() {
    static long prevCount = 0;
    static unsigned long prevTime = 0;
    unsigned long now = micros();
    float dt = (now - prevTime) / 1e6f;

    long delta = encoderLeft - prevCount;
    prevCount = encoderLeft;
    prevTime = now;

    // 330 脉冲/圈 → RPM = (脉冲差/dt/330) * 60
    return (delta / 330.0f / dt) * 60.0f;
}
```

> [!note] 编码器的三个要点（理解+面试）
> ① **A/B 两相 = 能判方向**（谁超前谁反）——完整实现用两路中断+相位判断；② **用中断不用轮询**——中断不丢脉冲（轮询会漏）；③ **RPM 计算**：脉冲差 ÷ 每圈脉冲（330）÷ 时间 × 60。**编码器 = PID 的"眼睛"**（没它 PID 不知道实际转速）——[[硬件选型指南]] 说"编码器 L3 才需要"，因为 SLAM 里程计（[[SLAM与定位]]）和速度 PID 都要它。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **不共地**——外部供电的舵机/模块不和 Arduino 共 GND → 信号乱（"共地"是接线第一课）。
> 2. **舵机吃 Arduino 5V**——电流不够，舵机抽搐/重启 Arduino；外部 5V 降压 + 共地。
> 3. **开环当闭环用**——电池一没电速度就飘；要稳必须 PID + 编码器反馈（闭环）。
> 4. **三个 PID 参数一起乱调**——一次只动一个；先 P（快）→ D（稳）→ I（准）。
> 5. **轮询读编码器**——丢脉冲，速度不准；用中断（attachInterrupt）。
> 6. **电机正负极接反**——小车"倒退"；对调 OUT 接线即可（或代码反转方向）。

## ✅ 检验自己（自测题）

> [!question] Q1：L298N 的 ENA/IN1/IN2 各管什么？"PWM 控速 + IN 控向"是什么意思？
> 提示：大力/方向。

> [!success]- 参考答案
> ENA 是 PWM 脚（控速：占空比决定"推多大力"），IN1/IN2 是方向脚（HIGH/LOW 组合决定"正转/反转"）。"PWM 控速 + IN 控向" = 电机控制的最小协议：占空比管力度、IN 组合管方向。L298N 本质是"放大器"（Arduino 5V 信号 → 电池 12V 大电流驱动电机）。

> [!question] Q2："共地"是什么？为什么外部供电的舵机必须和 Arduino 共地？
> 提示：信号参考。

> [!success]- 参考答案
> 共地 = 所有设备的 GND 连在一起。信号以 GND 为参考——不共地，Arduino 发的信号和舵机"没有共同的零点"，信号无法解读（像两个时钟不同步）。外部供电 + 共地是模块供电铁律：舵机电流大不能吃 Arduino 5V（用外部 5V），但必须共 GND（信号才有参照）。

> [!question] Q3：PID 的 P/I/D 各解决什么问题？调参顺序是什么？
> 提示：快/准/稳。

> [!success]- 参考答案
> P（比例）：对当前误差响应（快，但过大会超调震荡）；I（积分）：消除稳态误差（准，但过大会积分饱和）；D（微分）：预测误差趋势减少超调（稳，但放大噪声）。调参：一次只动一个，Ziegler-Nichols 给起点后手工微调——先 P 让响应够快 → D 压超调 → I 消静差。口诀"P 快、I 准、D 稳"。

> [!question] Q4：开环和闭环控制有什么区别？为什么 PID 必须配编码器？
> 提示：反馈。

> [!success]- 参考答案
> 开环：设 PWM 不管实际转速（电池电压降了转速就飘）。闭环：测实际（编码器）→ 对比目标 → 调整 PWM（"测量-对比-调整"循环）。编码器是 PID 的"眼睛"——PID 要"知道实际值"才能算误差，没编码器反馈就无法闭环（只能开环）。

> [!question] Q5：串口协议设计的三要素是什么？"S90T120\n"怎么解析？
> 提示：帧/命令/反馈。

> [!success]- 参考答案
> 三要素：① 帧格式（`\n` 做结束符，按行解析）；② 命令集（S=Steering、T=Throttle 带前缀，一个协议传多种数据）；③ 反馈机制（Arduino 定时回传编码器/电压，上层能看到底层状态）。解析："S90T120\n" 按 `\n` 收帧，`S` 后取 90 → setSteering(90)，`T` 后取 120 → motor(120)。这是 [[ROS2入门]] 通信架构的手工版。

## 🛠 动手练习

### 练习 1：接线上电验收（30 分钟）

按第一节接线，完成三个验收：
1. 上传 Blink 测试 Arduino 正常。
2. 电机：`motorLeft(100)` 轮子转；`motorLeft(-100)` 反转（对调接线或改代码）。
3. 舵机：`setSteering(90)` 回中、`60`/`120` 左右转。

> [!tip] 验收标准
> "轮子能转、舵机能摆"= 第一节过关。**每个零件单独验证后再组装**（不然全装好不转不知道哪坏了）。接线前断电，接完再上电（防短路烧板）。

### 练习 2：PID 调速闭环（60-90 分钟）

用编码器 + PID 做速度闭环：
1. 开环测试：设 PWM=100 测实际 RPM（电池不同电量 RPM 不同——体会开环问题）。
2. 闭环：`speedPID(2.0, 0.5, 0.1)` 设目标 120RPM，串口打印实际值。
3. 用 Ziegler-Nichols 法重调：先 Ki=Kd=0 增大 Kp 到震荡，记录 Ku/Tu，套公式。
4. 画"实际 RPM vs 时间"曲线，验证闭环更稳。

> [!tip] 这是"控制工程师"的入门仪式
> 亲手调出"速度稳定"的闭环，你就理解了所有自动驾驶控制的基础（PID 是 MPC 的"简化祖先"）。调参记录（Kp/Ki/Kd + 效果）存进 [[2026-08-20]]。

### 练习 3：写串口协议对接 Pi（可选，60 分钟）

按第四节协议，写 Pi 端 Python 发送代码：
1. `ser.write(b"S90T120\n")` 控制小车。
2. 读取 Arduino 回传的 `E...V...` 解析出编码器/电压。
3. 写一个"油门斜坡"程序（Throttle 从 0 缓慢加到 200，观察速度渐变）。

> [!tip] 这是 [[端到端小车实战]] 数据采集的硬件基础
> 行为克隆要"图像 + steering/throttle 标签"——标签就是从这套串口协议读的（[[端到端小车实战]] 第二节的数据采集脚本）。**先把协议跑通，L4 的数据采集就顺了。**
