## 〇、大白话总览

### 小车要回答的三个问题

```
① 我在哪？      → 定位（Localization）
② 周围有什么？  → 感知（Perception）
③ 我该怎么走？  → 规划（Planning）
```

### SLAM 的"鸡生蛋"问题（核心概念）

```
要定位需要地图 → 但地图需要定位才能建 → 鸡生蛋？
SLAM 的答案: 同时做（边建图边定位，互相纠正）→ 解开了
```

> [!note] 打个比方
> 一个人在陌生商场里：**边走边看路牌（定位）边记路（建图）**——"我走到这了（定位），这有个路口（建图），下一个路口应该在那（用图定位）"。**SLAM = "边走路边画地图边用地图"**——定位和建图互相促进，一起变准。

### 三个层次的定位精度

```
L0-L2: 不需要定位（循迹靠线，车道保持靠视觉）
L3:    里程计+IMU 融合（知道大致位置，不建图）
L3+:   LiDAR SLAM（建图 + 定位，能自主导航）
```

## 一、问题定义

小车需要回答三个问题：

| 问题 | 英文 | 依赖 |
|------|------|------|
| 我在哪？ | Localization | 里程计 + IMU + 视觉/LiDAR |
| 周围有什么？ | Perception | 摄像头 / 超声波 / LiDAR |
| 我该怎么走？ | Planning | 定位 + 地图 + 感知 |

SLAM 解决了"建图"和"定位"的鸡生蛋问题：
- 要定位需要地图，但地图需要定位才能建
- SLAM 同时做两者：边建图边定位

> [!note] 为什么 L0-L2 不需要 SLAM？（定位的价值边界）
> **循迹**：跟着黑线走（线就是"地图"，不需要知道全局位置）；**车道保持**：跟着视觉车道走（相对位置够用）。**L3 起要"自主导航"（A 到 B）才需要全局定位**（"我在哪"是导航的前提）——**"定位需求跟着任务走"**（和 [[硬件选型指南]] 的"算力跟着任务走"同一原则）。

## 二、里程计 (Odometry)

### 编码器里程计（最基础）

从左右轮编码器推算位姿：

$$\begin{aligned}
\Delta s &= \frac{\Delta s_L + \Delta s_R}{2} \\
\Delta \theta &= \frac{\Delta s_R - \Delta s_L}{W} \\
x_{t+1} &= x_t + \Delta s \cdot \cos(\theta_t + \frac{\Delta \theta}{2}) \\
y_{t+1} &= y_t + \Delta s \cdot \sin(\theta_t + \frac{\Delta \theta}{2}) \\
\theta_{t+1} &= \theta_t + \Delta \theta
\end{aligned}$$

其中 $W$ 是左右轮间距（轮距），$\Delta s_L, \Delta s_R$ 是左右轮位移。

```python
import math

class DifferentialDriveOdom:
    def __init__(self, wheel_base_mm):
        self.wheel_base = wheel_base_mm / 1000.0  # 米
        self.x, self.y, self.theta = 0.0, 0.0, 0.0
    
    def update(self, delta_left_m, delta_right_m):
        """输入左右轮位移（米），更新位姿"""
        ds = (delta_left_m + delta_right_m) / 2.0
        dtheta = (delta_right_m - delta_left_m) / self.wheel_base
        
        self.x += ds * math.cos(self.theta + dtheta / 2)
        self.y += ds * math.sin(self.theta + dtheta / 2)
        self.theta += dtheta
        self.theta = math.atan2(math.sin(self.theta), math.cos(self.theta))  # 归一化
```

> [!note] 差速模型的直觉（公式背后）
> **前进量 = 左右轮平均**（两个轮子一起走多少）；**转角 = 左右轮差 ÷ 轮距**（一个快一个慢 → 转弯，差越大转得越狠）。**"左右轮差速 → 转弯"是差速小车的运动学本质**——[[底盘与电机控制]] 的电机控制就是"调左右轮速差"。

### 编码器误差累积

编码器里程计的致命问题：误差无限累积。

| 误差来源 | 影响 |
|----------|------|
| 轮径不准 | 距离 scale 误差 |
| 轮距不准 | 转角 scale 误差 |
| 轮胎打滑 | 位移偏小 |
| 路面不平 | 随机误差 |
| 编码器分辨率 | 量化噪声 |

> 纯编码器跑 10 米，误差可达 30cm-1m。必须融合 IMU / 视觉 / LiDAR 校正。

> [!warning] 为什么"误差累积"是致命的？（面试核心）
> **编码器测的是"轮子转了多少"不是"车实际走了多少"**——轮子打滑、轮径不准、路面不平都会让"测量位移 ≠ 实际位移"，而且**每次误差叠加进下一次（累积）**。跑 1 米误差 3cm 看着小，跑 100 米就是 3 米——**"开环积分必漂移"**（和 [[传感器集成]] 里程计局限一致）。**解法：外部观测（IMU/视觉/LiDAR）定期校正 = EKF 融合**。

## 三、IMU + 编码器融合（EKF）

### 扩展卡尔曼滤波 (EKF)

EKF 是机器人定位最常用的传感器融合算法：

```
预测步骤（高频，靠 IMU + 编码器）：
  x̂(k|k-1) = f(x̂(k-1), u(k))     # 运动模型预测新位姿
  P(k|k-1) = F·P(k-1)·F^T + Q    # 协方差传播

更新步骤（低频，靠外部观测）：
  K = P·H^T·(H·P·H^T + R)^(-1)  # 卡尔曼增益
  x̂(k) = x̂(k|k-1) + K·(z - h(x̂)) # 状态更新
  P(k) = (I - K·H)·P(k|k-1)      # 协方差更新
```

> [!note] EKF 的直觉（"预测 + 修正"循环，[[计算机视觉基础]] 卡尔曼的机器人版）
> **高频预测**：靠运动模型（编码器+IMU）推算下一步（"按我的估计，应该到这"）——快但不准（会漂移）。
> **低频修正**：靠外部观测（磁力计航向/视觉特征/GPS）校正（"实际观测告诉我偏了"）——准但慢。
> **卡尔曼增益 K = 预测和观测的"信任度加权"**：谁的协方差小（更可信）就多信谁。**"又快又准 = 高频预测 + 低频修正"**——这就是 EKF 融合的本质。

### 推荐库：用 `robot_localization`（ROS2 包）

手写 EKF 容易出错，ROS2 的 `robot_localization` 是开箱即用的方案：

```yaml
# ekf.yaml — robot_localization 配置
ekf_filter_node:
  ros__parameters:
    frequency: 30.0
    sensor_timeout: 0.1
    two_d_mode: true          # 2D 平面小车
    
    # 输入话题
    odom0: /encoder/odom      # 编码器里程计
    imu0: /imu/data           # IMU
    odom0_config: [true, true, false, false, false, true, ...]  # 哪些轴用编码器
    imu0_config: [false, false, false, true, true, true, ...]   # IMU 提供哪些观测
```

```bash
# 安装
sudo apt install ros-humble-robot-localization

# 启动
ros2 launch robot_localization ekf.launch.py
```

> [!warning] "手写 EKF vs 用现成库"（工程判断）
> **EKF 实现容易出错**（雅可比、协方差传播的细节），**量产/工程用现成库**（ROS2 的 robot_localization 开箱即用，配置 yaml 就行）——**"先跑通现成方案，再手写理解原理"**是工程正道（[[笔记写作规范]] 的"先直觉后公式"同样适用于工具选型）。**但面试要能手推/能讲原理**（手写代码是理解，用库是工程）。

## 四、SLAM 方案选型

### 2D LiDAR SLAM（最稳，推荐）

| 方案 | 特点 | 适用场景 |
|------|------|----------|
| **slam_toolbox** | ROS2 原生，在线+离线 | L3+ 室内/结构化环境 |
| **Cartographer** | Google 的，闭环优秀 | 大型室内环境 |
| **Hector SLAM** | 不需要里程计 | 仅 LiDAR，但需要高更新率 |

```bash
# slam_toolbox 在线建图
sudo apt install ros-humble-slam-toolbox
ros2 launch slam_toolbox online_async_launch.py

# 保存地图
ros2 run nav2_map_server map_saver_cli -f ~/my_map

# 之后用已有地图定位（AMCL）
ros2 launch nav2_bringup localization_launch.py map:=~/my_map.yaml
```

### 纯视觉 SLAM（只用摄像头）

| 方案 | 特点 |
|------|------|
| **ORB-SLAM3** | 学术标杆，支持单目/双目/RGB-D |
| **OpenVSLAM** | ORB-SLAM 的现代化实现 |
| **VINS-Mono** | 视觉+IMU 紧耦合 |

```bash
# ORB-SLAM3 对小车算力要求高（需要 Jetson 级别）
# 对 L2 小车不推荐纯视觉 SLAM——特征点少（地面纹理弱），漂移严重
```

> [!note] 为什么小车推荐 LiDAR SLAM 而非纯视觉？（选型谈资）
> **LiDAR 直接给 3D 点云（几何信息充足）**，视觉 SLAM 靠特征点（小车场景地面纹理弱、特征少 → 漂移严重）。**"几何传感器比语义传感器更适合定位"**——和 [[多传感器融合基础]] 的"LiDAR 适合几何任务"完全一致。**视觉 SLAM 的用武之地**：算力受限/无 LiDAR/室内纹理丰富场景（ORB-SLAM3 是学术标杆，但小车场景通常不是最优选）。

### 小车 SLAM 推荐路径

| 阶段 | 方案 | 理由 |
|:--:|------|------|
| L1-L2 | 不需要 SLAM | 循迹/车道保持用不到全局定位 |
| L3 | 编码器 + IMU (EKF) | 知道大致位置即可，不建图 |
| L3+ | 加 2D LiDAR → slam_toolbox | 建图后做路径规划 |
| L4 | 2D LiDAR + 回环检测 | 实现"从 A 到 B 自主导航" |

> [!note] 推荐路径的"渐进"逻辑
> **L3 先用 EKF（不建图）→ L3+ 加 LiDAR 建图 → L4 加回环**——**"定位需求从'大致知道'到'精确自主导航'逐步升级"**，每次只加一个能力（符合 [[小车项目总览]] 的"不跳级"原则）。

## 五、回环检测

### 为什么需要回环？

编码器/IMU 误差累积导致轨迹漂移。回环检测（Loop Closure）在识别到"回到了来过的地方"时，强制修正全局位姿。

```
漂移前的地图:          回环修正后:
┌────┐                 ┌────┐
│    │                 │  ┌─┘
│    └──┐              │  │
│       │    →         │  │
│    ┌──┘              │  └─┐
│    │                 │    │
└────┘                 └────┘
```

> [!note] 回环的直觉："回到原点就校准"
> 地图漂移（左图：起点和终点对不上，本该闭合的圈错开了）——**当 SLAM 识别"我又回到了这个位置"（回环）时，用这个约束把整个轨迹"拽"回正确位置**（右图：圈闭合了）。**"回环 = 定位误差的'全局修正'**（EKF 只做局部修正）**——SLAM 能建"闭合地图"的关键。

### 小车的回环方法

| 方法 | 难度 | 效果 |
|------|:--:|------|
| 视觉词袋（ORB-SLAM 内置） | 中 | 需要丰富纹理 |
| LiDAR Scan Context | 中 | 2D/3D 都可 |
| WiFi / BLE 指纹 | 低 | 精度粗但鲁棒 |
| AprilTag 地标 | 低 | 需要贴标签在地面 |
| **手动标记** | 最低 | 按键标记当前位置，再次经过时校正 |

> [!note] 选回环方法的"精度 vs 成本"
> **视觉词袋/LiDAR Scan Context**（自动、精度高但复杂）；**AprilTag/WiFi 指纹**（人工布设但简单）；**手动标记**（零成本但最粗）。**小车 L4 用 LiDAR Scan Context（自动+2D LiDAR 就有）**，教学场景用 AprilTag/手动标记入门——**"回环方法 = 精度需求 × 布设成本"的权衡**。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为里程计"够准"**——纯编码器跑 10 米误差 30cm-1m（打滑/轮径/路面）——**误差累积是致命的，必须融合校正**。
> 2. **L0-L2 就上 SLAM**——循迹/车道保持不需要全局定位；**L3 才需要**（定位需求跟着任务走）。
> 3. **小车用纯视觉 SLAM**——地面纹理弱特征少 → 漂移严重；**LiDAR SLAM 更稳**（几何传感器适合定位）。
> 4. **手写 EKF 当生产方案**——EKF 细节容易错；**工程用现成库（robot_localization）**，手写只用于理解。
> 5. **忽略回环**——没有回环，地图永远"开着口"（起点终点对不上）；**回环 = 全局修正**（EKF 只做局部）。
> 6. **Q/R 乱调**——Q/R 决定"信预测还是信观测"，一次只调一个（[[训练排错实战手册]] 的调参纪律）。

## ✅ 检验自己（自测题）

> [!question] Q1：SLAM 的"鸡生蛋"问题是什么？SLAM 怎么解开？
> 提示：定位↔建图。

> [!success]- 参考答案
> 要定位需要地图，但建图需要定位——互相依赖（鸡生蛋）。SLAM 同时做两者：边建图边定位，互相纠正（"走到这（定位）→ 记下路口（建图）→ 用图找下一个路口（定位）"）。定位和建图互相促进、一起变准——"边走路边画地图边用地图"。

> [!question] Q2：差速里程计模型怎么推算位姿？误差为什么累积？
> 提示：平均/差速。

> [!success]- 参考答案
> 前进量 = 左右轮位移平均（ds=(dsL+dsR)/2）；转角 = 左右轮差 ÷ 轮距（dθ=(dsR-dsL)/W）；位姿 = 累加（x += ds·cosθ 等）。误差累积：编码器测"轮子转了多少"而非"实际位移"——打滑/轮径不准/路面不平造成每次误差，且逐次叠加（开环积分必漂移：10 米误差 30cm-1m）。解法：外部观测（IMU/视觉/LiDAR）EKF 校正。

> [!question] Q3：EKF 的"预测-更新"循环是什么？卡尔曼增益 K 的作用？
> 提示：高频预测+低频修正。

> [!success]- 参考答案
> 预测（高频，运动模型+编码器/IMU）：按估计推算下一步（快但会漂移）；更新（低频，外部观测）：用观测校正（准但慢）。K = 预测与观测的信任度加权——谁的协方差小（更可信）多信谁。本质："高频预测 + 低频修正"= 又快又准；Q/R 比值决定信预测还是信观测。

> [!question] Q4：为什么小车推荐 LiDAR SLAM 而不是纯视觉 SLAM？
> 提示：特征点/几何。

> [!success]- 参考答案
> LiDAR 直接给 3D 点云（几何信息充足）；视觉 SLAM 靠特征点，小车场景地面纹理弱、特征少 → 漂移严重。"几何传感器（LiDAR）比语义传感器（相机）更适合定位"（和 [[多传感器融合基础]] 一致）。视觉 SLAM 的用武之地：算力受限/无 LiDAR/室内纹理丰富场景（ORB-SLAM3 学术标杆，但小车非最优选）。

> [!question] Q5：回环检测是什么？为什么"没有回环地图永远开着口"？
> 提示：全局修正。

> [!success]- 参考答案
> 回环检测 = 识别"回到了来过的地方"，用这个约束把整个轨迹"拽"回正确位置（全局修正）。没有回环：误差累积导致地图起点终点对不上（"圈"开着口）——EKF 只做局部修正（每次校正一点），回环做全局修正（一次校正整条轨迹）。方法选择：LiDAR Scan Context（自动）/AprilTag（布设）/手动标记（零成本），按精度×成本权衡。

## 🛠 动手练习

### 练习 1：差速里程计仿真（30-60 分钟）

用 Python 实现 DifferentialDriveOdom 并仿真：
1. 让小车"直行 2 米"（左右轮同速），打印位姿（应该 x≈2, θ≈0）。
2. 让小车"原地转 90°"（左右轮反向），打印 θ（应该 ≈π/2）。
3. 加入 5% 轮径误差，跑 5 米，看误差多大——**亲手验证"误差累积"**。

> [!tip] 这是"误差累积"的亲身验证
> 仿真里加 5% 轮径误差跑 5 米 → 误差约 25cm——**你会亲眼看到"开环积分必漂移"**。写完存进 [[2026-08-20]]，面试讲"我做过里程计误差分析"直接加分。

### 练习 2：用 robot_localization 做 EKF 融合（60-90 分钟）

在 ROS2 环境（[[ROS2入门]]）里：
1. 发布 `/encoder/odom`（编码器里程计）和 `/imu/data`（IMU）。
2. 配 ekf.yaml（参照第三节），启动 robot_localization。
3. 对比"纯里程计 vs EKF 融合"的位姿输出——哪个更稳？

> [!tip] 这是"EKF 融合"的工程实战
> 用现成库跑通"编码器+IMU 融合"，你就理解 Q/R 怎么影响结果（把 R 调大/调小看差异）。**"先跑通库，再读原理"是工程正道**。

### 练习 3：slam_toolbox 建图 + 回环（可选，1-2 天）

有 2D LiDAR（YDLIDAR X4，[[硬件选型指南]]）的话：
1. 用 slam_toolbox 推着小车绕一圈，在线建图。
2. 保存地图（map_saver_cli），观察地图是否闭合（回环是否生效）。
3. 再跑一圈（AMCL 定位），验证"用已有地图定位"。

> [!tip] 这是 L3+ 的完整实战
> "建图 → 保存 → 定位"跑通，你的小车就有了"自主导航"的地基（[[路径规划与控制]] 的 nav2 就用这张图）。做完写 3 句总结进 [[2026-08-20]]。
