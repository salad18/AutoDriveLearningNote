## 〇、大白话总览

### 小车的"感官系统"

```
摄像头（眼睛）: 看路（车道线/障碍物）     ← 30Hz
超声波（耳朵）: 测距（"还有多远"）       ← 10-20Hz
IMU（内耳）:   姿态（"车正不正/在转吗"） ← 100-200Hz
编码器（脚）:  里程（"走了多远"）         ← 100Hz+
```

> [!note] 打个比方
> 小车的传感器 = 人的感官：**摄像头像眼睛（看得清但没距离）、超声波像耳朵（有距离但粗糙）、IMU 像内耳（平衡感）、编码器像肌肉记忆（走了多远）**——和 [[多传感器融合基础]] 的"眼睛/手杖/耳朵"比喻完全对应。
> **本篇 = 给每个感官写驱动（让数据进来）+ 让它们互相配合（融合）**。

### 两个核心思想（先记住）

```
① 传感器互补:  每个传感器有强项和盲区，融合 = 互相补盲（[[多传感器融合基础]]）
② 时间同步:    不同频率的数据要对齐到同一时刻，才能融合（否则"错位"）
```

## 一、摄像头（视觉感知）

### USB 摄像头选型

| 参数 | 推荐值 | 原因 |
|------|--------|------|
| 分辨率 | 640×480 或 1280×720 | 太高推理慢，太低检测不到 |
| 帧率 | 30fps 起步 | <15fps 控制延迟太大 |
| 视场角(FOV) | 100°~120° 广角 | 窄角看不到路口两侧 |
| 对焦 | 固定焦距 | 自动对焦在颠簸路面会反复对焦 |
| 接口 | USB 免驱 | 即插即用 |

> [!note] 选型的"权衡"逻辑（和 [[模型部署与延迟优化]] 呼应）
> **分辨率/帧率不是越高越好**——推理延迟预算（[[模型部署与延迟优化]]）和检测能力要平衡：640×480 够检测、30fps 够控制、120° 广角够看路口。**"固定焦距"是踩坑经验**（自动对焦在颠簸路面反复拉风箱）。

### OpenCV 基础管线

```python

    # 5. 计算中线偏移
    if lines is not None:
        # 分离左右线，计算中线，得到 steering offset
        pass
    
    cv2.imshow('frame', frame)
    if cv2.waitKey(1) & 0xFF == ord('q'):
        break

cap.release()
cv2.destroyAllWindows()
```

> [!note] 管线的五步 = 传统视觉的完整流程（和 [[计算机视觉基础]] 对照）
> **读帧 → ROI（只看路面，省算力）→ 预处理（灰度/高斯/Canny 边缘）→ 霍夫找线（车道线）→ 算偏移（转向量）**——这是 [[计算机视觉基础]] "车道线检测"的经典实现。**"ROI 裁剪"是工程技巧**（下半部分才是路面，省一半算力还滤掉天空噪声）。

### 相机标定（去畸变）

```
准备棋盘格 (9×6 内角点)，打印贴在硬板上。
从不同角度拍 20-30 张照片，运行标定脚本。
```

```python
import cv2
import numpy as np
import glob

CHECKERBOARD = (9, 6)
objpoints = []   # 3D 世界坐标
imgpoints = []   # 2D 图像坐标

objp = np.zeros((CHECKERBOARD[0]*CHECKERBOARD[1], 3), np.float32)
objp[:,:2] = np.mgrid[0:CHECKERBOARD[0], 0:CHECKERBOARD[1]].T.reshape(-1,2)

images = glob.glob('calib_images/*.jpg')
for fname in images:
    img = cv2.imread(fname)
    gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY)
    ret, corners = cv2.findChessboardCorners(gray, CHECKERBOARD, None)
    if ret:
        objpoints.append(objp)
        imgpoints.append(corners)

ret, mtx, dist, rvecs, tvecs = cv2.calibrateCamera(
    objpoints, imgpoints, gray.shape[::-1], None, None)

# 保存标定结果
np.savez('camera_calib.npz', mtx=mtx, dist=dist)

# 去畸变使用
frame = cv2.undistort(frame, mtx, dist)
```

> [!note] 相机标定 = [[3D视觉与投影几何]] 的实战
> 标定求的就是**内参 mtx + 畸变 dist**（[[3D视觉与投影几何]] 的 K 和畸变模型）——**"棋盘格找角点 → 解内参"**。**为什么小车要标定？** 不做伪 BEV 透视变换的前提就是"知道相机内参"（透视变换其实不严格需要，但畸变校正需要）。**[[BEVDet与BEVDepth]] 等 BEV 模型的数据管线第一步也是去畸变**——你在小车上做的和量产一模一样。

## 二、超声波（HC-SR04）

### 原理

Trig 脚发 10μs 高电平 → 模块发 8 个 40kHz 脉冲 → Echo 脚返回高电平，高电平时长 = 声波往返时间。

$$\text{距离(cm)} = \frac{\text{Echo 高电平时长(μs)}}{58}$$

### Arduino 代码

```cpp
#define TRIG 12
#define ECHO 13

float readUltrasonic() {
    digitalWrite(TRIG, LOW);
    delayMicroseconds(2);
    digitalWrite(TRIG, HIGH);
    delayMicroseconds(10);
    digitalWrite(TRIG, LOW);
    
    long duration = pulseIn(ECHO, HIGH, 30000);  // 30ms 超时 = ~5m
    if (duration == 0) return 999;  // 超时 = 无障碍
    
    return duration / 58.0;  // 厘米
}
```

> [!note] "除以 58"哪来的？（公式直觉）
> 声速 ~340m/s = 0.034cm/μs，往返时间 ÷ 2 = 单程 → 距离 = duration × 0.034 / 2 = duration / 58.8 ≈ **duration / 58**。**"声波来回 ÷ 2"是测距原理**——和 [[3D视觉与投影几何]] "深度 = 信号飞行时间"（ToF）同源，只是声波 vs 光。

### 注意事项

| 问题 | 原因 | 解决 |
|------|------|------|
| 读数偶尔跳变 | 反射面角度问题 | 中值滤波（取5次中位数） |
| 近距离不准 | 余震，盲区 ~2cm | 近距离改用 ToF |
| 多个互相干扰 | 交叉回波 | 分时触发，间隔 50ms |
| 软表面测不到 | 吸音材料 | 正常现象，超声波局限 |

```cpp
// 中值滤波
float readUltrasonicFiltered(int samples = 5) {
    float readings[5];
    for (int i = 0; i < samples; i++) {
        readings[i] = readUltrasonic();
        delay(10);
    }
    std::sort(readings, readings + samples);
    return readings[samples / 2];  // 中位数
}
```

> [!note] 为什么用"中值滤波"而不是"平均"？（工程直觉）
> 超声波偶尔有**异常大跳变**（反射角问题）——**平均值会被异常值拉偏**（100, 20, 25, 22, 24 → 平均 38），**中位数不受异常值影响**（100, 20, 25, 22, 24 → 中位 24）。**"抗离群点用中值、去噪声用平均"**是传感器滤波的基本功（[[模型基础知识补充]] 的滤波思想在硬件侧）。

## 三、IMU（MPU6050 / MPU9250）

### 获取的数据

| 数据 | 含义 | 用途 |
|------|------|------|
| **加速度计** (ax, ay, az) | 三轴加速度 | 倾角估计、碰撞检测 |
| **陀螺仪** (gx, gy, gz) | 三轴角速度 | 转向速率、姿态更新 |
| **磁力计** (9250) | 地磁方向 | 绝对航向（无 drift） |

### Arduino 读取（MPU6050）

```cpp
#include <Wire.h>
#include <MPU6050.h>

MPU6050 mpu;

void setup() {
    Wire.begin();
    mpu.initialize();
    mpu.setFullScaleGyroRange(MPU6050_GYRO_FS_250);  // ±250°/s
    mpu.setFullScaleAccelRange(MPU6050_ACCEL_FS_2);   // ±2g
}

void loop() {
    int16_t ax, ay, az, gx, gy, gz;
    mpu.getMotion6(&ax, &ay, &az, &gx, &gy, &gz);
    
    // 转换为物理单位
    float accX = ax / 16384.0;     // g
    float gyroZ = gz / 131.0;      // °/s
    
    // 互补滤波估算倾角
    static float angle = 0;
    float dt = 0.01;
    float accAngle = atan2(ay, az) * 180 / PI;  // 加速度计倾角
    angle = 0.98 * (angle + gyroZ * dt) + 0.02 * accAngle;
}
```

### 互补滤波 vs 卡尔曼滤波

| 方法 | 复杂度 | 效果 | 适用 |
|------|:--:|------|------|
| **互补滤波** | 极低 | 够用，参数简单 | L1-L3 小车 |
| **卡尔曼滤波** | 中等 | 最优估计 | L4 需要精确定位 |
| **Mahony/Madgwick** | 低 | 3D 姿态好 | 需要完整姿态 |

> 小车不需要精确 3D 姿态，互补滤波足够。重点取 `gyroZ`（偏航角速度）做转弯补偿。

> [!warning] 互补滤波的直觉（为什么 0.98/0.02？）
> **加速度计**：低频准（静态时重力方向明确）但高频噪声大；**陀螺仪**：高频准（瞬时角速度）但积分会漂移。**互补 = 取两者的长处**：`0.98×陀螺积分 + 0.02×加速度计角度`——**"信任陀螺的短时变化 + 用加速度计纠正长期漂移"**。**卡尔曼滤波是"统计最优版"**（[[计算机视觉基础]] 的卡尔曼在姿态上的应用）——小车互补滤波够用（L4 精确位姿才上卡尔曼）。

## 四、多传感器时间同步

### 问题

不同传感器采样频率不同，数据到达时间不同：

| 传感器 | 频率 | 延迟 |
|--------|:--:|:--:|
| 摄像头 | 30Hz | ~33ms |
| 超声波 | 10-20Hz | ~30ms |
| IMU | 100-200Hz | ~1ms |
| 编码器 | 100Hz+ | ~1ms |
| 串口指令 | 50Hz | ~10ms |

### 策略：以最慢传感器为主时钟

```python
import time
from collections import deque

class SensorFusion:
    def __init__(self):
        self.camera_data = deque(maxlen=5)
        self.ultrasonic_data = None
        self.imu_data = deque(maxlen=20)
        self.encoder_data = deque(maxlen=20)
    
    def update(self):
        """主循环 30Hz（与摄像头同步）"""
        frame = self.get_camera()         # 33ms
        self.ultrasonic_data = self.get_ultrasonic()  # 最新值
        imu_batch = list(self.imu_data)   # 取 buffer 里的所有 IMU 数据
        encoder_batch = list(self.encoder_data)
        
        # 融合：用 IMU 修正编码器里程计
        # 用超声波确认相机检测到的障碍物距离
        
        return self.make_decision(frame, imu_batch, encoder_batch, self.ultrasonic_data)
```

> [!warning] 时间同步 = 融合的地基（[[多传感器融合基础]] 的"生死线"）
> 摄像头 33ms 一帧、IMU 5ms 一帧——**不齐就融合 = "拿不同时刻的数据当同一时刻"**（[[多传感器融合基础]]：10ms 时间误差 ≈ 28cm 空间误差）。小车的做法：**以最慢的摄像头（30Hz）为主时钟**，快的传感器（IMU/编码器）用 buffer 存最新值——**"慢的定节奏，快的取最新"**。和量产的时间同步（硬件 PTP + 软同步）同一思想，只是精度要求低。

### 简单融合案例：超声波校验相机

```python
def obstacle_check(camera_dist_est, ultrasonic_dist):
    """
    如果相机和超声波估计的距离差 > 30%，以超声波为准（相机可能误检）
    """
    if ultrasonic_dist > 500:  # 超声波没检测到（超量程）
        return camera_dist_est
    
    diff = abs(camera_dist_est - ultrasonic_dist) / max(camera_dist_est, 1)
    if diff > 0.3:
        return ultrasonic_dist  # 超声波更可靠
    return (camera_dist_est + ultrasonic_dist) / 2  # 加权平均
```

> 💡 这对应你笔记 [[多传感器融合基础]] 中的"异质传感器互补"。在真实 L4 系统里这是前融合/后融合问题；在小车上，简单的 rule-based 融合就够。

> [!note] "超声波校验相机" = 融合的最小案例（面试谈资）
> **相机可能误检**（把阴影当障碍），**超声波没这个毛病**（物理测距）——**"可信的传感器校验不可信的"**，分歧 >30% 信超声波，一致则加权平均。**这就是 [[多传感器融合基础]] 的"互补"+"置信度"思想**——只是量产用网络学融合（BEVFusion），小车用规则融合。

## 五、编码器里程计

### 从编码器脉冲推算位移

```
编码器脉冲数 N → 车轮转过的圈数 R = N / (编码器线数 × 减速比)
行驶距离 D = R × π × 轮径

例：13 线编码器，1:30 减速比 → 390 脉冲/圈
    轮径 65mm → 周长 = π × 65 ≈ 204mm
    收到 3900 脉冲 → 10 圈 → 10 × 204 = 2.04m
```

```python
class Odometer:
    def __init__(self, pulses_per_rev, wheel_diameter_mm):
        self.ppr = pulses_per_rev          # 每圈脉冲数
        self.circumference = math.pi * wheel_diameter_mm / 1000.0  # 米
    
    def pulses_to_meters(self, pulses):
        return (pulses / self.ppr) * self.circumference

# 使用
left_odo = Odometer(390, 65)
right_odo = Odometer(390, 65)

dx = left_odo.pulses_to_meters(left_encoder_count)
dr = right_odo.pulses_to_meters(right_encoder_count)

# 两点模型推算位姿 (x, y, theta)
# 参见 [[SLAM与定位]]
```

> [!note] 里程计的"数学链"（理解即可）
> **脉冲 → 圈数（÷每圈脉冲）→ 距离（×周长）→ 位姿（两点模型）**——"左轮距离+右轮距离 → 前进量 + 转角"（差速模型）。**里程计是 [[SLAM与定位]] 的"粗略起点"**——纯里程计会漂移（轮子打滑），SLAM 用地图纠正它（[[SLAM与定位]] 的 EKF 融合）。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **摄像头分辨率开太高**——推理慢、控制延迟大；640×480 + 30fps 起步（[[模型部署与延迟优化]] 的延迟预算）。
> 2. **不做时间同步就融合**——不同时刻的数据当同一时刻 = 错位融合；**以最慢传感器为主时钟**。
> 3. **超声波用平均滤波**——异常跳变把平均拉偏；**抗离群用中值**。
> 4. **IMU 只用陀螺仪**——积分漂移越走越偏；**互补滤波（陀螺短时 + 加速度计纠偏）**。
> 5. **跳过相机标定**——畸变不矫正，伪 BEV 和检测都会偏（[[3D视觉与投影几何]] 的"去畸变是第一步"）。
> 6. **只看单传感器**——相机误检没人校验；**多传感器交叉验证**（超声波校验相机）。

## ✅ 检验自己（自测题）

> [!question] Q1：小车的传感器家族各自"强在哪、弱在哪"？怎么互补？
> 提示：眼睛/耳朵/内耳/脚。

> [!success]- 参考答案
> 摄像头（眼睛）：语义丰富但无距离、怕光照；超声波（耳朵）：物理测距可靠但粗糙、有盲区；IMU（内耳）：姿态/角速度准但积分漂移；编码器（脚）：里程准但打滑会偏。互补：超声波校验相机（防误检）、IMU 修正里程计漂移、摄像头提供语义——对应 [[多传感器融合基础]] 的"互补 + 置信度"思想。

> [!question] Q2：透视变换为什么是"手工伪 BEV"？BEVFormer 和它什么关系？
> 提示：IPM。

> [!success]- 参考答案
> 透视变换（IPM）把图像地面区域映射成俯视图（选定 4 个地面点 → BEV 矩形）——这就是 [[BEV感知全景]] 的"手工版伪 BEV"（[[3D视觉与投影几何]] 的 IPM）。BEVFormer 用 Transformer 学一个"比手工 4 点变换更好的变换"（可学习的空间变换）。**"手工版 → 学习版"的对比是理解 BEV 范式的钥匙。**

> [!question] Q3：超声波为什么用中值滤波？互补滤波的 0.98/0.02 是什么意思？
> 提示：抗离群/陀螺+加速度计。

> [!success]- 参考答案
> 中值滤波：超声波偶有异常大跳变（反射角问题），平均被异常值拉偏、中位数不受影响（抗离群用中值、去噪声用平均）。互补滤波：加速度计低频准但高频噪声大，陀螺仪高频准但积分漂移——0.98×陀螺积分 + 0.02×加速度计角度 = "信任陀螺短时变化 + 加速度计纠正长期漂移"（卡尔曼是统计最优版，小车互补滤波够用）。

> [!question] Q4：多传感器时间同步怎么在小车上做？为什么必须以最慢的为主时钟？
> 提示：慢的定节奏。

> [!success]- 参考答案
> 以最慢的传感器（摄像头 30Hz）为主时钟，快的传感器（IMU/编码器）用 buffer 存最新值，主循环每帧取"最新值"融合。原因：不同频率的数据不对齐 = "拿不同时刻当同一时刻"（[[多传感器融合基础]] 的时间同步生死线）——慢的定节奏（每 33ms 融合一次），快的取最新（不丢高频率信息）。量产是硬件 PTP + 软同步，小车是"主时钟 + buffer"。

> [!question] Q5：从编码器脉冲怎么算里程？里程计的局限是什么？
> 提示：脉冲→圈→距离。

> [!success]- 参考答案
> 脉冲数 ÷ 每圈脉冲（线数×减速比）= 圈数 → ×π×轮径 = 距离。局限：**轮子打滑/气压变化会让里程漂移**（编码器测的是"轮子转了多少"不是"车实际走了多少"）——纯里程计会越走越偏，SLAM 用地图/激光纠正它（[[SLAM与定位]] 的 EKF 融合）。

## 🛠 动手练习

### 练习 1：跑通摄像头管线（60-90 分钟）

用 OpenCV 管线（第一节）完成：
1. 摄像头画面 + ROI 裁剪 + 灰度/边缘。
2. 霍夫找车道线，画出检测结果。
3. 加透视变换（伪 BEV），在 BEV 图上重新检测车道线。
4. 对比"透视前 vs 透视后"的检测效果（哪个更稳？为什么？）

> [!tip] 这是"伪 BEV"的完整实战
> 亲手做透视变换 + BEV 检测，你就理解了 [[BEV感知全景]] 的"统一坐标系"价值（BEV 图上车道线是平行的，比透视图好检测得多）。做完把效果对比存进 [[2026-08-20]]。

### 练习 2：超声波 + 相机融合（60 分钟）

按第四节的 `obstacle_check`：
1. 相机检测障碍物（颜色/轮廓或简单模型）估距离。
2. 超声波实测距离。
3. 融合：分歧 >30% 信超声波，一致则加权平均。
4. 设计一个测试场景（放一个纸箱），验证融合比单传感器稳。

> [!tip] 这是 [[多传感器融合基础]] 的最小实战
> 亲手做一次"相机+超声波"融合，你就理解了"异质传感器互补"和"置信度"——量产 BEVFusion 就是它的学习版。做完写 3 句总结。

### 练习 3：编码器里程计 + 直线验证（可选，60 分钟）

按第五节 Odometer：
1. 让小车直线走 1 米，读编码器，算里程。
2. 实测距离 vs 里程计距离，误差多少？（轮子打滑/气压）
3. 走一个直角弯，用两点模型估算转角，对比实际。

> [!tip] 这是 [[SLAM与定位]] 的前置实验
> 亲手测出"里程计会漂移"，你就理解为什么 SLAM 需要地图纠正（[[SLAM与定位]] 的 EKF）。误差数据存进 [[2026-08-20]]。
