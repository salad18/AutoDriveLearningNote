## 〇、大白话总览

### 华为 ADS 三年干了什么？

```
ADS 1.0 (2021):  BEV 检测 + 高精地图 + 规则规划     → 能用（但依赖地图、怕异形障碍物）
ADS 2.0 (2023):  + GOD 异形障碍物 + RCR 无图        → 能去全国（无图）
ADS 3.0 (2024):  GOD 大网（去 BEV）+ PDP 端到端      → 开得像人（类人决策）
```

**每一代都在补上一代的短板**：
- 1.0 的短板：只会识别"白名单"（车/人），路上掉个石头识别不了 → 2.0 加 GOD（通用障碍物）。
- 2.0 的短板：依赖高精地图，很多地方没图 → 2.0 同期用 RCR 实时建图（无图化）。
- 3.0 的短板：规则规划不够"像人"、复杂路口犹豫 → 3.0 上 PDP 端到端规划。

### 核心哲学（一句话）

**"算法效率 > 堆算力"** —— 200 TOPS 单芯片做出比 400 TOPS 双芯片更强的能力；**"感知兜底 + 规则兜底"** —— 稠密占据兜底"看得到一切"，CAS 兜底"即使网络出错也刹得住"。

> [!note] 华为方案的本质：**量产导向的"组合拳"**
> 论文方案通常押注单一范式（纯视觉、纯端到端），华为是**"什么可靠用什么"**：
> - 感知：GOD（占据兜底）+ 白名单检测（精确语义）并用
> - 地图：RCR（实时推理）不用高精地图
> - 规划：PDP（端到端）+ 采样评分 + CAS（规则兜底）三层
> 这不是"技术不纯粹"，而是**量产安全对"冗余"的硬要求**——任何单一环节都可能失效，必须层层兜底。

## 一、三代演进总览

| 版本 | 发布时间 | 感知架构 | 规划 | 地图 | 代表车型 |
|------|----------|----------|------|------|----------|
| **ADS 1.0** | 2021.04 | BEV (白名单) | 规则+规划 | 有图 (高精地图) | 极狐阿尔法S HI |
| **ADS 2.0** | 2023.04 | BEV + **GOD** + RCR | 规则+规划 | **无图** (全国可用) | 问界M5/M7/M9 |
| **ADS 3.0** | 2024.04 | **GOD 大网** (去掉 BEV) | **PDP** 端到端 | 无图 | 享界S9, 问界全系升级 |
| **ADS 4.0** | 2025 (预期) | - | L3 试点 | 无图 | - |

```
演进路线:
ADS 1.0          ADS 2.0           ADS 3.0
  BEV         →   BEV+GOD      →   GOD大网
  有图        →   无图(RCR)    →   无图
  规则规划    →   规则规划      →   PDP端到端
```

> [!note] 三代演进的三条主线（记忆框架）
> 1. **感知**：BEV（2D 白名单）→ BEV+GOD（补异形）→ GOD 大网（3D 占据统一）。
> 2. **地图**：高精地图（贵、更新慢）→ RCR 实时建图（无图全国可用）。
> 3. **规划**：规则（写死的 if-else）→ PDP 端到端（数据驱动，像人）。
> 三条主线都指向同一个方向：**摆脱"手工工程"的局限，用"算法+数据"覆盖真实世界的无限场景。**

## 二、硬件方案

### 传感器配置演变

| 硬件 | ADS 1.0 | ADS 2.0 | ADS 3.0 |
|------|:-------:|:-------:|:-------:|
| **激光雷达** | 3 颗 (96线) | 1 颗 (192线 D3) | 1 颗 (D3 Pro, AI抗干扰) |
| **毫米波雷达** | 6 颗 | 3 颗 | 1+ 颗 (4D, 280m) |
| **感知摄像头** | 13 颗 | 11 颗 | 11 颗 |
| **超声波雷达** | 12 颗 | 12 颗 | 12 颗 |
| **DMS** | 1 颗 | 1 颗 | 1 颗 |

**趋势**：传感器数量减少（降本），但单传感器性能提升。

> [!note] "减数量、提单兵"背后的逻辑
> 3 颗 96 线 LiDAR → 1 颗 192 线：**单颗更贵但总量更便宜，且感知算法更强后不再需要"堆冗余视角"**。这是"算法进步 → 硬件降本"的正循环——和 [[多传感器融合基础]] 说的"不是越多越好，是覆盖失效场景"完全一致。

### 计算平台

| 项目 | ADS 1.0 | ADS 2.0/3.0 |
|------|---------|-------------|
| **平台** | MDC 610 (双芯片) | MDC 610 (单芯片) |
| **芯片** | 昇腾 Ascend 610 × 2 | 昇腾 Ascend 610 × 1 |
| **算力** | 400 TOPS | 200 TOPS |
| **成本** | ~10 万 | ~3 万 |

> 华为在 200 TOPS 算力下通过算法优化实现了更强的智驾能力，说明 **算法效率 > 堆算力**。

> [!warning] 为什么"200 TOPS 反而更强"值得深思？
> 因为 2.0/3.0 的算法架构（GOD 大网、端到端）**信息效率**远超 1.0（BEV+规则）：同样的算力下，好算法能处理的信息量完全不同。**这给我们的启示：先优化算法结构，再考虑堆硬件**——这也是 [[模型部署与延迟优化]] 的哲学。

### 激光雷达 (D3 Pro)

| 参数 | 数值 |
|------|------|
| **线数** | 192 线 |
| **探测距离** | 250m |
| **扫描频率** | 20Hz |
| **技术** | VCSEL 阵列, AI 抗高反/雨雾/扬尘 |

> [!note] 华为为什么坚持 LiDAR？（面试高频）
> 因为 GOD 任务（通用障碍物检测）**本质上更需要"几何"而非"语义"**：判断"那里有没有东西"，LiDAR 的精确 3D 测量比相机更可靠（[[占据网络与GOD]] 里讲过）。尤其远距离（80m+）和夜间雨雾，视觉占据会稀疏/劣化，LiDAR 稳定。**特斯拉用"纯视觉 + 海量数据"赌，华为用"LiDAR 兜底"稳**——两种哲学，见第六节对比。

## 三、核心技术

### 3.1 GOD 网络 — 通用障碍物检测

**GOD = General Obstacle Detection**，是华为 ADS 的核心感知网络。

```
GOD 的演进:

ADS 1.0:  BEV (只识别白名单障碍物)
ADS 2.0:  BEV + GOD (增加异形障碍物识别)
ADS 3.0:  GOD 大网 (去掉 BEV, 统一感知)
```

**GOD 的核心能力**：

1. **白名单识别**：标准目标 (车辆、行人、骑行者等)
2. **异形障碍物识别**：翻倒车辆、散落货物、落石、断树、纸箱...
3. **场景语义理解**：不只是"检测到物体"，还能理解"这是什么场景"
4. **3D 感知**：从 2D BEV 升级到 3D 占据式感知

**为什么 GOD 优于传统 BEV**：

| 传统 BEV | GOD 大网 |
|----------|----------|
| 2D 鸟瞰图 | 3D 占据式感知 |
| 只能识别白名单 | 通用障碍物 (不限类别) |
| 无法处理异形障碍物 | 天然处理长尾 |
| 感知+后处理 | 端到端感知理解 |

> [!note] GOD = [[占据网络与GOD]] 的量产化
> 学术界的"占据网络 + GOD 思想"在华为变成产品：**3D 占据兜底一切空间 + 白名单检测提供精确语义 + 场景理解提供上下文**。它证明了占据范式不是论文玩具，而是能扛住量产安全要求的。这正是 [[占据网络与GOD]] 第七节"从 BEV 到 GOD 演进"的工业落地。

### 3.2 PDP 网络 — 预测决策规控

**PDP = Prediction Decision Planning**，端到端规划网络。

```
传统方案:   预测 → 决策 → 规划 → 控制 (各自独立, 规则驱动)
PDP 方案:   预测+决策+规划 一张网 (数据驱动, 端到端)
```

**PDP 的优势**：
- 类人化驾驶：轨迹更像人类司机
- 高效通行：复杂路口通过率 > 96%
- 数据驱动：每日 3500 万公里仿真训练

> [!note] PDP = [[VAD详解]] 思想的工程化
> VAD 的"候选采样 + 评分"（显式规划）在 PDP 里变成"采样 + 优化 + **规则兜底**"——学术版的纯 learned scoring 不够安全，量产版加上了规则层（见第四节 PDP 设计）。**"论文的显式规划 → 量产的显式规划+规则兜底"**，这是学术到量产的标准加料。

### 3.3 RCR — 道路拓扑推理 (ADS 2.0)

**RCR = Road Cognition & Reasoning**

```
车载传感器 → BEV 特征 → RCR 网络 → 实时生成"虚拟高精地图"
                                          ↓
                               车道线 + 拓扑关系 + 路权
```

**意义**：摆脱高精地图依赖 → 全国范围"有路就能开"。

> [!note] "无图"的真相（别被营销词误导）
> **"无图"不是"没有地图"，而是"不用高精地图，靠车载传感器实时推理重建"**。RCR 实时输出车道线、拓扑、路权——相当于**车自己"画"地图**。好处：① 全国覆盖（不用等地图采集）；② 对道路变化（施工、重新划线）天然自适应（地图不会过期）。

### 3.4 CAS 3.0 — 全向防碰撞（安全兜底）

| 方向 | 能力 |
|------|------|
| **前向** | AEB + ESA (紧急转向辅助), 支持无先打方向盘自动转向 |
| **侧向** | 斜穿/横穿车辆、自行车、电动车 |
| **后向** | 倒车碰撞预警 |

响应时间：**200ms** 从检测到动作。

> [!warning] CAS 是"端到端"和"安全"之间的最后一道闸
> 端到端网络再强，也可能遇到没见过的情况（极端天气、对抗场景）。**CAS 3.0 独立于网络运行**：即使 PDP 输出不合理轨迹，CAS 的碰撞检测会 override（强制刹车/转向）。**这是"量产 vs 论文"最根本的区别：论文假设模型永远正确，量产假设模型一定会犯错，所以必须有独立兜底。**

## 四、核心架构深度解析

### 4.1 GOD 大网的网络结构（推理级细节）

GOD 不是单一的 "一个网络"，而是一组网络的统称：

```
GOD 大网 (ADS 3.0):
┌─────────────────────────────────────────────┐
│                多模态输入                      │
│   Camera(6) + LiDAR(1) + Radar(1+)          │
└──────────────────┬──────────────────────────┘
                   ↓
┌─────────────────────────────────────────────┐
│          多模态特征提取 & 融合                │
│  Camera: ViT/Swin → Image Tokens            │
│  LiDAR:  Voxel/Pillar → Point Tokens        │
│  Radar:  Point Cloud → Radar Tokens         │
│  → Cross-Modal Attention (早期融合)          │
└──────────────────┬──────────────────────────┘
                   ↓
┌─────────────────────────────────────────────┐
│          3D 占据感知 (Occupancy)             │
│  • 稠密 3D 占用栅格预测 (voxel-wise)          │
│  • 语义分割 (可行驶/不可行驶/未知)              │
│  • 运动预测 (per-voxel flow)                 │
│  → 输出: 3D Occupancy + Semantics + Flow    │
└──────────────────┬──────────────────────────┘
                   ↓
┌─────────────────────────────────────────────┐
│          通用障碍物检测 (GOD)                 │
│  • DBSCAN 聚类 occupied voxels → proposals   │
│  • 开集检测: 不限类别，所有被占空间 = 障碍物      │
│  • 运动判别: 静止/运动 → 过滤静态背景          │
│  → 输出: 通用障碍物列表 (不限于白名单)           │
└──────────────────┬──────────────────────────┘
                   ↓
┌─────────────────────────────────────────────┐
│       场景理解 + 白名单检测 (可选)              │
│  • 对 GOD proposals 做细粒度分类               │
│  • 常规目标: 车辆/行人/骑行者 (白名单)           │
│  • 异形障碍物: 保持 "通用障碍物" 标签           │
└─────────────────────────────────────────────┘
```

**GOD 的关键设计**: Occupancy（几何）覆盖所有空间，DBSCAN 聚类（无监督）发现候选障碍物，运动判别过滤误检 → **不需要预定义类别**。

> [!note] 四层结构的逻辑链
> **特征（多模态融合）→ 空间（3D 占据，回答"哪有东西"）→ 目标（聚类，回答"有几个东西"）→ 语义（分类，回答"是什么"）**。
> 注意顺序：**先"空间"后"语义"**——几何兜底在前，语义补充在后。这正是 [[占据网络与GOD]] 反复强调的"先感知空间，再认识世界"。

### 4.2 PDP 网络的具体设计

PDP = Prediction Decision Planning 融合网络：

```
PDP 输入:
  • GOD 输出: 3D Occupancy + 障碍物列表
  • RCR 输出: 实时车道拓扑图 (lane graph)
  • 导航目标: 高精/标精地图路径
  • 自车状态: 速度/加速度/朝向

PDP 网络:
  1. Scene Encoding (Transformer):
     障碍物 tokens + 车道 tokens + 导航 tokens → Self-Attention
     → Unified Scene Token [N_tokens, 256]

  2. Prediction Head:
     每个障碍物 → 多模态未来轨迹 (同 UniAD MotionFormer)
     → 6 modes × 6s trajectory

  3. Decision Head:
     场景 token + 交通规则 → 行为决策 (直行/左转/右转/变道/绕行)
     → 可解释的行为标签 (对比端到端黑盒)

  4. Planning Head:
     决策 + 场景 token → 自车轨迹生成
     → 采样 + 优化: 生成 K=32 候选 → 安全/舒适/进度评分 → 选最优
     (类似 VAD 的 explicit planning, 但更工程化)

PDP 输出:
  • 规划轨迹: [(x₁,y₁,t₁), ..., (x₃₀,y₃₀,t₃₀)] (3s horizon)
  • 碰撞风险评估
  • 盲区预警
```

**分体式 vs 端到端的核心差异**: PDP 保留可解释的中间表示（决策标签、trajectory scoring），模型的行为可以审计 → 这正是量产的关键需求。

> [!note] PDP 为什么比"大一统端到端"更适合量产？（面试高频）
> 纯端到端（特斯拉）把"感知→决策→控制"压成一个黑盒，出了问题不知道哪一环错。PDP 是**"分体式端到端"**：预测、决策、规划都是网络（数据驱动、端到端训练），但**中间有显式的决策标签和轨迹评分**——行为可审计、参数可调、出事故可回溯。**"端到端的性能 + 模块化的可解释"**，这是量产对可解释性的妥协性要求。

### 4.3 RCR 如何实现无图

```python
# RCR = Road Cognition & Reasoning
# 输入: 6 camera images
# 流程:
img_features = ImageBackbone(images)  # ViT/Swin
bev_features = BEVEncoder(img_features)  # 类似 BEVFormer 轻量版

# 1. Lane Detection Head (类似 MapTR):
lanes = LaneHead(bev_features)
# → 每条车道线: [(x₁,y₁), (x₂,y₂), ..., (x₂₀,y₂₀)] (polyline points)

# 2. Lane Topology Head:
relations = TopologyHead(lanes)
# → 车道之间的连接关系 (并线/交叉/分流)
# → 车道的交通属性 (限速/转向规则/路权)

# 3. 实时建图输出:
virtual_map = {
    'lane_centerlines': [...],    # 车道中心线
    'lane_dividers': [...],        # 车道分割线
    'lane_topology': [...],        # 拓扑连接
    'traffic_rules': {...}         # 交通规则
}

# 关键革新: RCR 不存储地图 — 实时推理!
# → "无图"不是没地图，是"不用 HD Map，靠实时推理重建"
# → 对道路变化 (施工/重新划线) 天然自适应
```

**RCR 的核心难点**: 远距离 (>100m) 的车道结构推理 → 需要时序多帧信息 + 道路先验知识。

> [!note] RCR = [[VAD详解]] 车道矢量化的量产应用
> VAD 的"车道线 polyline + 拓扑"在 RCR 里变成产品功能：**实时推理出车道结构**。学术的 Map Head（MAPTR 系）→ 华为的 RCR，又是一次"论文 → 量产"的迁移。

## 五、面试官追问

### Q1: GOD 的 DBSCAN 聚类在 Occupancy 上怎么做的？参数怎么选？

DBSCAN 在 3D Occupancy Grid 上聚类:
- 3D connected components 在 occupied voxels 上做聚类
- eps（邻域半径）= 0.8-1.2m（voxel size 的 2-3 倍）→ 保证同一物理物体被聚为一类
- min_samples = 3-5 voxels → 过滤噪声（如单个飘动的叶子）
- 聚类后每个 cluster 是一个 "通用障碍物" proposal

> [!note] 为什么用"聚类"而不是"检测头"找障碍物？
> 检测头需要类别标签（白名单思维）；聚类**不需要标签**——"空间上连在一起的一坨被占体素 = 一个障碍物"。这是"无类别感知"的工程实现（[[占据网络与GOD]] 的 GOD 路径 1）。

### Q2: 华为用 LiDAR 做 GOD，如果去掉 LiDAR 还能做 GOD 吗？

可以，但纯视觉 GOD 有两个关键挑战：
1. 远距离深度不准 → Occupancy 在 80m+ 变得稀疏 → DBSCAN 聚类失效
2. 夜间/雨雾 → 视觉 Occupancy 质量下降 → False positive 增多

这就是为什么华为坚持 LiDAR —— 在 GOD 任务上，几何传感器（LiDAR）比语义传感器（Camera）更可靠。特斯拉的解决方案是用时序多帧 + 更大模型弥补单帧视觉深度不足。

### Q3: PDP 和 VAD 的区别？

| | PDP (华为) | VAD (学术) |
|---|---|---|
| **规划方法** | 采样 + 优化 + 规则兜底 | 采样 + 优化 (纯 learned scoring) |
| **安全保证** | CAS 3.0 硬件层面兜底 | 学出来的 safety score |
| **场景覆盖** | 量产验证 (百万公里) | nuScenes 验证 |
| **可解释性** | 显式决策标签 | 隐式 scoring |
| **落地状态** | 量产 ✅ | 研究 🔬 |

**核心差异**: PDP 有**规则兜底** — 即使网络输出不合理轨迹，CAS 3.0 的碰撞检测会 override。这是量产 vs 学术的最关键区别。

### Q4: ADS 3.0 的 GOD 大网"去掉 BEV"是什么意思？

不是完全去掉 BEV 特征，而是**不再用传统 2D BEV 检测头**。GOD 大网直接输出 3D Occupancy，BEV 变成了一个中间特征（类似 neck），而不再作为最终输出空间。这是从 "BEV 检测" 到 "3D 占据感知" 的范式转换。

## 六、与特斯拉 FSD 的对比

| 维度 | 华为 ADS 3.0 | 特斯拉 FSD V12 |
|------|-------------|---------------|
| **感知路线** | 多传感器融合 (含 LiDAR) | 纯视觉 |
| **架构** | GOD (感知) + PDP (规划) 分体式端到端 | 感知→控制 统一大模型 |
| **地图** | 无图 | 无图 |
| **芯片** | 昇腾 Ascend | FSD Chip 2.0 |
| **算力** | 200 TOPS | ~144 TOPS (HW4) |
| **训练算力** | 7.5 EFLOPS | ~100 EFLOPS |
| **迭代周期** | 5 天 | 2 周 |
| **国内可用** | ✅ 全国 | ❌ (未入华) |

> [!warning] 这张对比表要读出"哲学差异"，不是"谁赢谁输"
> 1. **传感器哲学**：华为"LiDAR 兜底"（几何可靠），特斯拉"纯视觉 + 海量数据"（成本与规模）。各有前提：特斯拉有百万级车队的数据飞轮，华为有 LiDAR 的硬件冗余。
> 2. **架构哲学**：华为"分体式端到端"（可审计），特斯拉"大一统"（极致信息流）。华为要过国内安全认证、要可解释，特斯拉赌"数据足够多就不需要解释"。
> 3. **算力**：特斯拉训练算力是华为 14 倍（100 vs 7.5 EFLOPS）——纯视觉方案对数据的依赖度，从这个数字可见一斑。
> **记住：技术选型没有绝对对错，都是"约束条件下的最优解"。** 华为的约束是"要在中国量产、要过认证、要可解释"；特斯拉的约束是"要全球规模、要极致降本"。

## 九、关键创新总结

1. **GOD 取代 BEV**：从 2D 白名单检测跃迁到 3D 通用障碍物检测
2. **PDP 端到端规划**：类人化决策，替代规则引擎
3. **软关联融合**：用 Transformer 自适应匹配 LiDAR 点云与图像特征，降低传感器对齐要求
4. **算法换硬件**：200 TOPS 单芯片替代 400 TOPS 双芯片，降本不降体验
5. **去高精地图**：RCR 实时建模路边结构，覆盖全国

## 十、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为"无图"= 不用任何地图**——是用 RCR **实时推理重建**地图，替代"预采集的高精地图"（"无图"是"无高精地图"，不是"无地图"）。
> 2. **以为"去 BEV" = 不要 BEV 特征**——是不再用 BEV 作为**最终输出空间**，BEV 仍是中间特征（类似 neck）。
> 3. **以为 GOD 大网是一个网络**——是一组网络（感知/占据/聚类/语义），"大网"是产品概念。
> 4. **以为华为是"纯端到端"**——是"分体式端到端 + 规则兜底"（PDP + CAS），和特斯拉"大一统"是两种哲学。
> 5. **忽视数据飞轮**——5 天迭代、3500 万公里日训练里程才是 ADS 持续变强的真正引擎，算法只是起点。

## ✅ 检验自己（自测题）

> [!question] Q1：ADS 1.0 → 2.0 → 3.0 每一代补上了什么短板？用"感知/地图/规划"三条线回答。
> 提示：白名单、高精地图、规则规划。

> [!success]- 参考答案
> 感知线：1.0 BEV 只会白名单 → 2.0 加 GOD（异形障碍物）→ 3.0 GOD 大网（3D 占据统一）。地图线：1.0 依赖高精地图 → 2.0 RCR 实时建图（无图全国可用）。规划线：1.0/2.0 规则规划 → 3.0 PDP 端到端（类人决策）。三代演进 = 摆脱"白名单/地图/规则"三个手工工程局限，走向"通用/无图/数据驱动"。

> [!question] Q2：为什么华为坚持保留 LiDAR？纯视觉 GOD 的瓶颈在哪？
> 提示：GOD 需要几何。

> [!success]- 参考答案
> GOD（通用障碍物检测）本质需要"几何"而非"语义"——判断"那里有没有东西"，LiDAR 的精确 3D 测量比相机可靠。纯视觉 GOD 两个瓶颈：① 远距离（80m+）深度不准 → 占据稀疏 → DBSCAN 聚类失效；② 夜间/雨雾视觉质量劣化 → 假阳性增多。所以华为用 LiDAR 兜底 GOD，特斯拉用"时序多帧 + 更大模型"弥补。

> [!question] Q3：GOD 大网的"先空间后语义"四层结构是什么？为什么顺序不能反？
> 提示：特征 → 空间 → 目标 → 语义。

> [!success]- 参考答案
> ① 多模态特征提取与融合；② 3D 占据感知（回答"哪有东西"）；③ DBSCAN 聚类成通用障碍物（回答"有几个"）；④ 白名单分类/场景理解（回答"是什么"）。顺序不能反：几何兜底必须在前——先保证"不遗漏任何障碍"（空间），再补"它是什么"（语义）。反过来的话，遇到未知物体（无类别）就直接漏检了。

> [!question] Q4：PDP 和"大一统端到端"（特斯拉）的核心差异是什么？为什么量产更倾向 PDP？
> 提示：可解释性、中间表示、规则兜底。

> [!success]- 参考答案
> PDP 是"分体式端到端"：预测/决策/规划都是网络（数据驱动），但保留显式的中间表示（决策标签、轨迹评分），且有 CAS 3.0 规则兜底（网络出错会被 override）。特斯拉"大一统"把感知→控制压成一个黑盒，信息流最完整但不可审计。量产倾向 PDP 因为：可解释（出事故能回溯）、可调参（评分项独立）、有兜底（规则层强制安全）——量产必须假设模型会犯错。

> [!question] Q5：华为"无图"方案的原理是什么？相比高精地图有什么优势？
> 提示：RCR 实时推理。

> [!success]- 参考答案
> RCR（道路认知与推理）：车载传感器 → BEV 特征 → 车道线检测 + 拓扑推理 + 交通规则 → 实时输出"虚拟高精地图"。优势：① 全国覆盖（不等地图采集）；② 永不过期（施工/重新划线天然自适应）；③ 成本低（不用维护高精地图）。"无图" = 不用预采集高精地图，靠实时推理重建。
