# 3D 多目标跟踪（3D MOT）

> 一句话导读：检测只告诉你"这一帧有辆车"，跟踪告诉你"**这辆车从哪来、往哪去**"——它是检测到预测/规划的桥梁。感知岗高频考点（Momenta 面经也反复问卡尔曼滤波）。本篇讲清三件事：**怎么让帧间目标对上号（数据关联）、怎么估计运动（卡尔曼滤波）、为什么 3D MOT 比 2D 难**。

> [!tip] 用"追快递"理解跟踪
> 每一帧检测 = 快递员报"我看到几个人在街上走"；跟踪 = **给每个人贴上编号，并记录他的轨迹**。没有跟踪，每帧都是"一堆人"；有了跟踪，系统知道"3 号是前面那辆车，它刚才在加速"——**只有知道"过去和现在"，才能预测"未来"（给规划用）**。

## 一、跟踪的三大问题（所有 MOT 都绕不开）

| 问题 | 大白话 | 典型解法 |
|------|--------|---------|
| **目标出生（Birth）** | 新目标出现，给他建个"档案" | 置信度阈值 + 连续 N 帧确认 |
| **数据关联（Association）** | 这一帧的检测和上一帧的谁对应？ | 匈牙利/贪心匹配 + IoU/距离代价 |
| **目标死亡（Death）** | 目标消失了，什么时候删档案？ | 连续 M 帧未匹配 → 删除（或保留缓存） |

> [!note] 关联（Association）是 MOT 的灵魂
> 检测已经由检测器给出（YOLO/CenterPoint 等），跟踪的核心难点就是"**匹配**"——这一帧的框和上一帧的框，怎么知道是同一辆车？答案：**运动预测 + 外观/几何相似度 + 匹配算法**（匈牙利算法，见 [[智驾算法面试题库]] Q21）。

## 二、卡尔曼滤波：跟踪的"运动预测器"

### 2.1 为什么跟踪要用卡尔曼？

- 目标在动，下一帧位置**未知**——卡尔曼用运动模型**预测**下一帧位置（预测），再用检测**修正**（更新）。
- 好处：① 有预测，关联时能拿"预测位置"和检测比，比纯 IoU 更准；② 平滑检测噪声（检测抖动 → 轨迹稳）；③ 输出**速度/加速度**（检测器通常不直接给）。

### 2.2 卡尔曼五步（跟踪视角）

```
① 状态: x = [x, y, vx, vy]  (2D 位置+速度；3D 再加 z, vz)
② 预测: x' = F·x (F = 状态转移矩阵)     → 位置外推
        P' = F·P·Fᵀ + Q  (Q = 过程噪声)  → 不确定性变大
③ 观测: z = H·x + 噪声 (H = 观测矩阵)
④ 更新: K = P'·Hᵀ·(H·P'·Hᵀ + R)⁻¹   (K = 卡尔曼增益，决定信预测还是信观测)
        x = x' + K·(z − H·x')         (用观测修正预测)
        P = (I − K·H)·P'
⑤ 输出: x 更新后的状态（含速度）
```

**K 的含义（面试必考）**：K 大 = 信观测（R 小）；K 小 = 信预测（R 大）。Q↑→K↑、R↑→K↓。

### 2.3 扩展：EKF / UKF

- **EKF**：非线性系统（如用距离+角度的极坐标观测）→ 在当前状态处**线性化**（雅可比矩阵），再套卡尔曼。
- **UKF**：用一组 sigma 点近似非线性，比 EKF 精度高、无需求导。
- 智驾里：目标跟踪多为 EKF（状态含位置/速度/尺寸/朝向）。

## 三、MOT 方法演进（SORT → DeepSORT → ByteTrack → AB3DMOT）

### 3.1 SORT（2016）——"卡尔曼 + 匈牙利 + IoU"

```python
# SORT 流程（伪代码）
for frame in video:
    dets = detector(frame)                      # 检测
    for track in tracks:
        track.predict()                         # 卡尔曼预测
    matches = hungarian(tracks, dets, cost=IoU) # 匈牙利匹配
    for t, d in matches: t.update(d)            # 匹配上的更新
    unmatched_dets → new track                  # 出生
    unmatched_tracks > max_age → delete         # 死亡
```

- **核心**：卡尔曼预测 + IoU 匈牙利匹配 + 简单生命周期管理。
- **问题**：IoU 只靠位置，**遮挡/丢失后重识别困难**；外观信息没用上。

### 3.2 DeepSORT（2017）——"SORT + 外观特征"

- 加**外观 embedding**（ReID 网络提取的特征）→ 匹配时用"位置 + 外观"双重相似度。
- 解决：遮挡后重现时，靠外观认出"还是那辆车"。

### 3.3 ByteTrack（2021）——"低分检测也能关联"

- 核心：**低置信度检测框也参与关联**，但只做"补充"（高分框先匹配，低分框再与剩余轨迹匹配）。
- 解决：遮挡时检测分数下降但不代表目标消失——ByteTrack 避免"假死"。

### 3.4 AB3DMOT（3D 版本）——"3D IoU 匈牙利"

- SORT 的 3D 版：状态含 3D 中心 + 尺寸 + 朝向，匹配代价用 3D IoU（或 BEV IoU）。
- 常见于 nuScenes/Waymo 评测。

## 四、3D MOT 的特殊挑战（vs 2D）

| 挑战 | 说明 | 应对 |
|------|------|------|
| **3D 位置误差大** | 深度估计/检测的 z 误差大 | 用 BEV 平面做关联（BEV IoU 更稳） |
| **朝向估计抖动** | 角度回归不稳定 | 状态含 yaw，卡尔曼平滑 |
| **尺寸变化** | 大车/小车的尺寸尺度差 | 检测尺寸 + 卡尔曼联合估计 |
| **遮挡** | 3D 场景遮挡更常见 | 运动预测（卡尔曼）+ ByteTrack 低分关联 |
| **跨模态关联** | LiDAR 检测 + 相机检测要合并 | 多模态关联（[[多传感器融合基础]]） |

> [!note] 3D 跟踪的常用做法（工地实践）
> **检测（CenterPoint/BEVFormer）→ BEV 空间 3D IoU 匈牙利关联 → 卡尔曼（含 x,y,z,vx,vy,vz,yaw）→ 轨迹管理（出生/死亡）**。很多团队用 AB3DMOT 风格，再叠加 ByteTrack 的低分关联。

## 五、评估指标

| 指标 | 含义 |
|------|------|
| **MOTA** | 跟踪准确度（漏检/误检/ID 切换综合） |
| **AMOTA** | 平均 MOTA（不同阈值下平均） |
| **ID Switch** | 同一目标被换了 ID 的次数（关键：越少越好） |
| **mAP** | 检测质量（跟踪的上游） |
| **FPS** | 实时性（智驾量产硬指标） |

> 面试口述："3D MOT 主要看 **AMOTA + ID Switch + 速度**——准确、稳定、实时，三者缺一不可。"

## ✅ 自测一下（先想答案，再点开）

> [!question] Q1：跟踪里的卡尔曼滤波，预测和更新分别在做什么？K 怎么影响结果？

> [!success]- 参考答案
> 预测：用运动模型（状态转移 F）把上一帧状态外推到当前帧，协方差变大（不确定性增加）；更新：用检测（观测 z）修正预测，K 权重决定信谁——K 大信观测、K 小信预测，K 由 P（预测协方差）和 R（观测噪声）共同决定。Q↑→K↑、R↑→K↓。

> [!question] Q2：SORT → DeepSORT → ByteTrack 各自解决了什么？

> [!success]- 参考答案
> SORT：卡尔曼预测 + IoU 匈牙利匹配，简单有效但遮挡后难重识别；DeepSORT：加外观 ReID 特征做双重匹配，解决遮挡重现问题；ByteTrack：低分检测框也参与关联（先高分后低分），避免遮挡时"假死"丢轨迹。

> [!question] Q3：3D 跟踪和 2D 跟踪有什么区别？

> [!success]- 参考答案
> ① 状态多维度：3D 含 z/朝向/尺寸；② 关联空间：BEV 平面 IoU 比 2D IoU 更稳；③ 误差来源不同：深度估计误差大；④ 挑战更多：朝向抖动、跨模态检测（LiDAR+相机）关联、3D 遮挡。
