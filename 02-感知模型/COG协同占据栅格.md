# COG — 协同占据栅格

> COG (Cooperative/Collective Occupancy Grid) — 多车协同感知：通过 V2X 通信共享感知信息，构建更完整的环境占据栅格。

---

## 一、为什么要协同感知

### 单车感知的局限

```
┌─────────────────────────────────┐
│  大卡车遮挡 → 盲区              │
│         🚛                      │
│  🚗 ← 我在大卡车后面           │
│  看不见交叉路口的来车！         │
└─────────────────────────────────┘
```

| 问题 | 原因 | 后果 |
|------|------|------|
| **遮挡盲区** | 被大车/建筑遮挡 | 无法检测被遮挡的目标 |
| **远距离感知退化** | 传感器物理限制 | 远处物体检测不准 |
| **视角局限** | 单辆车只有 6-8 个相机 | 无法看到背后/被挡的物体 |
| **感知不确定性** | 单视角信息不足 | 遮挡区域的占据状态不明确 |

### 协同感知的优势

```
            ┌──────────────────────┐
            │  🚙 (前车)          │
            │  看到前方自行车      │
            │  ↓ V2V 共享信息     │
  🚗 (我)  │                       │
  收到共享信息 → 感知到自行车      │
  即使我的相机被前车遮挡！         │
            └──────────────────────┘
```

## 二、COG 核心概念

### 占据栅格 (Occupancy Grid)

将环境划分为离散栅格，每个格子标记为：
- **占据 (Occupied)**：有物体
- **空闲 (Free)**：可通行
- **未知 (Unknown)**：无观测信息

### 协同占据栅格 (COG)

多个智能体（车辆、路侧单元 RSU）各自维护占据栅格，通过通信共享、融合：

```
Agent 1 的占据栅格 ──┐
Agent 2 的占据栅格 ──┼──→ 融合 → 全局占据栅格 → 规划决策
路侧单元的占据栅格 ──┘
```

## 三、COG 技术架构

### 1. 单车占据预测

```
Camera/LiDAR → 特征提取 → 视图变换 → BEV/3D 占据栅格
```

基于 [[占据网络与GOD]] 的技术。

### 2. 通信共享

| 通信内容 | 数据量 | 优势 | 劣势 |
|----------|:--:|------|------|
| **原始数据** | 极大 | 信息无损 | 带宽不够 |
| **中间特征** | 大 | 较好平衡 | 对通信质量要求高 |
| **检测结果** | 小 | 轻量 | 信息损失大 |
| **占据栅格** | 中 | 结构化、易融合 | 需压缩/量化 |

**主流方案**：共享中间特征或占据栅格。

### 3. 融合策略

#### 加权平均融合

```
O_fused(x,y,z) = Σ w_i × O_i(x,y,z)
```

简单但未考虑信息质量和冲突。

#### 贝叶斯融合

```
P_fused(O|Z1,Z2) = P(O|Z1) × P(O|Z2) / [P(O|Z1)P(O|Z2) + P(F|Z1)P(F|Z2)]
```

考虑每个智能体的观测不确定性。

#### Transformer 融合 (CoHFF / V2VFormer)

```
各智能体的占据特征 → Cross-Attention 交互 → 融合特征 → 统一占据预测
```

端到端学习融合，允许复杂的特征交互。

## 四、主流协同感知方法

### CoHFF (2024)

> Collaborative Hybrid Feature Fusion

```
Agent 1: 图像 → 语义特征 + 占据特征
Agent 2: 图像 → 语义特征 + 占据特征
                    ↓
            V2X 共享平面语义特征
                    ↓
          ┌── Task Feature Fusion ──┐
          │ 语义特征 ↔ 占据特征融合  │
          └─────────────────────────┘
                    ↓
              统一 3D 语义占据
```

**关键创新**：
- 拆分语义和占据两个任务 → 分别预训练 → 融合
- 共享 TPV 模式中的两个平面 (XZ, YZ)

### V2VFormer / V2VFormer++

基于 Transformer 的多车特征交互：
```
各车提取 BEV 特征 → Global Transformer (全局交互) → Local Transformer (局部精修)
```

### V2X-ViT

统一处理 V2V 和 V2I (Vehicle-to-Infrastructure) 感知，用 ViT 模型做特征融合。

## 五、动态占据栅格 (DOG)

### 静态 vs 动态

| 静态占据栅格 | 动态占据栅格 (DOG) |
|-------------|-------------------|
| 每个格子只有占据状态 | 格子有占据 + 速度/运动状态 |
| 描述当前帧环境 | 可以预测未来状态 |
| 无法区分静态/动态障碍 | 支持轨迹预测 |

### DOG 实现

常用**粒子滤波器** (Particle Filter) 追踪每个格子的动态：

```
1. 每个占据格子维护一组粒子
2. 粒子携带位置 + 速度
3. 每帧根据观测更新粒子分布
4. 输出：占据概率 + 速度分布
```

## 六、关键挑战

| 挑战 | 说明 | 研究方向 |
|------|------|----------|
| **通信延迟** | V2X 传输有不可忽略的延迟 | 预测补偿、异步融合 |
| **通信带宽** | 无线信道有限，不能传整张特征图 | 特征压缩、关键点选择 |
| **异构性** | 不同车的传感器配置不同 | 统一表示、领域自适应 |
| **定位误差** | GPS/IMU 误差 → 融合对齐不准 | 鲁棒融合、在线标定 |
| **安全/隐私** | 共享感知数据有安全隐患 | 联邦学习 (FedBEVT) |
| **真实数据缺乏** | 协同感知数据集少 | 仿真 + 真实混合训练 |

## 八、与 BEV/占据的关系

```
BEV 感知 ──→ 占据网络 (OccNet) ──→ COG 协同占据 ──→ 端到端规划
   │              │                    │
   │    2D BEV → 3D Occ       多车共享 Occ
   │    (单车)                 (多车协同)
```

**演进方向**：
1. 单车 BEV → 单车 Occupancy → 多车 COG → 全局世界模型
2. 从"我能看到什么"到"我们能看到什么"
