## 一、相机模型

### 1.1 针孔相机模型——从"小孔成像"说起

你小时候可能玩过：一个暗盒开一个小孔，外面的景象会倒立地投影在盒内壁上。这就是**针孔相机**，也是所有相机模型的起点。

```
                物体（3D）
                  ▲
                  │
        ──────────┼───────────  小孔（光心）
                  │  Z（深度）
                  ▼
             成像平面（2D）
             物体在这里"倒立成像"
```

**关键观察：物体越远，像越小**。为什么？看侧面视角（相似三角形）：

```
        物高 H
     ┌──────────┐
     │          │
     └──────────┘
          │
          │ Z（物距）
          ▼
        ◯ ← 小孔（光心）
          │ f（焦距）
          ▼
     ┌──────────┐
     │  像高 h   │  ← 成像平面
     └──────────┘

相似三角形 → h / f = H / Z → h = f · H / Z
```

**这就是整个投影几何最核心的公式：`像高 = 焦距 × 物高 / 深度`。** 深度 Z 越大，像越小；焦距 f 越大（长焦），像越大。记住它，整篇都通了。

### 1.2 投影方程（完整版）

一个 3D 世界点怎么变成 2D 像素？两步：

```
第 1 步：世界坐标 → 相机坐标（用外参 [R|t]）
第 2 步：相机坐标 → 像素坐标（用内参 K，核心是"除以深度"）

s · [u, v, 1]ᵀ = K · [R|t] · [X, Y, Z, 1]ᵀ
```

其中：
- `(X, Y, Z)`：世界坐标系中的 3D 点
- `[R|t]`：外参（旋转 + 平移），把世界坐标搬到相机坐标系
- `K`：内参矩阵（3×3）
- `s`：深度（正是第 1.1 节里的 Z）
- `(u, v)`：最终像素坐标

> [!note] 为什么要写 `s·[u,v,1]` 而不是直接写 `[u,v]`？
> 因为 3D → 2D 有个"除以深度"的步骤，写成齐次坐标后，除法被吸收进等式左边的 `s` 里，整个变换就能用**一个矩阵乘法**表达。这就是齐次坐标的意义——**让"除法"变成"线性变换"，方便计算和求导**。

### 1.3 内参矩阵 K——相机的"出厂设置"

```
K = [ f_x   0   c_x ]
    [  0   f_y  c_y ]
    [  0    0    1  ]
```

| 参数 | 含义 | 直觉 |
|------|------|------|
| `f_x, f_y` | 焦距（像素单位） | 物距相同时，f 越大成像越大（长焦）；f_x ≠ f_y 说明像素不是正方形 |
| `c_x, c_y` | 主点偏移（像素） | 光轴和成像平面的交点通常在图像中心附近，但不完全在中心 |

> [!warning] 一个很实用的换算
> 焦距的像素单位 `f_x = f_mm / 像素尺寸`。比如传感器上每毫米有 100 个像素，焦距 4mm → f_x = 400 像素。**像素焦距直接决定了"这个相机看多远、多宽"**——BEV 模型里相机选型、分辨率配置都靠它。

### 1.4 外参 [R|t]——相机装在哪、朝哪看

- **R**（3×3 旋转矩阵）：相机相对世界坐标系的朝向（车头朝哪、相机俯仰多少度）。
- **t**（3×1 平移向量）：相机在世界坐标系中的位置。
- 合起来 [R|t] 回答一个问题：**"世界坐标系里的点，在我（相机）看来在哪？"**

> [!note] ego pose 也是 [R|t]
> 自车在世界坐标系里的位姿同样用 [R|t] 表示。**整个自动驾驶定位系统（IMU/GNSS/SLAM）输出的就是这样一个位姿**。所以"外参"和"位姿"本质是同一个数学对象，只是参考系不同。

### 1.5 畸变——现实世界没有完美镜头

真实镜头有加工误差，成像会发生形变：

| 畸变类型 | 原因 | 表现 |
|----------|------|------|
| **径向畸变** | 镜片弯曲 | 桶形（中间凸）/ 枕形（四角拉长） |
| **切向畸变** | 镜头与传感器不平行 | 图像整体倾斜偏移 |

**为什么自动驾驶必须矫正畸变？** BEV 感知要把像素精确投影到 3D 地面坐标，畸变不矫正，投影位置会偏几个像素——在 100 米外可能就是 1-2 米的误差。**所有 BEV 模型的数据管线第一步都是去畸变。**

## 二、坐标系变换——自动驾驶的"地图导航"

### 2.1 四级坐标系

```
世界坐标系 (World)      ← 绝对地图坐标（经纬度/UTM）
    ↓ [ego pose]         ← 自车在哪（定位系统的输出）
自车坐标系 (Ego/Vehicle) ← 车体中心：X 前、Y 左、Z 上
    ↓ [camera extrinsics] ← 相机装在哪（标定的输出）
相机坐标系 (Camera)      ← 光心为原点
    ↓ [intrinsics / 投影] ← 除以深度 + 乘内参
图像坐标系 (Image/Pixel) ← (u, v) 像素坐标
```

> [!note] 每级变换都回答一个"搬到哪"的问题
> - 世界 → 自车：**定位**（车在世界哪里）
> - 自车 → 相机：**标定**（相机在车上哪里、朝哪看）
> - 相机 → 像素：**投影**（3D 变 2D）
>
> **"把图像像素对应到世界坐标" = 把这条链倒着走一遍。** BEV 感知的核心工作之一，就是反复在这条链上"前进/后退"。

### 2.2 BEV 中的坐标变换链（后向投影，重要！）

BEV 感知最常用的是"3D → 2D"方向：

```
BEV Grid (x, y) → 3D 世界点 (x, y, z_pred) → 相机坐标 → 像素坐标 (u, v)
                                                          ↓
                                                   在 2D 特征图上采样
                                                          ↓
                                              得到该 BEV 格的视觉特征
```

**逐步解释（这是 BEVFormer 的核心步骤）：**
1. BEV 网格每个格子有一个已知的地面坐标 (x, y)，比如 (20, 3) = "前方 20 米、偏右 3 米"。
2. 假设一个高度 z（比如 1 米），得到 3D 点 (20, 3, 1)。
3. 用外参把该 3D 点从世界坐标搬到每个相机的相机坐标。
4. 用内参投影成像素 (u, v)。
5. 在图像特征图的 (u, v) 处采样特征，作为这个 BEV 格子的视觉证据。

> [!tip] 为什么这里"假设一个高度"？
> 一个 BEV 格子的地面坐标是确定的，但"物体有多高"不知道。BEVFormer 的做法是沿竖直方向放几个锚点（多个高度采样），让网络自己决定"这一层高度上有没有东西"。这比假设"所有物体贴地"更鲁棒——**立交桥、行人、货车高度都不同**。

## 三、投影方式分类——BEV 感知的两大路线

### 3.1 显式投影（LSS 方式）："先抬升，再拍平"

```
2D 图像特征 + 深度估计 → 3D 体素 (Frustum Voxels) → 拍平 → BEV 特征
```

**流程：**
1. 对每个像素预测"深度分布"（比如 0-50 米分成 40 个区间，每个区间的概率）。
2. 像素特征 × 深度分布 → 把 2D 特征"抬升"到 3D 空间（形成视锥 frustum）。
3. 把 3D 空间按 BEV 网格"拍平"（sum pooling），得到 BEV 特征。

**代表方法**：LSS、BEVDet、BEVDepth、BEVDet4D

**优点**：显式、可解释——你能看到"网络认为这个像素在哪个深度"。
**缺点**：**深度估计不准，整个 BEV 就歪了**（误差会随距离放大）。

### 3.2 隐式投影（Transformer 方式）："直接问图像要答案"

```
BEV Queries → Cross-Attention → 直接查询图像特征 → BEV 特征
```

**流程：**
1. BEV 网格上的 query 通过内外参投影到图像（见 2.2 的变换链）。
2. 在投影点附近做（Deformable）Cross-Attention，直接采样图像特征。
3. 网络**在训练中自己学会**"哪些图像区域对这个 BEV 格子有用"——深度信息被隐式编码进注意力里。

**代表方法**：BEVFormer、PETR

**优点**：端到端学习，**不依赖显式深度预测**，避免了"深度不准 → 全盘皆输"的级联误差。
**缺点**：计算量大（注意力贵），且"黑盒"——不好解释网络到底怎么理解的深度。

> [!note] 两条路线的本质区别（务必记住）
> - **显式（LSS 派）**：把深度当作"中间变量"**明确算出来**，再搬特征。—— "先量距离，再搬东西"。
> - **隐式（Transformer 派）**：**不单独算深度**，让网络在"查询-采样"过程中隐式学会 3D 关系。—— "凭经验直接拿"。
>
> 这也解释了为什么 BEVDepth 要用 LiDAR 监督深度：既然你显式算深度，那就把深度算准点（用真值监督）。而 BEVFormer 没有这个包袱——它压根不输出深度。

### 3.3 前向投影 vs 后向投影

| 方向 | 描述 | 方法 | 直觉 |
|------|------|------|------|
| **2D → 3D**（前向） | 图像像素"抬升"到 3D 空间 | LSS、BEVDet | 从像素出发，往上"长"出深度 |
| **3D → 2D**（后向） | 3D 采样点投影回图像查询 | BEVFormer、PETR | 从地面格子出发，往图像"要"特征 |

> [!warning] 前向投影的一个经典问题
> 前向投影后，BEV 网格上有的格子"分到"了很多像素特征，有的格子（远处）可能一个都没有——**特征分布不均匀**。后向投影每个 BEV 格子都主动去采样，天然均匀。这是 BEVFormer 系的一个隐性优势。

## 四、深度估计——单目的"阿喀琉斯之踵"

### 4.1 为什么深度估计这么难

单目相机成像时，**深度信息被"压扁"了**：3D 空间里同一条射线上不同距离的点，会落到同一个像素上。

```
        ● 距离 5 米            ● 距离 50 米
         │                      │
         ▼                      ▼
         └──────────◯──────────┘
         （同一个像素位置）
```

所以**"看单个像素，无法知道它对应的 3D 点有多远"**——这是几何上无解的问题（信息在投影时丢失了）。模型只能靠"猜"（用先验：车底贴地、物体大小已知、阴影、上下文……）。

### 4.2 各种"猜深度"的办法

| 方法 | 思路 | 代表 | 直觉 |
|------|------|------|------|
| **深度分布预测** | 预测每个像素的离散深度概率分布 | LSS、BEVDet | 不猜一个值，猜"概率分布"（更像分类） |
| **深度监督** | 用 LiDAR 点云投影到图像当深度真值 | BEVDepth | 用激光雷达的"精确测量"教相机"看距离" |
| **双目/时序** | 多视角几何（视差）重建深度 | BEVStereo | 两个眼睛看同一个点，三角测距 |
| **隐式学习** | Transformer 注意力隐式编码深度 | BEVFormer、PETR | 不显式输出深度，让网络自己悟 |

> [!note] 为什么"深度分布"比"深度回归"好？
> 直接回归一个深度值（比如 23.7 米），网络必须"蒙"得很准，且遮挡边界处深度突变，回归很难。预测**分布**（"大概在 20-25 米，峰值 23 米"）更平滑、更好训练，还能保留不确定性——这正是 LSS 用分类思路做深度的原因。

## 五、3D 数据表示——"把世界装进模型"的四种容器

### 点云（Point Cloud）——LiDAR 的原始语言

- LiDAR 直接采集：每个点有 (x, y, z) 坐标 + 反射强度。
- **稀疏**（一帧 10-20 万点）、**无序**（点的顺序没意义）、**精确**（毫米级距离）。
- 处理难点：无序性 → 不能直接用 CNN（CNN 要求规则网格）。常见做法：FPS（最远点采样）降采样、PointNet 这类对称函数直接处理无序点。

### 体素（Voxel）——把 3D 空间切成"骰子"

- 把 3D 空间划分成均匀网格（如 0.1m³ 一个格子），点云落进各自格子。
- **优点**：规则结构 → 可以直接用 3D CNN。
- **缺点**：分辨率 × 显存矛盾——分辨率翻倍，格子数变 8 倍。全空间体素化非常贵，所以常和"稀疏卷积"配合（只在有点的格子计算）。

#### 体素怎么处理（三步流程）

**① 体素化（Voxelization）——散点装进格子**

点云是"无序散点"（CNN 处理不了），体素化的作用 = **把无序变有序**：

```python
import numpy as np

def voxelize(points, voxel_size=0.2, grid_range=(-50, 50)):
    """点云 → 体素索引。points: [N, 3] 每个点 (x, y, z)"""
    indices = np.floor((points - grid_range[0]) / voxel_size).astype(int)
    return indices  # [N, 3] 每个点属于 (vx, vy, vz) 格子

# 每个格子聚合落进来的点（取均值/最大值）→ 格子特征
# 常见聚合：格子内所有点的 (x, y, z, intensity) 平均 + 点数量
```

**② 稀疏卷积（SparseConv）——只算"有东西"的格子（关键！）**

3D 空间 90% 是空气，全算浪费：

```
稠密 3D CNN:  所有 64 万个格子都算 → 90% 白算，显存爆炸
稀疏卷积:     只算"有点的格子"（通常 <5%）→ 显存省 20 倍（工业界标配）
```

**③ 体素 → 下游（两个方向）**

```
方向 1（3D 检测）: 体素特征 → 3D 稀疏 CNN → 检测头 → 3D 框（CenterPoint 系）
方向 2（BEV）:     体素沿 Z 轴"压扁"（sum pooling）→ BEV 特征图
                   ↑ 这就是 [[BEVDet与BEVDepth]] 的 Voxel Pooling
```

> [!warning] 体素三个必懂认知（面试/理解要点）
> ① **体素 ≠ 点云**：点云是原始测量（精确但无序），体素是规则化表示（有序但格子内细节被平均掉）；② **分辨率是双刃剑**：0.1m³ 的格子数是 0.2m³ 的 8 倍——"分辨率 × 显存"权衡；③ **稀疏性是核心挑战**：3D 空间极稀疏 → 稀疏卷积是标配（不然算不动）。
> **关联**：[[BEVDet与BEVDepth]] 的 Voxel Pooling（体素拍平到 BEV）、[[占据网络与GOD]] 的 Occupancy（给每个体素打"有没有+语义"标签）——体素处理的两个主要出口。

### 柱体（Pillar）——只在平面上切分

- **只在 XY 平面切格**，Z 方向不切（一个柱子贯穿整个高度）。
- 点云 → 每个柱子内聚合成一个特征（如取均值/最大值）。
- **PointPillars** 是经典方法。**平衡了稀疏性和结构规则性**：柱子数是"地面格子数"，远小于体素数，算得快。

### BEV 栅格——3D 体素在 Z 方向的"压缩"

- 把体素沿高度方向压缩成一张 2D 特征图（每个格子 = 一个柱子的聚合）。
- **为什么最常用**：下游规划天然在平面坐标系工作（车是在地面上开的）；2D 卷积处理 BEV 特征又快又成熟。
- 代价：**丢失高度信息**——所以纯 BEV 检测分不清"立交桥上层"和"地面"（这是占据网络出现的动机之一，见 [[占据网络与GOD]]）。

### 三视角平面（TPV）——三张"正交剖面"

- 三个正交平面：XY（俯视）、XZ（前视）、YZ（侧视）。
- 每个 3D 位置都落在三张平面上的投影处，三个特征相加 = 该位置的表示。
- **TPVFormer** 的核心思想：**用"三个 2D 平面"近似完整 3D 表示**，显存开销远小于真 3D 体素，又比纯 BEV 多保留了高度信息。

> [!note] 五种表示的记忆框架
> 从"信息完整度 × 计算成本"两个维度排序：
> **点云**（最原始、最稀疏）→ **体素**（规则化，贵）→ **柱体**（平面切分，便宜）→ **BEV 栅格**（Z 压缩，最常用）→ **TPV**（三视角折中，保留高度）。
> BEV 感知的演进史，很大程度就是"怎么在这几种容器之间做信息与成本权衡"的历史。

## 六、关键概念速记

| 概念 | 含义 | 一句话记忆 |
|------|------|-----------|
| **FOV** | 视场角 | 相机"看得多宽"（如 120° 广角） |
| **Voxel** | 3D 体素 | 3D 空间的"像素"（如 0.2m³） |
| **Ego-motion** | 自车运动 | 用于时序对齐（车动了，坐标系要跟着搬） |
| **齐次坐标** | (X, Y, Z, 1) 形式 | 把"除以深度"变成矩阵乘法 |
| **双目视差** | 两眼看到的水平差 | 视差越大 → 物体越近 |
| **LSS** | Lift-Splat-Shoot | BEV 显式投影的鼻祖范式 |
| **Frustum** | 视锥 | 一个像素沿射线延伸的 3D 柱体 |
| **外参标定** | 求 [R\|t] | 回答"相机装在车的哪里、朝哪看" |

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为内参是"相机固定不变的"**——内参随焦距、分辨率、畸变而变化；换相机、改分辨率都要重新标定或换算。
> 2. **混淆投影方向**——LSS 是"像素抬升到 3D"（2D→3D），BEVFormer 是"3D 点投影到图像采样"（3D→2D）。方向反了，整个理解就乱了。
> 3. **以为 BEV 有"高度"**——BEV 栅格是 Z 压缩的 2D 图，不区分高度。想区分高度要么用多高度锚点，要么升级到占据网络。
> 4. **忽略去畸变**——不矫正畸变就做投影，远处误差随距离放大，BEV 特征全是歪的。
> 5. **以为"深度 = 距离"**——深度是相机坐标系下的 Z 值（沿光轴），不是欧氏距离。差别在侧向视角时很明显。

## ✅ 检验自己（自测题）

> [!question] Q1：用相似三角形解释"为什么物体越远看起来越小"。
> 提示：像高 = 焦距 × 物高 / 深度。

> [!success]- 参考答案
> 成像平面、光心、物体构成相似三角形：像高/物高 = 焦距/深度，即像高 = f·H/Z。深度 Z 在分母，Z 越大像越小；焦距 f 在分子，f 越大（长焦）像越大。

> [!question] Q2：写出完整投影方程，并解释每个符号的含义。为什么需要齐次坐标？
> 提示：先外参后内参，除法被吸收进 s。

> [!success]- 参考答案
> s·[u,v,1]ᵀ = K·[R|t]·[X,Y,Z,1]ᵀ。(X,Y,Z) 是世界 3D 点；[R|t] 外参把世界坐标搬到相机坐标；K 内参（焦距、主点）把相机坐标变像素；s 是深度。3D→2D 有"除以深度"的非线性步骤，用齐次坐标可以把它写成统一的矩阵乘法，便于计算和求导。

> [!question] Q3：BEV 感知的"后向投影"具体是怎么做的？和 LSS 的"前向投影"有什么本质区别？
> 提示：出发点不同——一个从地面格子出发，一个从像素出发。

> [!success]- 参考答案
> 后向投影：BEV 格子 (x,y) → 加高度得 3D 点 → 外参变相机坐标 → 内参投影成像素 (u,v) → 在图像特征图上采样，作为该格子的特征。前向投影（LSS）：每个像素先预测深度分布，把 2D 特征"抬升"成 3D 视锥，再按 BEV 网格拍平。本质区别：一个显式算深度再搬特征（深度错则全错），一个靠注意力隐式学 3D 关系（端到端，但黑盒、算力大）。

> [!question] Q4：为什么单目深度估计本质上"不可能完美"？
> 提示：想想一条射线上不同距离的点会怎样。

> [!success]- 参考答案
> 单目投影时，3D 空间同一条射线上的所有点落到同一个像素，深度信息在投影这一步被数学性地丢失了。所以单像素无法确定深度，只能靠先验（物体大小、贴地假设、上下文）"猜"或"估计分布"，天然存在不确定性。

> [!question] Q5：BEV 栅格和占据网络（3D 体素）的主要区别是什么？分别适合什么场景？
> 提示：一个丢高度，一个保留高度。

> [!success]- 参考答案
> BEV 栅格是 3D 空间沿 Z 方向压缩的 2D 图，丢高度信息，但计算快、天然匹配平面规划，适合常规目标检测/分割；3D 占据保留完整高度信息，能区分立交桥上下层、悬空障碍物等不规则几何，适合更精细的通用障碍物感知（如 [[占据网络与GOD]]）。代价是显存和算力大幅上升。

## 🛠 动手练习

### 练习 1：手算一次完整投影（15 分钟）

给定一个世界点 `P = (10, 2, 5)`（单位米），相机外参为**单位变换**（相机就在世界原点、无旋转），内参 `K = [1000, 0, 640; 0, 1000, 360; 0, 0, 1]`（图像 1280×720）。

手算：
1. 相机坐标 = 世界坐标（因为外参为单位变换），即 (X, Y, Z) = (10, 2, 5)。
2. 像素坐标：u = 1000 × 10 / 5 + 640，v = 1000 × 2 / 5 + 360。
3. 验证：深度 Z=5 时算出的 (u, v)；再把 Z 改成 50，看看像素怎么变化。

> [!tip] 做完后自问
> Z 从 5 变 50，u 怎么变？（u 越来越接近主点 640——物体"向画面中心收缩"，这就是"远小"的数字体现。）

### 练习 2：用 numpy 实现投影与反投影（30-60 分钟）

```python
import numpy as np

def project(points_3d, K, R, t):
    """3D 点投影到像素。points_3d: [N, 3]"""
    pts_cam = (R @ points_3d.T + t.reshape(3, 1)).T      # 世界 → 相机
    depth = pts_cam[:, 2]                                  # 深度 Z
    pts_pix = K @ pts_cam.T                                # 相机 → 像素（未除深度）
    pts_pix = pts_pix / pts_pix[2]                         # 除以深度（齐次归一化）
    return pts_pix[:2].T, depth

K = np.array([ [1000, 0, 640],
              [0, 1000, 360],
              [0, 0, 1] ], dtype=float)
R = np.eye(3)          # 无旋转
t = np.zeros(3)        # 相机在世界原点

pts = np.array([ [10, 2, 5], [20, 4, 10], [0, 0, 1.5] ])   # 三个 3D 点
pix, dep = project(pts, K, R, t)
print("像素坐标:\n", pix)
print("深度:", dep)
```

> [!tip] 做完后自问
> ① 第 1 个点 (10,2,5) 和第 2 个点 (20,4,10)——它们的深度差一倍，像素坐标差多少？体会"远小"和"投影尺度"。② 把 t 改成 `[0, 0, -1]`（相机向后挪 1 米），所有像素怎么变？③ 试试真实的旋转矩阵（绕 Z 轴转 30°），看投影怎么倾斜。
