# 多传感器融合基础

> 一句话导读：没有一种传感器是完美的——相机"看得清但没距离"，LiDAR"有距离但认不出"，Radar"测速准但看不清"。融合就是让它们优势互补，合起来比任何一个都可靠。本篇讲清楚"为什么必须融合、在哪个环节融合、怎么融合"。

> [!tip] 用一个"盲人摸象"的变体来理解融合
> 相机像"眼睛"：看得到颜色、纹理、是谁（但不知道确切距离，晚上还瞎）。
> LiDAR 像"手杖"：精确知道障碍物在哪、多高多远（但不知道它是人还是树）。
> Radar 像"耳朵"：能听出东西来了、多快（但说不清形状）。
> **融合 = 眼睛 + 手杖 + 耳朵一起用，互相补盲。** 这也是华为 ADS 坚持保留 LiDAR 的核心逻辑（见 [[华为ADS技术方案]]）。

## 一、传感器对比——先知道每个选手的"人设"

| 传感器 | 数据形式 | 优点 | 缺点 | 成本 | 一句话人设 |
|--------|----------|------|------|:--:|-----------|
| **相机 (Camera)** | 2D 图像/视频 | 语义丰富、纹理细节、分辨率高 | **无深度**、受光照/天气影响 | 低 | 眼睛：看得最清楚，但没距离感 |
| **激光雷达 (LiDAR)** | 3D 点云 | **精确 3D 位置**、全天候 | 稀疏、无纹理、远距稀疏、怕雨雾 | 高 | 手杖：距离最准，但认不出东西 |
| **毫米波雷达 (Radar)** | 点/簇 + 速度 | **测速精准**、恶劣天气可靠 | 分辨率低、杂波多 | 低 | 耳朵：速度最准，但看不清形状 |
| **超声波雷达** | 距离 | 近距离精确、极低成本 | 范围短（几米）、信息少 | 极低 | 触须：停车入库的贴身保镖 |
| **高精地图 (HD Map)** | 结构化矢量 | 先验信息、超视距 | 维护贵、不实时 | 中 | 老司机记忆：知道路况，但可能过时 |
| **IMU/GPS** | 位姿/速度 | 定位基础 | 城市峡谷/隧道/地下不可靠 | 低 | 平衡感：知道自己在哪，但会漂 |

> [!note] 关键互补关系（务必记住）
> - **相机能回答"是什么"，LiDAR 能回答"在哪"** → 两者融合 = 又知道是什么、又知道在哪。
> - **Radar 能回答"多快"**（多普勒测速），相机和 LiDAR 都做不到直接测速 → 高速场景（前车急刹）Radar 不可替代。
> - **LiDAR/Radar 不怕天黑下雨，相机怕** → 全天候可靠性靠雷达系传感器兜底。
>
> 所以"传感器数量多"不是目的，**"覆盖彼此的盲区"才是**。每多一种模态，就是多堵住一类失效场景。

## 二、融合策略——在哪个环节融合？

### 2.1 按融合位置分类（最重要的分类框架）

```
早期融合 (Early Fusion)     ← 数据/低级特征级
中期融合 (Middle Fusion)    ← 特征级（BEV 空间）⭐ 主流
晚期融合 (Late Fusion)      ← 结果级（各检测完再合并）
```

**① 早期融合（Early Fusion）：原料级混合**

- 把原始数据或低级特征直接拼在一起喂给网络。
- 优点：信息损失最少（什么都没丢）。
- 缺点：**对齐极难**——图像是 2D 规则网格，点云是 3D 稀疏无序点，两者根本没有"能直接拼"的结构；而且冗余信息太多，网络很难学会正确利用。

> [!note] 直觉
> 就像做菜：**所有食材一起下锅炖**（原料级）。火候对了味道融合最好，但火候（对齐）极难控制，一个环节坏了整锅都完。

**② 中期融合（Middle Fusion）：特征级融合 ⭐**

- 各模态先各自提取特征，**在特征空间（通常是 BEV 空间）融合**。
- 优点：**平衡了信息量和对齐难度**——不用对齐原始数据（太碎），也不只融合结果（太粗），在"语义特征"这一层融合。
- 代表：BEVFusion、TransFusion、DeepInteraction。

> [!note] 直觉
> 就像做菜：**每道菜分别炒好，再装进一个盘子**（特征级）。每道菜（模态）有自己的火候，拼盘时只做最后整合。BEV 空间就是那个"统一的盘子"——大家都投到鸟瞰图上再合并。

**③ 晚期融合（Late Fusion）：结果级融合**

- 各模态**独立完成检测**，再把各自的检测结果（框、类别）合并。
- 优点：**简单、模块独立**（一个传感器坏了不影响其他），工程上最容易实现。
- 缺点：**丢失互补信息**——相机以为"这有个东西但不确定"，LiDAR 也拿不准，结果级融合只会各报各的，无法用对方的特征互相修正。

> [!note] 直觉
> 就像点菜：**每道菜单独上桌，你自己夹着吃**（结果级）。简单，但菜与菜之间没法互相借味。

> [!warning] 一个常见误区
> "中期融合一定比晚期好"——不一定。晚期融合在**工程鲁棒性**上有巨大优势：模块解耦、可单独迭代、传感器故障时 graceful degradation（[[多传感器融合与故障降级]] 详细讲）。很多量产方案其实是"中期为主 + 晚期兜底"的混合。

### 2.2 按融合粒度分类

| 融合方式 | 数据流 | 代表方法 | 优缺点 |
|----------|--------|----------|--------|
| **Proposal-level** | 各模态生成 proposal → 融合 | MVX-Net | 简单但割裂 |
| **Point-level** | 图像特征附加到 LiDAR 点 | PointPainting | 依赖 LiDAR 质量 |
| **BEV-level** | 统一转换到 BEV 空间融合 | **BEVFusion** | 统一表示，主流方向 |
| **Query-level** | Transformer Query 交叉查询 | **TransFusion** | 灵活，端到端 |
| **Voxel-level** | 3D 体素内融合 | OccFusion | 细粒度，计算量大 |

> [!note] 记忆线索
> 融合粒度从小到大：**Point（点）→ Voxel（体素）→ Proposal（框）→ Query（可学习向量）→ BEV（统一平面）**。粒度越小越精细但越贵，粒度越大越抽象但越省。**BEV-level 和 Query-level 是当前两大主流**——前者空间统一、工程友好；后者端到端、更灵活。

## 三、主流融合框架——三个代表作

### BEVFusion（2023，MIT）——"都搬到鸟瞰图上再合并"

```
Camera Stream:     图像 → Backbone → FPN → View Transform → Camera BEV
LiDAR Stream:      点云 → Voxelization → 3D Encoder → Compression → LiDAR BEV
                                                                      ↓
                                Concat + BEV Encoder → Unified BEV Features
                                                                      ↓
                                                          Detection Head
```

**核心贡献：**
1. **在 BEV 空间统一融合**——两种模态先各自变成 BEV 特征，再直接拼接（Concat）融合。这是"中期融合"的标准范式，也是它成为后续众多方案基础的原因。
2. **预处理加速**：GPU 加速体素化（原来体素化在 CPU 上，是瓶颈）。
3. **多任务头**：同一个 BEV 特征同时做 3D 检测 + BEV 分割。

> [!note] 为什么"统一到 BEV"是关键一步？
> 相机和 LiDAR 数据形态天差地别，但**一旦都变成 BEV 特征，就是两张同样大小的"地图"**，拼接、相加、卷积全都顺理成章。BEV 不只是感知表示，更是**多模态融合的"公共语言"**——这也是为什么 BEV 范式如此重要的原因之一。

### TransFusion（2022）——"LiDAR 为主，图像来补"

```
LiDAR 点云 → Pillar Encoder → LiDAR BEV
                                  ↓
                         Transformer Decoder
                            LR → HR queries
                                  ↓
                      Cross-Attention with Image Features
                                  ↓
                          3D Bounding Boxes
```

**核心创新：**
1. **LiDAR-first 设计**：以 LiDAR 检测结果为基础（LiDAR 的 3D 位置最可靠），图像特征作为"增强信息"来补充。
2. **Soft Association（软关联）**：不强制"这个 LiDAR 点 = 那个像素"的硬对应，而是让网络**自主学习跨模态关联**——用 Cross-Attention 让检测 query 自己决定"该从图像哪里取信息"。

> [!note] "软关联 vs 硬关联"的直觉
> 硬关联：LiDAR 点投影到图像上，取那个像素的特征（点对点，死了，标定稍差就错位）。
> 软关联：query 在图像上"扫一圈"（注意力），按相关度加权取特征（活的，标定误差也能容忍）。
> 这个思想在后面 [[华为ADS端到端架构]] 的"软关联融合优于硬关联"里被放大成核心设计原则。

### DeepInteraction（2023）——"双向交互"

- **双向交互**：图像特征增强点云，点云特征反过来引导图像（不是单向的 LiDAR→Image）。
- 多轮 Encoder-Decoder 交互，让两种模态的信息充分"对话"。

> [!note] 三者的定位
> - BEVFusion = **空间统一派**（都在 BEV 上干活）
> - TransFusion = **主从分工派**（LiDAR 主、图像辅，软关联）
> - DeepInteraction = **双向对话派**（互相当老师）
> 它们代表融合策略的三个探索方向：统一空间 / 主从分工 / 双向交互。

## 四、融合中的核心挑战——"融合难不在模型，在对齐"

### 4.1 时空对齐（这是生死线）

| 挑战 | 说明 | 解决方案 |
|------|------|----------|
| **时间同步** | 相机 30Hz、LiDAR 10Hz、Radar 20Hz，频率和相位都不同 | 插值/外推到同一时间戳；硬件打时间戳（PTP 同步） |
| **空间标定** | 各传感器外参不同，需精确标定到同一坐标系 | 标定板 + 在线标定（标定漂移是量产的痛点） |
| **运动补偿** | 传感器采集期间车在动（LiDAR 一帧要扫 100ms） | IMU 补偿、运动畸变校正 |

> [!warning] 为什么"时间同步"这么难？
> 一辆 100km/h 的车，1 秒走 28 米——**10ms 的时间误差 = 28cm 的空间误差**。相机 30Hz（33ms 一帧）和 LiDAR 10Hz（100ms 一帧）之间的时间差，折算成空间误差可能达到几十厘米到一米。**不做时间同步，融合出来的"同一时刻"根本不在同一时刻**，所有下游都会错。
>
> 这是"传感器融合"和"多模态深度学习"最本质的区别：**深度学习可以容忍特征错位几个像素，融合系统容忍不了时间错位几十毫秒。** 量产工程里，同步方案（硬件同步 + 软同步）的重要性甚至超过模型本身。

### 4.2 模态差异

- **密度差异**：图像是密集规则网格（H×W），点云是稀疏无序点（10 万点/帧）——特征表示天生不兼容。
- **语义差异**：图像有纹理/颜色/文字（"禁止停车"标志），点云只有几何——信息维度不对称。
- **视角差异**：图像是透视（近大远小），点云是 3D 世界（绝对位置）——"同一个物体"在两个模态里形态完全不同。

### 4.3 计算效率

- 多模态 = 多路 Backbone（每个传感器一个特征提取器），算力需求成倍。
- BEV 投影是计算瓶颈（相机特征投影到 BEV 要处理几百万像素 × 深度）。
- 所以量产方案都在做**轻量融合模块**：减少投影开销、共享计算、蒸馏压缩。

## 五、融合评估指标——怎么判断"融得好不好"

| 指标 | 含义 | 直觉 |
|------|------|------|
| **mAP** | 3D 检测精度（BEV / 3D） | 找没找到、框得准不准 |
| **NDS** | nuScenes 综合检测指标 | mAP + 位置/朝向/尺寸/速度精度 |
| **mIoU** | 分割精度 | 语义分割质量 |
| **ATE** | 平均平移误差 | 中心点位置差多少 |
| **AOE** | 平均朝向误差 | 朝向偏多少 |
| **ASE** | 平均尺度误差 | 尺寸差多少 |

> [!note] 融合效果还有一个"隐藏指标"：鲁棒性
> 单模态方案在"传感器完好"时可能和融合方案差不多，但**相机被太阳直射、LiDAR 被泥糊住、Radar 被干扰**时，融合方案要靠其他模态兜底。**评估融合系统不能只看平均精度，还要看"单传感器失效时精度掉多少"**——这才是融合存在的意义（详见 [[多传感器融合与故障降级]]）。

## 六、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为融合 = 传感器越多越好**——多一个传感器多一路成本、一个失效点、一处标定负担。量产考虑的是"覆盖哪些失效场景"。
> 2. **忽视时间同步**——论文里融合效果好，往往因为数据是精同步的；工程里时间同步做不好，模型再强也白搭。
> 3. **混淆"特征拼接"和"融合"**——把两个特征 Concat 起来只是融合的第一步，真正的融合是**让网络学到"何时信谁"**（注意力权重、置信度建模）。
> 4. **以为 BEVFusion 是"模型创新"**——它的突破一半在工程（GPU 体素化、高效投影），一半在"统一 BEV 空间"这个设计选择。
> 5. **忽视失效模式**——只测"全传感器正常"的精度，是融合评测的最大盲区。

## ✅ 检验自己（自测题）

> [!question] Q1：用"眼睛/手杖/耳朵"的比喻，说明相机、LiDAR、Radar 各自的核心优势和致命短板是什么？它们如何互补？
> 提示：一个管"是什么"，一个管"在哪"，一个管"多快"。

> [!success]- 参考答案
> 相机（眼睛）：语义最丰富、看得清"是什么"，但无深度、怕黑暗和恶劣天气。LiDAR（手杖）：3D 位置最精确、不怕天黑，但稀疏、认不出"是什么"、怕雨雾。Radar（耳朵）：测速最准、恶劣天气可靠，但分辨率低、看不清形状。互补：相机提供语义 + LiDAR 提供精确几何 + Radar 提供速度和全天候兜底，三者合起来既知道"是什么"又知道"在哪、多快"。

> [!question] Q2：早/中/晚期融合分别在哪一级融合？各自的最大缺点是什么？
> 提示：原料级 / 特征级 / 结果级。

> [!success]- 参考答案
> 早期在原始数据/低级特征级融合：信息损失最少，但对齐极难、模态结构不兼容。中期在特征级（BEV 空间）融合：平衡了信息量和对齐难度，是主流。晚期在检测结果级融合：模块独立、工程简单、单传感器故障不影响其他，但丢失互补信息，各模态无法互相修正。注意晚期融合的鲁棒性优势在量产里很有价值。

> [!question] Q3：为什么"时间同步"是融合系统的生死线？10ms 的时间误差意味着什么？
> 提示：算一下 100km/h 的车 10ms 走多远。

> [!success]- 参考答案
> 100km/h ≈ 27.8m/s，10ms 误差 ≈ 28cm 空间错位。相机（33ms 帧间隔）和 LiDAR（100ms 帧间隔）之间的时间差折算成空间误差可达几十厘米到一米。不同时刻的数据被当成同一时刻融合，位置直接错位，所有下游任务（检测、规划）都会出错。所以硬件同步（PTP 时间戳）+ 软同步（插值外推）是融合系统的地基。

> [!question] Q4：BEVFusion 为什么选择"在 BEV 空间融合"？这解决了什么本质问题？
> 提示：想想两种模态的数据形态差异。

> [!success]- 参考答案
> 相机是 2D 透视图像、LiDAR 是 3D 稀疏点云，原始形态完全不兼容，无法直接拼接。BEV 空间把两者都变成"同一坐标系下的 2D 特征图"，等于给了多模态一个统一的"公共语言"——拼接、相加、卷积都顺理成章，下游任务（检测/分割/规划）也在同一空间工作。这是中期融合的核心价值。

> [!question] Q5："软关联"（TransFusion）和"硬关联"（点投影采样）的区别是什么？为什么软关联更鲁棒？
> 提示：标定误差发生时，两种方案分别会怎样。

> [!success]- 参考答案
> 硬关联：LiDAR 点投影到图像取固定像素特征，标定稍有误差（哪怕几像素）特征就错位。软关联：query 在图像上做注意力扫描，按相关度加权取特征，标定误差只影响权重分布，不会导致"取错位置"的硬错误。软关联把"对应关系"从手工指定变成可学习的，端到端更鲁棒。

## 🛠 动手练习

### 练习 1：纸笔设计一个融合方案（20 分钟）

场景：夜间下雨的城市路口，需要检测 50 米外的行人。只有相机 + LiDAR + Radar 三种传感器可选。
1. 写出每种传感器在这个场景下的表现（谁会失效？谁会工作？）。
2. 你选谁做主传感器、谁做补充？为什么？
3. 如果只允许带 2 种传感器，你砍掉哪个？代价是什么？

> [!tip] 参考思路
> 夜间下雨：相机弱、LiDAR 受雨雾影响但近距离仍可用、Radar 最可靠。主 LiDAR + Radar 兜底 + 相机提供语义（行人是相机最擅长的）。砍 LiDAR 则失去精确几何、砍 Radar 则失去恶劣天气兜底——没有标准答案，关键是能说出 trade-off。

### 练习 2：手算一次时间对齐（15 分钟）

相机帧时间戳 t=100ms，LiDAR 帧时间戳 t=90ms 和 t=120ms，LiDAR 在 t=90 时测得前方障碍物 x=20m，车辆速度 v=10m/s 匀速前进。
1. 用线性插值估算：t=100ms 时障碍物相对本车的位置是多少？
2. 如果不做时间对齐，直接用 t=90ms 的测量结果，位置误差是多少？

> [!tip] 算完你会发现
> 10ms 的车速 10m/s → 0.1m 误差，看似不大；但高速（28m/s）且 LiDAR 频率更低时，误差会到几十厘米——这就是"时间同步是生死线"的数字证据。

### 练习 3：用 numpy 做"特征级融合"小实验（可选，30 分钟）

生成两组模拟的 BEV 特征（同尺寸随机矩阵，一个模拟相机、一个模拟 LiDAR），对比三种融合方式的效果：
```python
import numpy as np

np.random.seed(0)
cam_bev = np.random.randn(8, 8)     # 模拟相机 BEV 特征（带语义）
lid_bev = np.random.randn(8, 8)     # 模拟 LiDAR BEV 特征（带几何）

# 方式 1：直接拼接（相当于通道 Concat）
concat = np.stack([cam_bev, lid_bev])          # [2, 8, 8]

# 方式 2：逐元素相加
add = cam_bev + lid_bev

# 方式 3：加权融合（学习"何时信谁"的雏形）
w_cam, w_lid = 0.7, 0.3
weighted = w_cam * cam_bev + w_lid * lid_bev
```
思考：三种方式分别丢失/保留了什么信息？真实网络里的"注意力融合"相比"加权融合"多了什么能力？
