## 一、卷积神经网络（CNN）

### 1.1 从一个具体问题开始

假设我们要让计算机判断一张图片里有没有猫。图片在计算机里只是一堆数字：一张 224×224 的彩色图 = 224 × 224 × 3 个数字（宽 × 高 × RGB 三通道）。

如果用一个"全连接"网络来处理：把 15 万个像素全部拉平，第一层每个神经元都要和所有像素相连，参数量爆炸到不可接受，而且**图片的空间结构（上下、左右相邻的像素属于同一个物体）完全丢失了**。

**卷积神经网络（CNN）的核心思想就是：利用图片的局部性和平移不变性，用"小窗口扫描"代替"全图连接"，把参数量降几个数量级。**

> [!note] 两个关键直觉
> - **局部性**：图片里一个物体只占一小块区域，识别它不需要看整张图。猫的耳朵是局部特征，鼻子也是局部特征。
> - **平移不变性**：猫在图片左边还是右边，都是同一只猫。同一个特征（比如"耳朵轮廓"）应该在图片任何位置都能被识别出来。

### 1.2 卷积层——CNN 的心脏

#### 卷积在做什么？

卷积层就是一个**小窗口（卷积核 / kernel / filter）在图片上滑动，逐格计算点积**。

```
输入图片 (5×5)               卷积核 (3×3)               输出 (3×3)
[ 1  2  3  0  1 ]          [ 1  0  1 ]
[ 0  1  2  3  0 ]          [ 0  1  0 ]          →  对每个位置做"核与窗口逐元素相乘再求和"
[ 1  0  1  2  1 ]          [ 1  0  1 ]
[ 0  1  0  1  2 ]
[ 1  2  1  0  0 ]
```

比如核滑到左上角 3×3 窗口 `[1 2 3; 0 1 2; 1 0 1]` 时：
`1×1 + 2×0 + 3×1 + 0×0 + 1×1 + 2×0 + 1×1 + 0×0 + 1×1 = 1+3+1+1+1 = 7`，这就是输出左上角的值。

#### 几个必须懂的超参数

| 超参数 | 含义 | 直觉 | 常见值 |
|--------|------|------|--------|
| **stride（步长）** | 窗口每次滑几格 | 越大，输出图越小，计算越快，但会丢细节 | 1 或 2 |
| **padding（填充）** | 图片四周补一圈 0 | 让边缘像素也被卷积到，保持输出尺寸 | "same"（保持尺寸） |
| **kernel size（核大小）** | 窗口尺寸 | 越大感受野越大，但参数越多 | 3×3（最常用） |

> [!warning] 新手最容易混淆的一点
> **卷积核的数量 = 输出通道数**。比如第一层有 32 个 3×3 卷积核，输出就是 32 张特征图（32 个通道）。每个核负责检测一种特征：有的检测水平边缘、有的检测垂直边缘、有的检测颜色块……**网络越深，核检测的特征越抽象**（浅层是边缘/纹理，深层是"车轮""车窗"这种语义部件）。

#### 为什么"共享权重"？

同一个卷积核扫过整张图——**核的权重在所有位置共享**。这就是参数量骤减的第二个原因，也是"平移不变性"的数学来源：同一个特征模板，不管出现在哪，都用同一组参数去匹配。

#### 感受野（Receptive Field）

**感受野 = 输出特征图上"一个像素"对应到输入图片上的多大区域。**

- 3×3 卷积（无 padding）堆 2 层，感受野 5×5；堆 3 层，感受野 7×7。
- 直觉：网络每一层都在"看得更远"，所以深层的特征图每个像素代表的是输入图上一个较大区域的信息。
- 自动驾驶里为什么要关心？因为**小目标（远处的行人、锥桶）需要更大的感受野才能"看见"**，这就是后面 FPN 多尺度特征存在的意义。

### 1.3 池化层——压缩信息，扩大视野

池化就是"取一小块区域的代表值"：

```
2×2 窗口, stride=2:
MaxPool:  取最大值 → [ 2  3 ]     （保留最强响应）
          取平均 → [ 1.5 1.5 ]    （保留整体强度）
```

**为什么需要池化？**
1. **降采样**：图片缩小一半，计算量减 75%，防止过拟合。
2. **扩大感受野**：每一层池化，后续卷积的"视野"直接翻倍。
3. **增强平移鲁棒性**：物体挪动几个像素，MaxPool 结果往往不变。

> [!tip] 现代趋势
> 现在很多新网络（如 ResNet 后期、ViT）**用 stride=2 的卷积代替池化**，效果相当且更灵活。但理解池化依然是读懂经典网络的基础。

### 1.4 激活函数——给网络"非线性"

如果没有激活函数，多层卷积叠起来 = 一次线性变换，网络再深也没用（等于一层）。激活函数给网络**拟合任意复杂函数的能力**。

| 函数 | 公式 | 特点 | 使用场景 |
|------|------|------|----------|
| **ReLU** | `max(0, x)` | 简单、快、缓解梯度消失 | 最经典 |
| **GELU** | 平滑版 ReLU | Transformer 默认选择 | ViT、BEVFormer |
| **SiLU / Swish** | `x·sigmoid(x)` | 平滑、效果好 | 很多新检测头 |

> [!note] ReLU 为什么有效（直觉）
> 负值直接变成 0 = 让不相关的特征"闭嘴"，网络因此变得**稀疏**：每个神经元只对特定模式响应。这既省计算，又天然带正则化效果。

### 1.5 批归一化（BatchNorm）——稳定训练的神器

**问题**：训练时每层输入的分布一直在变（前面层的参数在更新），网络学得很痛苦，学习率稍大就震荡甚至发散。这叫 **Internal Covariate Shift**。

**BatchNorm 的做法**：对每个 batch，把每个通道的激活值标准化到均值为 0、方差为 1，再乘一个可学习的缩放 γ 和偏移 β。

```
x̂ = (x - μ_batch) / √(σ²_batch + ε)
y = γ·x̂ + β
```

**效果**：每层输入分布稳定 → 可以放心用更大的学习率 → 训练更快更稳。**几乎现在所有 CNN 都带 BN。**

> [!warning] 陷阱
> 推理时 BN 用的是**训练时累积的全局统计量**，不是当前 batch 的。所以"训练/推理模式切换"很重要（PyTorch 里 `model.eval()` 干的就是这件事）。另外 batch 太小（比如 bs=1）时 BN 统计量噪声大，要用 GroupNorm 或 SyncBN。

### 1.6 全连接层——最后的"分类脑袋"

CNN 的卷积部分负责**提取特征**，全连接层（FC）负责把特征"翻译"成最终答案。

```
特征图 → 展平 (flatten) → FC 层 → 输出向量（长度=类别数，如 80 类）
```

- FC 层参数最多，所以**只在网络最后用**，中间全靠卷积。
- 现代检测/分割网络里，FC 常被 `1×1 卷积` 或 `全局平均池化 + FC` 替代，更省参数。

### 1.7 核心组件一图总结

```
输入图片
   │
   ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 卷积层        │ →  │ 激活函数      │ →  │ 批归一化      │  ← 重复堆叠
│ 提取局部特征  │    │ 加入非线性    │    │ 稳定分布      │
└──────────────┘    └──────────────┘    └──────────────┘
   │
   ▼
┌──────────────┐    ┌──────────────┐
│ 池化层        │ →  │ 卷积+激活+BN  │  ← 重复"卷积块+池化"结构，特征图越来越小、通道越来越多
│ 降采样扩视野  │    │ (更深层)      │
└──────────────┘    └──────────────┘
   │
   ▼
┌──────────────┐
│ 全连接/头      │ → 输出（类别、框、掩码……）
└──────────────┘
```

## 二、骨干网络（Backbone）

**Backbone = 提取特征的"主干网络"**。在自动驾驶里，Backbone 吃进一张图，吐出一组多尺度的特征图，后面的检测/分割头再基于这些特征做任务。

| 网络 | 年份 | 核心创新 | 一句话直觉 | 在 BEV 中的使用 |
|------|------|----------|-----------|------------------|
| **ResNet** | 2015 | 残差连接 | 给网络加"捷径"，让深层网络也能训练 | 最广泛使用的 Backbone |
| **VoVNet** | 2019 | OSA 模块 | 每个层都直接"看"前面所有层，信息流动更高效 | FCOS3D |
| **Swin Transformer** | 2021 | 层次化 Transformer | 把图片分块做注意力，兼顾全局与效率 | BEVFormer v2 |
| **InternImage** | 2023 | 可变形卷积 v3 | 让卷积核自己学会"变形"贴合物体形状 | FB-BEV |

### ResNet 的残差连接为什么重要？

**背景**：网络越深，理论上能力越强，但实际训练发现层数多了反而更差（梯度消失 + 优化困难）。

**ResNet 的解法**：不直接学 `H(x)`，而是学**残差** `F(x) = H(x) - x`，输出 `y = F(x) + x`（x 通过"捷径"直接跳过去）。

```
常规块:     输入 x → 卷积 → 卷积 → 输出 H(x)
残差块:     输入 x → 卷积 → 卷积 → F(x) ─┐
                          └──────────→ + ─→ 输出 F(x)+x
                             (捷径/恒等映射 x 直接相加)
```

**为什么有效（直觉）**：
1. 梯度可以**沿着捷径直接回传**，浅层也能收到梯度 → 解决梯度消失。
2. 如果某一层学不到有用特征，网络可以让 `F(x) ≈ 0`，退化成恒等映射——**至少不会比浅层网络差**。这给了网络"保底选项"。

> [!note] ResNet-50 的数字含义
> 数字表示层数（50 层）。ResNet-50/101 是 BEV 模型最常用的 Backbone。`resnet50` 在 ImageNet 预训练后直接拿来初始化 BEVFormer/BEVDet，是业界标准操作。

### FPN（特征金字塔网络）——让网络"远近通吃"

**问题**：自动驾驶要同时检测近处的大货车（特征图上一个"大块"）和 100 米外的行人（特征图上可能只有几个像素）。单尺度特征做不到。

**FPN 的做法**：自顶向下融合多尺度特征。

```
输入 → Backbone → C2(大图,浅层,细节多)   P2 ←── 上采样融合
                 C3                    P3 ←── 上采样融合
                 C4                    P4 ←── 上采样融合
                 C5(小图,深层,语义强)   P5 ←── 1×1 卷积
```

- **C2~C5**：Backbone 输出的不同尺度特征（越深越小、语义越强）。
- **P2~P5**：FPN 融合后的输出——**浅层特征"借用"深层语义，深层特征"借用"浅层细节**。
- 直觉：就像你看远处先认轮廓（深层语义），近处再看细节（浅层纹理），两者互补。

**为什么 BEV 感知离不开 FPN**：BEV 检测头需要在统一坐标系下检测不同距离的目标，多尺度特征直接决定了小目标召回率。

## 三、目标检测

### 3.1 任务定义

目标检测 = **在图片里找出所有物体，并框出它们**。输出是若干组：`(类别, x, y, w, h)`（类别 + 框的位置和大小）。

### 3.2 三大流派

| 流派 | 代表 | 核心思想 | 速度 | 精度 |
|------|------|----------|:--:|:--:|
| **两阶段** | Faster R-CNN | 先粗筛候选框（RPN），再逐个精修分类 | 慢 | 高 |
| **单阶段** | YOLO 系列、FCOS | 一步到位：直接同时预测框和类别 | 快 | 中高 |
| **Transformer** | DETR 系 | 用"查询向量"端到端直接输出框，不要锚框不要 NMS | 中 | 高 |

#### 两阶段（Faster R-CNN）："先圈地，再审问"

1. **RPN（Region Proposal Network）**：在特征图上铺满各种大小/比例的"锚框"（anchor），快速判断哪些区域"可能有物体"，输出约 2000 个候选框。
2. **第二阶段**：对每个候选框做精细的分类和回归（精修位置）。

> [!note] 直觉
> 就像侦探先圈出 2000 个"可疑区域"（很快，粗筛），再对每个可疑区域仔细调查（慢，精细）。

#### 单阶段（YOLO/FCOS）："一次扫描全搞定"

- **YOLO**：把图片分成 S×S 网格，每个格子直接预测它负责的物体（框 + 类别 + 置信度）。速度极快，适合实时。
- **FCOS**（anchor-free）：不用预设锚框，直接对特征图每个位置预测"到这个位置最近的物体中心的偏移"。

> [!note] Anchor-free 为什么流行
> 锚框需要人工设计几十种尺寸比例（调参地狱），FCOS 这类方法让网络自己学目标中心，简单且泛化更好。现在 3D 检测的 CenterPoint 也是这个思路。

#### DETR：把检测当成"查字典"

DETR 是 Transformer 在检测上的开山之作（后面 [[Transformer架构详解]] 会细讲）：
- 固定 100 个可学习的 **Object Query**（查询向量），每个 query 通过注意力机制"问"图片：你负责找哪个物体？
- 训练时用**匈牙利算法**把预测和真值做最优匹配（二分图匹配），**不需要 NMS 去重**。
- 自动驾驶的意义：DETR3D、PETR 把 Object Query 从 2D 平面扩展到 3D 空间，成为 BEV 感知的主流范式。

### 3.3 3D 目标检测——通往 BEV 的必经之路

2D 检测只给出图像上的框，但**自动驾驶需要在 3D 世界中知道物体的真实位置**（距离、朝向），才能规划路径。

3D 检测输出：`(x, y, z, w, h, l, θ)`
- `(x, y, z)`：3D 中心坐标（通常 z 是高度）
- `(w, h, l)`：宽、高、长
- `θ`：朝向角（车头朝哪）

| 方法 | 输入 | 核心思路 | 一句话直觉 |
|------|------|----------|-----------|
| **FCOS3D** | 单目图像 | 2D 检测 + 深度回归 | 先找到车，再估它离我多远 |
| **PGD** | 单目图像 | 几何关系图 + 深度传播 | 利用"车底贴地、大小已知"等几何约束估深度 |
| **DETR3D** | 多视图 | 3D object query 投影到 2D 采样 | 在 3D 空间问问题，去图片里找答案 |
| **PETR** | 多视图 | 3D 位置编码 + DETR | 给每个像素标上"3D 地址"，隐式完成视角变换 |

> [!warning] 单目 3D 检测的本质困难
> 单张图片里，一个像素对应空间中的**一条射线**，深度被"压扁"了（2D→3D 信息丢失）。所以单目 3D 检测的精度上限受深度估计限制——这正是后面 BEVDepth 要用 LiDAR 监督深度、BEVFormer 用 Transformer 隐式学深度的原因。

## 四、语义分割 & 实例分割

### 4.1 三个任务的区别

| 任务 | 粒度 | 输出 | 自动驾驶中的用途 |
|------|------|------|-----------------|
| **语义分割** | 像素级 | 每个像素一个类别（车道线/路面/车/人……） | 可行驶区域、车道线检测 |
| **实例分割** | 目标级 | 每个像素 + 属于哪个具体实例 | 区分"前面那辆白车"和"左边那辆白车" |
| **全景分割** | 统一 | 语义（stuff）+ 实例（thing） | 完整场景理解 |

> [!note] 直观理解
> - 语义分割回答："这个像素是车"。
> - 实例分割回答："这个像素是**第 3 辆**车"。
> - 全景分割回答："这个像素是车（第 3 辆），那个像素是路面（stuff 不区分实例）"。

### 4.2 关键模型

- **FCN / U-Net（Encoder-Decoder）**：编码器逐层压缩提特征，解码器逐层上采样恢复分辨率。U-Net 靠"跳跃连接"把浅层细节传给深层，分割效果的关键。
- **DeepLab 系列**：空洞卷积（dilated conv）在不降分辨率的前提下扩大感受野 + ASPP（多尺度空洞池化）。
- **Mask R-CNN**：检测 + 分割一起做（在 Faster R-CNN 上加一个 mask 分支）。
- **MaskFormer / Mask2Former**：统一分割范式，用 mask 分类代替逐像素分类，Transformer 化，效果 SOTA。

> [!tip] 和自动驾驶的联系
> 车道线分割、可行驶区域分割是量产 ADAS 的基础功能；在 [[BEV感知全景]] 里，分割任务和 3D 检测共享 BEV 特征（多任务头），这是 BEV 方案的一大优势。

## 五、目标跟踪

### 5.1 跟踪解决什么问题

检测是"单帧"的：每一帧独立找物体。但**自动驾驶需要知道"这一帧的这辆车 = 上一帧的那辆车"**（稳定的 ID），才能预测轨迹、判断碰撞风险。这就是跟踪。

### 5.2 三种范式

| 范式 | 全称 | 做法 | 代表 |
|------|------|------|------|
| **TBD** | Tracking-by-Detection | 每帧先检测，再把相邻帧的框关联起来 | 工业界主流 |
| **JDT** | Joint Detection & Tracking | 检测和跟踪一个网络同时完成 | CenterTrack |
| **MOTR** | Transformer 跟踪 | 用 Query 跨帧传递"这是同一个物体"的信息 | 端到端时序 |

### 5.3 跟踪的三个核心组件

1. **卡尔曼滤波（Kalman Filter）**：运动状态预测。
   - 直觉：基于"上一帧位置 + 速度假设"预测这一帧物体应该在哪（预测），再用实际检测结果修正（更新）。预测和测量的加权 = 不确定性越小越信任谁。
   - 为什么用 3D 版本：BEV 空间里物体运动近似匀速直线，3D 卡尔曼滤波比 2D 图像空间稳定得多。

2. **匈牙利算法（Hungarian Algorithm）**：框匹配。
   - 直觉：上一帧有 5 个框，这一帧检测出 5 个框，怎么一一对应？构建"匹配代价矩阵"（比如 IoU 距离），用匈牙利算法求**全局最优匹配**——注意不是贪心，是全局最省代价的配对。

3. **Re-ID 特征**：外观匹配。
   - 直觉：车被遮挡 2 秒后重新出现，位置预测失效了怎么办？靠"外观指纹"（Re-ID 特征向量）找回它。特征越相似，越是同一辆车。

> [!note] 经典组合拳（工业界方案）
> 检测器 → 卡尔曼滤波预测位置 → 匈牙利算法按 IoU+Re-ID 综合代价匹配 → 匹配失败的新框开新轨迹、连续丢失的轨迹删掉。这套流程（类似 DeepSORT）是自动驾驶感知栈的标配。

## 六、核心评估指标——必须能默写

| 指标 | 全称/含义 | 公式直觉 | 用在哪 |
|------|-----------|----------|--------|
| **IOU** | 交并比 | 两个框的重叠面积 ÷ 并集面积 | 衡量预测框有多准 |
| **NMS** | 非极大值抑制 | 同一物体保留得分最高的框，抑制重复框 | 检测后处理（DETR 系不需要） |
| **mAP** | mean Average Precision | 各类别 AP 的平均 | 检测通用指标 |
| **mIoU** | mean IoU | 各类别 IoU 的平均 | 分割通用指标 |
| **NDS** | nuScenes Detection Score | mAP 加权 + 平移/朝向/尺度/速度/属性的误差惩罚 | nuScenes 综合指标 |

### IOU 计算

```
IOU = |A ∩ B| / |A ∪ B|
     = 重叠面积 / 并集面积        → 范围 [0, 1]
```

> [!example] 数字例子
> 预测框和真值框重叠 20 像素²，并集 50 像素² → IOU = 0.4。通常 **IOU > 0.5 算检测正确**（3D 检测常用 0.7 更严格）。

### mAP 是怎么算出来的

1. 对每个类别：按置信度降序排列所有预测框。
2. 逐个和真值匹配（IOU 达标且未匹配过的），算 Precision/Recall 曲线。
3. AP = 曲线下的面积（Recall 轴上 11 个点或全部点求平均）。
4. mAP = 所有类别 AP 的平均。

> [!note] 直觉
> mAP 同时惩罚"漏检"（Recall 低）和"误检"（Precision 低），是检测任务最权威的单一指标。

### NDS 为什么比 mAP 复杂

3D 检测光框得准不够，还要**位置、朝向、尺寸、速度全都准**，车才能安全避障。nuScenes 的 NDS 在 mAP 基础上叠加 5 个误差项（ATE 平移、ASE 尺寸、AOE 朝向、AVE 速度、AAE 属性）的惩罚：

```
NDS = (mAP + Σ(1 - min(1, mATE·10))) / 6  （简化示意，实际公式见 nuScenes 文档）
```

**记住**：mAP 只管"找没找到"，NDS 还管"找得有多精确"。所以 BEV 论文里两个指标都要看。

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **以为池化是必须的**——不是，现代网络常改用 stride=2 卷积。
> 2. **以为 ReLU 只是"让负数变 0"**——关键是提供非线性，否则多层网络退化为线性。
> 3. **混淆感受野和特征图大小**——感受野是"输入上的一块区域"，特征图大小是"输出的尺寸"。
> 4. **以为 mAP 高 = 车开得好**——mAP 是感知指标，规划决策还有一大堆其他指标（碰撞率、舒适度等）。
> 5. **忽视 BN 的 train/eval 模式**——推理忘调 `model.eval()`，结果可能莫名其妙变差。

## ✅ 检验自己（自测题）

> [!question] Q1：为什么全连接网络不适合处理图片？CNN 用哪两个特性解决这个问题？
> 提示：从"参数量"和"空间结构"两个角度想。

> [!success]- 参考答案
> 全连接把图片拉平成向量，参数量爆炸（15 万像素全连接），且完全丢失相邻像素的空间关系。CNN 利用**局部性**（卷积核只看局部窗口）和**平移不变性**（权重共享，同一特征全图通用）解决：参数量大幅下降，空间结构保留在卷积核的滑动过程中。

> [!question] Q2：一个 5×5 输入，3×3 卷积核，stride=1，无 padding，输出尺寸是多少？
> 提示：`输出 = (输入 - 核 + 2×padding) / stride + 1`

> [!success]- 参考答案
> (5 - 3 + 0) / 1 + 1 = 3，输出 3×3。如果 padding=1（"same"），输出保持 5×5。

> [!question] Q3：ResNet 的残差连接解决了什么问题？为什么"恒等映射保底"这个性质重要？
> 提示：从梯度回传和网络退化两个角度。

> [!success]- 参考答案
> ① 梯度沿捷径直接回传，缓解深层网络梯度消失；② 如果某层学不到东西，残差块可以退化为恒等映射（F(x)≈0），使深层网络至少不差于浅层，解决了"越深越差"的退化问题。

> [!question] Q4：语义分割、实例分割、全景分割三者的输出有什么本质区别？
> 提示：想想"像素属于车"和"像素属于第几辆车"。

> [!success]- 参考答案
> 语义分割：每个像素给类别（不区分个体）；实例分割：每个像素给类别 + 实例编号（区分个体）；全景分割：把语义（背景 stuff，不区分个体）和实例（前景 thing，区分个体）统一在一个框架里。

> [!question] Q5：mAP 和 NDS 分别衡量什么？为什么自动驾驶两者都要看？
> 提示：一个只管"找到没有"，一个管"找得多准"。

> [!success]- 参考答案
> mAP 衡量检测的"找没找到"（漏检+误检的平衡）；NDS 在 mAP 基础上还惩罚位置/朝向/尺寸/速度的误差，衡量"找得多准"。自动驾驶需要精确的 3D 位置才能安全规划，所以两者都要看——只追求 mAP 可能框的位置偏了半米，车照样不敢开。

### 练习 1：纸笔推演卷积（10 分钟）

手算一个 4×4 输入和 2×2 核，stride=1 的卷积输出（至少算 4 个位置）。再用 stride=2 算一遍，观察输出尺寸变化。**目标**：把"滑动窗口 + 点积"刻进肌肉记忆。

### 练习 2：用 PyTorch 亲手搭一个 CNN（30-60 分钟）

```python
import torch
import torch.nn as nn

class TinyCNN(nn.Module):
    """一个极简 CNN：2 个卷积块 + 1 个分类头，在 MNIST 上应该能到 99%"""
    def __init__(self, num_classes=10):
        super().__init__()
        # 卷积块：卷积 → BN → ReLU → 池化
        self.block1 = nn.Sequential(
            nn.Conv2d(1, 32, kernel_size=3, padding=1),  # 1通道→32通道
            nn.BatchNorm2d(32),
            nn.ReLU(),
            nn.MaxPool2d(2),                             # 28×28 → 14×14
        )
        self.block2 = nn.Sequential(
            nn.Conv2d(32, 64, kernel_size=3, padding=1), # 32→64通道
            nn.BatchNorm2d(64),
            nn.ReLU(),
            nn.MaxPool2d(2),                             # 14×14 → 7×7
        )
        self.head = nn.Linear(64 * 7 * 7, num_classes)   # 全连接分类头

    def forward(self, x):
        x = self.block1(x)
        x = self.block2(x)
        x = x.flatten(1)          # 展平：[B, 64, 7, 7] → [B, 64*7*7]
        return self.head(x)

model = TinyCNN()
print(model)
# 用 torchvision 加载 MNIST 训练 3-5 个 epoch，观察 loss 下降和精度上升
```

> [!tip] 做完后自问
> ① 如果把 `kernel_size` 从 3 改成 5，参数量怎么变？② 去掉 BN 训练，loss 还稳吗？③ 把池化换成 stride=2 卷积，输出尺寸还一样吗？——这三个问题答上来，CNN 就算真入门了。
