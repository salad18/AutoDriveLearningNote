## 一、常用损失函数——"模型靠什么知道错了"

> [!note] 先建立直觉：损失函数 = 给模型"打分"
> 训练就是反复执行：模型预测 → 算损失（预测和真值差多少）→ 反向传播（把"差多少"变成梯度的方向）→ 更新参数。
> **损失函数定义了"差多少"的数学形式——它决定了模型会朝哪个方向优化、优化得多快。选错损失函数，模型训练得再好也是错的。**

### 1.1 分类损失

**CrossEntropy（交叉熵）**——最基础的分类损失：

$$L_{CE} = -\sum_{c} y_c \cdot \log(p_c)$$

> ⚠️ 问题：**对类别不平衡敏感**（见下方 Focal Loss 的动机）。

**直觉**：模型对正确类别的预测概率 p_c 越接近 1，-log(p_c) 越接近 0（损失越小）。**预测越自信且正确，损失越小**；预测错了还自信，损失爆炸。

**为什么对类别不平衡敏感**：如果 99% 的样本都是"背景"，模型只要全部预测"背景"就能拿到 99% 正确率，损失很小，但正样本（1% 的车）一个都学不会。自动驾驶里 BEV 网格大部分是背景——这正是 Focal Loss 出现的原因。

**Focal Loss（焦点损失）**——给交叉熵加"调制因子"，专治类别不平衡：

$$FL(p_t) = -(1-p_t)^{\gamma} \cdot \log(p_t)$$

- $\gamma = 0$ → 退化为标准 CE
- $\gamma = 2$ → 常用值，大幅降低简单样本权重
- $\alpha$：类别加权（如 $\alpha = 0.75$ for rare class）

> 适用：3D 检测中的正负样本不平衡（BEV grid 中大部分是背景）。

**直觉**：`(1-p_t)^γ` 是"调制因子"——预测已经很准的样本（p_t 接近 1）权重趋近 0（**简单样本：别浪费时间教了**）；预测不准的样本权重大（**难样本：重点关照**）。γ=2 时，p_t=0.9 的样本权重降为 0.01，p_t=0.5 的样本权重保持 0.25。

**Quality Focal Loss（QFL）**——将 IoU 分数作为分类标签的 soft target：

$$L_{QFL} = -|y - \sigma|^{\beta} \cdot \left( (1-y)\cdot\log(1-\sigma) + y\cdot\log(\sigma) \right)$$

> 适用：需要同时预测类别和质量的场景。

**直觉**：传统检测把"框准不准"（IoU）和"类别对不对"分开处理。QFL 把 IoU 变成分类的 **soft label**——预测的 IoU 得分 σ 要逼近真实的 IoU y，模型学会"我不仅要知道这是车，还要知道自己框得有多准"。|y-σ|^β 同样是难样本加权。

### 1.2 回归损失——"框的位置差多少"

```python
# L1 Loss: |x - y| → 对离群点不敏感, 零点不可导
# Smooth L1: 0.5x² if |x|<1 else |x|-0.5 → 兼顾两者

# GIoU Loss (Generalized IoU):
# L_GIoU = 1 - IoU + |C \ (A∪B)| / |C|
# 其中 C 是 A 和 B 的最小外包矩形 → 解决 IoU=0 时梯度消失

# DIoU Loss (Distance IoU):
# L_DIoU = 1 - IoU + ρ²(b_A, b_B) / c²
# ρ = 中心点距离, c = 最小外包矩形对角线距离
# → 中心点直接回归, 收敛更快

# CIoU Loss (Complete IoU):
# L_CIoU = 1 - IoU + ρ²/c² + α·v
# v = 4/π² · (arctan(w/h) - arctan(w_gt/h_gt))²  ← 长宽比一致
# α = v / (1 - IoU + v)  ← 动态权重
```

> [!note] 为什么从 L1 一路演进到 CIoU？（进化路线）
> 1. **L1**：算坐标差，简单。但坐标差的"像素尺度"和"框质量"脱节——差 10 像素，对大框可能无所谓，对小框就完全错了。
> 2. **Smooth L1**：小误差用平方（平滑），大误差用线性（抗离群点）——解决 L1 零点不可导、L2 对离群点敏感的问题。检测回归的默认选择。
> 3. **GIoU**：直接优化 IoU 本身。解决"预测框和真值框完全不重叠时 IoU=0、梯度消失"的问题——不重叠时用"外包矩形里没盖住的部分"兜底给梯度。
> 4. **DIoU**：GIoU 收敛慢，因为 IoU 对"中心点距离"不敏感。DIoU 把中心点距离直接加进损失，收敛更快。
> 5. **CIoU**：DIoU 不管长宽比。CIoU 再加一项长宽比一致性 v。
>
> **记忆口诀：L1（差多少）→ Smooth L1（抗离群）→ GIoU（重叠度）→ DIoU（中心距离）→ CIoU（长宽比）**。每一步都补上一个"前一步没管到的事"。

### 1.3 分割损失

```python
# Dice Loss: 直接优化 IoU
Dice = 2|X∩Y| / (|X|+|Y|)
L_Dice = 1 - Dice

# BCE + Dice (最常用组合):
L = L_BCE + λ·L_Dice  # λ 通常 0.5-1.0

# Lovász-Softmax: 直接优化 mIoU 的 surrogate
# 对类别不平衡更鲁棒
```

**直觉**：分割任务里"车道线"可能只占图像 5% 的像素，用逐像素 BCE 训练，模型学会"全预测背景"损失就很低。**Dice 是"区域级"指标**——它直接衡量预测区域和真值区域的重合度，类别再小也有明确信号。所以"BCE（逐像素细节）+ Dice（区域重合）"组合是分割标配。

### 1.4 BEV 感知特有损失

```python
# Depth Supervision Loss (BEVDepth):
# 用 LiDAR 点云投影到图像 → 得到稀疏深度真值
# → 监督 depth distribution 网络
L_depth = BinaryCrossEntropy(depth_pred, depth_gt_from_lidar)

# Ego-motion Loss:
# 自车运动预测 vs 实际 IMU/里程计
L_ego = SmoothL1(ego_pred, ego_gt)

# Planning Loss (UniAD):
# 碰撞惩罚 + 偏离目标惩罚 + 舒适度惩罚
L_plan = λ1·L_collision + λ2·L_deviation + λ3·L_comfort
```

> [!note] 三个特有意思的设计
> - **深度监督（BEVDepth）**：LiDAR 点云投影到图像上，得到"稀疏但真实的深度真值"（像素位置有 LiDAR 命中才有真值），监督深度网络。**用"贵传感器"的真值训练"便宜传感器"（相机）的深度估计**——这是数据闭环里的经典思路（[[数据闭环总览]]）。
> - **Ego-motion 监督**：让网络自报"车动了多少"，用 IMU/里程计当真值。为什么网络要学这个？因为 BEV 时序融合需要 ego-motion 对齐，与其外部给，不如让网络自己学（UniAD 里它真的自己学）。
> - **规划损失（UniAD）**：不是"预测得多准"而是"开得好不好"——撞没撞（碰撞）、偏没偏（偏离）、舒不舒服（舒适度）。**这是从"感知损失"到"驾驶损失"的思维转变**，端到端模型的标志性设计。

## 二、训练超参数调优——"训练的科学与玄学"

### 2.1 学习率策略

| 策略 | 公式 | 优点 | 适用 |
|------|------|------|------|
| **Step Decay** | lr = base × γ^(step/stepsize) | 简单 | Baseline |
| **Cosine Annealing** | lr = lr_min + 0.5(lr_max-lr_min)(1+cos(π·T/T_max)) | 平滑 | 主流选择 |
| **Linear Warmup + Cosine** | warmup: lr linear↑, then cosine↓ | 稳定 | 大模型 |
| **OneCycleLR** | 先升后降 + 最终退火 | 快速收敛 | 微调 |
| **CyclicLR** | 周期性升降 | 逃离局部最优 | 训练震荡时 |

> [!note] 为什么现在都用 Cosine + Warmup？
> - **Warmup（预热）**：训练一开始参数是随机的，梯度方向噪声极大，一上来就大学习率会"一步登天然后翻车"。先用小学习率走几百步，让参数进入"合理区域"再提速。
> - **Cosine（余弦退火）**：学习率像余弦曲线一样**平滑下降**，比 Step Decay 的"断崖式下降"更温和——每个阶段模型都在"微调"而不是"被砸一下"。
> - 组合逻辑：**Warmup 管开头（别翻车），Cosine 管全程（平滑收尾）。** 这是当前大模型/检测模型的事实标准。

```python
# 推荐配置
optimizer = AdamW(params, lr=2e-4, weight_decay=0.01)  # BEV 模型
scheduler = torch.optim.lr_scheduler.CosineAnnealingLR(
    optimizer, T_max=total_steps - warmup_steps, eta_min=1e-6
)
# warmup 在 trainer 中手动实现
```

### 2.2 优化器选择

| 优化器 | 适用场景 | 推荐 LR | 注意事项 |
|--------|----------|---------|----------|
| **AdamW** | Transformer, 端到端 | 1e-4 ~ 2e-4 | weight_decay=0.01~0.1 |
| **SGD + Momentum** | CNN (ResNet, CenterPoint) | 0.01 ~ 0.1 | momentum=0.9, 需要 LR warmup |
| **LAMB** | 超大 batch (8K+) | 1e-3 ~ 5e-3 | 自适应 LR per layer |
| **Adam** | 不建议 (无 decoupled weight decay) | — | 用 AdamW 代替 |

**关键区别：**
- **AdamW**：weight decay 直接作用于参数，**不与梯度耦合** → 更好的泛化。Transformer 类模型的默认选择。
- **SGD**：需要更仔细的 LR tuning，但**有时最终精度更高**（尤其是 CNN 检测器）——因为 SGD 的噪声天然带正则效果，不容易陷入尖锐极小值。

> [!note] 为什么 Transformer 几乎都用 AdamW？
> Transformer 参数多、结构深，Adam 类优化器（自适应学习率）对每类参数"自动调节步长"，训练稳定。而 SGD 在 Transformer 上经常收敛慢甚至发散。**经验法则：Transformer 家族 → AdamW；经典 CNN 检测器 → 两者皆可，SGD 有微弱的最终精度优势。**

### 2.3 Batch Size 影响

**Linear Scaling Rule（Goyal et al., 2017）**：

$$\text{batch\_size} \times N \rightarrow \text{lr} \times N \quad (\text{近似线性缩放})$$

> 例：$\text{bs}=32, \text{lr}=0.1 \rightarrow \text{bs}=256, \text{lr}=0.8$（但实际需要微调）

实际经验：
- 小 bs（2-8）：每步噪声大 → 需要大 LR 和更多 epochs
- 中 bs（16-64）：标准配置
- 大 bs（256+）：需要 LARS/LAMB 优化器
- BEV 模型：bs=4-16 per GPU 常见（显存限制）

> [!note] 直觉：batch size 是"每步用多少样本估计梯度"
> 梯度是"往哪个方向调参数"，但每步只能看到一小批样本，是**真实梯度的估计**。
> - batch 小 → 估计噪声大 → 步子（lr）要小点、多走几步（epoch 多），但噪声本身有正则效果。
> - batch 大 → 估计更准 → 步子可以大（lr 线性放大），但太大容易过拟合尖锐极小值。
> - **BEV 模型的现实约束**：一张图几百万像素、还要多相机 + 时序多帧，显存直接打满，bs=4-16 很常见——所以 SyncBN、梯度累积（gradient accumulation）这些技巧在 BEV 训练里是刚需。

### 2.4 EMA（指数滑动平均）——"白嫖"一个更好的模型

```python
# 维护一个参数的滑动平均版本，推理时使用 EMA 模型
class EMA:
    def __init__(self, model, decay=0.9999):
        self.model = model
        self.decay = decay
        self.shadow = {name: param.clone().detach()
                       for name, param in model.named_parameters()}

    def update(self):
        for name, param in self.model.named_parameters():
            self.shadow[name] = self.decay * self.shadow[name] + \
                               (1 - self.decay) * param.data

# 用途: 推理时 EMA 模型通常比最新 checkpoint 好 0.5-2%
# decay 选择: 0.999 (小 batch) ~ 0.9999 (大 batch)
```

> [!note] EMA 为什么有效？（直觉）
> 训练中参数在"最优解附近来回震荡"。EMA 维护一个参数的**历史加权平均**：`shadow = decay·shadow + (1-decay)·param`，相当于把震荡**平均掉**，得到一个更接近"谷底中心"的参数。就像给 volatile 的信号做低通滤波。
> **几乎零成本（只是复制参数）白赚 0.5-2% 精度**——所有量产检测模型的标配。

## 三、数据增强（BEV/3D 特有）——"无中生有"地变出数据

> [!note] 为什么增强在 BEV 里"处处是坑"？
> 2D 图像增强很成熟（翻转、裁剪、颜色扰动），但 BEV 训练**输入是多相机 + 3D 标签**——你动图像，就得同步动 3D 标签，否则标签就错了。
> **核心原则只有一条：任何增强都必须保持"图像 ↔ 3D 世界"的一致性。** 违反这条的增强，等于给模型喂错误标签。

### 3.1 2D 增强（在 BEV 中的特殊性）

```python
# ⚠️ BEV 中使用 2D 增强的陷阱:
# 如果只用相机数据做 BEV → 2D 增强直接可用
# 如果融合 LiDAR → 2D 增强需要考虑 3D 一致性

transforms:
  # 安全: 不影响 3D 几何关系
  - ColorJitter(brightness=0.3, contrast=0.3, saturation=0.3, hue=0.1)
  - RandomGaussianNoise(mean=0, std=0.01)

  # 谨慎: 会改变相机内参关系
  - RandomResizeCrop: 需同步调整相机内参矩阵

  # 禁止: 破坏多相机一致性
  - 逐相机独立 flip (除非所有相机同时左右翻转)
```

> [!warning] 逐条解读（每条都是血泪教训）
> - **ColorJitter 等颜色扰动：安全**。改颜色不改几何，3D 标签不受影响。
> - **RandomResizeCrop：危险**。裁剪会移动主点、缩放会改变焦距（像素焦距变化），**必须同步修改内参矩阵 K**，否则投影全错。
> - **逐相机独立 flip：禁止**。6 个相机只翻转其中一个，相当于这个相机"拍到了镜像世界"，和另外 5 个相机的几何关系全乱了——3D 标签在数学上对不上。

### 3.2 3D 增强——直接在世界空间里"动刀子"

```python
class BEV3DAugmentation:
    """BEV 感知的 3D 空间增强"""

    def __init__(self):
        # 全局旋转: 绕 Z 轴 (垂直轴) 随机旋转
        self.global_rotation = RandomRotation3D(
            angle_range=[-22.5, 22.5],  # 度
            axis='z'
        )
        # 全局缩放
        self.global_scaling = RandomScaling3D(
            scale_range=[0.95, 1.05]
        )
        # 全局平移
        self.global_translation = RandomTranslation3D(
            std=[0.5, 0.5, 0.1]  # x, y, z (米)
        )
        # 随机水平翻转 (镜像世界)
        self.flip = RandomFlip3D(
            prob=0.5,
            direction='horizontal'  # 左右翻转
        )

# 关键: 对点云和 3D box 标签同步变换
```

> [!note] 3D 增强的思路和 2D 完全不同
> 2D 增强是"处理图像"，3D 增强是**"把整个世界旋转/平移/缩放一下"**——点云、3D box、ego pose **全部一起动**，就像给整个场景换了个视角。因为世界是一起变的，图像和标签的一致性天然保持（前提：图像也要用同样的变换重新投影）。
> 注意只绕 Z 轴旋转（绕 X/Y 会违反"地面是平的"物理约束），缩放范围很小（0.95-1.05，防止尺寸语义被破坏）。

### 3.3 GT-Aug（Copy-Paste）——"复制粘贴"真实物体

```python
# 从其他场景 Copy 3D objects → Paste 到当前场景
# 模拟复杂交通场景，增加小目标密度

class GT_Augmentation:
    def __call__(self, scene):
        # 1. 从 database 随机采样 N 个 object (含点云 + 标注)
        objects = sample_from_database(n=5)

        # 2. 对每个 object:
        for obj in objects:
            # 放置到当前场景的可行区域 (路面)
            obj = place_on_ground(obj, scene.bev_map)

            # 碰撞检测: 不与已有 object 重叠
            if not check_collision(obj, scene.existing_objects):
                scene.add_object(obj)

        return scene

# 效果: 提升小目标和长尾类别的检测精度
# 使用时注意: TTA 时需要关掉 GT-Aug
```

> [!note] 直觉：把"别的场景里的车"搬进"这个场景"
> 数据集的痛点：很多场景里车太少了（稀疏路段），模型没见过"车多"的世界。GT-Aug 从数据库里**复制真实标注过的物体（点云+标签一起）**，粘贴到当前场景的空地上——数据量直接翻倍，还天然解决了"标注成本"问题（标注是现成的）。
> 为什么有效：**模型见过更多"车挤车"的场景，泛化更好**，尤其小目标（远处的车）密度大幅提升。

### 3.4 Camera Dropout——"训练时假装相机坏了"

```python
# 训练时随机丢弃某些相机视角
# → 模型学会利用多视角冗余信息

class CameraDropout:
    def __init__(self, drop_prob=0.1):
        self.drop_prob = drop_prob

    def __call__(self, images):
        mask = torch.rand(len(images)) > self.drop_prob
        images[~mask] = 0  # 将丢弃的相机图像置零
        return images, mask

# 效果: 对某个相机故障/遮挡更鲁棒
```

> [!note] 直觉：给模型做"断臂训练"
> 真实世界相机可能被遮挡、故障、进水。如果模型只在"6 个相机全好"时训练过，某天一个相机坏了，模型直接崩。Camera Dropout 训练时随机"弄瞎"某些相机，**逼模型学会用剩下的相机互相补充**——这是把"传感器失效"这个工程问题直接编码进训练（呼应 [[多传感器融合与故障降级]] 的鲁棒性思想）。

## 四、训练技巧

### 4.1 常用 Tricks 速查

| Trick | 作用 | 典型值 | 使用场景 |
|-------|------|--------|----------|
| **Label Smoothing** | 防止过拟合（把 one-hot 标签"磨圆"） | ε=0.1 | 分类任务 |
| **DropPath** | ViT/Swin 正则化（随机丢弃残差路径） | 0.1-0.2 | Transformer |
| **Gradient Clipping** | 防止梯度爆炸（梯度超阈值就截断） | max_norm=1.0 | 所有训练 |
| **SyncBN** | 跨 GPU 同步 BN 统计量 | — | 小 batch 训练 |
| **Weight Decay** | L2 正则化（参数向 0 收缩） | 0.01-0.1 | AdamW |
| **Warmup** | 稳定训练初期 | 500-2000 steps | 所有训练 |
| **SWA** | 模型权重平均（训练末尾多个 checkpoint 求平均） | — | 最终提升 |

> [!note] 两个容易误解的 Trick
> - **Label Smoothing**：把标签从 `[0,0,1,0]` 改成 `[0.03,0.03,0.88,0.03]`（ε=0.1 时），防止模型"过度自信"到把权重全押在训练集上（过拟合的极端形式）。
> - **Gradient Clipping**：梯度范数超 max_norm 就按比例缩回去。**防止一次"爆炸性更新"把参数冲到未知区域**——loss 突然出现 NaN 的常见原因就是梯度爆炸没被截住。

### 4.2 预训练策略

```
ImageNet Pretrain → 自动驾驶微调:
  1. 加载 ImageNet pretrained backbone
  2. 冻结 backbone 前几层 (通用特征)
  3. 只训练 FPN / Neck / Head
  4. 1-2 epochs 后解冻全部参数
  5. 用 1/10 的 LR fine-tune backbone

自监督预训练 (MAE/BEiT):
  - 在大量驾驶数据 (未标注) 上做 masked image modeling
  - 学习到驾驶场景的时序/空间表征
  - 比 ImageNet pretrain 在下游任务好 3-5%
```

> [!note] 为什么"先冻结再解冻"？
> 直接全参数微调：预训练学好的通用特征（边缘、纹理）会被很快"冲掉"，而且学习率不好把握。**先冻结 backbone 只训新加的头部**（FPN/Head 是随机的，需要先学起来），等头部有点样子了再解冻 backbone 用 1/10 学习率微调——**既有迁移效果，又不破坏预训练特征**。
> 自监督（MAE 等）在驾驶数据上预训练为什么更好？ImageNet 是"万物图片"，驾驶数据是"道路场景"——在**同域数据**上做自监督预训练，学到的是更贴合驾驶的表征（车辆、道路、遮挡模式）。

### 4.3 知识蒸馏——"大老师教小学生"

```python
# BEV 蒸馏: 大教师模型 → 小学生模型

class BEVDistillation:
    def __init__(self, teacher, student):
        self.teacher = teacher.eval()  # 冻结
        self.student = student

    def distil_loss(self, x):
        with torch.no_grad():
            t_bev = self.teacher(x)['bev_feature']  # [B, C, H, W]
        s_bev = self.student(x)['bev_feature']      # [B, C', H, W]

        # Option 1: L2 蒸馏
        loss = F.mse_loss(proj(s_bev), t_bev)

        # Option 2: Attention 蒸馏 (蒸馏 attention map)
        # loss = KL(t_attn || s_attn)

        # Option 3: Detection head 蒸馏 (更轻量)
        # loss = KL(t_det_logits || s_det_logits)

        return loss
```

> [!note] 直觉：学生模型"抄"老师模型的作业
> 老师（大模型，离线训好，冻结）知道的比标签还多——比如"这个框虽然标成车，但老师知道它更像卡车"（软标签里的信息）。蒸馏让学生**既学真值标签，又学老师的"判断倾向"**。
> 蒸馏的位置也很有讲究：**特征级（Option 1/2）教得深但代价大（要对齐特征维度），logits 级（Option 3）最轻量但信息少**。BEV 场景常用特征级蒸馏——老师把"BEV 空间的理解"直接传给小模型。

### FLOPs vs 显存 换算

**模型复杂度速查**：

- **FLOPs**：一次前向所需的浮点运算次数
- **参数量**：模型文件大小（影响加载速度）
- **推理延迟**：端到端推理时间（影响实时性）

典型换算（A100, FP16）：100M FLOPs ≈ 0.1ms（理论）；实际 ~30% 理论峰值（受内存带宽限制）。

显存估算：$\text{显存} \approx \text{参数量} \times \text{precision} \times \text{batch\_size} + \text{激活值}$

> 例：68M params × FP16 × bs=1 ≈ 136MB（参数）；激活值 ~200-1000MB（取决于输入分辨率）。

> [!note] 三个量别混淆
> **FLOPs**（算力需求，影响推理延迟）、**参数量**（存储需求，影响模型文件大小）、**显存**（训练需求，参数 + 激活值 + 梯度）。推理延迟不只看 FLOPs——内存带宽、访存模式往往才是瓶颈（这就是 [[模型部署与延迟优化]] 里"理论 FLOPs 远低于实际延迟"的原因）。

## 六、常见 Debug 流程——"训练崩了怎么办"

### 训练不收敛排查

```
1. 小数据集过拟合测试 (100 samples)
   → 确认模型有学习能力

2. Loss 曲线分析:
   - Loss 一开始就高且不降 → LR 太小 或 初始化问题
   - Loss 快速下降到 NaN → LR 太大, gradient explode
   - Loss 缓慢下降后震荡 → LR schedule 需要调整
   - Loss 下降但 val 不降 → 过拟合

3. 梯度检查:
   - 打印 gradient norm (每层的 L2 范数)
   - 正常范围: 0.01 ~ 10
   - 如果 > 100 → gradient clipping 需要更小 max_norm
   - 如果 < 1e-4 → vanishing gradient, 检查初始化和网络结构

4. 数据检查:
   - 可视化几个 batch 的输入和标签
   - 检查归一化是否正确 (range 检查)
   - 查看数据分布 (类别平衡, 位置分布)
```

> [!note] 第一步为什么是"先过拟合"？
> 如果模型连 100 个样本都拟合不了（loss 不降），说明**模型/数据本身有问题**（结构错误、标签错位、归一化错），这时候调学习率纯属浪费时间。**先证明"模型能学"，再讨论"学得好不好"。** 这 4 步的顺序是有讲究的：模型 → 损失 → 梯度 → 数据，从"最可能的根因"开始排查。

### 显存 OOM 排查

```python
# 模块化排查显存

import torch

def check_memory():
    print(f"Allocated: {torch.cuda.memory_allocated()/1024**3:.2f} GB")
    print(f"Cached: {torch.cuda.memory_reserved()/1024**3:.2f} GB")

# 逐步排查:
check_memory()
x = batch['img'].cuda()          # Step 1: 输入
check_memory()
feat = backbone(x)                # Step 2: Backbone
check_memory()
bev_feat = bev_encoder(feat)      # Step 3: BEV Encoder
check_memory()
loss = head(bev_feat)             # Step 4: Head + Loss
check_memory()
loss.backward()                   # Step 5: Backward (最吃显存!)
check_memory()

# 常见显存炸弹:
# - 激活值 (backward 时释放)
# - 时序多帧 (每帧都有激活值 → gradient checkpoint)
# - 大 resolution 特征图
```

> [!warning] 两个反直觉的显存事实
> 1. **backward 比 forward 更吃显存**——反向传播要保存中间激活值算梯度，所以 `loss.backward()` 那一步显存飙升是正常的。
> 2. **"释放"不等于"立即归还"**——PyTorch 的 `cached` 显存是保留复用的，OOM 要看 `allocated` 和峰值。排查时用上面的分步打印，找到"哪一步涨得最猛"，再针对优化（gradient checkpointing、降分辨率、减帧数）。

## 七、常见误区速查

> [!warning] 新手最常踩的坑
> 1. **损失函数乱选**——分类用回归损失、检测用逐像素损失……先明确任务类型再选损失，BEV 里"分类 + 回归 + 质量"往往是多损失加权组合。
> 2. **增强不同步**——2D 增强改了图像却不同步改内参/3D 标签，模型在学错误标签（BEV 增强的第一大坑）。
> 3. **LR 策略一刀切**——Transformer 和 CNN 的推荐 LR 差一个数量级（2e-4 vs 0.01），照抄别人配置前先看模型类型。
> 4. **不看 loss 曲线只看最终指标**——loss 曲线是训练健康的"心电图"，NaN/震荡/不降各有含义（详细排查见 [[训练排错实战手册]]）。
> 5. **混淆 FLOPs / 参数量 / 显存**——三个不同的东西，影响三个不同的资源。
> 6. **忘了 EMA**——几乎免费的精度提升，很多新手训完模型才想起来。

## ✅ 检验自己（自测题）

> [!question] Q1：Focal Loss 解决了什么问题？γ 调大调小分别有什么效果？
> 提示：想想"简单样本"和"难样本"的权重。

> [!success]- 参考答案
> 解决类别不平衡（如 BEV 网格大量背景 vs 少量目标）：标准 CE 会被海量简单样本（背景）淹没。Focal Loss 用 $(1-p_t)^{\gamma}$ 调制：预测越准的样本权重越小（简单样本少教）、越不准的权重越大（难样本重点教）。γ 调大 → 简单样本权重压得更狠、更聚焦难样本，但 γ 过大难样本权重也过强、训练不稳定；γ=0 时退化为标准 CE。

> [!question] Q2：GIoU → DIoU → CIoU 分别补上了前一个的什么短板？
> 提示：重叠度 → 中心距离 → 长宽比。

> [!success]- 参考答案
> GIoU：解决 IoU=0（不重叠）时梯度消失，用外包矩形补偿梯度；DIoU：GIoU 对中心点距离不敏感、收敛慢，直接把中心点距离加入损失；CIoU：DIoU 不管长宽比，再加长宽比一致性项 v 和动态权重 α。

> [!question] Q3：为什么 BEV 训练里"逐相机独立 flip"是禁止的？ColorJitter 为什么安全？
> 提示：从"3D 几何一致性"角度想。

> [!success]- 参考答案
> 逐相机独立 flip 只翻转其中一个相机，这个相机看到的是"镜像世界"，和其他相机的空间对应关系被破坏，3D 标签在数学上对不上（模型在学错误标签）。ColorJitter 只改颜色不改几何，所有相机的投影关系、3D 标签完全不受影响，所以安全。

> [!question] Q4：EMA 为什么能在推理时"白嫖"更好的精度？decay 大小怎么选？
> 提示：参数在最优解附近震荡，平均掉震荡会怎样？

> [!success]- 参考答案
> 训练中参数在最优解附近来回震荡，EMA 维护参数的历史加权平均（shadow = decay·shadow + (1-decay)·param），把震荡平均掉，得到更接近"谷底中心"的参数，推理时用它比用最新 checkpoint 更稳，通常白赚 0.5-2%。decay 越大越平滑但对最新变化反应越慢：小 batch（噪声大）用 0.999，大 batch（噪声小）用 0.9999。

> [!question] Q5：训练不收敛，排查顺序应该是什么？为什么"先过拟合小数据集"排在第一位？
> 提示：从"最可能的根因"排序。

> [!success]- 参考答案
> 顺序：① 小数据集过拟合测试（先证明模型能学）；② Loss 曲线分析（LR 太大/太小/过拟合）；③ 梯度检查（gradient norm 范围 0.01~10）；④ 数据检查（可视化输入标签、归一化、分布）。先过拟合排在第一位，是因为如果模型连 100 个样本都拟合不了，说明是模型结构/数据/标签的根本问题——这时候调学习率纯属浪费时间，先排除"模型本身坏没坏"。

## 🛠 动手练习

### 练习 1：手算 Focal Loss（20 分钟）

给定一个二分类样本，模型预测正类概率 $p=0.9$（这是难样本还是简单样本？），真值 $y=1$。
1. 计算标准 CE 损失：$-\log(0.9) = ?$
2. 计算 Focal Loss（γ=2）：$-(1-0.9)^2 \cdot \log(0.9) = ?$
3. 对比两个损失，说明 Focal 把权重降到了多少。

> [!tip] 算完你会发现
> $0.1^2 = 0.01$——**一个 90% 置信的简单样本，Focal Loss 把它的贡献压到 1%**。这就是"忽略简单样本、聚焦难样本"的数字证据。

### 练习 2：动手训练一个小模型观察 LR 效应（30-60 分钟）

用 [[计算机视觉基础]] 练习里的 TinyCNN（MNIST）做实验：

```python
import torch
import torch.nn as nn

# 用上一篇文章的 TinyCNN（略）

# 实验 1: lr 太大 → 观察 loss 发散/震荡
opt = torch.optim.AdamW(model.parameters(), lr=0.1)
# 实验 2: lr 太小 → 观察 loss 几乎不动
opt = torch.optim.AdamW(model.parameters(), lr=1e-6)
# 实验 3: 标准配置 + Cosine + Warmup → 观察平滑下降
```

每个实验只训练 2 个 epoch，打印每 100 步的 loss，画成曲线。**目标**：用眼睛认识"lr 太大/太小/合适"三条 loss 曲线的形状——这是以后排查一切训练问题的直觉基础。

### 练习 3：写一个带 3D 一致性的增强（进阶，可选）

给定一张 BEV 场景（点云 + 3D boxes），实现"全局绕 Z 轴旋转 θ 度"：
1. 3D box 的中心和朝向都旋转 θ。
2. 点云坐标全部旋转 θ（旋转矩阵 `[ [cosθ, -sinθ], [sinθ, cosθ] ]` 作用于 x-y 平面）。
3. 验证旋转后 box 和点云的相对位置关系不变（点云是否还在 box 内）。旋转矩阵用 `R = [ [cosθ, -sinθ], [sinθ, cosθ] ]` 作用于 x-y 平面。

> [!tip] 做完后自问
> 如果只旋转点云不旋转 box，会发生什么？（标签错位，模型学到错误对应——这正是"增强必须一致"的现场演示。）
